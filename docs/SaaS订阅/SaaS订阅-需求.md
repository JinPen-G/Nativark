## 1. 目标、范围与文档关系

### 1.1 产品目标

1. 商户能够准确知道自己使用什么版本，以及当前套餐的统一系统有效期；不需要分别续基础服务和 PRO。
2. 商户能够理解 PRO 相比基础版增加什么、哪些功能已可用、哪些仍在规划，以及是否适合自己的品类。
3. 商户能够从管理后台查看标准套餐价、提交升级 / 续费申请、查看处理结果，也可联系 SaaS 管理员线下办理。
4. SaaS 管理员能够直接为租户设置版本和有效期，记录线下收款 / 其他明确办理依据与变更历史；租户申请不是直接开通的必经前置。
5. 到期、降级及模块停用保护既有订单、合同、资金、证据与未决业务，避免因订阅变化无法归还、退款或结算。

### 1.2 本专项首期必须交付

- 基础版 / PRO 版的租户级套餐、统一期限与按年服务模型。
- 租户后台独立「版本与订阅」页面、PRO 介绍 / 对比页面、升级及续费申请、申请详情与处理记录。
- 租户小程序读取同一版本 / 期限和实际权益，提供只读版本入口、菜单 / 页面授权控制、到期提醒与授权刷新。
- SaaS 管理员的租户订阅管理、申请处理、线下到账备注与直接开通 / 续期 / 设置期限。
- 专业功能目录：版本归属、适用品类、上线状态、外部费用及启用前提。
- 统一的版本权益判定、到期与降级规则，以及在途业务保护。
- 管理后台与既有客户 / 员工业务入口的一致边界；客户侧不展示商户的订阅价格和内部申请。
- 历史租户的兼容初始化、基础操作记录、租户后台左下角到期浮窗及明确的验收场景。

### 1.3 首期明确不开发

- 任何新的 PRO 专业业务模块，包括专业会员 / 企业合同价、额外审核和四品类专业作业等；全部暂缓，日后另行启动，目录和授权框架不能代替实际功能。
- SaaS 自助线上支付、自动扣费、自动续订、销售佣金、订阅财税系统和自动发票。
- 自动试用 PRO、自动发放固定优惠、自动宽限期及自动退款；升级按剩余期间补差，首期管理员依据标准价人工核对，不建设复杂余额抵扣系统。
- 专门客服 / 财务 / 授权开通角色、多级审批、逐租户报价谈判和在线报价接受状态机。
- 按每个品类模块单独收费的复杂商城、空间混合版本、订单量抽成。
- 智能柜、车联网、保险等真实外部设备或服务的接入。
- 因版本规划删除已有基础版功能，或另建一套租赁订单和资金流程。

### 1.4 文档关系

- 基础租赁经营、品类与历史快照继续遵守[多品类租赁平台需求说明](../管理后台/管理后台-需求.md)。
- 本文件专门细化 SaaS 商户版本、订阅、有效期、PRO 目录与升级；不改变租赁客户会员等级和客户付费会员。
- 既有 §3.7 / §3.8 专业扩展是功能储备，版本归属按本文件梳理，上线仍须逐模块验收。
- 开发状态、子任务、依赖和验收证据统一维护在[SaaS 版本订阅与 PRO 升级专项开发任务](SaaS订阅-开发任务.md)；[后台开发任务](../管理后台/管理后台-开发任务.md)仅保留入口，本文件不记录代码完成率。
- 本专项不把现有文档中的「已开发」「已注册 capability」「已通过静态检查」等同于已可售或已可经营。
- 租户小程序页面定位遵守[租户端小程序需求说明](../小程序/员工小程序/员工小程序-需求.md)，本专项定义其中 SaaS 版本框架规则；进度仍由独立专项的 `SUB-MP-*` 唯一维护。

## 2. 基本概念与版本原则

| 对象 | 定义与范围 |
| --- | --- |
| SaaS 租户 | 购买系统使用权的租赁商户，版本和订阅归属于此对象 |
| 基础版 `standard` | 当前基础租赁经营能力及其已承诺的完整闭环 |
| PRO 版 `pro` | 基础版全部能力，加已交付并授权的专业经营扩展 |
| 当前套餐 | 租户当前适用的基础版或 PRO；同一时点只能有一个生效套餐，空间不单独购买版本 |
| 系统有效期 | 当前套餐统一的开始与截止时点；PRO 不另设扩展到期日，套餐到期影响该套餐的所有新增业务 |
| 服务状态 | 待生效、有效、即将到期、已到期或历史待确认；与基础版 / PRO 版本名称分别展示 |
| 功能目录 | 描述功能属于哪个版本、适用品类、交付状态和外部依赖；与空间能力配置分别管理 |
| 功能下放 | SaaS 管理员使原本归 PRO 的功能可供基础版使用；租户套餐 / 期限不因此改变，实际使用仍需功能上线、品类与业务前提满足 |
| 单租户额外授权 | 公共功能仍归 PRO，但 SaaS 管理员只向指定租户授予该功能；其他基础版租户不受影响，不引入第三种系统版本或第二套系统期限 |
| 升级 / 续费申请 | 商户的购买意向和办理记录，不表示已付款或已开通 |
| SaaS 办理记录 | SaaS 管理员设置版本 / 有效期、记录标准价和实际线下收款或其他明确依据的简单记录；不得混入客户租赁订单、押金或企业授信账 |

原则：

1. 对外只有基础版和 PRO 两个系统版本。「已到期」「待开通」「试用」是服务状态，不是第三个版本。
2. 基础版和 PRO 均按年收费，采用公开标准套餐价；租户统一订阅，PRO 包含各适用品类已发布的专业软件功能，不逐空间或品类再出售 PRO 版本。
3. 租户升级覆盖该租户适用空间，新建空间继承版本资格，但仍须配置品类、权限、依赖和实际服务条件。
4. 基础版可独立完整经营；既有基础版功能的缺陷修复、已承诺闭环和基础安全要求不转为 PRO 收费项。
5. 有 PRO 资格不等于模块已上线、空间已启用或员工有操作权限。
6. 升级不自动改价、不自动发布配置、不自动启用硬件或高风险业务、不反向更改历史订单。
7. 未实现、未验收或未完成外部接入的功能必须说明状态，不承诺购买 PRO 后立即可用。
8. PRO 统一软件权益不等于账号、空间、存储等资源无限；容量额度另行确认。短信、外部签章、保险、硬件和外部接入费用明确另计，不自动扣款；未来功能收费范围须明确告知。
9. 本文功能矩阵列出默认版本归属，不把专业功能永久锁在 PRO。管理员下放后，实际权益、介绍和业务检查统一按已发布配置判定，PRO 继续包含基础版权益。

## 3. 基础版与 PRO 功能边界

### 3.1 通用功能矩阵

| 领域 | 基础版必须保留的范围 | 默认 PRO 增强范围（允许下放基础版） |
| --- | --- | --- |
| 商品、资产、库存 | 型号 / 分组、序列化和数量库存、套装、预约与分配、现有入库盘点调拨报损范围 | 指定具体资产预约、专业资产健康 / 寿命与高级经营分析 |
| 价格与优惠 | 当前基础价、日期价、阶梯、封顶、使用量适用模型、已实现的营销 / 券 / 会员金额权益 | 独立会员价、企业合同价、高价值特殊价格及相应授权 |
| 订单与履约 | 报价下单、确认、配货领取、续租、变更、部分归还、取消及结算；开放的配送 / 寄送按既有任务完成闭环 | 高价值 / 特殊价格额外审核、项目清单和复杂服务协同 |
| 交接与异常 | 基本检查、附件清点、照片证据、建议费用、审核、客户确认 / 申诉、人工处理与退款 | 多人高价值交接链、专业检测、事故理赔和复杂事后费用 |
| 资格与可出租条件 | 经营场景必须具备的人工核验、必要证照和有效性检查、停运与检查门禁 | 批量资格作业、外部核验、专业复审与管理分析 |
| 清洁与维修 | 人工工单、隔离、检查验收、恢复可租及基础处理记录 | 周期 / 使用量触发、健康趋势、专业养护计划和成本分析 |
| 企业业务 | 企业主体、人工审核、现有权益、已承诺的授信和月结闭环，不因新增 PRO 被删减 | 专属合同价、复杂合同及项目协同等独立增强 |
| 官网 / 小程序 / 员工端 | 已交付的基础预约与现场操作；能执行已承诺基础业务 | 已交付的项目化、专业服务、自助与设备相关能力 |
| 报表与凭证 | 现有基础经营报表、业务凭证、必要历史查询和授权导出 | 资产投资回报、项目贡献、采购淘汰和跨空间经营分析（后续专项） |

说明：矩阵规定版本归属，不表示表中所有功能目前已实现；基础使用量、寄送、授信等继续完成原任务，不以本专项更改其交付状态。基础成本口径、专业收益分析等新增建议先列储备，另立需求后实施。

### 3.2 品类专业扩展目录

以下为规划归属，首次录入默认「规划中」；只有逐项实际验收并获准销售后才能转「已上线」。不能把同一行所有能力一次标为已交付。

| 模块 | PRO 规划功能 | 基础版必须保留的基础处理 |
| --- | --- | --- |
| 摄影专业经营 | 电池健康 / 校准、配置复位作业、项目器材清单、数据介质作业、高价值双人交接 / 封箱 / 多次转交责任链 | 已有兼容核对、附件清点、基础检查 / 养护、客户数据处理确认和异常责任 |
| 露营专业经营 | 专项卫生作业、装备寿命、多人尺码与人员清单、环境适配 / 活动清单 | 发现霉变等风险后隔离，基本清洁晾晒、缺件 / 耗材区分和必要安全处理 |
| 车辆专业经营 | 多驾驶人作业、专业事故理赔 / 救援替换流程、事后费用、整备计划、自助取还 / 围栏 | 必要驾驶 / 车辆证照、车况与里程油电、事故和故障人工处理及既有交接 / 整备底线 |
| 工程专业经营 | 属具专业匹配、项目进场管理、施工日报、停机责任管理、运输方案、人员班组、遥测诊断 | 必要操作资格 / 检验、基本现场条件、工时和故障证据、已销售服务的安全履约与结算 |
| 跨品类专业经营 | 人员排班、专业物流调度、周期维修、电子签章、自助设备、IoT、外部保障 / 保险流程 | 基础服务履约 / 人工凭证、必要条款确认、收退款和异常处理 |

### 3.3 功能目录最低信息

每项功能维护：功能标识、名称、默认归属、当前已发布权益归属及生效时间、模块、适用品类、客户价值、具体范围、前提条件、上线状态、外部费用说明、介绍内容版本和变更历史。默认归属用于规划，当前归属用于实际使用，不在业务逻辑中固定写死为 PRO。

上线状态至少包括：

- `planned` 规划中：可在路线图介绍，不计入当前可购买权益。
- `pilot` 受控试点：写明需申请、适用范围及未验证边界，不向所有 PRO 商户默认开放。
- `released` 已上线：有实际验收，符合条件的租户可申请启用。
- `paused` 暂停新启用：说明原因，已成立业务继续按善后规则处理。
- `retired` 已停止新使用：保留历史查询和既有业务处理，不删除历史事实。

SaaS 管理员可以把 PRO 功能下放给基础版，按 §3.5 明确适用范围并保存。该能力不授权把基础版既有承诺功能静默转为收费、停用或删除；目录的上线状态与收费归属分别维护，修改归属不能把未交付功能改成已上线。

### 3.4 首批交付与 PRO 正式销售条件

- 已确认采用「摄影、露营、车辆、工程四品类各交付一批，再正式销售 PRO」，不采用仅摄影上线就面向全部品类售卖的顺序。
- 每个品类须确定一个首批专业业务包，写明具体功能、适用商户、启用条件、完整流程和异常出口；至少有可完成的专业业务场景，不能只有介绍页或新增字段。
- §3.2 是储备目录，不表示四品类全部规划功能同时开发。各品类首批具体清单、试点商户和排期仍须按第 14 节确认。
- 四个首批业务包逐类验收通过、标准价格和销售清单发布后，SaaS 管理员才能按该销售清单收费开通 PRO。销售清单按当前归属维护，已下放基础版的功能不重复作为该租户的 PRO 独占卖点；若已无实质额外权益，不售卖空壳升级。
- 订阅页面和管理功能可先开发；条件未满足时只接受升级咨询或有明确范围的受控试点，不收正式 PRO 升级费。单个模块完成不自动代表 PRO 正式销售已放行。

### 3.5 PRO 功能下放给基础版

1. 已确认支持 PRO 功能可供基础版使用；同一项功能复用同一业务流程、配置和历史，不另开发「基础版缩水副本」，也不把基础版租户整体标为 PRO。
2. 两种范围均已确认纳入首期：公共下放修改基础版套餐的公共功能清单，影响全部符合条件的基础版租户；单租户授权保持公共归属为 PRO，只给选定基础版租户额外开放。两种操作必须明确区分，不把单租户特批扩散给所有租户。
3. 办理由现有 SaaS 管理员操作，不增角色或多级审批。公共下放在功能目录中设置「基础版可用」并显示「影响所有基础版租户」；单租户授权在租户订阅详情的「额外功能授权」中勾选已上线 / 可试点功能，显示「仅当前租户」。保存记录功能、范围、生效时间和原因，不要求审批人；首期保存后生效，不增加定时发布状态机。
4. 功能下放不改变标准套餐价、租户版本或统一有效期，不自动退款 / 续费 / 开启空间配置；期限已过的基础版租户仍不能新增使用下放功能。首期单租户授权依附租户有效订阅，不设单独到期日。暂时到期不删除授权配置，正常续费后重新核验功能前提；管理员明确撤销时记录原因并保护既有承诺。
5. 下放只对已上线或明确受控试点的功能有效；适用品类、资格 / 安全、操作权限、必需配置及外部服务费用继续有效。已上线单项功能可以按明确范围下放，但不代表四品类 PRO 首批销售条件全部通过。
6. 租户页面清楚区分「基础版已包含 / 已获授权」与「仍需 PRO」。被下放的功能不能继续列为该租户必须升级才可用的独占卖点；介绍、权限和各端入口保持一致。
7. 公共下放后 PRO 租户继续可用，因为 PRO 包含基础版权益。不重算原订单和套餐费用，不删除专业记录，不因调整归属解除已知风险。
8. 将已下放功能重新收回或改为仅 PRO 时，不允许直接静默撤掉既有承诺；须另明确生效范围、租户告知及历史 / 在途业务保护，首期不把该动作当作无影响的目录编辑。
9. 功能来源分别显示「基础版公共权益」「租户额外授权」「PRO 权益」。当前可用功能按生效套餐公共权益与该租户有效额外授权的并集判定，再检查功能交付、品类、空间配置和操作权限；不会因单项特批把其他 PRO 功能一起开放。
10. 公共下放后基础版 / PRO 对比同步更新；单租户授权仅改变该租户的当前权益说明，公共套餐介绍仍保持原归属。PRO 租户同样保留已记录额外授权，后续接续基础版时按有效订阅和授权记录使用，避免错误丢失。

## 4. 订阅、有效期与使用状态

### 4.1 时间口径

1. 每个租户的当前套餐统一保存版本、开始时点、截止时点、来源和变更记录；不分别设置系统 / PRO 两套期限。续费和未来降级可登记下一段套餐，授权段不冲突、不同时生效。
2. 统一采用 `[开始时点, 截止时点)`。截止时点到达即过期，界面同时显示日期、时间及时区；剩余天数仅作辅助，不能替代准确截止时点。
3. 日期输入必须明确时区。租户订阅使用租户 / 平台约定服务时区，不随着当前空间切换；不能将空间营业日历用于 SaaS 到期计算。
4. 只录入截止日期时，界面说明「可使用至该日结束」，实际截止为下一日本地零点；不得把该日零点误当完整一天。
5. 正常售卖按年办理。SaaS 管理员可选服务年数并核对截止日期，也可直接填写明确起止时间；自定义期限用于已约定服务、试点、历史登记或临时延长，须记录原因，不据此新增月付商品。日历周年在目标年份无同日时取该月最后一日同一时刻，保存原计费周年锚点，避免闰年逐次续期漂移；保存前展示最终日期，不用固定 365 天替代每个服务年。
6. 首期所有正常开通必须有明确截止时间，不提供「永久」快捷开通；日期缺失显示待确认，不解释为永久有效。已有特殊长期承诺须按历史登记政策处理。
7. 首期不默认开启 PRO 试用。后续试用仍属于 PRO 的有期限授权来源，需单独确认试用规则。

### 4.4 升级、续费与降级

- 升级只改变未来可使用权益，不修改既有报价、订单、客户承诺和空间配置。
- 有效基础版升级为 PRO 后保持原统一截止时间；同一计价口径下，补差金额按「PRO 与基础版完整周期价格差 × 剩余期间 / 完整期间」核对。首期 SaaS 管理员依据已发布标准价、实际计费段和约定优惠人工核对，保存本次金额与期间，不建设余额钱包；没有有效基础套餐时不能只交升级差价获得全年 PRO。
- 同时升级和续费时分别写明本期补差、下一年度套餐费与接续时间，办理后仍只有一个当前生效套餐和统一到期日。
- 有效期内续费优先接续当前截止时点；已过期的续费按双方确认的新开始时点开通，不自动追补过去未提供的服务。
- 下期降级为基础版在当前 PRO 期限结束后生效，当前已付费期间保持 PRO 权益；基础版接续本身须有已确认的服务依据。仅申请降级或不续费不自动获得基础版授权。提前降级、退款和作废由 SaaS 管理员按约定处理，不默认自动退款。
- PRO 到期或降级后，专业配置和数据保留；当前套餐及明确授权不再覆盖的功能标记不可新增使用，已下放并被有效基础版覆盖的功能仍可用。再次授权时重新核验依赖，不自动发布旧配置。
- 原来因专业规则判断为危险、需检查或停运的资产，不得因降级而被放行；专业授权失效不能抹除已知风险。
- 到期业务限制在相关商业政策确认、租户期日核对并通知后启用；文档发布或迁移文件创建不自动触发营业停用。
- 已确认不设统一自动宽限期：套餐到期即停止新业务。付款核对、历史登记等特殊情况由 SaaS 管理员填写原因并设置新的明确截止时间，留变更记录；临时延长不伪造收款、不自动续费，也不解除安全冻结。

- 位置与形态已确认：租户管理后台全局布局的左下角小浮窗，基础版和 PRO 都提醒。不以顶栏摘要或只在订阅页面提示替代该浮窗；无全屏遮罩，不阻断正在进行的操作。
- 按视窗左下角定位并避开菜单、空间切换和主题等底部控件；窄屏保持小卡片形式，留安全边距和关闭入口，不覆盖主要操作按钮。
- 展示当前版本、统一到期时间、剩余天数或「已到期」、简短影响说明。租户管理员可点「续费 / 查看订阅」进入版本页；已有申请时显示「查看办理进度」。普通员工看到必要期限摘要和「联系管理员」，不展示金额、转账信息或内部备注。

- 建议默认在到期前 30 天进入提醒范围，以 7 / 1 天和实际到期为加重阶段；阈值可配置，具体数值属于交互默认建议，不是强制收费规则。只有期限事实完整才触发到期浮窗。
- 提醒范围内，当天首次进入后台自动展示，持续登录跨日或跨提醒阶段也能更新。用户可关闭，同一账号 / 租户 / 授权修订 / 阶段当天不重复弹出；切换页面或经营空间不重弹。更紧急阶段或实际到期可再次提醒，关闭浮窗不改变业务限制。
- 管理员续费、升级或临时延长后重新查询最新订阅；不再满足提醒条件时立即撤下旧浮窗，仍临近新期限时改为新内容。不得继续按旧到期日催续费。网络失败保留明确错误处理，不生成虚假的到期或永久有效状态。
- 首期实现后台浮窗、版本页状态和基础站内记录；短信 / 邮件另行接入。客户预约端不展示商户订阅金额和平台办理信息。

### 5.5 租户小程序的版本框架准备

| 入口 | 本期要求 |

| 「我的」版本摘要 | 当前基础版 / PRO、统一截止时间、服务状态；可进入「版本与权益」只读页面 |
| 「版本与权益」 | 当前套餐、期限、已获得功能及来源、功能是否已上线 / 需配置 / 规划中；按当前品类和空间展示适用性，但空间切换不改变租户套餐 |
| PRO 了解入口 | 租户管理员可查看已发布介绍、规划范围和联系平台方式；可复用已有咨询入口，不另建小程序支付 / 报价 / 开通流程。无可用扩展时明确待上线，不虚构可操作的专业模块 |
| 首页 / 工作台提示 | 两版临近到期和已到期均显示适合手机的小提示卡，点击查看版本；「我的」保留状态。页面布局不覆盖扫码、主要作业按钮或底部导航 |

普通员工只查看必要摘要和与本人岗位有关的可用功能，提醒引导联系租户管理员；不默认展示年费、转账凭证、平台内部备注或全部商业办理记录。Web 的左下角浮窗要求保持不变，小程序采用移动端提示卡布局。

#### 5.5.3 功能入口与操作判定

1. 小程序从服务端读取当前套餐、统一期限、服务状态和实际功能权益，复用 §3.5 / §9 的公共权益与租户额外授权规则，不自行维护另一套套餐表。
2. 可用入口同时满足租户权益、功能交付、当前空间 / 品类配置和员工权限；租户是 PRO 不代表员工获得全部操作权，基础版特批也不连带开放其他专业功能。
3. 菜单隐藏或显示之外，直接进入页面、扫码 / 深链接、返回旧页面和提交动作也要检查当前访问资格；服务端仍执行最终校验，不靠前端隐藏保护功能。
4. 规划中的扩展无可用作业入口；可在介绍中标明规划，不能点击后当成已交付功能。专业模块日后开发时接入同一框架，不另建 PRO 小程序应用。
5. 到期停止新单等新增业务；已确认订单履约、归还及小程序原本有权执行的善后动作仍按原规则处理。订阅保护不能给员工额外的退款 / 资金执行权，也不能为补齐小程序业务而新增这些动作。

#### 5.5.4 授权刷新与提醒

- 登录 / 会话恢复、进入前台、切换经营空间、打开版本页或重新进入相关页面时刷新当前服务事实；升级 / 降级、续费、公共下放、特批 / 收回后，下一次刷新须反映新修订，不要求退出重登。
- 订阅到期由服务端按准确截止判断，不依赖客户端长期缓存。提交动作若返回权益变化 / 到期错误，小程序解释原因并刷新入口，不能保留可继续提交的过期权限。
- 提醒阈值与 Web 共享 §5.4 的配置，关闭轻提示按账号 / 租户 / 期限修订 / 阶段当天去重；跨日或更紧急阶段可再提醒。续费 / 临时延长后及时撤下旧提示或展示新期限。
- 查询失败、断网或过期缓存显示未能刷新，不虚构基础版、PRO、永久有效或已到期。已有只读缓存不能授予关键写操作权限，仍按现有联网校验处理。
- 跨租户、退出登录和切换账号清除或隔离缓存 / 提醒关闭记录；同一租户切空间更新空间适用功能，不覆盖成另一个租户的权益。迟到请求不得覆盖新会话 / 空间事实。

## 6. PRO 介绍与版本对比

1. 介绍至少包括：适合哪些商户、可解决的经营问题、基础版 / PRO 差异、品类专业模块、当前可用功能、后续路线图、费用与启用条件、常见问题、升级入口。
2. 将「当前可购买」和「规划中 / 受控试点」分开展示；规划项不得计入本次办理的承诺交付功能。
3. 对每个功能给出可理解的业务示例，例如高价值器材交接、多驾驶人、施工日报；页面不展示 capability code 或内部实现版本作为销售文案。
4. 价格已发布时展示标准年费、币种、含税 / 未税口径、升级补差和外部费用边界；价格未发布时显示「价格待公布 / 联系平台」，不展示 0 元、虚构原价、折扣或自动试用天数。
5. 基础版能力、PRO 增强范围和当前授权目录使用同一份已发布销售内容，保存内容版本；变更介绍不反向更改已成立的服务承诺。
6. PRO 介绍页面的「申请升级 / 联系平台」与版本页进入同一办理流程，保留来源便于追踪，不形成两套申请；未满足四品类销售条件时明确标为咨询。
7. 可查看全部品类介绍，也可筛选自己经营的品类；未经营品类标明需要相应空间和运营准备，不承诺升级自动开出该品类。
8. 不宣传已投保、已接通设备、提升某个百分比等未经实际证明的效果。

## 7. 升级、续费申请与首期办理流程

### 7.1 已确认的首期简化流程

`查看标准套餐 / 联系平台或提交申请 → 线下转账 → SaaS 管理员核实到账 → 选择租户、套餐和有效期 → 保存开通 → 租户查看结果`

首期只有 SaaS 管理员负责办理，不拆客服、财务、开通角色，不做多级审批。管理员可以直接在租户订阅页面开通，租户线上申请不是必需前置；申请用于保留升级入口和处理进度，不要求再走在线报价接受流程。

正常收费按已发布标准套餐价执行，特殊折扣由 SaaS 管理员记录金额及原因。租户提交申请或上传转账凭证不会自动开通；管理员核实真实到账后保存版本及期限。受控试点、历史登记或临时延长须明确来源，不伪造已付款。

### 7.2 申请表

| 字段 | 规则 |
| --- | --- |
| 申请类型 | 升级 PRO、续购基础版、续购 PRO、升级咨询、申请下期基础版、到期不续费 |
| 当前版本和期限 | 只读，由当前租户事实取得 |
| 目标 | 根据申请类型确定，不能借自由文本直接改版本 |
| 希望使用的模块 | 按适用品类多选，只表达意向，不自动启用或保证规划项交付 |
| 联系人 / 联系方式 | 可回填当前授权联系人，允许确认；与营销授权分别处理 |
| 意向期间 | 从已发布的按年服务方案选择；价格未发布时只记录咨询意向，最终以管理员办理结果为准 |
| 需求说明 | 可选，记录规模、需求和期望时间，不要求商户填租赁客户信息 |
| 确认说明 | 清楚告知申请不等于开通、外部费用可能另计，以及当前可用 / 规划范围 |

提交成功返回真实申请编号和状态；失败保留填写内容并说明原因。同租户同类型未关闭申请防重复；网络重试返回同一申请。租户可撤销未办理申请，已实际收款或已完成开通时需联系 SaaS 管理员处理，不伪造退款。

### 7.3 申请状态

| 状态 | 含义与下一步 |
| --- | --- |
| 待处理 `pending` | 等待 SaaS 管理员办理，可联系平台或撤销 |
| 已办理 `processed` | 关联实际开通、续费、下期降级或不续费登记；未来生效的业务另显示具体生效时间，不冒充已生效 |
| 已拒绝 `rejected` | SaaS 管理员拒绝，显示可公开原因 |
| 已撤销 `cancelled` | 撤销未办理申请；已有资金须另处理 |

不设报价中、等待报价接受、财务审核等额外状态。申请已办理不等于收款成功或套餐已生效，应展示真实办理结果和生效时间；到期不续费登记不提前停止当前已付费服务。

### 7.4 线下收款与直接开通

- 正常办理保存租户、套餐 / 价格方案版本、起止时点、本期金额、币种 / 税口径和实际收款备注；升级记录补差口径，优惠记录原因。首期不要求先创建报价单、在线接受或建设完整财务系统。
- SaaS 收款以平台收款账户和平台商业记录为依据，不使用商户支付配置，不进入客户租金 / 押金账。
- SaaS 管理员核实线下到账，可填写转账日期和备注，凭证附件按需提供；上传凭证不等于核实到账，不要求另一个角色复核。
- 保存前核对租户、目标套餐、起止时间、办理依据和当前授权；正常收费 PRO 还须满足四品类首批销售条件。
- 收款已核实但开通保存失败时明确「已核实收款、未开通」，管理员可重试，不要求租户重复付款，不把失败写成退款或已生效。
- 人工开通、续期、降级或变更期限保留基础操作记录；同一保存重试不重复延长，不增加审批层级。
- 自助线上支付后续单独启用，须另验收平台商户账户、收费订单、回调、退款和对账，不能复用消费者支付成功状态当作 SaaS 开通。

## 8. SaaS 平台管理端

### 8.1 订阅管理入口

建议在「平台管理」下增加「租户订阅」，建议路由 `/platform/subscriptions`；租户管理详情保留关联入口，但不混入经营空间编辑表单。

列表至少显示：租户名称 / 编码、当前套餐、服务状态、统一截止日期、剩余天数、待处理申请和最近办理；按版本、状态、到期范围和租户筛选。

详情至少包含当前套餐 / 期限、直接办理表单、额外功能授权、申请记录、线下收款 / 办理备注、历史和待生效套餐；无需拆多个审核工作台。

直接办理表单至少包括：目标租户、办理类型、基础版 / PRO、开始日期、服务年数或自定义截止日期、办理来源、实际收费金额 / 转账备注（收费办理时）、调整原因。选择服务年数后展示推算的截止日期，管理员可以按约定修改并确认。开始不得晚于截止；租户端不能编辑这些字段。

### 8.2 平台可执行动作

- SaaS 管理员查看 / 处理申请，直接为选定租户开通基础版或 PRO，不要求租户先提交申请。
- 同一个 SaaS 管理员核实线下到账并填写办理记录，或录入明确的试点 / 历史登记依据。
- 设置有效期、续期、登记下一期套餐及降级、不续费；特殊情况填写原因后临时延长，不设置自动宽限或永久快捷开通。
- 纠正错误期限或提前撤权需确认操作、说明原因并保留历史；使用同一管理员权限，不增加另一审批角色，不能悄悄覆盖已承诺期限。
- 发布 PRO 介绍和可销售功能目录；规划内容、试点和已上线严格区分。
- 在功能目录中公共下放 PRO 功能，或在租户订阅详情仅给该租户额外授权；保存前显示影响范围，不要求给租户整体升级。
- 查看已核实收款但未开通、期限冲突等结果并重试；不建立独立客服 / 财务审批任务。

平台不能通过订阅操作替代安全冻结、修改租赁规则、删除经营数据，或直接操作租户的客户资金。

## 9. 版本授权、空间能力与历史保护

### 9.1 新增专业业务的判定

新增专业动作同时满足：租户当前套餐有效、该功能被当前套餐或明确授权覆盖、功能已上线 / 明确试点授权、适用品类、空间已启用、必需配置与外部条件完整、操作人具备权限、业务动作本身可执行。

订阅授权、功能交付、空间启用和人员权限分别给出拒绝原因。直接请求、后台、客户自助、员工端、自动任务和外部调用遵循同一事实，不能只靠隐藏按钮收费。

### 9.2 既有业务保护

- 新专业订单或变更保存当时功能、授权来源和适用条款快照，便于区分新增使用与履约收尾。
- PRO 到期后允许完成到期前已成立专业订单、已承诺交接链、既有理赔 / 维修 / 签署流程；不得把创建时间字段伪造为早于到期来绕过。
- 到期前创建但尚未确认的普通申请、项目草稿、未接受报价等不自动获得永久专业使用权。
- 已确认未来租赁订单继续按承诺履约；新的专业项目、续租或扩大需求重新检查授权。
- 专业模块停用不删除数据，不解除已知资产风险，不重算历史价格；未交付新功能也不能用历史快照放行。
- 订阅判断失败、配置缺失或服务异常时明确提示；不能默认为 PRO、永久有效或已开通。

复用现有 SaaS 管理员、租户管理员和员工身份，不为本专项新增客服、财务、授权经办人、专门开通人员等角色，不建设多级审批链。

| 现有身份 | 首期操作范围 |
| --- | --- |
| SaaS 管理员 | 查看租户订阅，处理申请，核实线下收款，直接开通 / 升级 / 续费 / 设置期限 / 临时延长 / 登记降级，维护标准价 / 介绍、公共下放功能及指定租户额外授权 |

订阅归租户，空间管理员身份不能自行改变整个租户的版本。租户之间的申请、办理记录和附件相互隔离；租户页面不显示平台内部备注。SaaS 管理员的操作范围沿用现有平台管理规则。

保留最少必要操作记录：租户、操作人、时间、操作类型、版本 / 期限前后值、办理来源 / 原因；正常收费办理附实际金额和转账备注。功能下放记录功能、范围、生效时间和前后权益；申请处理、价格和目录发布也留基础记录。不要求额外审核人、二次审批或专门审计工作台；通知不能替代真实开通结果。

### 11.2 接口最低能力

- 当前租户订阅概览、当前可用权益、已发布 PRO 介绍 / 版本对比。
- 租户小程序的只读订阅 / 权益摘要、服务状态与修订号，通过既有员工身份和数据边界访问；不向该门面暴露管理员开通 / 修改期限 / 授权接口。
- 当前租户申请列表 / 提交 / 撤销 / 详情、标准套餐价和办理结果查看、浮窗提醒及关闭状态。
- SaaS 管理员查询租户订阅与申请、直接开通 / 续期 / 设置期限 / 临时延长 / 登记下期降级、价格及目录发布、基础版公共功能配置和指定租户额外授权。

- 具体路径与 DTO 在开发时落入平台业务入口及共享契约，契约包含错误原因、可执行动作、分页和幂等标识。
- 申请提交及管理员办理的重试和并发受保护；同一保存最多产生一次有效授权。另一管理员已更新期限或价格时提示刷新，不覆盖新结果，不重复收费或续期。
- 时间经过后的有效版本立即正确，不能依赖每天定时任务才过期；任务主要负责通知、排期与异常跟进。
- 功能判断统一读取当前套餐权益及明确授权，不直接用「租户版本必须是 PRO」作为专业功能的唯一门槛；各入口共享同一已生效配置，不可只有页面展示放开而接口继续拒绝。

## 12. 历史租户与初始化

1. 初次部署先盘点历史租户和已启用功能，保留现行基础经营能力；不能因没有新订阅记录就批量停业。
2. 历史租户标记「订阅待确认 / 兼容运行」，不展示虚构付款、试用结束日或永久 PRO。
3. 原有已交付能力按基础版保留，不把现有 capability 注册 / 启用结果直接迁为 PRO 收费授权。
4. SaaS 管理员逐户补登记服务依据、当前套餐和统一期限；正式限制前通知租户并完成历史政策核对。
5. 新租户开通须明确服务来源与期限；默认基础版，不能从名称、演示空间或任意缺省值得到 PRO。
6. 试点 / 内部演练按明确来源登记，演示数据和模拟商业记录不计实际 SaaS 收款。
7. 初始化 / 补登记不得修改租赁客户会员身份、历史订单、资金、资产和已知停运状态。
