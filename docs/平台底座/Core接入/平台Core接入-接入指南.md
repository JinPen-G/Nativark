# 业务 Core 接入指南

版本：v0.1；日期：2026-10-31。

> **用途：提前给其他AI/开发者准备接手路径。** 平台跨行业Core合同及可运行样例尚未交付；本文不能作为当前已有SDK的操作手册，不含虚构安装包或启动命令。需求见[正式需求](平台Core接入-需求.md)，接口语义见[接口与生命周期设计](平台Core接入-接口与生命周期设计.md)，真实实现见[开发记录](平台Core接入-开发记录.md)，活动授权见[协作接续](平台Core接入-协作接续.md)。
> PCH-11须在工程实现时，将本指南补成可直接复现的步骤并经独立接手验证；本次文档不等于已完成该交付。

## 1. 先判断你要扩展什么

| 目标 | 正确入口 | 不应做 |
| --- | --- | --- |
| 摄影之外增加服装等租赁类型 | [品类治理需求](<../../Rental Core/品类治理/品类治理-需求.md>)、[任务](<../../Rental Core/品类治理/品类治理-开发任务.md>) | 为每个租赁类型重写Core |
| 为租赁增加新计费算法或专业流程 | 原Rental领域/策略/capability任务，明确业务与验收 | 只添动态字段就宣称新算法可用 |
| 平台承载CRM/TMS等另一业务领域 | 本专项PCH合同及新的业务Core | 把CRM当第五租赁品类，复用租赁状态机改名字 |
| 更换Agent运行框架或模型SDK | [原Runtime/SDK方案](<../../AI Native/未来规划/AI Native-Runtime替换方案.md>) | 与业务Core抽离捆绑实施 |
| 接入外部Agent客户端 | [MCP专项](../../MCP服务/MCP服务-需求.md)及具体Host合同 | 用传输可连接证明业务Core可替换 |

## 2. 接手前必须取得的信息

1. 读取[根AGENTS](../../../AGENTS.md)、[README](../../../README.md)、[文档导航](../../文档导航.md)，再读本专项四册、接口设计和目标Core业务需求。
2. 核对工作目录、分支、HEAD、暂存区、未提交归属、合并/拣选状态及并行写入者；仅在明确工作树/文件范围施工，不接管别人的WIP。
3. 取得获准的正式合同版本、平台宿主构建、目标Core范围、公共依赖和验证环境。没有合同/样例时先做PCH-01/02，不自行发明兼容SDK。
4. 明确本轮是否只读、文档、代码、离线验证或真实环境；文件里的命令不构成启服务、连库、安装、迁移或发布授权。
5. 涉及管理后台先读[admin规则](../../../apps/admin/AGENTS.md)和[界面规范](../../公共技术资料/界面规范/管理后台-界面规范.md)。不另建UI框架，不改vendor。

## 3. 接入顺序与每步出口

### 步骤一：定义业务边界

给出目标Core的对象、状态、人员角色、资源范围、正式命令、读写所有者、外部副作用及历史规则。明确哪些公共服务必需、哪些可选。

例如CRM样例可以用线索与跟进来验证接入，但字段、状态和允许转换须由样例业务合同确定；不能套用租赁领取/归还。客户身份共享与业务客户资料共享是不同决定，不能默认共表。

**交付：** 一页领域边界、依赖清单及代表链；不凭“CRM”名称推出完整CRM范围。

### 步骤二：登记Core与兼容要求

通过正式公共出口声明Core身份、实现/合同/数据版本以及后端、前端、事件/作业贡献。宿主组合显式选中，冲突ID和缺依赖拒绝。

**交付：** Core描述和装配配置；这里不接受运行时下载脚本、任意URL或模型生成包路径。正式包名/配置文件由PCH-02交付，当前没有可复制命令。

### 步骤三：接入当前身份和业务范围

消费原可信主体、租户和授权；提供本领域资源归属、权限资源/动作及范围解析。把用户传来的对象ID再交服务端验证，不信任前端的Core/租户/容器字段。

**交付：** 正常访问、受限范围、撤权、跨租户/跨audience及相同ID碰撞的正反例。缺授权适配保持不可用，不能用`true`临时通路证明接入。

### 步骤四：实现数据、初始化及正式动作

定义自己的仓储和前进迁移，经受限事务协调连接平台绑定。初始化不注入虚构经营事实；正式动作保留校验、对象修订、锁、幂等与原收据。明确失败发生在提交前还是提交后，unknown只核对原操作。

**交付：** 数据所有权和引用说明、真实持久化、同键重复/输入冲突/并发修改/失应答行为。外部调用与业务事务分开，不能因同进程就假设所有步骤原子。

### 步骤五：接公共服务与异步处理

按真实需要接权益、文件ACL、通知、审计、可靠事件及作业；不要为了“完整插件”安装不需要的依赖。文件归属、敏感投影和事件schema由Core明确，原回调定位原业务所有者。

**交付：** 依赖缺失/撤回、重复事件、迟到回调、重启与停用行为；没有真实供应商证据时标未验，不返回假成功。

### 步骤六：挂载业务UI

通过正式页面贡献入口提供路由、菜单、对象详情/动作链接、语言与权限声明。复用平台React/UIArc壳和缓存隔离；不修改公共壳内部去识别样例Core，不依靠改租赁标签实现新业务。

**交付：** 可操作真实页面、直接URL权限、空/错/加载态、未保存保护和绑定变化后的旧请求取消。浏览器验证和代码/类型证据分别登记。

### 步骤七：按需接AI/工具

普通页面业务先独立可用。确需AI时，登记严格输入输出、事实来源、字段释放、风险/副作用、业务批准与原收据查询，并由原通用任务和Gateway机制消费。MCP与Harness只经各自正式受控合同接入。

**交付：** 不启AI仍可业务运行；启用时撤权/缺依赖/重复/unknown处理正确。工具说明和模型内容不能代替授权或业务批准，不允许绕开原Core。

### 步骤八：运行一致性与独立接手验证

使用平台正式合同测试、Rental对照和非Rental样例验证接点。记录冻结的平台构建，接入期间仅修改Core及允许的组合配置；需要改平台合同就停止本次冻结验证，修复后重新固定。

由独立开发者/AI按照本指南复现，不提供本会话记忆或人工隐藏步骤。收集卡点并修资料；不以作者自己演示成功当独立接手通过。

**交付：** 实际命令、退出码、环境、构建/合同标识、所改文件范围、正反例及未验项。当前测试命令应由PCH-11随真实实现补齐，不能拿`docs:check`替代Core接入测试。

### 步骤九：升级、停用与回退

先检查API/worker/客户端/数据兼容组合和历史依赖，再开放新准入。停止新业务、排空、历史读取和移除实现分阶段进行；未核对完unknown或在途依赖不能卸载唯一执行者。

**交付：** 最低可回退程序、历史读取、原收据、失败恢复与残留清单。改用另一Core不自动迁移旧业务数据；数据库恢复、发布和生产启用另需批准。

## 4. 接手交付单

以下是每个实际接入必须填写的交付栏目，不是新的活动进度表；填写结果随完整阶段写入该Core的开发记录，链接正式合同，不在指南累积运行流水。

| 栏目 | 必须给出的证据 |
| --- | --- |
| 范围 | Core目标/非目标、需求版本、获准工作树和文件范围 |
| 可复现组合 | 平台/Core/合同/数据版本，正式依赖和构建产物来源 |
| 接入位置 | 实际入口→适配→领域服务→仓储/外部服务→直接消费者及测试，仓库相对链接 |
| 身份与数据 | 当前授权来源、业务范围、对象引用、表/迁移和读写所有者 |
| 提交与恢复 | 原键、修订、批准、事务、外部副作用、unknown和收据查询 |
| UI/工具/作业 | 已登记贡献、启停条件、当前发布/材料政策和取消释放 |
| 验证 | 实际命令/退出码、正常及拒绝场景、真实与替身边界、独立接手卡点 |
| 运维 | 升级兼容、最低回退、停用排空、历史读、残留与尚未授权事项 |

## 6. 明确禁止的接入捷径

不把CRM/TMS加进租赁枚举；不将整个Prisma client、管理员token或任意HTTP/SQL能力交给Core适配；不靠前端隐藏代替后端授权；不以空成功或全unavailable做“通用平台”；不删除原Rental/AI源码与测试；不复制另一树dist/生成物；不根据超时换原操作ID；不因资料内有命令便启服务、迁移或发布。
