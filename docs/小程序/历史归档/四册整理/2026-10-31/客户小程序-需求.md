## 1. 产品目标与首期范围

### 1.1 面向谁、解决什么

- 一个租户以自己的品牌在一个微信小程序中提供多个品类的租赁服务；客户面对的是“同一个商户”，不是几个独立会员系统。
- 客户注册/登录一次，在商户已开放的摄影、露营等服务间切换；会员身份、资料和方案租户共享。
- 客户可以完成：浏览设备 → 选择租期、数量和交付方式 → 确认服务端报价 → 提交订单 → 付款 → 查看取还安排 → 必要时取消或续租 → 跟踪结算与退款。
- 管理端继续承担配货、领取交接、实际归还、检查、异常裁定和退款执行；小程序不替代运营人员，不通过客户点按钮直接改变实物状态。
- 小程序工程、首期页面及多数服务端接口已经实现；真库组合、真实支付/短信/文件、真实 AppID 和商户试点仍未放行。

### 1.2 首期必须具备

| 范围 | 首期内容 | 不包含 |
| --- | --- | --- |
| 商户与服务入口 | 商户信息、服务选择、游客浏览、商品搜索/列表/详情、地点信息 | 平台商户市场、跨租户搜索、复杂广告 CMS |
| 账号 | 微信授权手机号登录/注册、短信验证码备用、协议确认、会话恢复/退出、个人资料、注销入口 | 自助换绑手机号、多账号切换、社交关系、付费认证 |
| 租赁交易 | 同一服务空间内多商品清单、统一租期、地点/配送地址、服务端报价、已有会员权益及券选择、提交订单 | 跨空间购物车、不同租期混单、永久收藏夹、批量企业采购 |
| 支付 | 微信小程序支付、按空间配置的线下付款说明、结果核对、补款与退款状态 | 在小程序内嵌支付宝 SDK、储值充值、在线预授权/信用免押、自动财务系统 |
| 订单 | 当前客户在本租户的统一本人订单列表、详情、取消预览与确认、续租、取还指引、费用确认/异议、结算状态 | 企业全部员工订单、经营报表、客户自己分配资产/确认收货归还/裁定费用 |
| 基础资料 | 姓名/邮箱、配送地址、必要资质提交与状态、本人已授予会员权益 | 积分商城、邀请返利、升级任务、会员购买、企业组织管理 |

**首期前端兼容四品类术语，不等于四品类均可正式经营。** 对外只展示已完成相应经营能力验收、被商户显式发布到小程序的服务；不能因为空间 active 或 capability 标记就自动上架全部品类。摄影作为第一条集成验收场景，再验证一个合格的第二空间/品类可复用相同账号与页面。

自取、配送和异地归还是平台已确认方向：首期均应有完整交互和服务端校验，但单个商户可不启用某种方式。开发中暂缺配送接口时可以先做自取内测，不能把该内测结果记为整个 MP-R1 已交付。

### 1.3 首期不做与全产品边界

首期不做独立 App、H5 商城、营销首页装修器、分销、积分/营销余额使用、领取中心、评论晒单、智能推荐、IoT/智能柜、电子签章、发票开具、企业授信自助管理、取货后自助换货和客户端部分取消。已有优惠券可在确认单中选择，已有金额会员权益自动参与报价，不因此扩出营销系统。

其中合理的客户自助完善功能已在第15～18节写入后续需求；独立App/H5、平台商户市场、真实充值储值钱包和运营后台本身不属于本小程序产品的默认范围。任何阶段均不做跨租户身份合并、跨空间混合订单、客户端直接裁定费用或任意改库存。

## 2. 身份、服务空间与统一订单入口

### 2.1 租户与客户端渠道（微信小程序、后续 APP）

- 首期按“一套小程序发布配置对应一个租户”设计；同一租户的小程序中可以有多个已发布服务空间。部署配置、AppID 与租户映射须由服务端校验，客户页面不提供手填 tenantCode 或租户切换。
- 商户品牌、客服电话、协议、隐私政策、帮助内容、服务空间和渠道支付能力来自服务端公开配置；前端不能从任意二维码参数改写受信租户。这些配置是**租户级**的（见第 12.4 节），小程序与后续 APP 读同一份；只有渠道凭证（微信 AppID/AppSecret、APP 包名/推送凭证等）按渠道分开保存。
- AppSecret、商户私钥、session_key 等只在服务端保存；小程序包内只允许公开 AppID/渠道标识及 API 环境地址。
- 首期不设计一个平台 AppID 下任意切商户的市场模式；未来做多商户渠道需要独立需求，不复用“切服务空间”冒充跨租户授权。
- 后续 APP 以“复刻小程序功能”为目标：同一客户端 API、同一租户级渠道配置、同一账号与订单；APP 不做微信手机号一键登录与小程序 JSAPI 支付，改用短信/密码登录与 APP 渠道的支付方式（另立任务），其余页面与规则一致。

### 2.2 面向客户的用词

| 内部概念 | 客户界面名称 | 约束 |
| --- | --- | --- |
| tenant | 商户名称/品牌 | 不展示租户 ID 或“租户”技术词 |
| workspace | 租赁服务，如“摄影器材”“露营装备” | 同品类多个空间时，用商户配置的服务名称区分，例如“摄影器材·中心店” |
| itemGroup / pricingGroup | 型号/租赁选项 | 不让客户输入内部 ID，不把定价组当成已分配的实物 |
| serialized allocation | 已分配设备 | 分配前显示“商户确认后安排”，不得伪造序列号 |
| capability | 不直接展示 | 转换为具体说明，如“需要驾驶资格”“暂不支持配送” |

首页显示当前服务名称并提供选择面板，不使用管理端“经营空间管理”的概念。切换服务不注销账号、不新建会员、不重新同意同一版本协议。

### 2.3 三条隔离规则

1. 每张订单、每份报价和每次库存预占仍只属于一个租户、一个空间、一个统一租期和一种结算币种；不同空间不能混单。
2. “我的订单”允许展示当前客户在本租户多个空间的**本人订单索引**，这是负责人本次确认的客户自助入口，不是商户跨空间经营汇总：不开放其他客户/其他员工订单，不汇总跨币种消费金额。
3. 订单详情和动作仍校验原订单空间、当前客户与当前权限。首期可由统一列表返回可信 workspaceCode，详情打开前复用服务端切换空间接口，再读原有订单接口；不得通过在前端循环切换会话来拼出“全部订单”。

**切换与草稿：**有未提交的租赁清单时，切换服务须提示“切换后需要重新选择本次租赁内容”，提供“继续当前租赁 / 清空并切换”；不能静默清空。进入另一空间历史订单同样保护未提交清单。已提交订单不受此影响；正在提交或支付结果未知时，不以切换服务开启第二次提交。

已登录业务请求使用客户端会话与可信业务上下文；游客公开请求只定位已发布商户/服务，不要求登录，也不因传入公开标识取得私有权限。切换服务时取消旧读取、更新令牌与上下文、清空旧空间商品/报价/券缓存；迟到响应按发起时的上下文版本丢弃，不能把摄影的价格显示在露营商品上。

## 4. UI 与通用交互规范

### 4.1 视觉方向

风格是**清晰的租赁交易工具**，不是营销大屏：设备图片、租期和可执行动作占主位置，金额分账易读，少装饰。沿用 Rental OS 蓝色识别，不照搬管理端密集表格，不使用虚构销量/五星评价/倒计时促销。

| Token | 建议值 | 用途 |
| --- | --- | --- |
| primary | `#165DDB` | 主按钮、当前选择、重要链接 |
| page | `#F6F8FB` | 页面背景 |
| surface | `#FFFFFF` | 表单与内容底色 |
| text | `#1F2329` | 正文、标题 |
| secondary | `#606A78` | 次要说明；不可淡到不可读 |
| border | `#DCE1E8` | 列表分隔与输入边界 |

成功使用深绿 `#237804`，待处理/提示使用深金 `#A46100`，错误/危险动作使用 `#B42318`；状态同时显示文字，不只用颜色。首期使用这一套浅色样式，不扩出完整主题商城；必须校验微信系统深色环境中页面背景与原生控件的可读性。

- 以 750rpx 宽设计，左右留白 32rpx，内容间距 16/24/32rpx；分区优先用标题和分隔，不给所有内容叠相同卡片阴影。
- 字体用系统中文字体栈；标题 36rpx/600，分区标题 30rpx/600，正文/表单 28rpx，辅助文字不小于 24rpx，主要金额 40–44rpx。
- 普通按钮高 88rpx、主要 CTA 高 96rpx；图标约 36rpx，但点击热区不小于 88×88rpx。输入行高至少 96rpx。
- 内容区圆角约 16rpx、主按钮约 12rpx；警告提示以文字和轻背景表达，不全屏红色。
- 自定义导航避让微信胶囊；固定底栏叠加系统安全区，末条内容不得被 TabBar/提交按钮/键盘遮挡。

- 页面不使用自动轮播首屏广告；面板开合和加载反馈采用短动效，不影响输入。系统要求减少动效时关闭非必要动画。

### 4.3 共用状态

- 首次加载：骨架屏；列表加载更多：底部加载状态。网络错误保留已加载数据并显示重试，不把错误当“没有订单”。
- 空列表：说明当前服务暂无设备/暂无本人订单，并给“更换服务”“去租设备”等准确入口。
- 提交中：按钮禁用并保留本次幂等键；返回上一页不等于撤销后台请求。
- 错误说明至少给“哪里有问题、如何继续”；表单错误贴字段，价格或库存冲突用可阅读面板，不只弹瞬时 Toast。
- 登录失效：尝试一次共享的刷新流程，刷新失败清理身份并返回登录；成功后恢复原页面，报价/库存必须重新核对，不自动补点支付或注销。
- 下拉刷新、切前台和返回订单页会读取最新事实；首期不依赖 WebSocket，也不在后台持续轮询。
- 金额展示币种、单位和正负方向；不同币种不能相加。本文使用人民币示例不等于已确认所有真实商户的地域与税务。
- 时间按订单/空间营业时区显示，显示“09-20 周日 10:00”等本地营业时间；跨时区商户附时区说明。不得用设备时区自行计算夜数、自然日或费用。
- 支付截止、报价有效期、领取截止分别显示，不能共用一个倒计时。倒计时由 serverNow 和服务端截止时间校准，归零后刷新，不由前端直接取消订单。

## 5. 基础账号与隐私

### 5.1 P11 登录/注册

负责人确认：**微信授权手机号为主，短信验证码登录为备用，不要求新用户先设置密码。** 原有密码账号可作为兼容登录方式保留，密码找回可通过同手机号验证后的重设流程处理，不恢复明文密码。

页面从上到下：商户 Logo/名称、说明“一个账号租用本商户多种设备”、主按钮“微信手机号登录”、次入口“其他手机号登录”、未默认勾选的协议区；商户与协议名称必须真实，不显示平台默认品牌冒充商户。

| 字段/控件 | 输入或展示 | 校验/交互 |
| --- | --- | --- |
| 商户名称/Logo | 公开渠道配置（租户级，见 12.4） | 配置失败可重试；不能回落到演示租户；未配置 Logo 时显示中性占位，不用平台品牌冒充商户 |
| 微信登录 code | `wx.login` 获取，隐藏 | 由服务端交换身份；不是本站 access token |
| 手机号授权 code | 微信手机号组件用户主动触发，隐藏 | 服务端解析手机号；不信任前端自行传来的 openid/手机号 |
| 手机区号/手机号 | 短信备用入口输入 | 按首发地区策略校验；区号独立处理，不写死所有客户只能 +86 |
| 验证码 | 数字输入 | 长度、有效期、重发时点由服务端返回；显示验证码不会写进日志 |
| 服务协议/隐私政策 | 名称、版本、正文（后台配置，见 12.4）；可附外部链接 | 必须主动勾选；两个文档可分别阅读并返回；正文在小程序内直接渲染，不依赖 web-view 打开外链 |
| 同意时间/来源 | 服务端记录 | 记录租户、AppID、协议版本、确认时间与登录/注册方式 |
| 返回目标 | 原页面及非敏感草稿 | 登录后恢复原上下文；目标必须在本租户白名单页面内 |

业务规则：
1. 微信身份按 `(tenantId, appId, openId)` 绑定本站客户账号；unionId 如存在仅作辅助，不能假定总能获得，不能跨租户自动合并客户。
2. 以服务端验证过的手机号复用本租户主档/账号/会员；已存在密码账号也应进入同一客户，不产生第二个微信会员。
3. 短信备用登录成功后，仍须通过 `wx.login` 取得本 AppID 下服务端验证的微信身份，并在该已认证客户上下文中安全绑定；拒绝微信手机号授权不等于不能取得支付所需微信身份。已有账号未绑定本 AppID 时，支付前完成此步骤；未完成不能创建 JSAPI 支付，不把“已登录”直接视为“已有支付身份”。
4. 已绑定微信身份与本次手机号指向不同客户时拒绝自动覆盖，提示联系商户；不使用昵称或头像匹配账号。
5. 新会员执行租户统一 automatic/manual 注册策略；登录成功不代表审核通过，更不代表资质通过。
6. 拒绝手机号授权后仍可浏览公开商品，也可改用短信登录；不能反复弹授权强迫同意。
7. 短信挑战须区分 login/register/password-reset/close-account 等目的；证明一次性、限时、绑定租户和手机号，不能用注册证明重放成注销授权。
8. 同一请求重复回调、微信 code 重放、同手机号并发登录只产生一份身份绑定与会员；禁止把重复注册当成恢复暂停或注销账号。
9. 微信登录、手机号获取、短信、协议记录任一失败都不得先显示“登录成功”。服务端身份交换成功后返回本站客户端令牌。

**型号展示与预约保证：**详情和确认单必须说明实际预约对象。按定价组预约时，展示组名称、允许分配的型号范围及“不保证指定型号”的说明；型号图片不构成指定实物承诺。只有内核已经支持并返回“保证指定型号”的预约契约时才可如此标注，首期不得隐含新增锁型号能力。可用性也应按真实预约对象校验，不能拿一个展示型号的库存结果冒充整个定价组是否可订。

### 6.4 P04 本次租赁清单、租期与交付

首期是一次订单的临时清单，不是长期购物车；只有同空间商品可加入，同一商品与租赁选项合并数量。支持删除/修改数量、继续选择设备；清单为空时不能进入确认单。

| 输入 | 控件/校验 |
| --- | --- |
| 商品及租赁选项 | 来源于公开目录；新增/变更后旧报价失效 |
| 数量 | 整数步进器，最少 1，上限按服务端规则；不依据本地缓存断言最终可用量 |
| 起租/结束 | 同一日期时间面板，先选领取再选归还；结束晚于开始，显示营业时区 |
| 计价单位 | 只列当前租赁选项已支持的单位；默认值来自服务端，不自行时租转日租 |
| 领取方式 | 首期门店自取/配送；仅显示商户已启用且本商品组合可用方式 |
| 领取地点 | 地点名称、地址、营业时段、取货能力；关闭时段禁选且解释原因 |
| 归还地点 | 默认原地点；异地归还必须选择有接收能力的地点并重新报价 |
| 配送地址/时间 | 配送时必填；地址在支持区域内，所选窗口可履约，不等同于单一精确送达承诺 |
| 可选服务 | 名称、数量、适用商品/地点、参考费用；必选服务不能删但必须解释触发原因。独立预约服务还需计划开始/结束或时间窗及营业时区 |

服务按声明区分“随设备租期”与“独立时间窗”。教学、安装等需独立时段的服务在选择面板填写自己的计划时间，变化后重报费用并核验容量；尚无字段/输入能力的服务不向客户开放，不默认按设备整段租期收费或占容量。续租预览须列明哪些服务发生项追加/延长，已完成一次性服务不默认重复。

日历只禁用不能办理领取/归还的时段，不能因为租期跨过闭店日就错误拒绝整个租期。起租/最短最长租期、预约提前量、库存缓冲、跨年规则由服务端返回/校验。

资质、库存或服务容量预检失败时定位具体行，并允许改期、减量、删行或联系客服；不把已失败的一行悄悄移除后继续成交。摄影组合不兼容按服务端判定阻止或展示提示，客户不能自行勾选“忽略安全限制”。

## 7. P05 确认租赁与提交

### 7.1 确认页字段

| 分区 | 字段与显示规则 |

| 使用人 | 当前本人姓名、脱敏手机号；默认个人预约，不允许代选任意客户 |
| 企业身份 | 首期默认个人；如后续激活企业预约只显示本人有效关系，本期不提供企业管理/账期自助入口 |

| 优惠 | 自动优惠、已选券、实际会员减免及未适用原因；个人/企业方案不叠加 |

| 本次需付 | **当前可执行付款动作**的金额与用途，不直接把订单总额当本次支付额 |
| 有效期 | 报价失效时点；与建单后资源保留/付款倒计时区分 |
| 协议 | 租赁规则、取消/逾期/损坏规则版本、必要服务条款，主动勾选确认 |

展示模型中“本次需付、待付押金、待冻结额度”应由服务端聚合输出；现有 `payableAmount/receivableAmount` 等字段必须先核对语义再映射，不能靠字段名猜。税额如已含价，只作拆分，不再加一次；押金不是租赁收入。

### 7.2 已有优惠券与会员权益

- 只选择当前空间、当前客户已有且可用于本次报价的券；首期不开发领券中心。
- 券面板展示名称、适用范围、门槛、有效期、预估优惠、不可用原因；确认选择后由服务端重新报价。
- 会员卡全租户共享但权益逐条限范围；例如摄影权益在露营单不适用，应显示原因，不提示“请重新加入露营会员”。
- 服务端按既有优惠链计算并分摊。客户端不自行计算百分比、不叠加多张方案、不把优惠折成可退现金。

### 7.3 提交流程与异常

1. 输入完整后取报价，界面以返回快照渲染；用户看到最终费用及关键规则后主动确认。
2. 更改商品、数量、租期、地点、地址、服务、券或身份，必须废弃旧报价并重新请求。
3. 单纯后台发布新价格不在有效报价内静默改价；提交时复核当前身份、安全与库存，但不覆盖已确认商业快照。
4. 点击“提交订单”生成稳定的提交幂等键，禁用重复点击；报价转订单必须同时处理库存、券预算与服务容量。
5. 提交失败且明确未创建，可回确认页修正；网络超时/响应丢失先查询本次提交结果或用同键同内容重试，不创建新键试运气。
6. 发现价格/规则差异时展示前后差异并再次确认；库存不足则定位缺货行，不先收款再提示无货。
7. 成功返回订单后清理草稿；有租金待支付进入收银台，无需支付但待商户确认则进入订单详情。
8. 会员待审核、暂停、资质未通过时明确阻断原因及补件/客服入口，不将每个错误都提示成“库存不足”。

## 8. P06 收银台、支付结果与保证金

### 8.1 首期资金路径

| 用途 | 小程序首期处理 |

| 租金、已确认服务/履约费用 | 微信 JSAPI 小程序支付；或商户明确启用的线下支付路径 |
| 续租正差额、已批准且客户确认的尾款 | 必须绑定对应业务用途后支付，不能随意填金额 |
| 普通押金 | 本期不承诺在线押金支付；允许有完整操作流程的到店/发货前线下登记，单独展示状态 |
| 真实预授权/信用免押 | 不在首期新增能力；要求此能力却没有真实办理路径的服务不得对客户开放自助成交 |
| 租金退款 | 小程序查看进度；取消/核减产生待退，运营或既有退款服务受权执行，成功后显示已退款 |
| 押金退还、预授权释放 | 分别展示，不能以“租金退款成功”替代 |
| 支付宝 | 平台保留已确认渠道；微信小程序不内嵌支付宝 SDK。本期渠道能力不足时不展示一个点不开的支付宝支付按钮 |

无可用支付路径时，在报价/确认阶段就说明，不能创建一个用户没有办法支付或办理保证金的订单后才报错。配送商品必须在发货/交付前满足实际收款、保证金和资格要求，不能把线下说明当作已收款。

### 8.2 收银台字段与流程

| 字段 | 要求 |
| --- | --- |
| 订单号、商品摘要、商户名称 | 与本次支付单对应，避免误付另一订单 |
| 支付用途 | 租赁款/续租补款/结算补款等明确名称；可同时展示关联续租单 |
| 支付金额/币种 | 服务端当前待收金额；不能前端提交任意 amount |
| 已收/尚待处理 | 已付租金、待付押金、待冻结额度分别列示 |
| 支付方式 | 当前微信渠道真正可用的方式，不照搬租户全部 provider 列表 |
| 截止时间 | 服务端付款截止与资源保留说明，不能与微信 prepay 有效期混为一谈 |
| 微信参数 | timeStamp、nonceStr、package、signType、paySign；只使用服务端一次性返回值，不长期存储 |
| 结果提示 | 处理中、到账已确认、用户取消、明确失败、结果待核对分别表达 |

服务端使用可信 appId/openId 创建 JSAPI 支付，校验该商户与 AppID 绑定；短信登录客户也须先按§5.1完成本AppID支付身份绑定。现有 Native 的 `checkoutUrl/code_url` 不能传给 `wx.requestPayment`，不能把二维码支付页当作小程序支付已完成。

微信渠道使用服务端配置的、已启用且通过对应运行链验收的微信提供方；租户默认提供方若为支付宝，不要求客户或小程序擅自切换全租户默认配置。MP-07须建立明确的渠道选择规则，支付单保留实际提供方，后续查询/退款仍用原提供方；无合格微信路径则如实不可用，不能假定“租户有支付provider”就能调起小程序支付。

`wx.requestPayment` 成功回调仅表示客户端流程结束；必须读服务端支付单与资金事件，才显示“已付款”。小程序切后台、微信弹窗关闭、网络断开后，返回前台重新核对；结果未知保留待核对，不自动记失败或重复创建付款。

前台查询可采用短周期有上限重试，例如 2/5/10 秒，30 秒仍未知则停止自动查询并显示“稍后查看/联系客服”；具体限流以服务端为准。用户取消微信弹窗不自动取消租赁订单，可在有效期内继续付款。已付款但订单已超时的情况进入明确的退款/人工处理状态，不吞款、不把旧订单直接复活。

## 9. P07/P08 本人订单与详情

### 9.1 统一本人订单列表

默认展示本租户本人全部服务的订单，按创建时间倒序分页；可筛选“全部/待处理/待取件/使用中/已结束”和服务名称。聚合接口只返回本人订单，不按企业身份扩成公司订单，不显示全租户营业额。

订单卡片显示：服务名称、订单号末段、主状态、副状态提示、首张商品图、商品名称摘要、商品种类/数量、租期、领取/归还方式、租赁应付及当前待补/待退提示、一个主按钮和“查看详情”。卡片不将押金并入租金，不跨币种合计。

从其他空间订单打开详情时，先建立该订单的可信业务上下文再读详情；处理快速连点两张不同空间订单、切前台和历史深链接，防止迟到响应串单。

渠道下架/暂停新租与空间停用/冻结必须区分：渠道下架但空间仍有效时，本人历史订单照常可查；空间或租户冻结时按平台D-05及安全规则处理，不通过普通切空间失败后回退默认空间读取原单。本人索引与交易空间上下文分开设计，失效上下文应重新进行租户级身份核验或返回明确服务状态；无法合法打开详情时提供原因与商户善后联系入口，不让客户陷入反复切空间/登录循环，也不擅自新增绕过冻结的历史读写特权。

## 10. 订单自助动作

### 10.1 P09 取消订单

入口仅在服务端允许时显示。取消面板必须先取**服务端取消预览**，展示：取消原因选项/补充说明、当前租赁应付、取消费、不可退的已发生服务/履约成本、核减额、取消后最终租赁应付、已确认抵扣、最终待补或预计待退金额、押金/预授权后续处理说明、预览有效期及不可取消原因。

- 主按钮明确为“确认取消”；有费用时，按钮附近同时展示取消后全部应付及待补/待退结果，不能只写取消费而隐去已发生成本，更不能点完才通知要补多少钱。
- 预览不改变订单或资金。确认须带预览标识/订单版本及幂等键；若状态、实收或规则适用结果变化，返回新预览供再次确认。
- 取消成功不等于退款成功；根据资金事实显示“订单已取消，退款待处理/处理中/已退回”。取消后仍有合法待收余额时保留对应用途的补款/线下办理入口，不能因订单终态隐藏债务，也不能为付款而复活原订单。
- 确认响应丢失时保留取消幂等键，查询或同键同内容重放原动作；结果未知期间不再提交第二次取消。恢复小程序后先读最新订单和资金结果，再决定显示成功、仍处理中或可重试。
- 已领取、已爽约等不支持自助取消时不显示可提交表单，给出原因与客服；不以修改取消 reason 绕过限制。
- 首期不支持部分取消、取货后换货；后续沿通用订单变更任务扩展。

### 10.2 P10 续租

顶部显示当前有效归还时间、已租商品及不可续租原因；仅选择一个新的结束时间，不另建订单或重新选择优惠叠加。

| 字段 | 规则 |
| --- | --- |
| 新归还时间 | 必须晚于当前有效结束时间，按空间时区输入 |
| 适用续租方式 | 服务端经营规则决定，客户不可自行选择更优惠的计费算法 |
| 新旧租期/计费说明 | 服务端预览返回，说明哪些已发生费用不变 |
| 租金/服务差额 | 正、零、负明确显示，不能只给一个总数 |
| 押金/预授权增量 | 单独显示办理要求；不支持的资金方式不能放行 |
| 可用性/服务容量 | 服务端复查完整新增时段及缓冲，不以预览代替占用 |
| 支付与生效 | 是否先补款、补款截止、申请状态、最终有效结束时间 |

正差额：申请后按规则补款，只有资金与资源满足后才显示已续租；零差额仍等服务端确认资源；负差额进入审核核减/退款，不直接显示“已退款”。`extensions/{id}/pay` 是资金校验后的生效动作，不是微信支付入口。

已有待补款续租时优先恢复该申请，不重复提交；部分归还、已逾时或其他不支持组合按服务端原因限制。明确失败不改变有效租期；响应丢失属于结果未知，须按原幂等键查询/同键重放，恢复原extensionId及最新生效事实，不自行假定失败或成功。结果未明确前禁止另发同一意图的续租。

补款已实际到账但续租生效失败时，仍展示服务端原有效租期，并显示“款项已收、续租未生效，待核对/退款”的独立待办；不能当成支付失败再收一次。重启、切前台及网络恢复后，以订单当前有效结束时间、申请记录和资金事实共同决定页面，不只读取本机缓存。

### 10.3 取还指引

小程序展示去哪、何时、携带什么、如何联系商户，以及真实交接进度。客户可打开地图或拨号；不要求首次启动就授权定位，不做后台持续定位。

首期不制作可被截图重放的静态“取货成功码”，也不新增自助确认领取/归还接口；实物交接由管理端执行。部分归还由运营逐批登记，小程序只展示已还/未还数量和待检查状态；“已交回”不等于已结算，维修完成也不自动证明客户已付费用。

### 10.4 P17 费用确认与异议

只展示已批准且需要本人响应的费用：项目、原因、发生时间、证据、安全可见金额、责任说明、商户联系信息。待审核建议金额不可显示成最终应收。

提供“确认此费用”和“提出异议”；确认前展示将增加/保留的应付，异议必须填文字原因。首期不做复杂申诉附件工单，现有检查证据只读。客户响应追加身份、时间、版本与历史，不能提交任意费用金额、裁定结果或改写旧响应。

异议处理中标记等待商户复核；复核后金额变化需再次响应。客户确认不等于已付款，费用批准不等于已退款；结算仍由既有服务端门禁决定。

## 11. 地址、资质与会员权益

### 11.1 P14 配送地址

配送地址是当前客户在租户内共享的个人资料，**不是现有联系人表**。地址列表显示收件人、脱敏电话、地区+详情、默认标识和编辑/删除；从确认单进入时增加“选择此地址”。

| 字段 | 必填/说明 |
| --- | --- |
| 收件人 | 配送必填，普通姓名文本，不默认为微信昵称 |
| 电话区号/联系电话 | 配送必填；服务器校验，列表脱敏；已有脱敏值不能原样提交成新号码 |
| 国家/地区、省市区 | 按首发经营地域的地址结构；不得强制所有地址有相同三级行政区 |
| 详细地址 | 必填，明确楼栋/门牌；不以地图坐标替代 |
| 邮编 | 按地区规则可选/必填 |
| 经纬度 | 地图选择时可保存；拒绝定位后仍可手工填写 |
| 默认地址 | 每客户最多一个有效默认地址，变更幂等 |
| 地址 ID/版本 | 隐藏，用于归属和并发校验；禁止指定其他客户 ID |

从微信收货地址导入需用户主动同意，导入结果仍须确认和服务端区域校验。删除/修改地址不改变已提交订单的交付地址快照；订单后续改地址不在首期自助范围，联系商户按订单变更处理。

### 11.2 P15 资质资料

列表按当前服务所需资料和本人已提交记录展示：证件名称、状态、有效期、审核原因、提交时间、补交按钮；跨服务复用同一合法证件，不重复注册或默认重复认证。

提交表单字段：证件类型、号码（如该类型要求）、签发日期、有效期/长期有效标记、附件槽位说明、图片、声明确认。要求与格式来自服务端 Type/规则，不把所有品类写死成驾驶证。

- 手机图片选择须用户触发；首期支持 JPEG/PNG，建议客户端单张不超过 10MB且不超过服务端上限，压缩后须保持证件可辨认。
- 需要正反面等多槽位时，槽位、必填和数量由服务器声明；现有单个 evidenceRef 不够时必须补附件列表及版本快照，不能前端收两张只保存一张。
- 上传会话 → 对象上传 → 服务端完成确认 → 取得不透明文件引用 → 提交审核；任何一步失败可在授权范围重试，不能凭上传进度 100%直接显示审核通过。
- 只读取本人受保护附件，临时链接过期重新申请；不缓存长期证件 URL、objectKey或证件原文日志。
- 已拒绝/补件说明可见；新提交追加版本，旧审核不能覆盖新提交。资料日期清空时不得错误保留旧证件日期。
- 审核权限仍在运营端；小程序只能提交本人资料，不能设置 approved、reviewer 或绕过有效期门禁。

### 11.3 P16 我的会员权益

顶部为当前免费方案名称、有效期、会员状态；下方逐条列“权益名称、计算说明、适用服务/品类、当前服务是否适用、未生效原因”。例如金卡的摄影折扣与露营折扣同属一张卡，不显示两个需要再申请的空间会员。

只展示已授予事实和 APP 可见方案，不提供购买/升级/自动领卡按钮；实际订单优惠仍以报价为准。非金额权益未接执行点时标“暂未生效”，不得声称优先配货或已延长报价。

## 12. 前后端展示契约与剩余接口差距

### 12.1 共用展示对象

| 对象 | 必需字段 |

### 12.3 安全与并发底线

- 游客接口只返回已发布公开 DTO；不得返回客户、会员、资产序列号/数量台账、内部规则 JSON、租户后台联系方式或任何私有附件。
- 统一“我的订单”必须绑定验证后的 tenantId/customerId；列表、详情、资金、凭证、深链接与幂等回放均检查本人，企业员工不能读取同事订单。
- 读本人索引不等于对任意 workspaceId 授权，写动作不扩成跨空间事务。不得从小程序取客户端自报的身份、金额或终态。
- 微信 code、验证码证明、支付事件和上传会话都绑定用途和主体；重试指纹一致、并发唯一、失败回滚，不能双建账号/订单/扣款。
- 外部支付/短信/文件未知结果保留待核对；完整支付通知必须穿过真实 HTTP/全局 Guard 到验签处理器，不以直接调 service 的测试代替。
- 客户端 token 存储按微信平台安全能力实现；敏感数据不进分析日志、崩溃日志、分享参数或剪贴板。退出后清理本人缓存。
- 密钥在服务端加密，日志脱敏；手机号解密与资质文件访问留审计。公开图片与私有资质附件使用不同授权路径。

- `GET /public/bootstrap` 增加 `client` 参数（`wechat_miniprogram` 缺省、`app`），共用部分一律来自租户级配置；`wechat_phone` 登录方式与 `capabilities.wechatPay/wechatBinding` 只在小程序渠道且微信凭证就绪时为真，APP 渠道固定为假。
- 协议与帮助正文单独经公开文档接口读取（`GET /public/documents/{kind}`，`kind` 为用户协议/隐私政策/帮助），启动配置只带名称、版本与是否有正文，避免启动响应过大。
- 客户端不再依赖降级投影：租户级配置未发布时，启动接口返回租户名并把品牌/协议/帮助标记为“商户未提供”，登录页如实显示，不内置占位协议。

**就绪检查：** 开业配置页增加“客户端渠道”项：品牌名、客服电话、两份协议（版本+正文）、至少一个发布服务齐全才算完成；微信凭证为可选项，缺失时客户端只开放短信/密码登录并提示“小程序内微信支付未开通”。

**协议版本变更（建议纳入）：** 客户在登录/注册时以当时版本留痕；版本升级后，已登录客户下次启动看到“协议已更新”提示，需重新阅读并同意后才能提交新订单（浏览不受影响），同意记录经登录态接口写入。此项不影响本节其他配置，可单独裁剪。

**不做：** 营销首页装修器、多语言文案、按渠道分别配置品牌/协议、平台统一默认协议。

## 13. 验收场景

以下同时用于任务验收与自动化用例设计，不要求开发过程中反复操作普通浏览器；默认交付证据以代码复核、契约/单元/集成/真库测试为主。微信授权、支付等宿主能力需在获授权的开发者工具/真机测试账号与环境验证，未取得证据时如实保留发布门禁，不能用浏览器模拟冒充通过。

| 编号 | 场景 | 必须证明 |
| --- | --- | --- |
| AC-01 | 游客首次进入、拒绝授权 | 可看真实公开商品与地点；不能看私有资料/订单；无默认演示租户回退 |
| AC-02 | 微信手机号首次登录、已有密码账号登录 | 同租户同手机号复用一份客户/账号/会员；用户主动协议确认，重复回调不重复创建 |
| AC-03 | 微信授权失败、短信备用、验证码重放 | 可切备用入口；证明绑定目的/租户/手机号；超限、过期、并发正确处理 |
| AC-04 | 同一会员切摄影与第二服务 | 不重新入会；金卡按范围正确生效/不生效，列表和草稿不串空间 |
| AC-05 | 搜索、下架、无图、无价、空结果 | 无假图假价假库存；数据失效能返回列表并说明 |
| AC-06 | 正常多商品/数量/套装租赁 | 同空间同租期正确报价、建单，耗材不要求归还；资产分配仍由商户 |
| AC-07 | 日期、停业、跨年、时区、库存竞争 | 日历与计价遵守服务端；选择可用不代表最终预占一定成功，冲突可恢复 |

| AC-09 | 价格/会员/券变化与重复提交 | 历史快照不重算；输入改变重报价；丢响应同键重放不重复订单/预算/库存 |

## 14. 开发顺序与待落实的上线条件

开发顺序：先固定展示契约与渠道配置，再做身份/公开目录；以自取订单打通清单、报价和订单；随后接微信收银、本人订单中心、配送/异地归还、取消/续租、资料与异常处理，最后做组合验收。可以并行开发不同页面，但不得让两个任务各自实现一套会话、价格计算、付款状态或会员逻辑。

| 条件 | 当前口径 | 未落实时的处理 |
| --- | --- | --- |
| 登录与订单入口 | 负责人已确认微信手机号主入口、短信备用、统一本人订单 | 纳入首期实现，不再按空间重复注册 |
| 商户与AppID主体 | 首期一套发布配置绑定一个租户；真实AppID、认证资格及主体待提供 | 可做代码/测试替身，不能宣称真实授权通过 |
| 后台渠道配置 | 品牌/客服/协议/帮助/发布服务的后台页面与接口已实现；迁移和真库组合仍待收口 | 未配置时小程序显示租户名与“商户未提供”，不内置占位品牌或协议；真库验收未完成前不对真实客户发布 |
| 微信支付 | 需商户号/AppID绑定、JSAPI能力、证书、合法域名与回调环境 | 仅做内部集成，不向真实客户开放支付按钮 |
| 短信/文件 | 复用真实provider控制面与运行链，但需要实际可用配置、模板与对象存储 | 必要验证码/资质不能完成时阻断相关上线，不静默模拟 |
| 交付地域/币税 | 沿平台 D-01/D-03/D-11 与商户确认 | UI示例不作为地域、税率或配送范围决策 |
| 品类和商品发布 | 平台能力验收＋商户显式渠道发布 | 未验收服务不上架，不因枚举存在就宣传可租 |
| 隐私与协议 | 商户在后台提供协议名称、版本与正文（可附外链）、客服及依法保留说明 | 不以内置占位协议提交审核或对外放行；正文缺失时登录页如实标注“商户尚未提供协议正文” |

首期完成标准是本文件范围内的真实可执行闭环和可解释失败，不是页面齐全、模拟付款成功或接口数量达标。对外发布仍要经过平台 PILOT-01 和对应微信渠道验收，不把内部联调直接称为可生产经营。

“完整”指客户在该商户中的完整租赁服务生命周期，不是把营运后台、SaaS管理、商户财务或所有可能的营销工具搬进小程序。每个后续模块仍复用统一客户、订单、库存、资金、服务与审计事实。

## 16. 后续完整功能需求

### F01 账号安全、手机号换绑与身份恢复

**目的：**在不创建重复客户的前提下处理换手机、微信身份变化、密码遗忘及设备遗失。

- P19展示：脱敏手机号/验证状态、当前微信绑定状态、最近登录时间、客户端名称/设备摘要、会话状态、可执行安全操作。不得显示session_key、令牌或完整微信标识。
- 换绑流程：核验当前身份 → 验证新手机号 → 检查本租户唯一性/身份冲突 → 二次确认影响 → 服务端原子变更 → 撤销旧会话并重新登录；订单、会员和权益仍归原客户，不按新手机号创建新主档。
- 原手机号无法使用时进入人工恢复入口，展示申请号、所需资料和进度；不能只凭订单号、姓名或新手机号接管账号。
- 新手机号已对应本租户另一客户时，不在小程序自动合并；由受权人员按客户合并流程处理，历史资金和证件不随意搬移。
- 支持查看本人会话并退出单个/全部设备；本机退出、全设备退出、注销账号是不同按钮和确认文案。
- 密码重设凭证与登录凭证分用途；不查看原密码、不向客服展示验证码。频率限制、异常提示及敏感操作审计复用服务端安全设施。
- 最低验收：换绑并发唯一、旧令牌立即失效、其他租户同号独立、身份冲突不覆盖、恢复审核前不能获得旧客户权限。

### F02 收藏、最近浏览、常用租赁清单与对比

**目的：**方便重复租赁，不用购物车状态冒充库存或价格承诺。

| 对象/字段 | 交互与规则 |
| --- | --- |
| 收藏项 | 商品公共ID、服务空间、名称/图片快照、当前发布状态、收藏时间；重复收藏幂等 |
| 浏览记录 | 同设备近期记录，提供清空；登录合并策略须明确，不上传非必要敏感行为 |
| 常用清单 | 名称、空间、商品/组选项、数量、可选服务偏好；不保存个人支付信息 |
| 对比项 | 型号、服务名称、关键规格、套装组成、单位/参考价、资质要求；不同品类不强行横向比价 |

- P20可按租赁服务筛选，商品下架/价格选项失效时明确标记，不能静默替换成另一型号。
- “再次租赁”复制选择意图而非旧订单价格、券、资格或已分配资产；用户重新选择租期/地点，再由服务端报价。
- 每个常用清单仍属于单空间；跨空间收藏可以同页查看，但不能一键混成一单或跨币种支付。
- 本模块不提前占库存、不锁优惠券、不对“收藏后涨价”作锁价承诺。
- 最低验收：下架清单可解释恢复、数量不超限、旧优惠不复活、跨空间条目拆分、清空浏览不删除订单。

### F03 完整订单变更、部分取消、改期与换货

**目的：**让客户提出业务变更并理解成本；批准、金额和库存仍由Rental Core决定。

P22以“原订单摘要 / 可变更项 / 新方案 / 差额与处理方式 / 确认”布局。字段包含：变更类型、涉及原订单行/数量、原及新时间、地点/地址、替换组选项、关联服务、原因、报价版本、有效期、原新费用及保证金差额、所需客户确认、处理状态。

- 领取前改期、地点/地址变更、增减商品、数量部分取消分别校验是否支持；已锁定/已履约部分不能通过整单覆盖删除历史。
- 序列化资产和套装按既定粒度处理，数量库存可在明确规则下拆分；不把“减一件商品”误作整单取消。
- 提交先预览，确认时复核订单版本、当前资格、价格适用快照、库存/服务容量、券预算与资金；任一步失败整体回滚。
- 商户需要审批的变更状态为待受理/待补充/待客户确认/待补款/已生效/拒绝/取消，独立于原订单主状态；申请不等于原订单已经改变。
- 取货后换货沿平台已确认规则：原价或替换商品当前价由经营规则/受权确认确定，只重算未发生租期，差额统一最终结算，替换资源立即锁定，原资源按回库/下架处理。
- 客户不能自己改资产ID、处置结果、价格基准、损坏金额或绕过交接检查。UI展示商户提出的方案并让客户确认，而不是开放一个任意改价表单。
- 已执行服务不因商品取消而消失；取消费、不可退成本、待补/待退款全部先说明。结果未知按原变更幂等键恢复，不再建立另一笔变更。
- 最低验收：两次并发变更互斥、部分行/已发生服务不丢、资源释放与新占用原子、负差额审核不冒充退款、换货历史能还原。

### F04 企业员工预约、企业管理与账期

**身份边界：**企业管理员仍是租户中的个人客户账号，通过有效企业关系获得客户侧企业权限；不是商户营运账号，也不获得租户管理员权限。

| 页面/字段 | 展示与操作 |
| --- | --- |
| P23 企业身份 | 企业名称、本人部门/员工号、角色、关系有效期、可用权益、当前预约身份；一单只能选一家企业 |
| 企业预约 | 使用人始终为经核验个人；分别显示权益来源、签约主体、付款主体及结算方式，默认不把企业优惠等同企业付款 |
| P24 员工管理 | 个人会员引用、姓名/脱敏电话、部门、员工号、角色、状态、生效/失效时间、原因和历史 |
| 企业授权 | 明确可预约服务/订单金额范围/审批要求；未配置时不凭企业管理员身份自动放宽 |
| P25 账单 | 账单号、企业/币种、账期、到期日、关联订单分摊、应收/已回/未清、逾期、付款/核对状态 |
| 回款信息 | 回款编号/日期/金额/方式、分摊订单或账单、凭证状态；客户上传凭证不等于商户已确认到账 |

- 普通员工默认只看本人订单；“查看企业订单/账单”“维护员工”“审批预约”“管理合同资料”分别授权，不由成员角色名称推断。
- 企业管理员查看非本人企业订单必须有独立的企业客户数据授权，并限制到该企业、允许空间和字段；该能力未启用时继续只看本人订单，不能复用§2的本人索引绕过。
- 不在客户端新建虚假员工账号：通过邀请/手机号核验找到本租户个人会员，双方确认或企业受权流程后建立关系；同一人加入多家企业相互隔离。
- 企业方案与个人方案不叠加；企业优惠可由个人付款，企业授信仅在签约/付款主体与授信规则满足时使用。欠费、逾期、额度不足必须有明确阻断原因。
- 自助额度申请只产生申请及状态，额度生效由商户受权审批；不能编辑信用额度、回款到账、账单终态或审批人。
- 账单与回款须复用完整企业账务能力；在平台订单级回款分摊、到期与逾期规则未收口前，此客户侧模块保持未启用。
- 最低验收：离职立即失去新企业权益、个人历史保留、多企业不串单、企业管理员不能看其他企业、付款凭证不伪造入账。

### F05 服务预约、人员协作与履约反馈

P26服务卡与详情字段：名称、服务类型、适用设备/订单行、地点、计价方式、数量、计划开始/结束或时间窗、营业时区、包含内容、必要资格、容量结果、取消规则、服务负责人公开称呼、实际状态与证据摘要。

- 默认依附租赁订单或其服务发生项；独立纯服务交易需另行确认Core能力，不能偷偷创建另一套服务订单系统。
- 租期关联服务按配置随租期计算；独立时段服务如教学、安装、搭建、操作员班次须让客户选择独立时段，不能自动覆盖整个设备租期。
- 展示可预约时段和已确认时段；“提交预约/商户已安排/服务中/已完成/未到场/失败”分开。时钟到点不自动完成服务。
- 是否允许选择人员由服务能力决定；未提供人员选择能力时只显示“商户安排”，不展示虚构排班。
- 客户可提交迟到/未到场/结果异议，由服务端追加事件；不能自填实际完成数量/结算金额来直接核销容量或退款。
- 续租时按具体服务发生项决定延长、追加或不重复：一次性教学不因设备续租自动收费，已完成服务不改写原事实。
- 最低验收：容量并发不超售、时段/地点匹配、部分服务执行正确分摊、未履约退款与客户确认状态可追溯。

### F06 配送、寄还预约与物流跟踪

P27字段：关联订单、配送/寄还任务号、服务名称、收寄地址快照、预约时间窗、承运方公开名称、运单号、包裹/设备数量、实际事件时间、当前位置说明（有真实数据才显示）、预计时间及其来源、签收/异常结果、客户应做事项。

- 支持预约配送、寄还申请、改约申请、填写经校验的运单信息；改变已确认任务需按时间截止和费用规则重新确认。
- 外部物流接单、揽收、运输、到达、签收与租赁设备交付/归还检查是不同事实；物流签收不自动结束订单或把设备恢复可租。
- 客户提交“已寄出”需要运单/包裹关联，状态为待核验；不能直接释放库存、停止所有费用或退押金。
- 多包裹、部分到达和拒收必须保留数量与任务关系；不把一个包裹完成误作整单完成。
- GPS/预计送达仅在真实提供方支持并获授权时展示；过期数据标注更新时间，不伪造“实时”。拒绝定位不影响手工地址流程。
- 最低验收：改约冲突、地址变更不改历史、部分签收、运单重放、物流故障仍可联系商户处理，不丢原订单。

### F07 消息中心与微信订阅提醒

P28使用“交易消息 / 服务通知”列表，重要未处理事项置顶；不混入未同意的营销推送。字段：消息ID、标题、类型、摘要、关联订单/服务、发生时间、已读状态、过期标识、可执行入口。

- 消息来源是客户可见业务事件，不直接把短信provider发送日志展示为“客户消息”。未读是站内阅读状态，不等于短信未送达。
- 创建订单、付款、领取提醒、归还提醒、续租结果、退款、审核和费用响应可以请求微信订阅；每次请求需用户明确操作，拒绝订阅不阻断租赁。
- 订阅模板、触发条件、频率、静默时间和退订说明可配置；渠道通知只发送该客户授权范围内的信息。
- 消息点击先重新核对会话与原业务归属；旧消息指向已取消或已完成订单时显示最新状态，不能重放过期操作。
- 外部发送受理、发送失败、已送达和用户已读分开，不用模拟消息号伪装真实通知。
- 最低验收：重复事件只生成一条业务消息、批量已读幂等、跨客户消息不可读、失效链接安全、拒绝订阅后业务仍正常。

### F08 售后、设备故障与完整争议处理

P29表单字段：订单/订单行或已分配设备、问题类型（故障/缺件/不符/服务问题/费用争议）、发生时间、问题描述、必要图片/视频、期望处理方式、联系人与可联系时间；资料选择必须来自本人订单，不手填任意资产ID。

- 提交后显示服务单号及待受理/补件/处理中/待客户确认/已解决/已关闭状态；服务单状态不覆盖租赁订单状态。
- 商户处理方案可为指导排查、维修/替换安排、改约、费用复核、部分退款等；客户查看方案、同意或提出异议，记录条款版本与证据。
- 客户报告故障不自动停止计费；经营方责任、客户责任和停机时段按规则及审核确定，生效减免追加订单费用事实。
- 图片/视频绑定具体订单与申请，限制类型/大小，删除/补交保留版本；不向企业同事或其他客户暴露证件、联系方式。
- 退款申请、批准、供应商受理、实际退款成功分别显示；不允许客户端通过选择“已解决”抹掉欠款、退款或争议。
- 支持评价处理结果或申请复核，但不无限重建重复工单；截止与升级处理规则须商户确认后配置。
- 最低验收：一单多问题能定位、重复申请幂等、换货/费用复核复用原事实、争议未结不正常关单、结案仍保留证据。

### F09 合同、业务凭证、电子签章与开票

P30按订单展示报价单、交付清单、归还检查、结算对账、租赁合同及发票入口；每份文档显示编号、类型、模板版本、生成时间、关联订单版本、状态和有效说明。

- 业务凭证来源于服务端不可变快照；订单变化生成新版本，历史版本可查，不用当前主档重新渲染后冒充原文档。
- 正式PDF须可下载、可受保护存储并验证内容一致性；HTML预览不能标成已归档PDF或法定票据。
- 电子签章启用后，展示签约主体、合同全文、签署人资格、签署过程与结果。跳转供应商成功不等于签署完成，以验证过的回执/查询为准。
- 签署人必须符合该合同的个人/企业授权关系；不能因为是企业员工就代签全部企业合同。签署过程拒绝、超时、补签、撤销均有明确入口。
- 开票申请字段：发票类型、抬头/企业名称、税号（适用时）、接收邮箱、适用订单/费用、可开金额、开票状态/原因。已开金额、退款红冲/作废按税务规则处理，不能开超过合法范围的金额。
- 税种、币种、地域、电子签章法律适用和发票服务商未确认前，相关按钮不开放；不自行假设所有商户都能开同类发票。
- 最低验收：越权文档不可读、历史哈希稳定、供应商回调幂等、签章未完成不显示已签、退款后开票状态可解释。

### F10 优惠券中心与完整会员权益

P31包含“可领取 / 我的券”，券字段：名称、类型、适用服务/品类/商品、门槛、优惠方式、上限、叠加关系、有效期、领取/使用次数限制、状态、不可用原因。没有公开发行权限的券不进入领取中心。

- 领取、锁定、核销、释放、到期、作废及退款恢复全部以服务端事实为准；客户端不能改剩余发行量或用新幂等键绕过限领。
- 已领券保留原版本，活动暂停不随意改历史承诺。报价可展示“可用但非最优”与选择结果，不暗中消耗用户更高价值券。
- 现有券仍按空间隔离；未来跨空间通用券须先明确适用范围、统一预算、核销锁与归属，不能因会员统一就直接让所有券跨空间使用。
- P32展示当前等级、有效期、适用权益、等级来源/升级依据、待生效或将到期状态；升级/保级/降级由发布规则决定，不写死消费金额或成长阈值。
- 非金额权益必须有单位、触发点、有效期、冲突优先级及真实执行结果，如报价有效期延长、优先预订、服务权益；未实现执行点只能显示未生效原因。
- 优先预订不突破已占库存、法律资质或安全限制；人工授予/撤销保留历史，不能改旧订单优惠。
- 最低验收：预算并发、旧券快照、优惠分摊、等级变更与历史订单独立，会员有效但当前服务无权益时说明准确。

### F11 积分、营销抵扣额度与邀请奖励

本模块是营销权益，不是真实储值钱包。**任何阶段都不能默认提供充值、提现、转账、收益或兑换现金**；真实预付资金账户属于另行合规与资金系统设计。

| 页面字段 | 规则 |
| --- | --- |
| 积分/抵扣额度 | 分开显示可用、待生效、已锁定、已使用、即将到期、已撤销；单位明确 |
| 流水 | 发放/锁定/使用/释放/到期/撤销/补偿、批次、数量、时间、来源订单/活动、原因 |
| 结算使用 | 显示本次可用上限、适用费用、使用量、抵扣结果及未用原因；默认是否使用由已发布规则决定，不暗扣 |
| 邀请活动 | 活动名称/版本、资格、起止时间、触发条件、双方奖励、有效期、次数/预算限制、风控及退款撤销说明 |
| 奖励进度 | 邀请关系确认、条件达成、冷静期、待生效/已生效/撤销/风险复核，不展示被邀请人私有订单金额或证件 |

- 积分、营销额度和奖励流水按活动/经营空间归属；报价试算不变余额，提交/生效时锁定或使用，失败/取消按规则释放。
- 不抵扣押金、预授权或未获授权费用；先到期批次优先、退款返还、过期不恢复及补偿规则须由经营方确认。
- 租户统一会员只注册一次：邀请活动必须区分“租户新客注册”与“某空间首个有效订单”，不得通过切空间或再建会员制造新客奖励。
- 邀请关系的租户/活动绑定粒度、是否允许各空间不同邀请来源、冷静期及撤销责任须在F11开工前确认；未确认不发奖励、不自行选预算或金额。
- 分享需用户主动触发，不强制读取通讯录；禁止自邀、循环邀请、重复事件、多账号冒领与用客服操作绕过限制。
- 奖励被部分使用后撤销应显示剩余撤销和待追偿/复核，不自动从用户银行卡扣钱；任何余额变化只追加流水。
- 最低验收：同租户多空间不重复认新客、并发不超预算、退款撤销可回放、不同单位/币种不混加、无充值提现入口。

### F12 评价反馈与四品类专属客户触点

**评价（可选完善）：**P35仅允许真实有资格订单评价，字段为关联商品/服务、评分维度、文字、可选图片、匿名展示选择、提交时间与审核状态。匿名仅影响公开展示，不取消后台追溯；图片须脱敏和审核，不虚构销量/评分，不强制好评换取退款或奖励。已退款/争议订单的评价资格和修改期限须先明确。

**品类触点：**P36通过品类/capability字段与模板注册接入，不创建四套订单页面或资金逻辑。

| 品类 | 客户侧可展示/填写 | 不得越权的边界 |
| --- | --- | --- |
| 摄影 | 型号/允许分配范围、镜头/配件兼容提示、实际附件清单、使用教学、介质与设备交接注意、本人问题反馈 | 不由客户勾选“忽略物理不兼容”，客户上传读数不直接变成计费依据 |
| 露营 | 人数/容量/季节/场景提示、套装必还与耗材清单、清洁说明、搭拆服务参数、天气改约申请 | 适用性提示不是天气/安全保证，天气申请不自动退款，需清洁设备不能因客户确认恢复可租 |
| 车辆 | 驾驶资格、准驾条件、取还地址、里程/能源和车况证据、异地归还说明、已发生费用说明 | 不接受任意代填驾驶人替代核验；定位/开锁/违章费用须真实来源和授权，不能自行修改里程或扣款 |
| 工程 | 操作资质、项目地址/进场条件、设备规格、安全说明、工时/班次、运输安装及操作员服务申请 | 客户声明不能替代安全检查、设备检验证照或经营方交付审核；故障停机减费需责任和时段依据 |

同一证件可以按合法适用范围复用，但每个目标品类在动作时重新判断。客户可补充事实和确认交接内容，最终资产分配、取还检查、异常费用与维修状态仍受运营权限控制。

最低验收：模板/术语随当前服务变化、无品类硬编码主流程、不可用capability无入口、客户上报与核验事实分开、实际组成与费用可追溯。

### F13 智能柜、自助网点与设备连接（条件性储备）

只有对应网点/设备capability已启用、真实设备链验证通过、应急流程明确时开放P37。

字段：本人订单/分配设备、网点/柜口、开放时段、当前步骤、需满足条件、动态凭证有效期、设备最后通信时间、操作进度与失败原因；不展示长期设备密钥或可复用控制口令。

- 自助领取先核对资金、资格、完整分配、设备状态与必要交接；动态码/挑战绑定订单、设备、客户、用途和短期有效期，防截图重放。
- 开柜/开锁、物品被取出、检查/交接完成分别记事实；不能收到一个设备成功回调就直接把整单设为已领取。
- 自助归还须识别实际归还资源及数量，必要检查待商户完成；关柜门不等于器材无损、可出租或押金已退。
- 远程控制只允许已授权设备的允许动作，危险动作明确确认、服务端限流与审计；租期结束/关系撤销及时收回权限。
- 仅在实际操作必要时申请定位/蓝牙/相机权限，拒绝后给替代服务路径；不做无理由后台定位。
- 设备离线/断电/通信结果未知保留待核对，提供人工取还/客服。不能靠页面重试反复开锁，也不能制造虚假遥测。
- 最低验收：真设备或正式厂商沙箱、命令重放、并发、断网恢复、撤权、部分归还、资金状态联动与人工应急。

### F14 付费会员与订阅（条件性储备）

免费方案与人工授予继续存在；只有价格、期限、权益单位、退款、续费、到期和法务口径确认后，才开放P38。

- 售卖页展示方案目标类型、价格/币种、有效期、完整权益与限制、适用服务、是否自动续费、续费金额/周期、取消续费与退款规则、协议版本。
- 默认不勾选自动续费；首次购买与后续自动扣款分别获得明确授权，用户可查看和取消下一周期续费。
- 购买未付款/付款处理中/已支付待生效/已生效/退款中/已退/已到期分别记录；不能在客户端支付回调后立即人工加等级。
- 会员费用使用独立业务用途与账务记录，复用支付provider但不伪装成设备租金或押金。重复回调只生效一次，外部成功内部失败可恢复。
- 退费涉及已使用权益时，展示按已确认规则计算的方案；不自行规定按天退款或全额扣回，也不直接改历史租赁单金额。
- 此功能不等于真实储值钱包；充值、提现仍不在默认范围。
- 最低验收：真实扣款/退款、并发幂等、到期/停续、重复授予、防隐性续费、旧订单快照不变；未确认规则时保持Reserved。

### F15 多语言、地域与可访问性完善

- P39可选择已提供的语言，商户内容无翻译时明确回退语言；协议、合同和关键计价说明不能用未经确认的机器翻译替代适用版本。
- 手机、地址、证件、货币小数位、营业时区和税价展示按经营地区配置；不因为切界面语言就变更订单币种或计价规则。
- 同一订单只用一个结算币种；不同币种订单不合计，不在客户端自行换汇。新地区支付、税务、发票和数据合规须专项放行。
- 支持系统字号、可读焦点顺序、状态文字与足够点击区域；金额/协议/错误不以颜色或动画作为唯一表达。
- 弱网下允许浏览已授权的非敏感缓存并标注时间，付款、取消、续租、控制设备等动作必须联网确认，不实现离线交易队列。
- 最低验收：长文本/大字号不截断关键费用，语言切换不丢表单且不改金额，跨时区显示准确、拒绝权限不形成死路。

## 17. 完整功能共用约束与待确认项

### 17.1 新功能必须继承的规则

1. 账号、客户主档和租户会员只有一套；企业、营销、设备和签章身份是关联授权，不另造客户密码体系。
2. 订单、资源、费用与资金仍是统一内核事实；任何新入口的列表、详情、附件、异步回调、导出和幂等重放均校验主体。
3. 多空间收藏/本人订单/消息可有统一入口，但交易按空间拆分；企业授权查询与经营汇总须独立授权，不能借“统一入口”放宽数据。
4. 新服务、权益、规则或通知发布后不覆盖历史快照；撤销、补偿、退款、追偿全部留追加事实与原因。
5. “客户提出”“商户受理”“供应商受理”“实际执行”“资金已到”分别展示，未知结果不伪装失败或成功。
6. 所有后续功能均按功能可用性控制入口；未建设、未配置、未验收、暂时不可用四种状态有不同说明，不能只放灰按钮不解释。
7. 本文字段是业务/展示要求，不授权采集所有可获得的个人信息；权限与隐私按最小必要原则设计，敏感访问和关键变化留审计。
