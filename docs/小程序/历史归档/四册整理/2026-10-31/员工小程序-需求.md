### 0.1 方向调整

| 项 | v1.0 | v2.0 | 依据 |
| --- | --- | --- | --- |
| 使用者 | 门店/仓库/现场交付人员 | **两层**：执行层（现场人员）+ 处理层（店长、现场负责人、租户管理员） | v1.0 把费用复核、取消、续租审核、收款确认、审核全部排除，管理员在门店"能看不能办"，仍要回电脑处理，与"小程序承担执行和基础管理"的目标不符 |
| 权限 | 另建 8 个 `staff:*` 权限码 | **复用平台权限目录**（`rental-os:order:*`、`rental-os:member:*`、`rental-core:maintenance:*` 等），只新增 1 个窄权限 `rental-os:order:offline-payment` | 平台已有 60 余个权限码并要求"分别授权"的动作清单已定（§4.7.15、§4.6.14）；再建一套会形成第二权限体系，Web 与小程序对同一动作的授权可能不一致 |

| 履约地点数据范围 | 视为既有能力 | **列为后端前置**（STAFF-BE-01） | 代码盘点：`WorkspaceMember` 与履约地点无关系，订单查询无 `locationId`，Rental Core 不按数据范围过滤，仅按会话空间隔离 |
| 客户扫码确认交接 | 首期必备 | 现场签字留证为首期必备；扫码确认作为**并行跨端任务**（STAFF-BE-07），不阻塞首期 | 后端无交接确认令牌，客户小程序无确认页，需三端配合 |
| 任务转派、订阅消息 | 首期 | **移出首期** | 后端无订单任务转派模型；通知仍为模拟适配器 |
| 线下收款 | "登记待对账"一个动作 | **登记（窄权限）与确认到账（结算权限）两段式** | 现有资金事件 `initiate/capture` 天然支持两段；登记不改支付状态，确认才入账 |
| 配置类功能 | 未逐项列出 | 逐项列出并要求**服务端不暴露路由**（§1.3） | 不能只靠前端隐藏 |

## 1. 产品定位与范围

员工履约小程序面向租户的门店、仓库、现场交付人员以及店长和租户管理员，不面向租赁客户，也不替代 Web 运营后台。它承担两件事：

1. **现场执行**：从备货到交付、再到归还、检查、处置和工单的现场闭环，减少回到电脑补录事实。
2. **基础管理**：把订单在门店最常发生、需要当场决定的问题处理搬到手机上——确认、取消、爽约、续租审核、费用复核、收款、审核——让持有相应权限的店长和管理员不必回电脑。

配置类工作（商品、价格、规则、日历、账号、角色、渠道、第三方接入等）留在 Web 后台，小程序不提供入口，服务端也不暴露对应路由。

平台提供一套统一小程序服务多个租户。员工使用租户编码和租户运营账号登录；后续可增加微信身份绑定以便快速登录，但绑定关系不能绕过账号状态、成员关系、空间权限和地点数据范围。

### 1.1 STAFF-MP-R1 首期包含

**执行层**

- 登录、会话恢复、退出和密码修改入口。
- 选择/切换获授权的经营空间和履约地点。
- 今日待办、逾期待办、任务筛选和扫码查单。
- 订单摘要、客户交接信息、资金/资质/条款门禁结果。
- 预分配、扫描实物、调整分配并锁定资源。
- 领取检查、客户现场签字留证、现场交付。
- 整单或逐批归还、归还检查、异常事实和库存处置。
- 养护工单的领取、开始、提交（清洁、整备、维修）。
- 在获得单独权限时登记现金或银行转账收款及凭证。
- 操作记录、本人作业历史和失败恢复提示。

**处理层（按权限可见）**

- 工作台"待处理事项"区：待确认订单、待支付超时、爽约待判定、费用待复核、续租待审、收款待确认、工单待验收、审核待办。
- 订单确认、取消、待支付超时处理、爽约通知/判定/恢复领取。
- 续租代办试算与申请、续租负差额退款审核。
- 检查异常费用复核、再复核、客户申诉处理。
- 线下收款确认到账。
- 库存处置恢复可租、工单验收。
- 会员注册审核与证件审核（仅持有租户级审核权限者）。
- 解锁/释放/改配、操作锁人工解除（必填原因）。
- 订单内部备注。

### 1.2 首期不包含

- 代客下单、新建报价（客户自助小程序与 Web 后台已覆盖；是否进 R2 见 §13 SD-01）。
- 结算、强制关闭、任何形式的退款执行（在线退款、线下退款、押金退还、预授权释放/转扣）、对账。
- 改期与其他订单变更审批；换货/部分取消仅在后台 ORDER-CHANGE-01 收口后条件性纳入。
- 经营例外：免费取消、取消/逾期减免、人工调价。
- 任务转派、跨地点调拨审批、跨租户工作台、跨未授权空间汇总。
- 离线推进领取、归还、收款或库存终态。
- 微信订阅消息推送（通知 provider 真实接入前只做应用内待办计数）。
- IoT 开锁、物流承运、电子签章、开票和完整财务对账。

### 1.4 基础版 / PRO 的移动端框架接入

此项已由负责人确认纳入当前版本框架准备，不等于提前开发任何专业扩展。业务规则唯一来源为[SaaS 版本订阅与 PRO 升级专项需求说明](../SaaS订阅/SaaS订阅-需求.md) §5.5；开发状态及验收由[独立专项开发任务](../SaaS订阅/SaaS订阅-开发任务.md)的 `SUB-MP-01～SUB-MP-04` 维护，本文件规定移动端页面和边界。

- 「我的」展示基础版 / PRO、统一到期时间和服务状态，可进入只读「版本与权益」。区分公共套餐包含、指定租户额外授权和 PRO 权益，不自行维护另一套套餐表。
- 功能入口按实际权益、功能上线、空间 / 品类配置与员工权限共同控制；基础版获特批不需要标为 PRO，PRO 也不扩大员工权限。菜单、扫码 / 深链接、页面进入、提交请求和服务端校验保持一致。
- 登录 / 恢复前台、切空间、页面重入及收到权益变化错误时刷新；平台续费、降级、下放或收回授权后无需退出重登。缓存 / 迟到请求不能串租户或覆盖新会话。
- 首页 / 工作台使用小提示卡，「我的」保留状态；两版均提醒临近到期和已到期，按本端账号 / 租户 / 期限修订 / 阶段当天去重，续费后撤旧提示，不遮扫码及底部导航。
- 到期停止新业务，保留小程序原本获权的已有履约 / 归还等善后动作；不因此给员工新增退款、对账或资金执行权。SaaS 开通与租赁现场收款是不同业务，不用现场收款成功来修改租户版本。
- 普通员工不默认看到年费、转账凭证、平台内部备注。租户管理员可了解已发布 PRO 介绍 / 联系平台，但本期不提供小程序支付升级或改套餐 / 期限 / 功能授权。
- 未上线专业功能只展示真实规划状态，无作业入口；以后适合手机执行的专业模块再接入同一框架，不另建 PRO 小程序应用。当前没有可用专业模块时用空态 / 待上线说明，不为测试授权开发专业业务。

## 2. 身份、权限与数据范围

### 2.1 身份与会话

- 员工身份就是租户运营账号（`Tenant` + `User`），登录参数为租户编码、账号、密码，与 Web 后台同一套账号、密码策略和 `mustChangePassword` 规则。
- 员工端使用**独立会话**：`/api/staff/v1/auth/*` 签发受众为 `staff` 的令牌，与 Web 运营令牌、客户端令牌互不通用；撤权、`tokenVersion` 递增和租户冻结对三种会话同时生效。
- 当前经营空间只存于服务端会话（沿用 `AuthSession.currentWorkspaceId`），切换空间走服务端校验成员资格后重签。客户端提交的 `workspaceId`、`locationId` 只能缩小范围，不能扩大。
- 微信身份绑定为后续能力；绑定后仍以租户账号和成员状态为准。

### 2.2 授权层级

有效访问范围为：

`租户账号有效 AND 租户成员有效 AND 经营空间成员有效 AND 角色操作权限通过 AND 履约地点数据范围命中`

- 只有一个有效经营空间时直接进入；有多个时必须选择，可随时切换。
- 每次切换空间都重新加载权限、地点范围、品类术语、capability 和待办数据，并清空上一空间缓存。
- 员工可拥有不同空间的不同角色。
- 空间内可进一步限定一个或多个履约地点（§2.5）。未授权地点的订单、资产、库存、工单和任务不得出现在列表、搜索、扫码结果或统计中。
- 撤销空间或地点权限后，旧会话下一次请求立即拒绝。
- 租户级动作（会员注册审核、证件审核）额外要求"用户基础租户角色的对应权限 + 租户级 `dataScope=all`"或租户管理员，与平台 §2、§4.8.14 一致；不能用空间 `*` 或多个空间授权并集取得。

### 2.3 权限：复用平台权限目录

小程序不新建平行权限体系。每个动作对应平台权限目录（`apps/api/src/modules/platform/platform.service.ts`）中的既有编码；服务端在 `/api/staff/v1` 路由权限映射中按下表校验，Web 与小程序对同一动作的授权口径一致。

| 报价并新建订单 | `rental-os:order:create` | 报价快照与下单内容必须一致，提交带幂等键 |

| 领取检查、现场签字、交付 | `rental-os:order:pickup`（+ operate） | |
| 归还、逐批归还、归还检查 | `rental-os:order:return`（+ operate） | |

| 异常费用复核、再复核、客户申诉处理、费用复核单 | `rental-os:order:fee-review` | 必填原因，保存原/新金额与审批人 |
| 换货、部分取消（条件性） | `rental-os:order:operate` | 依赖 ORDER-CHANGE-01 |
| 线下收款登记 | **`rental-os:order:offline-payment`（新增）** | 只能创建"已登记/待确认"的资金事件，不能确认、不能退款 |
| 线下收款确认到账 | `rental-os:order:settle` | 对应资金事件 `capture` |
| 会员注册审核 | `rental-os:member:review` + 租户级 `dataScope=all` | |
| 证件审核 | `rental-os:member:qualification-review` + 租户级 `dataScope=all` | |

### 2.4 三档能力包与租户角色映射

平台没有"员工/主管"固定角色，租户在 Web 的角色配置里把下面的能力包授予自己的角色（例如"门店员工""店长""区域经理"）。小程序只根据 `session-context` 返回的权限集合和数据范围渲染入口，不判断角色名。

| 能力包 | 包含权限 | 典型使用者 |
| --- | --- | --- |
| 执行档 | `order:view`、`order:operate`、`order:pickup`、`order:return`、`maintenance:view`、`maintenance:manage`、`asset:view` | 门店/仓库/现场交付人员 |
| 处理档 | 执行档 + `order:cancel`、`order:extend`、`order:fee-review`、`order:reassign`、`maintenance:review`、`order:offline-payment` | 店长、现场负责人 |
| 管理档 | 处理档 + `order:settle`（确认收款）+ 租户级 `member:review`、`member:qualification-review`（审核待办） | 租户管理员、区域经理 |

- 三档只是推荐组合，租户可自由增减；但 §1.3 的配置类权限即使授予，小程序也无入口。
- 缺少某权限时对应按钮不显示，且服务端拒绝；前端隐藏不作为权限控制手段。

### 2.5 履约地点数据范围（后端前置 STAFF-BE-01）

当前平台的数据范围 `all | organization | store | own` 中，`store` 指向组织单元而非履约地点，且 Rental Core 查询不按数据范围过滤。员工端必须按履约地点限定可见范围，因此需要新增：

- 空间成员上的地点范围：`WorkspaceMember.locationScope = { mode: "all" | "selected", locationIds: string[] }`（或等价关联表）。默认 `all`，与现有账号行为兼容，不影响 Web 后台既有用户。
- Web 后台"账号与空间成员"页增加履约地点多选（这是配置，留在 Web）。
- `/api/staff/v1` 所有列表、详情、扫码、统计、写操作按地点范围过滤，fail-closed：订单以 `fulfillmentLocationId` 或 `returnLocationId` 命中；资产/库存/工单以所在地点命中；无法判定地点的对象不返回。
- 地点范围变化后，旧会话下一次请求即按新范围执行。
- Web 后台在本期不强制按地点范围过滤（保持整空间可见），后续按平台 §4.1"授权地点"统一收口；两端口径差异必须在文档和验收中写明。

## 4. 端到端作业流程（执行层）

### 4.1 登录与进入工作范围

1. 员工输入租户编码、账号和密码。
2. 服务端校验账号、租户成员关系和可访问经营空间，签发员工会话。
3. 仅一个空间时自动进入；多个空间时显示选择页。
4. 空间内仅一个授权地点时自动选中；多个地点时由员工选择，也允许"我有权限的全部地点"。
5. 进入后加载品类术语、capability、权限集合、地点范围和待办；任一步失败都保留重新登录或重选范围的出口。

### 4.2 备货、预分配与锁定

1. 工作台按预约领取时间展示待配货订单（含配送订单的发货门店）。
2. 员工进入订单，查看资源需求和可分配候选项。
3. 员工扫描具体资产、数量库存或套装组件；服务端复核地点、状态、租期冲突、缓冲时间和品类限制。
4. 普通调整形成预分配；提交锁定时使用订单修订号（`expectedRevision`）和幂等键。
5. 资源已被他人锁定、状态变化或不兼容时，当前提交整体失败并提示冲突项，不留下半套锁定结果。
6. 解锁、释放、改配必须持有 `order:reassign` 并填写原因，原分配及覆盖关系保留审计。

### 4.3 现场交付

允许交付必须同时满足：

`订单允许领取 AND 资源锁定完整 AND 资金门禁通过 AND 客户资质通过 AND 领取检查完成 AND 交接确认完成 AND 在营业时段内`

前置状态由服务端在交付提交时统一复核（沿用现有 `handover/pickup` 的资金、资质、营业时段和企业授信校验），小程序只展示各项门禁结果与缺项，不能前端绕过。

交接确认两种方式：

- **现场签字留证（首期必备）**：员工设备显示交接摘要（订单、批次、商品、客户脱敏信息、条款要点），客户在屏幕签字；签字图像作为证据上传并绑定订单、批次、操作者、时间、地点。该签字是现场交接证据，不等同于电子签章。
- **客户小程序扫码确认（并行任务 STAFF-BE-07）**：员工端向服务端申请一次性交接令牌并展示二维码，客户用本人账号在客户小程序扫码确认，服务端校验本人、订单和令牌。上线前，交付只能以现场签字完成。

交付提交成功后由服务端原子推进订单和资源状态。客户不在场或拒绝确认时不允许交付，也不提供"跳过确认"的人工例外；确需例外的情况在 Web 后台按订单例外流程处理。

配送订单：首期员工端以"发货门店交付给配送人员/客户"作为交付事件，展示收货快照（收件人、脱敏电话、地址）；配送任务、路线与承运跟踪等待 SHARED-LOG-01A/01 后另行纳入。

### 4.4 归还、逐批归还与检查

1. 员工选择整单归还或本批归还项；已归还数量/资产不能再次选择。
2. 扫描实物并记录数量、套装组件、外观、功能、使用量及品类专属读数；检查模板按品类与阶段从服务端取得。
3. 缺件、损坏、超用或逾时只登记事实和证据（随检查提交），不由执行档直接确定最终费用；费用建议由规则和事实生成，进入 §5 的复核流程。
4. 提交后形成不可重复的归还批次（`batchNo` 或幂等键）；同一幂等键重试返回原结果。
5. 资源按检查结果进入回库可用、待清洁、待维修、下架或待复核状态；"已归还"不自动等于"可出租"。
6. 未归还部分继续保持占用并按平台规则计算逾时；已归还部分不再重复累计。
7. 异地归还订单按订单固化的归还地点执行；归还地点不在员工地点范围内时不可见。

### 4.5 库存处置与养护工单

- 归还检查产生的处置结果（回库、待清洁、待维修、下架、待复核）在 S10 可见；恢复可租需要 `maintenance:review`，并沿用现有处置恢复逻辑与缓冲规则。
- 清洁、整备、维修工单：执行档可领取、开始、提交结果（含证据）；验收恢复库存需要 `maintenance:review`。
- 处置与工单都不直接修改资产主档；库存数量与资产状态变更全部通过既有工单/处置事实产生。

### 4.6 现场收款登记（执行档，单独授权）

- 只有持有 `order:offline-payment` 的人员可登记现金或银行转账。
- 登记内容：订单、收款用途（租金/押金）、金额、币种、方式、时间、收款人、凭证、备注、幂等键。
- 登记结果为"已登记/待确认"（资金事件处于 `initiated`），不改变订单支付状态，不能冒充在线支付回调或财务对账完成。
- 确认到账见 §5.2。

## 5. 订单基础问题处理（处理层）

### 5.1 待处理事项来源与工作台聚合

工作台"待处理事项"由服务端投影产生，沿用并扩展现有 `workbench/todos`（已有 `pending_payment`、`no_show`、`return_overdue`、`fee_review`、`refund`、`work_order`、`notification_failure`），新增 `pending_confirm`（待确认订单）、`extension_review`（续租待审）、`offline_payment_pending`（收款待确认）、`review_task`（注册/证件审核待办）、以及现场任务类 `pending_allocation`、`pending_pickup`、`pending_return`、`pending_disposition`。

- 每类计数必须与对应列表筛选结果一致；按权限与地点范围裁剪；无权限的类别不返回。
- `refund`、`notification_failure` 在小程序只读，处理在 Web。
- 审核待办为租户级，不受空间与地点范围限制，但只对持租户级审核权限者返回。

### 5.2 逐项处理规则

| --- | --- | --- | --- | --- | --- |

| 操作锁人工解除 | 他人锁未到期 | `order:reassign` | 原因 | 锁释放并记录 | 操作锁能力扩展 |
| 内部备注 | 任意状态 | `order:operate` | 内容 | 仅运营可见，不对客户显示 | `orders/:id/internal-notes`（STAFF-BE-08） |

所有处理动作必须幂等、校验当前状态和修订号，保存操作者、时间、原因和前后差异；与 Web 后台对同一动作产生完全相同的事实与审计记录。

### 5.3 审核待办（条件性模块）

- 会员注册审核与证件审核是租户级动作，只对同时满足"对应审核权限 + 租户级 `dataScope=all`"或租户管理员的账号显示 S14。
- 小程序审核页只展示审核所需的最小资料（证件类型、脱敏号码、有效期、照片短时链接、提交时间），不提供客户主档编辑、账号管理或敏感资料揭示。
- 不满足条件的员工在订单详情看到客户"资质待审核"时，只显示状态与提示"请联系有审核权限的管理员"，不出现审核按钮。
- 是否把审核权限授予店长由租户决定（见 §13 SD-02）。

### 5.4 明确留在 Web 后台的处理动作

结算、强制关闭、所有退款执行（在线退款、线下退款、押金退还、预授权释放/转扣）、对账与差异确认、改期与其他订单变更审批、经营例外（免费取消、减免、人工调价）、客户敏感资料揭示、客户合并/注销、代客下单、通知失败重发。小程序在对应待办上只显示状态与"在后台处理"提示。

## 7. 扫码、文件与证据

- 扫码由服务端解析（`POST /api/staff/v1/scan`），至少区分订单、任务、工单、商品型号、序列化资产和套装/容器；码值只用于定位候选对象，最终仍校验租户、空间、地点、状态和权限。
- 现有 `/api/files/*` 要求 `system:integration:manage` 且租户级 `dataScope=all`，现场员工不可用。员工端使用独立的上传会话端点（`/api/staff/v1/uploads/sessions` + `complete`，沿用客户端资质文件的"上传会话 + 完成回执"模式），服务端签发短时凭证；小程序包和日志不得包含存储密钥或长期地址。
- 照片、签字、收款凭证、工单证据都作为文件资产绑定业务类型、订单、履约批次/工单、采集人、采集时间、服务端接收时间和校验信息；检查与交付 DTO 只引用已完成上传的文件 ID，服务端校验归属。
- 证据上传失败时不假装提交成功；可保存本地草稿并提示重试。改变订单、库存或资金状态的最终提交必须确认所需证据已被服务端接收。
- 客户信息脱敏：姓名保留、手机号脱敏、证件号脱敏；配送收货快照中的电话仅在交付当日对持 `order:pickup` 的操作者按需显示，且记录访问审计。

## 8. 并发、离线、失败恢复与提醒

- 同一订单同一作业阶段只允许一个有效操作锁（沿用现有 `operation-lock` 与 `x-operation-token`）；其他员工可只读查看并知道占用人和失效时间。
- 锁具有短期租约和续约机制，异常退出后自动失效；人工解除需 `order:reassign` 与原因。
- 分配、交付、归还、处置、工单、收款登记/确认和所有处理动作均使用幂等键、订单修订号和事务；重复点击、网络重试和扫码重放不产生重复事实。
- 断网时只允许保存检查草稿、照片待上传列表和未提交备注。恢复联网后必须重新读取订单状态、权限和资源占用，再决定是否可以提交。
- 服务器已成功但客户端未收到结果时，按幂等键查询原结果，不允许直接重复执行。
- 权限撤销、空间停用或地点范围变化后，未提交草稿可放弃，不能继续推进业务状态。
- 提醒：首期只做应用内待办计数与角标；微信订阅消息在通知 provider 真实接入并通过验收后另行纳入。通知不改变业务状态，发送失败不阻止已合法完成的事务。

## 9. 接口与技术边界

员工端使用独立的 `/api/staff/v1/*` 契约与员工会话，不直接复用客户 token，也不把管理端 `/api/rental/v1/*`、`/api/platform/*` 暴露给小程序。服务端实现为现有 Rental Core、会员、资金、文件服务之上的**薄门面**：不复制状态机、计价、库存或权限逻辑，只做路由、权限映射、地点范围过滤和移动端 DTO 投影。

- 路由权限映射沿用 `api-auth.guard.ts` 的集中式方式，为 `/api/staff/v1` 单独维护映射表并纳入 `validate-route-permissions` 校验；未匹配路由默认拒绝；§1.3 的配置类路由不注册。
- DTO 在 `packages/shared` 新增 `staff.ts`（`Staff*` 前缀），只返回移动作业需要的字段，客户证件、联系方式和内部金额按权限最小化、脱敏。
- 首期接口域：`auth`、`contexts`（空间、地点范围、权限集合、品类术语、capability）、`tasks`（工作台投影与列表）、`orders`（搜索、详情、服务端报价与新建、内部备注、确认/取消/超时/爽约）、`assets`（序列化资产登记/编辑及查询）、`customers`（基础资料新增/编辑与查询）、`allocations`、`inspections`、`handovers`（签字证据、交接令牌）、`returns`、`dispositions`、`work-orders`、`fees`（复核、申诉、续租审核）、`payments`（线下登记、确认）、`reviews`（注册/证件审核）、`scan`、`uploads`、`history`。
- 每个写接口必须声明权限、数据范围、前置状态、幂等键、修订号、成功结果、冲突结果和可恢复方式。
- 客户扫码确认交接涉及客户端契约：`/api/client/v1/orders/:id/handover-confirm` 与客户小程序新增确认页，作为跨端任务单独登记。

## 10. 首期验收

| 场景 | 必须证明的结果 |
| --- | --- |
| 多租户与登录 | 同一小程序可登录不同租户，但一个会话只属于一个租户；错误租户编码、停用账号和撤权旧会话均被拒绝；员工令牌不能调用 Web 运营或客户端接口 |
| 空间与地点范围 | 员工只能看到和操作获授权空间/地点；切换后术语、权限和缓存同步更新；伪造 `workspaceId`/`locationId` 不越权；地点范围为"全部"的既有账号行为不变 |
| 权限一致性 | 同一账号在 Web 与小程序对同一动作的允许/拒绝结果一致；缺权限时按钮不出现且服务端拒绝；配置类路由在员工 API 不存在 |
| 配货锁定 | 扫描正确资源可锁定；租期/缓冲冲突、不兼容或他人占用时整体失败且无半套分配 |
| 现场交付 | 资金、资质、资源、检查、签字确认和营业时段全部通过才交付；签字证据完整可追溯；客户不在场不能交付 |
| 逐批归还 | 相同商品分批归还数量准确，同批重试不重复；未还部分继续占用，已还部分进入正确检查/处置状态 |
| 订单基础处理 | 店长在手机完成确认、取消（含取消费）、爽约判定、费用复核、申诉处理、续租审核，客户端状态正确回显；每个动作有原因与审计，与 Web 结果一致 |
| 线下收款两段式 | 登记只产生待确认事件且不改支付状态；确认到账才入账并推进订单；重复登记/确认不重复入账；无 `offline-payment` 权限不能登记，无 `settle` 权限不能确认 |
| 审核待办 | 只有租户级审核权限者看到 S14 并可处理；空间级权限并集不能取得审核能力；审核结果在客户端正确显示 |
| 处置与工单 | 处置恢复与工单验收需要复核权限；执行档只能提交不能验收；恢复后库存可用性正确 |
| 四品类 | 四类空间复用同一主流程并显示各自术语和检查项；未知品类安全降级，缺必选能力不放行 |
| 并发与恢复 | 两名员工争抢操作锁只有一人成功；断网、超时、客户端重启和结果未知均可查询恢复且不重复写入 |
| 文件与隐私 | 上传密钥不进入小程序包；证据按租户/空间/订单隔离；客户敏感字段按最小权限脱敏；员工上传端点不需要 `system:integration:manage` |

新增版本框架验收按 SaaS 专项 A32～A37 执行，覆盖两版、公共下放 / 单租户特批、岗位权限、直接页面访问、授权刷新、到期提醒和已有订单善后；状态和证据在 `SUB-MP-*` 唯一维护。未实现专业业务留待以后，不要求为版本框架验收提前开发。

STAFF-MP-R1 只有在真实数据库、至少两个租户、同租户两个空间、不同地点范围、执行档与处理档两类账号、四品类代表性检查以及微信开发者工具/真机流程均通过后，才能标记完成。页面存在、静态检查或接口返回 200 不能单独作为完成依据。
