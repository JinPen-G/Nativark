## 2. 顺序和跨专项所有权

1. 01/02固定主档、会员、关系、财务与本端信任边界，不先复制营运后台或放宽/my/orders。
2. 03～05交付开通和成员真实纵向链，申请人候选、个人会员审核、企业审核和管理员授予分别记录。
3. 06/07先在服务端证明授权、撤权、审批与原子消费，再让08的客户小程序/网站调用。
4. 09/10建立最少订单/财务读模型和申请，11随每片接真实页面，不用假额度或mock填缺生产者。
5. 12核对多租户、多企业、多空间、历史、并发/unknown与启停。正式账单或资金依赖未齐，相关完整验收继续阻断。

前置为所需固定子交付，不一律等待前项100%。会员/授信、Core、shared/OpenAPI、认证、两端消费者和新Web壳必须在本轮实施前明确唯一作者及固定合同，并行时使用独立工作树。文档阶段不预先抢写这些公共文件。

## 3. 分项实施出口

### ECP-01/02：基线与正式合同

- 从现有认证/会员/关系及Core生产者追到客户消费者，登记可信主体、租户/企业/空间来源、原业务所有者、外部副作用、当前缺口和合同版本。
- 固定企业管理端路由/audience适配、独立动作权限及最少DTO；复用shared正式出口、运行时校验和OpenAPI，不私建同名协议或泄漏ORM类型。
- 落实需求§1.1已批准入口：同租户网站origin的独立Web应用（公共站点`/:tenantCode/enterprise`、绑定域`/enterprise`）、原客户登录/注册、安全回跳及有效会话免重复登录。固定客户会话持有/衔接/单刷新所有者和撤销合同；API仍复验当前企业关系/权限，不依同域存储自授权，不通过URL传token，不混营运或小程序会话。
- 分离成员关系、租赁授权、企业付费权、审批政策、历史订单读取和资金查看；不将一个admin布尔值当所有授权。
- 建立两类企业订单字段白名单、旧自费单告知准入、财务分组及附件规则；明确未配置/已撤销/缺证据结果。仅技术方案不改原个人接口语义。
- 出口：可定位生产者→正式入口→应用服务→仓储/适配→直接消费者及验证；需求§8参数已获对应依据，不编造包名/数据库迁移或生产开关默认。

#### 第一片已登记的实施合同

- [客户入口](../../apps/api/src/modules/client/client-api.controller.ts) → [企业访问服务](../../apps/api/src/modules/client/enterprise-access.service.ts) → 原客户/账号/会员/企业关系及增量门户grant；DTO和动作登记经[shared正式出口](../../packages/shared/src/enterprise.ts)及[OpenAPI](../../apps/api/src/contracts/enterprise-schemas.ts)。首片仅`portal:enter`和`members:read`，未配置保持拒绝；原本人订单接口不扩权。
- 商户经[原会员Controller](../../apps/api/src/modules/platform/membership.controller.ts)和[配置服务](../../apps/api/src/modules/platform/enterprise-portal.service.ts)显式开启；租户行事务锁、期望修订及原键收据共同约束。原收据回读不重新授予已撤销权限；明确的`enterprise_revision_conflict`是写入前拒绝，客户端重新读取修订并保留表单，不把`not_recorded`推断成unknown操作未执行。
- [共用会话](../../packages/web-client/src/session.ts)对登录、刷新、退出、空间切换使用同源同商户的一把Web Lock。API前缀只允许本站`/api/client/v1`，相对/同源绝对写法统一；两端只订阅已提交会话，不回写迟到页面响应。退出锁内读取刷新后继再撤销；失应答/未决刷新只做本机退出并明确服务端结果待核对，不盲目重发。仅GET可完成轮换后重读，业务写不自动重试。
- [独立Web](../../apps/enterprise-portal/README.md)与网站仅共用原客户认证及窄UI呈现，构建拒绝营运auth/http/路由进入客户bundle。资产`/enterprise-assets/`与两类文档路径分开，正式host和深链接回源须在获准环境核验，离线预览不提供业务数据。
- [迁移](../../apps/api/prisma/migrations/20261101000100_enterprise_portal_access/migration.sql)默认关闭、零grant，无存量backfill。迁移未执行；数据库结构验证/事务并发和真实代理仍为未验，不靠已有角色或测试替身开放生产。

### ECP-03/04：申请和邀请

- 企业申请复用真实个人账号，商户通过后同事务复用企业会员、管理员关系和审计；同主体竞争、重复申请、存量认领及审批失应答均有原结果。
- 有界邀请散列存储；原申请占用/审核/撤销/失效的次数语义明确，会员待审核不能提前激活。
- 邀请落地页仅最少企业说明，认证后获取本人申请；商户全部会员搜索和跨租户查手机号不开放。
- 出口：真实商户审核页面/服务与企业端申请/入企消费者接通；重复、撤权、过期、滥用猜测和并发限额负例成立。

### ECP-05/06：成员、交接与政策

- 复用原关系主键及修订，关系终止不硬删除。暂停/退出/恢复和管理员交接分别授权；最后管理员保护在事务中，不只UI禁用。
- 商户上限、企业收窄、员工收窄/付费权和单笔金额上限的版本/适用范围分别固定；历史读取不跟新租赁白名单混用。
- 关系/政策撤销通知与缓存失效在提交后执行，服务端最终动作复验不依赖通知送达。
- 出口：同人多企业、离职有在途、其他企业不误伤；新空间/品类、政策收窄与审批/订单竞争仍拒绝不合格新业务。

### ECP-07/08：企业审批与真实租赁消费

- 首期单级审批，明确免逐单/逐单配置、非自审、当前审批人、批准/拒绝/撤回原子竞争。
- 保存申请修订、报价指纹/有效期、主体、关系、企业政策和单次批准；准备/批准不占库存或额度。政策与批准复验落原应用/Core正式提交边界，覆盖客户、商户代客及其他受控入口，不能只约束新Web；存量按显式启用范围切换，不补造企业授权。
- 批准后通知员工返回原申请，核对仍有效的报价/主体再明确提交；审批请求本身不创建订单，失效申请重新报价/审批。原批准消费与Core订单/变更正式提交的原子性/恢复证据必须可验证；跨模块同进程不自动等于同事务，未知保留原键。
- 保证金合同默认企业承担；明确员工承担时固定租赁付款主体与保证金实际出资/授权来源、本人确认、原事件/退款人、抵扣与债权分账。核对原共享/资金/预授权端口能否真实表达混合承担，不能仅增DTO/UI放行；无支持保持该模式不可用。变更承担/金额/方式需重新报价与审批，离职和合同更新不改原来源。
- 客户小程序与租户网站分别接三种身份选择、报价刷新、可见性告知、审批结果/失效及原订单回读；只启本专项最小入口。
- 出口：正常/无权/超额/资格不符、并发审批与撤权、报价到期、批准后库存不足、提交失应答、续租/换货新增支出均有直接消费者证据。

### ECP-09/10：企业读模型与财务申请

- 企业订单专用reader以原快照归属＋当前权限投影，分页/计数/跨允许空间索引同边界；个人付款组不泄露凭证/住址/证件。
- 财务数据从原服务端来源读取，锁定原币种/空间、payment与allocation口径，缺账单不伪造编号/到期/终态。真实账单是本项完整验收前置，不以订单明细页代替。
- 对账/资料/额度申请仅保存待商户核对事实，商户使用原财务/会员权限处理，凭证上传不入账；复验原企业/对象关联、文件ACL、审计和回读。
- 出口：在职/离职历史、企业承担/优惠自费/纯个人三分组、旧单缺告知、当前权限收窄、回款重复/部分/异议和跨空间财务一致。

### ECP-11/12：Web交付、安全与收口

- 独立客户端壳复用React/UIArc基础和客户认证，不直接复制营运路由。按固定合同配置同域/enterprise的静态资源、已注册子路由与深链接回源，不能被租户网站的通用SPA回退错误接管；真实站点域名/反向代理配置在获准环境核对，不提前部署。
- 租户网站“企业服务”和企业直接访问共用身份分流：未登录安全返回、有效客户会话免重复输入密码、一个企业直达/多个企业选择、普通员工/申请人只进本人页面。覆盖登录失效、管理员撤权、退出、切企业/商户、迟到响应及拒绝任意return URL；小程序引导不传token或承诺未经验证的免登录。
- 各页加载/空态/不可用/冲突/未保存/unknown出口真实可操作，企业登录完成不等于企业管理准入通过。
- 待办、通知、审计、导出和下载全部复验当前权限，不能把原角色缓存当长期授权。短信/微信只走获准渠道，原码/敏感材料不进日志。
- 固定存量显式开通、没有首位管理员的认领、停止新准入、历史和unknown继续核对及最低可回退条件；不清理原事实让旧程序兼容。
- 一次独立审查，修确认问题后定向复验。逐项提交ECP-A01～18证据和未验环境，列原依赖仍缺部分；全部研发不等于商户/生产开通许可。
