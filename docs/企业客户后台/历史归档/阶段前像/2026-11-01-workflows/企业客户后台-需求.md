## 1. 产品定位

本端供**商户租户的企业客户管理者**使用，不是商户营运后台，也不是商户自己的员工履约小程序。例如租车商户A的企业客户B，B的员工使用企业身份租车，B的管理员管理成员、租赁授权、审批、企业订单和对账。

首期采用独立响应式Web客户端：桌面优先，手机可完成申请、入企审核和订单审批；沿用客户账号和可复用UI基础，不嵌入商户后台或借营运token。员工仍从客户小程序/租户网站的企业身份入口租赁；管理者自己租赁时也有明确个人使用人，不在本管理端重做商城。

### 1.1 已确认的入口与登录方案

**界面独立，客户登录共用，企业管理权限单独核验。** 首期企业Web与消费者网站同一origin：公共站点以`/:tenantCode/enterprise`定位商户，已登记商户域名以`/enterprise`进入并由服务端核验域名绑定。例如`/demo/enterprise`中的demo是商户编码，不是企业、经营空间或品类；登录后再核验本人可管理的企业。未知/冲突域名或入口不回退演示租户，不允许查询参数覆盖商户归属。无需另建企业账号、密码或独立企业域名。网站提供“企业服务”和已注册子页直接访问，静态资源与深链接须分发给独立企业应用；方案获准不表示已经上线。

| 进入时的状态 | 应到达的页面与处理 |
| --- | --- |
| 未登录或客户会话无效 | 使用当前商户的客户登录/注册入口；成功后仅返回本端已注册且受权的原目标页面，不接受任意外部return URL |
| 已有有效客户会话 | 服务端核验当前客户、商户及会话后衔接企业端，不重复要求输入密码；继续单独核验企业关系和动作权限 |
| 只有一个可管理企业 | 进入该企业工作台，持续显示当前商户与企业；直接访问其他企业资源仍须拒绝 |
| 有多个可管理企业 | 展示本人可管理企业选择器，切换后重新核验企业权限并取消旧请求、隔离数据/草稿，不继承上一企业权限 |
| 普通企业员工 | 仅本人企业关系、加入申请及已获准的租赁/审批状态，不开放管理员工作台、同事订单或企业财务 |
| 尚无企业关系或申请待审核 | 提供申请企业会员、通过邀请申请加入及本人申请进度；未审核通过不展示企业内部数据 |

“企业服务”是按当前身份分流的入口，不是让所有客户都获得管理能力。商户由网站已登记域名/租户入口解析并由服务端复核；相同域名、客户ID、链接中的企业ID或本地缓存不授予跨租户/企业权限。切换商户必须重新取得目标租户的可信客户会话，不建设跨商户统一登录或共享企业组织。

两套Web应用可共享原客户认证服务及受控会话衔接，但不把同域或共用localStorage当授权证明，也不复制一套独立refresh轮换者引发重复刷新。正式会话持有、衔接、刷新和撤销合同由ECP-02固定；商户营运账号/token不得进入企业客户授权面，API、深链接、导出及附件每次按当前企业权限校验。客户退出、会话撤销或管理员降权后，旧企业管理视图与请求均不可继续使用。

客户小程序“我的”可提供企业身份/申请入口及进入Web企业服务的受控引导；原小程序会话不能直接充当浏览器会话。需要衔接时通过正式服务端机制，否则浏览器正常登录，不在跳转链接中携带access/refresh token。邀请与登录回跳也不传业务凭据。独立域名部署或跨origin免登录留后续另行批准，不能因本轮同域方案自行扩大。

企业付费订单以企业为签约和付款主体、个人为实际使用人；企业优惠自费单仍由个人签约付款。选择企业优惠不能暗中转成企业债务，个人单不能事后自动挂到企业。

| 首期必须交付 | 本期不扩展 |
| --- | --- |
| 企业申请、商户审核、首位管理员、存量认领 | 跨商户统一企业身份/组织、集团统一账本 |
| 邀请码/链接、个人入会引导、加入审核与撤回 | 营销邀请奖励、分销、商户全部会员搜索 |
| 员工/管理员、部门标签/工号、停用/移除/交接 | 复杂组织树、HR/SSO/SCIM、批量导入自动建账号 |
| 商户可租范围上限、企业/员工收窄和付费权限 | 自动周期预算、成本中心分摊、任意审批流引擎 |
| 逐单/免逐单企业付费、原Core真实执行 | 超额自动放行、任意代签、重建交易状态机 |
| 企业承担与企业优惠自费订单的受控查看 | 纯个人订单、实时轨迹、私人证件/银行卡全文 |
| 授信、应收、正式账单、回款、对账异议与材料 | 客户改额度/到期日/账本、确认到账、执行退款 |
| 待办、审计、必要导出、安全恢复与受控启用 | 新供应商、资金池/钱包、自动扣款/开票/签章 |

## 2. 身份和管理授权

### ECP-R01：租户独立与个人会员基础

1. 管理员和员工必须关联**当前商户租户的个人会员及客户账号**，复用CustomerProfile、CustomerAccount、CustomerMembership和企业员工关系。不必购买付费会员，也不要求先完成个人租赁；不在员工表另存一套姓名、手机号、密码替代账号。
2. 未注册者打开邀请后，先核验本人联系方式、同意该商户协议并注册/复用个人会员。商户采用人工入会审核时，可以保留入企申请，但个人会员未满足激活条件前不激活企业关系。个人会员审核、企业加入审核、实名/驾驶资格审核是不同事实，企业管理员不能代替商户审核证件。
3. 同一法律实体可分别成为多个商户租户的企业客户；各租户的主档、管理员、员工、范围、授信、账单和材料独立。相同信用代码/手机号不触发跨租户合并、自动同步或存在性泄露。切换商户重新取得目标可信会话，不做跨商户金额汇总。
4. 同一人在同租户可加入多个企业；当前操作明确选一个企业，订单仍单空间/单币种。服务端验证tenant、customer、corporate、关系与当前上下文，不信任URL/缓存声明。

### ECP-R02：角色和最小动作权限

首期沿用admin/employee关系语义，不新增登录身份。角色通过受控映射获得明确企业客户动作，不等于商户营运角色或全租户dataScope。支持多个管理员；加入企业不自动得到管理员、付费权限或审批权。

| 主体 | 允许 | 不允许 |
| --- | --- | --- |
| 企业申请人 | 提交/补件/撤回本人申请，查看状态 | 未审核即查现有企业员工/订单/信用资料 |
| 普通员工 | 本人加入/退出申请、关系、可租范围、本人租赁和审批状态 | 查同事订单/企业账本、审批自己、改范围上限 |
| 企业管理员 | 依当前明确权限管理邀请/员工/其他管理员、企业政策、订单审批、企业订单和财务读/申请/导出 | 租户账号/角色、商户经营数据、正式金额裁定、收退款和资质审核 |
| 商户受权人员 | 在原权限和财务范围内核验企业/管理员、设置品类/空间上限、授信及账务 | 因管理企业获得其他租户资料；借企业角色绕过自身原财务授权 |

企业订单查看、财务查看、成员维护、管理员授权、政策管理、预约审批、资料申请、导出为独立动作；首位管理员可获得本企业的预设管理动作，后续授权可收窄。员工晋升管理员是独立高风险动作，须重新验证当前管理员资格和目标身份，不能由邀请参数直接写入角色。

最后一个有效管理员不能自行退出、被降级或移除，除非同事务完成向已核验个人会员的交接。交接接受、失应答回读和并发保护必须真实存在。全部管理员失联/账号冻结时，由商户经原身份核验、授权证明和审计恢复，不开放“知道企业名/信用代码即可认领”。

### ECP-R03：企业申请、认领与首位管理员

- 已认证个人会员在目标租户申请企业会员，提交企业名称、有效主体标识、地区、联系人、必要授权证明和协议确认。资料按地区/所选服务要求校验，不把中国统一社会信用代码强制用于所有司法辖区。
- **默认申请人为首位企业管理员候选人**；商户审核企业和申请人的代表资格通过后，才原子建立/复用企业会员、激活管理员关系并留审计。仅提交申请、个人会员自动审核通过或持有邀请链接都不能授予管理员权。
- 审核通过不自动开授信/免押、不自动开放所有品类；可租上限由商户明确设定。预付企业可入会，不强制虚构授信合同或额度。
- 状态覆盖草稿、待审核、待补件、通过、拒绝、撤回；重复提交/审批同键同结果，资料改变以修订校验重新提交，旧批准不能覆盖新资料。
- 同租户已有企业时走现有管理员邀请或独立认领申请，不自动新增重复企业，也不直接追加管理员。不同申请人竞争同一主体，由商户核对，不泄露已有企业敏感详情。
- 商户代建的存量企业必须显式选定并核验首位管理员，不能把联系人手机号自动认领为账号。冻结/退出/关闭的企业保留原历史，不能重新申请新ID绕过限制。

## 3. 成员加入与生命周期

### ECP-R04：邀请码、邀请链接与加入审核

邀请只提供**加入申请资格**，不是登录凭据、企业管理凭据或租赁批准。管理员可以生成指向本租户/企业的代码或链接、复制、停用和重新生成；记录创建者、有效期、允许使用次数/人数、用途和状态。期限/上限由正式配置确定，必须有界，本文不编造具体天数。

流程：查看最少邀请说明 → 登录/注册目标租户个人会员 → 本人确认企业、员工资料及使用企业身份的数据规则 → 提交申请 → 企业管理员审核 → 复验会员/企业/邀请和关系 → 激活或拒绝。会员仍待审核时保留阻断原因，个人激活不能未经审核自动成为企业员工。

- 申请包含本人引用、部门/工号等适用信息；未经核验的部门/工号只是申请资料，不能授予权限。
- 待审核申请可撤回；拒绝/重新申请保留原原因和历史。已在职重复申请回读原关系，不新增另一条活动关系；已被停用/移除者须新审核，不能凭旧码复活。
- 邀请到期/撤销后拒绝新申请和未完成的激活；已激活员工不因邀请码失效自动离职。次数占用/释放按申请和审核原键记录，重复/并发不能突破限额。
- 代码具足够随机性、服务端散列保存、限速防猜测；链接仅指向已登记本端路径，日志/通知不泄露原码或私有资料，不能执行外部任意URL。链接泄漏仍不能绕过个人认证和管理审核。
- 企业加入邀请与原营销邀请奖励无关，不触发注册奖励、不改原推荐关系；不让企业管理员搜索/枚举该商户全部个人会员。

### ECP-R05：员工管理、停用、移除与退出

列表/详情包含必要身份展示、脱敏联系方式、部门/工号、关系角色/状态、生效/失效时间、已授权范围和待处理事项。可修改企业内资料、设置关系有效期、停用/恢复、移除，均需当前权限、目标关系修订、原因和审计；不能改个人证件、账号密码、个人会员状态或另一企业关系。

移除采用关系终止，不删除个人会员或历史。员工主动退出须明确确认；有在途业务时显示交接待办，但不能靠拒绝退出无限延续其新企业消费权。停用/离职立即取消新企业权益、付费准入和未消费批准，在所有空间生效；其他企业和个人身份不受该关系操作影响。

已成立订单的签约/付款主体、债权及快照不因离职转个人或取消。个人仍按原本人权限处理允许的归还/争议，企业仍按原责任处理对账；未确认订单、未执行续租等须复查原状态/授权，不能一律自动取消、退款或重做。已确认待取订单的履约及安全准入由Core和商户按原合同处理，企业端只发起交接请求/联系商户，不直接改使用人或实物状态。

## 4. 可租范围、企业付费与审批

### ECP-R06：商户上限与企业收窄

商户以当前租户内企业为对象明确配置可用的品类及经营空间、企业身份功能是否开放、企业付费资格与结算方式；企业管理员不能增加商户未许可的品类/空间。仅用企业优惠但个人付款也须在该企业身份范围内。没有明确配置时，新企业身份业务不可用，不默认全部品类。

在商户上限内，企业可设置企业允许范围和员工范围，并为员工单独开启企业付费权；允许只给企业优惠自费资格。员工默认不因入企自动获得企业付费权，审核页可明确同时授予并留痕。企业进一步设置的单笔申请金额上限为可选、按币种显式配置；未配置不等于0元，也不等于可越过授信。首期不做月预算/费用报销系统。

**实际可用范围为交集**：商户当前企业授权、企业/员工授权、空间发布与营业条件、企业和个人会员状态、关系有效期、适用品类能力/资格、订单业务条件；账期另查有效授信及逾期。品类授权不是优惠权益范围，两者分别判断；有折扣但不在可租范围仍拒绝。新增空间/新品类不从旧白名单自动获权，明确全品类模式也须有可审计配置和动态品类兼容。

改范围、改额度或停用须有修订冲突检查及审计；报价/申请/批准/正式提交之间范围收窄须在最终提交点重新校验，失效批准不执行。停止新业务范围与历史读取范围分开：不能因后来停止租车而藏掉既有账单，也不能以历史读取权限重启新租赁。

### ECP-R07：企业付费审批可配置

企业付费有两种模式，由有权管理员明确配置并保留版本；未配置不放行企业付费，但符合授权的个人付款可独立使用。

| 模式 | 行为 |
| --- | --- |
| 免逐单审批 | 有明确企业付费权的员工在全部范围/限额/授信内自行提交；记录该次命中的授权和政策版本，不伪造人类审批记录 |
| 逐单审批 | 员工提交真实报价基础上的申请，指定企业的有权管理员在有效上下文批准/拒绝；批准只是企业承担本次费用的授权，不等于订单已成立、已付或商户审核通过 |

审批页面包含申请人/实际使用人、企业、空间/品类、商品/数量、租期、履约方式、用途/备注、报价明细、已知租金/服务/税费、保证金安排、付款/签约主体和结算方式。未来损坏/超期等按原合同待裁定的费用须说明，不伪造固定最终总价。

1. 首期为单级审批；有权且非申请人/实际使用人的管理员任一批准即可，其他并发动作必须读同一结果。不得自审；只有一名管理员且其为使用人时，逐单模式阻断直至有另一合格审批人，或由有权人员另行明确调整适用政策，不能后台自动代批。
2. 状态至少区分草稿、待审批、已拒绝、已撤回、已批准未消费、已失效、执行中、已执行/结果待核对。审批记录绑定申请修订、报价引用及指纹、企业/员工关系、政策、金额/币种、范围和原操作，不以“approved=true”长期通行。
3. 申请/审批不预占库存、额度或优惠预算；正式Core阶段仍按原机制原子占用。页面说明“审批不保证库存或价格仍有效”。原报价到期、关键输入改变、关系/权限撤销、范围或政策不再满足时不可使用旧批准；重新报价并重新审批，不暗中提价或延长原报价。
4. 批准后由申请员工回到原请求，核对仍有效的报价/主体并明确提交；审批动作本身不自动替员工下单。首次提交结果未知时先查原收据，不用再次确认按钮生成新单。批准消费与正式提交须有可恢复的原子关联，避免批准已消耗但无订单、或同一批准产生多单。重复/并发、首响应丢失、进程重启均按原申请/订单键核对，不换键/换企业重试。审批不能替代商户自身订单审核、资格审核或资金门禁。
5. 逐单模式下主动新增企业支出的续租/换货/新增服务必须申请对应变更批准；不得借旧订单批准无限增加费用。实际已发生的合法债权及商户裁定不因企业未批新预算而丢失，申诉和核对依原规则；原退款/归还善后不被新的消费审批阻断。
6. 免逐单改逐单、降额、员工撤权等影响未消费授权，提交时校验当前政策。已执行交易不因事后改政策回滚；已批准申请不得自动转为个人付费。

### ECP-R08：员工租赁与原Core接通

客户小程序/租户网站提供三种清晰选择：个人、企业优惠个人付款、企业签约付款；默认保持个人，用户明确选企业及费用归属。每次切换身份/企业/付款选择重新取得Core报价，不叠加个人和企业方案。使用人一直是有交易资格的个人会员，不由管理员代填另一个未核验身份。

企业使用范围/付费授权/审批在原正式服务端应用与Core提交边界生效，覆盖客户端、商户后台代客及其他已获准业务入口；不能仅在新Web按钮检查而允许绕道提交。后台代客也须取得可核对的企业常设授权或本次批准，不把商户营运权限等同企业委托。存量企业按R14分阶段显式迁入该政策，未迁入的历史行为不因本端发布被静默改写或批量补授权。

企业付费不等于无款放行：可采用商户已批准的预付或账期方式。账期须满足企业同时签约付款、有效授信/可用额度/核定到期和逾期规则；押金和外部预授权仍按原订单独立，企业身份不自动免押。企业预付的实际收付款渠道沿原配置；未实现的保证金或代付能力明确不可用，不返回模拟成功。

**保证金承担（2026-11-01负责人确认）：** 按商户与企业的有效合同配置，默认企业承担；只有明确约定且原业务/支付合同真实支持时，才允许员工承担押金或提供个人预授权。该选择仅改变保证金的实际出资/授权来源，不把企业签约付款的租赁债务转给员工，也不把员工保证金计为企业租金回款。

- 报价、企业审批和员工最终确认分别展示保证金方式、金额/币种、承担主体、实际付款/预授权人及适用合同依据；原快照同时保留这些事实。不能只保存订单企业付款主体就推断保证金也由企业实际提供。
- 员工承担模式须本人明确确认，不允许企业管理员代员工授权扣款/冻结私人账户。未配置已批准的保证金减免规则时，默认企业承担不等于默认免押，也不等于虚构企业冻结成功。
- 释放/退款返回该笔保证金的原付款/授权来源，不因员工离职、企业管理员更换或当前合同变化而转给企业或另一个人。抵扣需原合同和正式裁定依据，企业租赁债权、员工保证金及退款分别记账，不重复清偿或随意挪用。
- 保证金承担、方式或必要金额变化属于关键输入变化：原报价和未消费批准失效，重新报价及审批；历史保证金依据不随当前合同改写。原资金端口尚不能表达或执行混合承担时，该模式保持不可用，不以新增UI字段放行。

报价、订单和变更保存个人、企业、关系、签约/付款/使用主体、命中方案/权益、企业政策/审批依据、数据告知依据以及原价格/规则快照。个人优惠券等是否适用继续由Core决定，不因为企业付费把个人资产转给企业。

仅本次企业身份/审批/告知所需的客户小程序和租户网站消费者纳入本专项增量；不启动完整MP-F04/P23～P25移动企业管理工作台、APP或员工履约端。通用订单、资金、账期修复仍归原任务，不重复开发或重复计进度。

## 5. 订单、隐私与财务

### ECP-R09：企业订单可见范围

企业管理员有明确企业订单查看权限后，可按企业订单快照读取以下两组；普通员工继续只看本人，不可因同企业读取同事订单。

| 分组 | 可见依据及最小内容 | 财务归属 |
| --- | --- | --- |
| 企业承担订单 | 当前企业是原签约/付款主体；订单号、员工必要身份、服务/品类、商品、租期、履约摘要、费用/应收/回款和异常状态 | 计入该企业原币种/原空间账务 |
| 企业优惠自费订单 | 原报价/订单明确选择本企业预约身份/权益来源，并具合规告知依据；展示订单号、员工姓名/部门、品类/商品摘要、租期、订单状态、公开租赁费用及企业优惠 | 独立标记“个人付款，不计企业应收”；不得显示私人付款工具/凭证，不计企业用信或账单 |
| 纯个人或其他企业订单 | 不属于本企业授权，无论员工现在是否在职 | 不可见，包括搜索命中数量、导出和通知摘要 |

- 员工在选择企业身份、提交入企申请及相关协议中明确获知：企业管理员可见企业身份订单，含个人付款订单；普通个人模式不共享。订单保存适用条款/告知版本和时间。拒绝企业模式时仍可在个人资格允许范围内个人租赁；不能默认勾选或用含糊“同步资料”代替告知。
- 新能力不自动追溯开放全部历史企业优惠自费单。旧单缺可核实的告知/授权依据时保持不可见，另行合规确认；不得补写用户曾同意。企业承担订单按原合同/当前授权提供必要履约对账信息，不借此公开个人证件。
- 不开放员工证件影像、证件全号、住址/精确私人取送地址、紧急联系人、私人支付账户/凭证、商户内部备注、其他客户信息；必要交接证据须有独立最少字段/附件权限，不继承运营DTO全部字段。
- 员工离职后，企业对其原企业责任及具合法依据的企业身份订单仍可在当前授权下查证；不把离职者新个人单/新企业单混入。管理员本人离职/降级则立刻失去非本人企业视图。
- 可在同租户内提供本企业已授权空间的统一索引；每个子查询都落实企业、空间、字段和当前权限，任一汇总/分页计数/导出不包含无权空间。金额按币种与责任主体分组，不自动汇率换算；数据不全时明确覆盖范围，不用0补缺。
- 当前可租范围不是历史读取授权。历史授权由服务器依据企业合同、对象归属和当前管理资格单独判断，保留停止新业务后的必要对账；不得以URL传space越权。企业整体被安全冻结时，历史/善后入口也须符合原冻结规则，不自动例外放行。

### ECP-R10：授信、债权、账单与对账

1. 只读展示该商户对本企业实际批准的授信状态、币种、额度上限、未释放占用、未清债权、可用额度、已核定到期日、逾期/未核定阻断及更新时点，数值全部来自原服务端资金/企业账务。未获授信显示“未开通”，无法计算显示“待核对/不可用”，不是0元或无限授信。
2. 额度账户、空间使用范围和金额聚合按现有正式合同映射，不能只把各订单可用额度相加。企业不跨租户、跨企业、跨币种混用；原账务无完整范围或计量证据时对应动作关闭。
3. 正式账单展示账单编号、企业、币种、涵盖空间/周期、版本、订单分摊、期初/新增应收/核减/回款核销/未清、核定到期日、争议和付款核对状态。不得用前端按月汇总冒充正式账单；未建立账单时可明确展示原应收明细，但不能据此完成本项账单验收。
4. 回款读取原payment及payment_allocation，前者总回款、后者分摊，不相加重复记收入；企业优惠个人付款订单不计企业债权/用信。现金、企业回款核销、保证金、退款各自展示原来源及状态，退款批准不等于已退钱。
5. 首期到期日仍采用原已批准的“财务核定到期日”；企业管理员可查看/提出异议或延期申请，不自行设置、延后或按当前账期天数补造历史到期日。自动账单周期生成/回款核销等底层能力未收口时不以本端可见表格宣称完成。
6. 企业可发起授信/范围调整、资料更正、账单异议、回款凭证核对申请，给出原对象/版本、金额币种（适用时）、原因、证据和原操作键。商户按原授权处理；提交凭证不能入账、批准申请不能假定供应商到账，重复凭证/申请不得重复核销。
7. 账单争议不自动免债、释放占用或解除逾期；租户真正裁定后追加调整和原收据。负差额、退款、原回款冲销仍由原业务域执行，企业端不能写账本或替商户确认收款。
8. 已有线上支付通道只有在对应主体/用途真实支持并获准时才可引用；首期不承诺新增企业自动扣款、共用钱包或任意支付链接。未核实的支付/保证金入口保持关闭。

### ECP-R11：企业资料、通知、审计与导出

- 企业资料显示已核验主档、企业会员状态、管理员、合同/开票资料和商户联系入口。管理员可提出修改申请，主体标识/代表资格/敏感合同更改由商户复核并保留版本；不能改企业授信状态、商户审查结论或员工个人档案。开票资料不等于已开发真实发票开具。
- 消息中心至少覆盖企业申请结果、加入审核、关系/管理员变更、待审批及结果、订单异常、账单/核定到期/逾期、对账反馈。站内待办与操作状态由原持久事实派生；外部短信/微信等沿获准渠道，通知受理≠送达，发送unknown不自动重发。
- 操作记录包含操作者、租户/企业、对象/修订、动作、原因、结果/原收据和时间，审计不含原邀请密钥、证件全文或支付敏感资料。企业只读本企业允许的管理审计，不读商户内部安全日志。
- 提供按当前权限导出企业承担订单、优惠自费订单和财务明细，三者明确分组；服务端复验导出创建和下载时的当前权限，缓存/异步文件不让已撤权管理员继续下载。文件短时、可追溯，数据规模有界，文本导出防表格公式执行；不得导出比页面更宽的字段。

## 6. 安全、界面与兼容交付

### ECP-R12：授权、并发与恢复

复用原Auth/Guard/ALS及真实客户会话；服务端解析企业上下文和权限。企业客户查询是独立受控能力，不放宽原/my/orders本人索引、staff门面或operator路由；未知权限、关系/政策/配置缺失时拒绝相关能力。不能因为无企业工作空间就授予租户全空间。

邀请、申请、审核、关系/管理员交接、政策、批准消费、对账申请均有原键、输入指纹、期望修订和持久结果；同键同输入读原结果、同键不同输入拒绝。跨实例同时审批/移除/降额/下单须在明确原子边界复验当前事实。事务提交后才发通知/刷新缓存，外部调用不占业务长事务。

超时、取消、TTL、浏览器关闭不证明未提交或可重做；结果未知保留原引用查询，不生成第二次企业付款/订单。身份、租户、企业切换取消旧请求并隔离草稿/缓存；过期/撤权清理可见材料，不靠隐藏按钮授权。当前服务端撤权适用于API、深链接、导出、附件和异步回读。

### ECP-R13：页面与操作体验

### ECP-R14：存量、启停和专项边界

- 新能力按商户/企业显式启用，存量企业不自动领管理员、全品类、企业付费或历史自费单查看权。先盘点可信关系/授权/材料来源，再经受权配置；不批量把联系人变管理员，不自动补历史同意记录。
- 独立接点复用现有Core、会员/信用与文件服务；底层缺陷/完整账单/真实资金能力由原CLOSE、CORP-SETTLE等任务推进，本专项交付客户侧生产者/消费者增量及组合证据，不重新算原任务完成度。
- 受控停止本端新准入与历史/未决操作核对分别设计；回退不得把企业客户路由改为宽松operator权限，也不能丢申请/批准/原收据/企业债权。存在unknown/在途时保留原所有者与核对通道，不因前端下线删除事实。
- 本专项的员工租赁接线不自动交付小程序完整F04、APP、商户员工端；它们原储备范围仍保留。管理后台需求原不开放企业他人订单的默认，只有本专项正式授权、字段投影和启用门槛满足后，在专用企业视图内扩展；原普通客户接口不变。

## 8. 实施前必须固定、不得猜测的参数

各商户独立、审批模式可配置、企业优惠自费单可见、保证金按合同配置且默认企业承担、批准后由员工再次提交，以及§1.1独立企业界面/共用客户登录/同域`/enterprise`入口六项产品选择已确认，不再列为待决。入口尚待工程实现，不把已批准方案写成现行可用服务。下列实施/环境项随任务ECP-01/02固定，不能默认填生产值：企业客户站点/域名与渠道、会话/audience及路由正式合同；商户审核材料/地区与隐私保留依据；邀请期限/限额/速率与申请数据保留；审批有效窗口、金额上限基数（租金/服务/税费与保证金分列）及币种精度；受控试点企业/商户、真实账单/资金/通知环境与启用责任人。无法落实时保持相应能力不可用；改变已确认产品范围须再经负责人批准。
