# 门市租赁 MVP 开发任务台账

更新时间：2026-06-09

## 使用规则

- 本文作为后续持续开发的任务台账，每轮开发前先读取本文，开发后更新状态。
- 页面实现必须参考 `营运端/` 原型；顶栏按当前系统统一顶栏处理。
- 业务逻辑、状态流、资金流、车辆与据点规则必须参考 `PRD/门市租赁/` 和 `业务知识库/`。
- 不修改根目录 PRD、原型和业务知识库文件；只在本项目目录内写代码和开发文档。
- 企业端、用户 H5 本期只预留接口和边界，先完成营运端核心闭环。
- 会员管理、企业客户管理当前没有独立 PRD，先严格按原型开发页面、字段和交互，再补后端真实数据模型和权限。
- 工作台、排班优化、战情室、分时租赁、渠道团票不是当前门市租赁开发范围；原型中若有入口，仅保留视觉占位，不开发业务逻辑。
- 车务运营、合同单据、TBox 设备管理当前没有独立 PRD，先按原型与现有门市租赁流程补齐页面、数据模型、权限和 mock 集成边界。
- 新增页面、菜单、路由、独立功能模块必须能在“资料依据”表中找到 PRD 或原型依据；只有底层接口但没有原型的能力，状态只能是 `Reserved`，不得出现在营运端菜单和路由。
- `Reserved` 只允许保留后端接口、DTO、表结构或业务页面内的预留字段；禁止开发独立可见页面、独立导航入口和脱离业务流程的运维中心页。
- 每次合并分支前后必须做 PRD/原型偏离审计：列出新增/修改的菜单、路由、页面、接口和任务项，逐项标注依据；缺少依据的内容必须记录风险、标注用户确认情况，再决定保留、下线或拒绝合并。

## 继续开发时的默认起手顺序

1. 先读本文件的“开发任务”“下一阶段执行队列”“推荐冲刺清单”“Sprint 实施清单”。
2. 然后确认当前实际正在执行的是哪个 Sprint。
3. 只做当前 Sprint 的任务，不跨 Sprint 乱跳。
4. 开发前先确认任务有 PRD/原型依据；没有依据的只允许标 `Reserved`，不得新增菜单、路由和页面。
5. 合并分支前后必须执行偏离审计，检查新增/修改页面、菜单、路由、接口和任务项是否有依据。
6. 当前 Sprint 完成后，再更新状态、文档、交接说明，进入下一 Sprint。
