### Agent 底座的后续 Runtime 可替换性（重点开发约束）

**本专项服务端当前继续自研，但必须从现在的开发方式上为以后替换 Agent Runtime 做准备。暂缓服务端框架替换不等于暂缓可替换性设计；目标是以后主要替换编排运行层及其适配器，而不是重写业务工具、授权、审批、预算、知识服务和客户端。** 具体候选与迁移约束见[未来 Runtime 方案](<未来规划/AI Native-Runtime替换方案.md>)，不承诺尚未经验证的无缝切换；另行批准的本地 Harness 路线不是替换在途服务端任务的许可。

1. **隔离可替换部分。** 计划推进、步骤调度、等待/恢复、取消及运行事件通过清晰的内部契约与宿主服务连接；自研 Runtime 的内部对象、控制流程和异常不得扩散到业务工具及对外协议。未来框架专用类型、节点、消息、checkpoint 和配置应限制在适配层，由显式组合入口装配。
2. **保留系统自己的业务边界。** Runtime 只编排受控能力，不取得业务授权裁决权。原 Auth/Guard/执行上下文、唯一 Gateway 与预算单账、人工审批、Core 事务/幂等、知识与文件访问控制继续作为独立服务复用；换 Runtime 不能绕过、复制或降低这些约束。模型供应商适配与 Runtime 适配是两种独立边界。
3. **状态与恢复可解释、可映射。** 任务、run、step、actionId、输入指纹、方案/政策版本、结果引用和事件采用本系统的版本化契约；框架 checkpoint 不能成为订单、审批消费或预算结算的唯一事实来源。文档必须说明持久化事实与运行时状态的对应关系，以及等待输入、等待确认、取消、unknown/reconcile、部分完成、lease/fencing/CAS 的含义。恢复不得因换引擎而生成新业务动作或重发未知副作用。
4. **迁移与回退有依据。** 后续切换前必须明确在途任务是由旧 Runtime 排空、固定在原版本执行，还是经验证迁移；未经证明不能直接把旧状态交给新引擎继续执行。状态转换、兼容版本和回退路径需保留说明；回退不得撤销已提交业务事实、重复消费审批或重复扣费。
5. **开发同步留下接手资料。** 底座相关切片在既有实现/协作记录中维护实际入口、接口输入输出、依赖方向、状态与错误映射、持久化归属、副作用/重试边界、现有耦合点和未来替换步骤。给出相关源码与验证入口，明确哪些已实现、哪些只是预留、哪些需要迁移；不能只留一句“以后可接 LangGraph”。契约变化时同步更新，不依赖原作者记忆。
6. **轻量准备，不过度设计。** 优先复用已有 ports、服务和组合入口，在当前功能开发中增量消除硬耦合；不为未知框架建立空适配层、第二套状态机/存储或通用编排平台，不提前复制 LangGraph API。既有源码和测试实际保留，不为迁移准备大规模重写。功能优先，每片按受影响边界做一次定向冒烟/必要类型检查，完整跨 Runtime 兼容验证留到实际切换时执行。

可参考、复用 LangGraph 等成熟项目的设计及许可证允许的适用局部实现，复用时记录来源与必要声明。上述要求落实到原 AIN-R16 架构与原任务交付中，不新增框架接入任务，不改变原28项分母、任务状态、业务验收口径或生产启用边界。

## 1. 产品目标与边界（AIN-R01）

系统应支持用户通过自然语言、表单、图片或语音提出经营目标，生成可检查的方案，经适当授权后调用真实业务能力完成任务，并展示实际结果。任务可持续、可接管、可追溯；传统页面和人工业务入口继续可用。

职责划分：

| 主体                 | 负责                               | 不承担                              |
| ------------------ | -------------------------------- | -------------------------------- |
| 模型                 | 识别意图、澄清歧义、选择允许的工具、总结证据、生成草稿与操作计划 | 自行计算最终租金、决定库存是否足够、宣称到账、修改权限或历史依据 |
| 任务执行层              | 身份与上下文、计划版本、授权、持久化步骤、预算、恢复、结果验证  | 绕过 Core 的捷径写库或以提示词替代授权           |
| Rental Core 及既有业务域 | 定价、资格、库存、状态、资金、责任流程和事实持久化        | 将自然语言直接当作可执行业务命令                 |
| 人员                 | 确认有业务影响的方案、现场事实、责任裁定、授权与例外处理     | 必须阅读模型长篇推理才能知道将执行什么              |

目标覆盖 SaaS 管理员、租户管理员、运营人员、员工履约端、客户小程序和租户预约网站，包括可独立访问的管理后台 Web。原独立移动 APP 本期只预留同一客户端契约，不启动移动 APP 工程；运营桌面 Harness 另按 §1.3 独立专项接入，不能以本条否定已批准桌面范围。摄影、露营、车辆、工程共用工具和流程，差异来自服务器解析出的品类版本、能力及模板。

不纳入本专项：任意代码生成并运行（§10明确允许的隔离展示代码除外，仍不得取得业务执行权）、通用数据库写入、任意 HTTP/SQL/终端工具、独立四品类 Agent 内核、自动修改业务规则、模型自主裁定赔偿或退款、重建订阅或支付体系、自建基础模型训练平台。外部 MCP 服务市场、独立 APP、跨空间合并经营分析为 Reserved，详见任务文档。现有租户自带 AI（BYOK）保留并纳入首期双轨接入，不再作为后置储备。

### 1.1 AI Native 产品定位与分阶段闭环

本节明确 AIN-R01、R06、R09、R10、R12 已有目标的产品含义，对应[开发任务的目标与完成口径](<AI Native-开发任务.md#ai-native-目标与场景完成口径>)。不新增业务工具、异常类型或自动执行权限，不替换原需求，不改变原28项任务、依赖、分期和风险等级；客户首期预约页面确认、敏感验证及原人工审核要求继续有效。

1. **以目标组织业务，而不只是提供聊天建议。** 在已开放的场景内，用户表达目标、补充必要条件并确认关键决策；AI 负责组织受权事实查询、方案准备、受控执行及结果跟踪。全局入口、业务页面入口和主动待办共用同一任务体系。传统页面继续承担事实查看、精细调整和人工接管；除原需求规定的人工办理或确认环节外，不应把所有任务步骤默认转交用户自行跨页面组织。
2. **根据真实反馈有界推进。** 在当前工具白名单、权限、批准及累计资源上限内，根据工具结果决定继续查询、请求澄清、调整尚未批准的方案、请求重新确认或停止。把一句话匹配到一个接口，不等于完成复杂目标；也不要求把适合固定流程的业务改成模型自主规划。输入、方案或执行效果变化不得覆盖旧冻结依据或沿用旧批准；unknown 仍只核对原操作。计价、资格、库存、资金和状态转换由 Core 或原业务域决定，模型不取得业务裁决权。
3. **主动经营按限定场景形成闭环。** AIN-R12 已限定的正式事件或确定性检查发现异常后，依次核实当前事实、形成有证据的方案/待办、取得所需授权、推进获准操作并核对结果；受阻时说明原因和人工接管位置。每个场景明确仅提醒、可准备方案、可经人确认执行或可按政策有限自动执行的边界。影子模式仅观察与建议，不代表执行闭环已开放；不扩展异常种类，不允许模型轮询猜测事实，不开放 R3 无人执行。
4. **按用户目标而非模块数量判断场景完成。** 场景应有实际调用入口和消费者，明确该阶段承诺的结果、人工节点、失败/部分完成/待核对及接管出口，并以持久业务事实验证。原阶段只承诺解释或草稿时，以其真实交付结果为准，不强加业务写入；承诺确认执行时，不能以方案、导航或接口存在代替执行结果。正确拒绝是必要能力，但依赖缺失的 unavailable 不算正向场景交付，局部模块或离线冒烟通过也不代表整项验收。

允许按原开发任务 M1～M4 分阶段达成上述目标：先完成用户发起的可用解释/草稿任务，再接通经确认的业务执行，随后推进限定异常的主动经营及获准的有限自动化；不要求首个可用版本同时具备全部主动能力。各阶段按原适用范围和放行条件验收，仍保留传统人工路径，不因 AI Native 定位扩大原业务或生产启用授权。

依赖缺失的拒绝路径不能代替正向交付；不同端、不同身份、普通业务与异常收尾分别记证据。后端准备成功不证明浏览器/微信已接通，客户草稿成功不证明企业付款或资金处置可用。详细字段和引用复用既有契约，不新增平行场景状态机。

### 1.3 与本地运营客户端的并行关系及冲突处理

**管理后台 Web 明确提供自己的 AI 聊天页面**，用户无需 Harness 即可提出目标、连续澄清、查看真实业务材料 / 报价、完成所需人类确认 / 审批并追踪原任务结果。其模型和编排由服务端承担，不是只交付 API、传统页面或只读任务中心。本地 Harness 聊天同时保留；桌面嵌入 Web AI 页面时，该页面仍调用服务端 Agent、使用服务端配置与预算，必须显示通路和费用归属，不自动改成个人模型或复制整份对话。

**后续允许本地 Agent 受控调用服务端 Agent 的能力**：以注册场景工具委托原任务、读取获准知识 / 事实、获取持久结果，不能仅限于打开网页。首次采用原订单解释场景，后续能力按原任务实际成熟度开放；这不是新增通用远程 Agent 平台。服务端按当前发起人的权限与场景政策运行，不能把机器、管理员或自动主体权限借给客户端。场景输入有界、原键可恢复、云模型调用显式计费、人类等待不可由模型自答批准；结果送回本地模型前再次按最少字段与外发政策投影。首批禁止自动递归跨端委托，避免本地与服务端来回派发形成循环；已有 Task / Run / Step 与原收据为唯一持久关联，不另建账本或任务状态机。详细消费者边界见 Agent 接入改造的 R13.2。

**冲突处理以调用和业务动作的实际归属为准：**

**两端业务范围对齐：** 本地 Harness 的 Rental OS 业务能力最多为服务端统一定义并允许开放能力的子集，按同一主体、audience、scope、地点和数据范围核验；不要求两端 UI 或工具接线同时完成。早期服务端 Agent 尚未接齐时，本地可经已登记受限入口复用当前获准的 Web 正式业务 API，不能把接口存在当作授权，也不能绕过安全停用、审批或未实现的 Core 能力。用户页面可见数据仍不等于可发给模型。原能力登记区分业务 API、本地适配和服务端 Agent 的就绪状态，接齐后复用同一业务合同；一次动作不双跑，unknown 不换通路重做。此上限不要求服务端复制 Harness 的个人聊天、文件或终端能力，但个人工具不得获取业务凭据、外发敏感数据或绕过业务边界。具体接入及验收沿 Agent 接入改造 R09.2 / A11，不新增原 28 项或改变完成百分比。

1. 本文“统一 Gateway / 平台预算 / 服务端模型配置”的要求适用于服务端发起的模型调用，不强套到已批准的本地自付模型。实际把任务交给服务端并调用模型时，必须重新满足原配置、能力、价格、输入上界和预算；不得冒充本地调用逃账，也不得为同一本地调用补记平台模型费用。
2. 本地自付不免业务权限、SaaS / 业务权益、业务额度、库存、原审批、幂等和适用任务累计资源。平台模型余额不足与租户禁止本地业务工具是不同拒绝原因；前者不单独封锁纯本地自付的获准业务查询，后者必须阻止新工具执行。历史原收据仍按当前独立读取 / 善后权限处理。
3. 协同只交换必要原任务 / 业务引用、输入 / 批准版本、当前执行归属与结果，不默认同步全部个人聊天、附件、推理或凭据。先接同主体订单解释的原任务发起 / 受权回读，后接原报价 / 提案的跨端人类确认与原订单收据；更广跨用户委派仍沿原独立权限和阶段门，不因“桌面协同”自动开放。
4. 受理不等于执行，通知不等于结果；客户端退出 / 断线不证明任务取消，重连只能先读原任务 / 收据。模型换端、引擎替换、重复通知或两端同时点击均不能换键重做 unknown。正式取消 / 人工接管沿原修订、代次与证据，已经提交的业务事实不回滚为未执行。
5. 共用接口、Action、错误、原请求 / 批准 / 收据字段及版本只维护一份正式合同，并指定唯一作者；先提供真实生产者再接两端消费者。桌面专用传输与 UI 类型留客户端适配层，不能扩散到 Core 或迫使官网 / 小程序引入 Electron。当前合同有缺项，受影响动作 unavailable，其他合法场景继续，不私造同名 DTO。
6. 本文服务端运行上限、留存及验收与桌面自身限制分别适用；同一调用同时受约束时取更严格者。例如本地前台活跃时间允许更长，不得延长已受理服务端任务的原期限或重置其累计额度。本地缓存清理不能删服务端 unknown 所需最少证据，服务端保留核对证据也不授权永久保存整个私人会话。
7. 本地首批不开放自动退款 / 扣款等资金及高风险例外，不取消原服务端已规划的受控能力；服务端能力可用也不自动进入本地工具白名单。未交付接口、真实模型 / 桌面 / 微信验收分别记录，不以另一端通过替代。

本节只明确两条路线的相容约束；不授权安装 / 迁移、开启自动化或生产发布，不重写既有业务需求。不因桌面接入删除或空壳化服务端、Web、测试和 WIP。遇两份需求对同一共享业务语义冲突，先按现有更严格权限与原证据保全，登记待负责人裁定，不用任一端文档放宽另一端安全边界。

## 2. 当前事实与依赖（AIN-R02）

实现依赖必须以所用分支、目标部署和实际服务为准：复用 Rental Core 的计价、库存、订单、检查与资金入口，现有身份与范围约束、业务幂等、历史版本/快照、可靠事件及正式报表口径。不能把模拟连接、接口名称或另一工作树的代码当成已交付或已部署证据。

AI 工具登记 `unavailable / preview_only / executable`，由服务端根据实现和验收清单控制，不允许租户或模型把未交付工具标成可执行。只读和草稿工作可先行，写入依赖逐项验收，不等待无关专项全部结束，也不借 AI 补造未实现的业务。缺状态历史时不提供历史利用率，缺成本时不宣称实际利润分析；当前配置不得替代旧订单依据。

## 3. 角色与授权上下文（AIN-R03）

| 身份       | 可用数据与动作                        | 关键限制                            |
| -------- | ------------------------------ | ------------------------------- |
| SaaS 管理员 | 平台 AI 配置、发布目录、脱敏运行指标、品类草稿及影响预览 | 平台身份不自动授予所有租户订单、客户、财务和提示词全文访问   |

| 运营人员     | 当前空间和数据/地点范围内的经营工具             | 继承原岗位权限，不能通过 AI 取得被菜单隐藏的动作      |
| 员工履约人员   | 授权空间、地点、订单和检查任务                | 复用员工接口白名单，不复用后台管理员令牌            |

每次读取、执行、下载、事件推送和任务历史访问，校验 audience、tenantId、workspaceId（适用时）、操作者、当前权限、成员状态、dataScope、locationScope、业务资源归属与订阅条件。共享会员、平台品类等非空间对象必须声明 `tenant` 或 `platform` 范围，不创建虚假默认空间。

服务器从认证上下文解析范围；模型可建议切换，但不能提交任意 tenantId/workspaceId 来取得权限。切换空间必须走既有授权流程，创建新任务上下文或显式派生任务。旧任务保留原范围，禁止把原对话、结果缓存或授权转到新空间。

异步执行前重新解析最新授权。用户撤权、成员退出、地点范围缩小、租户/空间冻结或执行政策关闭后，阻止下一步并转待人工；不能把创建任务时的权限快照当永久授权。订阅到期的新业务/既有善后规则继续由原业务域决定，AI 额度不足不阻止人工处理既有订单。

## 5. 方案、确认与授权（AIN-R05）

| 等级  | 含义                                     | 默认政策                                       |
| --- | -------------------------------------- | ------------------------------------------ |
| R0  | 读取、解释                                  | 现有权限内执行；敏感读取照常审计与限量                        |
| R1  | 持久化 AI 草稿、正式报价等已声明副作用                  | 用户发起对应任务后可生成；草稿不自动发布、不锁库存、不发消息；正式报价副作用单独标示 |
| R2  | 建单、资料修改、提交检查、允许的配置写入或发送通知              | 展示具体方案并确认；阶段三仅对登记的低风险工作流允许有限自动执行           |
| R3  | 退款/免赔或责任裁定、资金处分、价格/规则/品类发布、权限修改、敏感批量导出 | 保留业务权限、明确人工确认及原审核链；本期不允许无人自动执行             |

操作方案必须包含：任务/方案 ID、revision、动作清单及顺序、目标对象、变更前后、金额与币种（如有）、数量、地点、规则/报价/对象版本、影响说明、外部副作用、失败处理、截止时间。金额由 Core 返回，不由模型生成后直接采用。

确认服务绑定 `proposalId + revision + canonicalPayloadHash + actor + scope + expiresAt`，输出不可由模型伪造的授权凭据。确认页允许修改或拒绝，任何影响操作的修改生成新 revision 并使旧授权失效。模型不能调用“替用户确认”的工具。

提交前重查权限、订单版本、报价有效期、库存、能力和业务前置；事务内或相应业务提交点完成最后校验。任一变化使已确认的对象、金额或效果改变时，返回新方案要求重确认，不能自动沿用旧确认。授权单次消费与动作幂等共同保障重复点击/重试不重复执行。同一actionId和相同请求指纹的重试可返回已有业务结果，不再消费或执行；不同动作不得复用已消费授权。幂等查询返回结果前也要重查当前访问权限。

批量方案逐对象列出动作与结果，禁止使用“处理所有问题”这种开放授权。没有现成全批事务的操作必须明确允许部分完成；外部短信、支付等不能承诺数据库回滚可撤销。取消后停止尚未发出的动作，已经提交的结果继续核对或走显式补偿。

## 6. 任务运行与恢复（AIN-R06）

任务流程：`queued → running → waiting_input / waiting_confirmation / waiting_external → running → succeeded / partially_succeeded / failed / cancelled`；`cancel_requested` 表示停止请求已接收但结果尚待确定。每次迁移有原因、时间和执行者。UI 不将 `waiting_external` 显示为成功。

- 澄清输入与确认分开：缺客户、日期、商品或地点时等待选择；不能把普通回答当作对新副作用的授权。
- 原任务恢复与重新发起是不同操作。恢复使用同一业务 actionId/idempotencyKey；“再做一次”需生成新方案且走授权。
- Worker 使用持久化领取、租约及 fencing/version 校验，过期 Worker 不能继续提交新步骤；每步开始重验权限、预算和任务取消状态。
- 网络失败后先核对业务结果，再决定重试。支付、通知等未知结果进入对账；不能因换模型/重启而再发一次。
- 调用模型时不持有业务事务。计划可并行只读；同任务影响同一资源的写步骤有序执行，跨任务并发由 Core 的锁和版本校验兜底。
- 任务及步骤重启可恢复。历史幂等记录过期后，先查询关联业务事实；无法确定时转人工，禁止盲目重放。
- 步骤上限、运行时间、输出长度、模型超时、工具超时与总预算可配置。建议初值：单轮最多20步、主动运行180秒、只读并发3、写入串行、单次模型超时30秒、确认有效期5分钟。主动运行时间不包括等待用户输入/确认；等待外部结果按独立核对期限处理，不因180秒截止直接宣称取消成功。等待期间释放Worker执行槽，恢复仍遵守任务级累计步骤/成本上限，防止通过反复恢复绕开预算。上线前以评测结果登记实际值。
- 人工接管能看到已完成/未知/未执行动作；接管或取消不会删除已生效的业务事实。

### 6.1 外部副作用的观察与恢复

下表解释任务展示和恢复语义，不新增一套业务状态枚举。支付、退款、保证金和通知的正式状态仍由原业务域决定，资金依据遵守[平台需求 §4.7.12](../租赁平台/租赁平台-需求.md#4712-结算)。

| 已有证据 | 可以表达/办理 | 不得推断 |
| --- | --- | --- |
| 准备、草稿或批准完成 | 展示原材料/批准及尚未执行动作；执行前复核当前准入 | 已派发、已建单、已付款或永久执行授权 |
| 准入/预算已占用，但无可靠派发结论 | 核对原 invocation/dispatch/预留，不明确时保持待核对 | 占用等于调用成功；超时等于未发送 |
| 有可信证据证明未发送 | 经当前善后权限释放对应未发送预留；新执行仍走原准入 | 换键、换供应商或换Runtime自动再做一次 |
| 已发送或远端受理，终态未明 | 保留原操作标识和必要占用，按原收据查询或人工核对 | 已成功、已回滚、额度可因TTL释放 |
| 已取得可信用量/业务终态，内部入账或应答未完成 | 先保留最少原始事实和关联，以原键完成本地账务/收据恢复 | 因观察、日志或本地提交应答失败而否定远端成功或重发外部动作 |
| 原业务/账务已提交，当前交付被拒绝或中断 | 保留已提交事实；当前有独立读/善后权限者可核对 | 撤权后继续向原用户交付敏感文本；把取消请求当成撤销已执行事实 |

已收到并核验来源、原调用关联和单位的usage，应能独立于文本交付、配置轮换及观察记录失败保留到唯一财务证据链；只保存必要计量与关联，不借财务善后保留额外敏感正文。用量尚未取得或不可信时保持unknown，不能补造零用量；记录原事实不授予新调用或业务执行权。

## 7. 模型服务、预算与租户设置（AIN-R07）

本节约束**服务端模型调用**；包括平台托管及服务端 BYOK，不包括 §1.3 已批准的本地用户直连自付模型。本地委托云端任务产生的实际模型调用重新适用本节；业务 API 的授权 / 批准不因调用端不同而变化。

### 7.1 双轨模式与用户体验

AI 设置提供“Rental OS AI（推荐）”与“自定义 AI 服务 / BYOK”。新租户默认 `platform_managed`；普通租户无需填写 Base URL、API Key、协议或具体模型，也不展示底层供应商。平台准备好合法供应商配置及套餐权益后，租户可直接使用当前套餐允许且已验收的场景；平台配置缺失、停用或额度不足必须如实提示，不能以 mock 假装开箱可用。

`tenant_managed` 保留租户管理协议、Base URL、API Key 和模型的入口，适用于已有模型账号、国内供应商、企业 Gateway 和私有模型。只能选择已实现的受控协议适配器。未知协议拒绝；自定义 Endpoint 仍遵守出网策略，不代表可访问内网、任意 URL 或执行 HTTP 工具。密钥仅受权管理写入，加密保存，读视图只显示配置/轮换状态。

### 7.2 统一网关、路由与适配器

服务端模型调用链统一为：AI 功能 / Agent → AI Gateway → Provider Router → 平台或租户配置 → Provider Adapter。上层业务不得读取 Base URL、API Key、具体模型或供应商 SDK。Agent 提交场景和必需/可选能力；实际模型由服务端按当前模式、已验证能力、可用状态及既定限额选择。不得因换供应商改变 Agent、Prompt、Tools、Context、Permission、Workflow、Audit、Guardrails 或 Memory，也不得绕过 Rental Core 的确定性业务接口。

Provider 以中立接口预留 invoke、stream、structuredOutput、toolCall、healthCheck。首期优先兼容已有协议，不要求同时实现所有供应商和所有方法；未实现能力明确不可用。平台配置与租户配置的凭据所属范围严格分开，调用绑定租户、配置 ID/修订、实际协议/模型及凭据引用；配置轮换、模式切换或停用后旧任务必须重新校验，不隐式跨租户或跨供应商回退。

#### 7.2.1 为后续开源 Provider SDK 接入提前准备（重点开发约束）

**Provider SDK 与 Agent Runtime 同样属于现在就要考虑可替换性的底座边界。当前继续使用已有实现，但新增或修改模型协议代码时，应尽量让以后通过小范围适配接入成熟开源 SDK，而不是重写 Gateway、租户配置、场景和预算体系。** AI SDK Provider 是候选，不是当前已选定、已安装或已验证的依赖；SDK 接入与 LangGraph 切换可独立推进。

1. **隔离协议实现。** 请求编码、响应/流解析及供应商专有类型收敛在现有 ModelAdapter 或等价内部适配边界。场景、业务工具、Runtime 和客户端只依赖本系统稳定契约，不直接依赖 SDK 消息类、流事件、异常或供应商配置。优先复用已有端口，不新增同义 Gateway 或空壳抽象。
2. **控制权留在本系统。** 平台/BYOK 配置、凭据归属与修订、能力准入、唯一派发和预算单账继续由现有服务负责。SDK 只承担被批准的协议调用，不引入第二套 Agent 循环、自动工具执行、隐式模型回退或额外扣费。每次实际请求仍受原 invocation/dispatch/计量关联约束。
3. **传输可注入，安全边界不迁就 SDK。** 保持受控传输与取消信号的明确接点，记录 URL、method、header、认证、超时、背压、响应上限及取消清理语义。未来 SDK 必须接入现有出网控制；不能回落全局 fetch、环境密钥、默认云代理、任意媒体下载或未经批准的遥测。无法满足控制要求的候选保持不可用。
4. **结果与用量不得丢失语义。** 文本、工具调用、结构化结果、终止原因、流错误和 usage 映射回本系统契约。缺失用量与真实零用量区分，SDK 补值或生成的标识不能冒充供应商原始证据；部分流、超时、取消及 unknown/reconcile 不得被映射为成功。输入冻结、请求指纹与实际发送内容保持一致。
5. **重试和回退必须显式。** 记录当前请求次数、重试归属和原收据核对方式。实际接入时验证 SDK 是否存在隐藏重试并禁用未获准的额外请求；结果未知不能因换 SDK、换配置或回退适配器而重新派发。旧新路径只在明确离线夹具下比较，不双发真实请求做差分。
6. **同步留下适配资料。** 相关切片记录实际端口、请求/响应字段、流终态、错误与用量映射、传输依赖、默认行为、耦合点、兼容测试入口和未来替换/回退步骤。候选版本、Node/CJS/ESM/TS/Zod、许可与维护状态在实际采用时复核，不把历史研究当已完成兼容验证。

后续每批 Gateway、Provider、模型调用及相关底座任务，正文必须同时重申 Runtime 与 Provider SDK 的提前准备要求。保持功能优先，每片一次定向冒烟/必要类型检查，实际接入时再集中验证兼容与故障边界；不提前安装 SDK、不重写未触及模块、不建设全协议通用 SDK。全部既有协议实现和测试实际保留，后续停用路径与删除源码分别处理；本文不授权删除、上线，也不能覆盖负责人另行作出的暂停指令。

### 7.3 能力检测与场景准入

至少区分 Text、Streaming、Tool Calling、Structured Output、Vision、Embedding、Reasoning，并保留上下文/输出限额和用量可得性。连接成功不代表支持这些能力；每项能力标记已验证支持、已验证不支持或未验证，并附测试方式、mock/live、配置修订和时间。接口名称、供应商宣传或模型名称不能单独作为检测证据；无法客观探测的能力必须标未验证。

场景声明必需与可选能力，例如 经营方案生成（配置/品类草稿）场景必需 Tool Calling 与 Structured Output，可选 Vision。必需能力缺失或未验证时，在运行前给出明确原因，不让 Agent 进入执行后随机失败。可选能力缺失只影响相应辅助功能，不改变业务权限。按场景选择模型，底层预留 AI Profile，不将整个系统绑定单个 `tenant.modelId`；首期可以只有一个默认模型，不要求多模型高级 UI。

### 7.4 配置兼容与首期交付

保留已有配置字段、加密密钥和模型。旧记录无 mode 但已配置自定义 AI 时按 `tenant_managed` 兼容读取；无配置的新租户默认 `platform_managed`。不通过“补默认值”清空、覆盖旧凭据；从 BYOK 切平台模式保留旧自定义配置，只有明确删除凭据才清除。历史不完整配置不补造可用状态，需提示修复。升级/回退须记录兼容策略及空库、旧记录、模式切换、并发修订冲突的测试证据。

首期实际交付是默认 Rental OS AI、保留 BYOK、双模式设置、统一 Gateway/Router、可插拔 Adapter、真实连接测试、基础能力检测和兼容迁移。暂不实现智能成本路由、多模型负载均衡、自动故障转移、完整模型市场、企业 VPC、本地模型自动发现及多模型高级管理界面，只预留扩展。

场景定义包含稳定code、说明、适用身份、模型/提示词版本、可用工具集合、输出卡片、限额与发布状态。模型、提示词及场景政策调整须有草稿、差异、评测结果、发布/回退记录；运行时保存实际采用版本。首期可由版本化代码配置发布，不要求搭通用可视化Agent编排器。租户可配置平台明确开放的字段与业务知识，不能通过自定义提示词扩大工具/范围或覆盖系统授权。提示词改写不视为新业务能力交付，变更后须重跑受影响评测再放行。

凭据复用或扩展服务端加密托管，只展示是否配置、掩码和轮换状态；模型上下文、日志、前端响应不得包含密钥。真实测试分别返回配置无效、认证失败、超时、限流、能力不支持和成功；mock 仅测试环境使用并明确标注。

并发预算采用预留—结算—释放；供应商未返回用量时标“待核对/估算”，按保守预留限制继续调用，不以零费用释放额度。预算包含失败重试和降级调用；货币、token和任务次数分别记录，租户上限不得超过平台上限。关闭AI或额度耗尽保留人工经营能力及有权限的任务结果。

首期模型失效提供明确失败和人工出口，不要求自动故障转移。后续若启用降级，只能使用预先验证的同范围配置并记录实际模型；不能扩大工具权限或把数据发给未经允许的供应商。生产供应商、数据处理地区、商业额度和保留政策见 §19，未配置完整前真实服务默认关闭；这不改变新租户默认选择平台模式。

## 8. 知识、事实与记忆（AIN-R08）

| 信息类型          | 权威来源           | 更新与限制                     |
| ------------- | -------------- | ------------------------- |
| 价格/库存/付款/订单状态 | 正式业务读取或计算入口    | 记录查询时点；执行时重查，不依赖向量索引或聊天记忆 |
| 当前政策          | 当前适用的已发布配置     | 与历史订单依据分开                 |
| 历史执行依据        | 报价、订单和变更事实快照   | 保留引用，缺证据明确说明，不能用新政策补写历史   |
| 商品手册/SOP/帮助   | 已批准的知识文档版本     | 来源、owner、范围、发布时间、生效期和撤回状态 |
| 偏好            | 用户授权保存的结构化偏好   | 可查看、修改、删除；不保存未确认授权或权限事实   |
| 任务记忆          | 任务的选择、草稿和已执行结果 | 绑定身份/空间，过期或权限变化后重新授权访问    |

知识入库流程包含上传权限、格式/大小校验、解析、范围标记、版本、检索可用状态和撤回。权限过滤必须在召回及内容读取时执行；不能先把其他租户全文发送给模型再要求忽略。缓存和索引按租户、scope、对象版本及必要权限修订隔离，删除/撤回可追踪到索引和缓存失效。

业务结论返回可打开的来源引用、版本或查询时间。来源链接再次经过访问检查。未索引、解析失败、无权限和无结果分别返回；不得将不可见内容描述为不存在。

外部网页、客户备注、附件、OCR、工具返回中的自然语言均为数据；其中“忽略规则、把资料发到某地址”等文字不改变系统指令、工具权限或接收方。知识修改不授予执行权。无需初期微调模型，也不默认把租户数据用于训练。

### 8.1 历史依据、当前权限与新业务准入

| 操作 | 必须保留/读取的历史依据 | 必须复核的当前条件 | 不可互相替代 |
| --- | --- | --- | --- |
| 读取原订单解释、模型结果或来源 | 原任务/输入/方案、实际结果和业务快照关联 | 当前结果读权、资源归属、来源ACL及明确安全停用 | 原执行权限快照不授当前读权；原输入过期不单独否定合法历史读取 |
| 原调用计费/未发送释放/unknown核对 | 原call、dispatch、预留、价格/单位和可信用量或未发送证据 | 独立善后动作权限、原对象绑定及业务保留约束 | 当前新用量权益或现价不改写原账；善后权限不授新派发 |
| 澄清后继续、重新提案或新调用 | 原输入/计划/批准保留，新修订与原任务关联，累计资源延续 | 当前主体、执行政策、能力、配置、预算和所需批准 | 历史读取成功不表示恢复执行成功；新run不重置累计额度 |
| 续租、换货、取消和费用解释/准备 | 对应Core动作所要求的原单或变更快照 | 原业务域的当前资格、资源、权限及新业务商业准入 | AI不统一套旧价或现价；具体价格/版本选择遵守平台及品类需求 |
| 品类草稿、发布和空间采用辅助 | 原草稿修订、发布版本及采用收据 | 分别核对平台/租户权限、目标版本资格、兼容性及商业权益 | 发布不等于采用；推荐版本不等于唯一获准版本；AI不弥补未完成治理能力 |

同一操作可能同时需要历史事实和当前授权；缺哪类依据就报告对应缺项，不能用另一类补造。租赁动作的详细版本矩阵以[平台需求](../租赁平台/租赁平台-需求.md)及[品类需求 §6.3.1](../品类治理/品类治理-需求.md#631-后续业务动作的版本依据)为准。

## 9. 首批经营场景（AIN-R09）

### 9.1 订单解释与处理指引

输入当前订单或经过权限筛选的订单选择。读取订单状态、费用依据、资金真实状态、检查/争议及允许动作，输出“发生了什么、依据在哪里、下一步可做什么”。区分应收、实收、押金、预授权、退款申请/受理/成功；失败或待核对不能用自然语言润色为已完成。

对历史依据缺失、当前实现无法处理的动作，提供已有人工入口及缺项原因。只提出工具目录允许的下一步，不生成未经实现的按钮。模型回答与业务事实不一致时阻止写入，并保留可复查证据。

### 9.2 自然语言报价与开单

流程：识别需求→澄清客户/企业身份、商品、数量、日期时间、地点及履约方式→读取资格/营业条件/可用性→Core正式报价→展示结构化方案→确认→提交点重查→返回真实订单与后续步骤。

“周五晚上”“两套”“张先生”等歧义必须明确；按空间时区解析并展示绝对时间，采用Core现有计价进位规则。同名客户需最少脱敏候选，不能默认选择；商品替代需明示差别和价格。报价不能直接声称锁库存；建单、收款、确认及交付分别显示。缺货、报价过期、优惠失效等返回重做方案，不擅自改商品或金额。

首期支持已有正式下单模式，不由模型扩展企业授信、组合价格或品类能力。客户助手使用独立客户工具集合和本人身份；内部开单与客户预约不能互换令牌和权限。

### 9.3 开业诊断与配置草稿

读取现有开业检查、品类支持范围、当前规则版本和服务平台配置状态，给出缺项、影响、对应页面及可生成的草稿。区分必需、可选、尚未实现、等待真实外部凭据。模型不能编造营业地址、证件、收款账号、密钥或真实连接成功。

配置草稿逐分区保存与确认，标出原值、新值、影响和当前修订。发布规则、价格或品类仍走原版本机制及R3审核，不把多个独立配置伪装成全部原子成功。若没有现成草稿保存入口，先保存AI提案，不能为展示进度直接改活动配置。

## 10. 管理后台与任务交互（AIN-R10）

增加全局任务入口、订单/客户/资产等页面内入口和任务中心。页面上下文只是待核实的资源引用；不能信任浏览器发送的金额或权限。用户可从AI结果打开原页面，并使用普通表单完成相同动作。

任务中心按状态、场景、发起人和时间筛选，展示提问、澄清、来源、方案、授权、步骤结果、费用用量摘要及人工出口。组织内可见范围受原权限和显式任务共享策略约束，不能默认公开所有员工对话。

右侧 Agent 工作区允许模型按本次回复动态组织内容、布局和生成新的展示组件代码，不限定为选择预制卡片。生成物只在§10.5规定的隔离展示环境内运行；业务按钮、确认弹窗和执行入口由平台固定组件及可信宿主管理。宿主复用现有 UIArc 适配层（@/components/ui）、主题 token、中英翻译和响应式规范，不引入第二套后台框架。原“禁止动态代码”条款在此调整为“允许受限展示代码，禁止其获得宿主权限或直接执行业务”；§18A固定 Action 与导航边界不变。

流式文字不是完成依据；业务状态由持久化任务和正式结果决定。支持重新连接、事件游标去重、刷新、取消、重试和接管。通知与来源链接可键盘访问，状态不只依赖颜色，减少动态效果设置生效。模型不可用时明确失败并保留人工入口，不能无限加载或假成功。

### 10.1 能力、提示词与会话边界

每种经营能力分别配置版本化系统提示词、工具白名单、业务数据范围和输出要求；可以复用公共提示词和工具，不要求独立部署多个Agent。有效能力取当前用户权限、租户/经营空间政策与该能力允许范围的交集。提示词指导行为，不代替服务端授权；模型不能通过更换能力名扩大权限。

同一能力可有多个独立对话，会话及结果绑定当前主体、范围、能力及对应任务/输入版本，不把一个任务ID当成所有会话的共享授权。切换对话、能力、空间或身份时，迟到文字、代码、工具结果和确认请求不得写入当前工作区。界面展示能力分类不代表全部工具已经实现，缺依赖保持不可用。

**对话与消息生命周期：** 首期包括新建、当前身份下的有界历史列表、重开、归档和删除；不以多个任务详情页代替对话。对话组织消息及任务引用，一段对话可关联多个正式任务；同一目标的澄清/恢复沿原任务和输入版本，新增目标按原场景生产新的受权请求，不能修改旧任务的范围或批准。对话、消息轮次、原请求和Task/Run分别可识别并保留关联，不在此指定新表或复制业务状态机。

- 消息发送前建立可恢复的原请求关联；受理应答丢失、重复点击及多标签页同轮提交只核对原请求，不重复创建任务或调用模型。用户消息已受理、模型生成中/已结束和业务是否完成分别显示。
- 首期同一对话只允许一个当前自动推进轮次；进行中再输入保留为未发送草稿，不隐式排队、替换目标或启动第二轮。原等待问题的回答仍走其专用输入契约；多标签页通过服务端原修订/幂等约束冲突，前端按钮禁用不替代并发控制。不同对话可并行，但共用适用的租户预算和任务资源上限。
- 切换、关闭、归档或删除对话不是取消任务。已受理任务仍按原政策继续或等待，并可从有权访问的任务中心找到；取消需单独的原正式操作。删除撤回普通历史展示及上下文复用，正文按§17清理；运行中/unknown关联的最少证据按原hold保留，审批、订单、账务和原收据不随对话删除。

**长对话与能力版本：** 每轮只取当前能力、用途和权限允许的历史；切能力不默认带入全部旧上下文，所需正式引用重新受权。压缩摘要继承来源、范围、版本、最短保留期限及撤权约束，不因总结洗掉限制；人类明确选择、待回答问题、原输入/批准版本和unknown操作必须有独立持久事实，不能仅存在于模型摘要。超过上下文容量时采用有界筛选/摘要或明确要求缩小目标，不静默丢弃关键约束后继续执行。记录每轮实际提示词/能力版本；新轮使用当前获准版本，历史结果保留原版本，已受理任务的版本迁移/恢复沿§6和原冻结计划，更新提示词不重派已执行或unknown动作。

### 10.2 动态展示与视觉要求

系统提供版本化展示提示词及可用展示环境说明，由模型根据当前回复和受权材料决定分区、标题、摘要、列表、表格、对比及输入表单，不要求每次相同版式；没有新材料时不强制生成空工作区。

- 分类有序、重点突出、列表清晰、信息足够核对，避免花哨装饰、无意义动画、过多颜色或过度留白；沿用平台字体、主题、圆角、间距和语言。长文本/表格、窄屏、键盘和读屏均须可用。
- 报价清楚区分租金、押金、币种、租期和保存/资源占用状态；风险包含对象、原因、证据和观察时间；差异显示原值、新值和影响。布局灵活，必要事实与关键状态不能因此省略。
- 展示描述/代码、业务事实、可编辑字段定义、交互请求和确认请求分别传输与校验。关键金额、状态、对象及版本采用正式事实绑定和可信宿主摘要，不能由生成代码替换、遮挡或伪造为已验证事实；无法可靠绑定时退回可信事实展示。
- 模型说明/推荐与正式业务字段分开，不能覆盖Core结果。展示合同和组件桥接由平台版本化管理，不传播Runtime/Provider专有对象，不依赖后台内部模块、任意npm包或远程组件。

### 10.3 可编辑表单与重新准备

用户可以在右侧直接修改数量、租期、取还地点等获准参数，无须一律回聊天框重述。模型负责表单组织、标签和说明；字段code、类型、约束、必填性、候选范围、可编辑性及正式默认值来自服务端业务输入契约，不由模型新增业务规则或资格。

输入先作为未提交候选，经平台桥接进入原准备/报价入口，资源按ID重新受权读取，模型抽取与人类明确输入/选择分别记录。缺客户、歧义、时间或资格继续澄清；金额、押金、优惠、库存、订单状态等正式结果不得作为可随意修改的报价事实。

沙箱消息中的字段值即使符合schema，也只算候选，不能自报为人类已输入/已选择。字段业务含义、单位、候选身份和最终采用值由可信宿主核对；人类明确输入/选择须经平台控制的输入接点或固定核对环节建立，脚本自动填值、合成事件、模型声明或沙箱回传的来源标记不能替代。保留模型生成布局，不将布局可信等同输入来源可信。

未提交字段草稿由可信宿主按对话/材料及字段修订管理，不仅保存在可销毁的生成组件里；新回复、主题切换或渲染失败不得静默覆盖编辑。新材料与草稿冲突时保留当前合法草稿并要求核对，不能拼接不同修订；失权、身份/空间变化时撤回旧草稿，不以保留编辑为由泄漏。字段编辑不逐键触发持久报价，须经明确的重新准备动作；核验中标明状态，失败保留可合法继续的输入并提供可信表单/原页面，不要求重新输入整段目标。

修改后重新核验当前权限、字段规则、资源版本和可用性，金额仍由Core产生；重新报价若持久化须声明副作用并走原政策。新输入/选择修订/指纹与新材料绑定，旧确认及批准失效，旧报价保留为历史。未重新准备成功前不得把新输入和旧金额拼成可提交方案；并发修改、过期、撤权及unknown分别呈现，不静默覆盖或自动重复创建报价。

### 10.4 平台固定确认控件与执行

模型可以返回结构化“需要用户确认”请求及提示内容，说明对象、拟做动作和待核对内容。平台核验正式Action/Proposal/材料及当前政策后，使用现有固定按钮和弹窗呈现；纯信息展示不默认附带业务确认按钮。服务端判定必须确认/审批的动作，即使模型漏报或返回false也必须拦截并补齐，不能通过缺标记绕过。

弹窗可使用安全处理后的模型说明；操作对象、实际效果、数量/时间/地点、金额/币种、风险、材料版本及有效期等关键内容由服务端绑定材料填充，模型不能改写或隐藏。不存在、未开放或无权限的动作不生成可执行按钮，提供准确不可用说明或原人工入口。

业务按钮和确认弹窗由隔离区域之外的可信宿主拥有，生成代码不能仿造可执行确认、制造点击或直接提交批准。展开/筛选等纯展示交互可以存在；重新准备等业务交互仍经固定受控组件与桥接，键盘提交同样不能绕过确认。

提交绑定当前actor/scope、会话/任务、action/proposal、输入指纹、材料/对象版本和原操作幂等关联。“确认输入”“确认报价”“批准建单”“批准资金操作”按原流程分别处理，确认文案及点击展示页面本身不授予业务权限。材料变化要求重确认，重复点击仅核对原操作；成功须有正式收据，超时/断线/缺回执保持unknown，不自动换键重试。

### 10.5 生成代码隔离与受控数据读取

生成代码是不可信输入，须使用独立来源沙箱或等效隔离宿主，实际阻断父页面DOM、登录态、Cookie、token、宿主存储、文件系统和业务凭据访问。不得在主应用上下文直接执行生成脚本，也不得以静态关键词检查代替隔离。不开放顶层导航、弹窗、任意下载、任意网络请求或远程脚本/依赖加载；样式限于本区域，不遮挡宿主控件或伪装系统授权窗口。

模型或界面需要补充数据时，只能发起结构化受控请求；宿主/服务端从已登记工具中选择并核验参数、资源、用途及当前权限，返回最少脱敏事实。不允许拼接任意URL、API路径、SQL或任意工具名。需再次调用模型时仍走唯一Gateway和预算单账；正式报价等R1不能以“补数据”为名伪装只读，业务写入仍受原批准与Core约束。

消息桥校验来源、实例/通道绑定、协议版本、白名单动作与封闭payload，只接受当前会话/任务/材料修订的消息。模型或代码回传的actor/scope不能自授权，不能通过消息伪造批准或调用任意宿主函数。禁止先向沙箱传入无权数据再依赖UI隐藏；平台图片、附件及来源仍按原ACL和有期限引用读取，不能借资源加载外发资料。

代码体积、组件深度、表格/来源数量、文本量、消息大小/频率、工具调用次数及渲染时间/资源须有可执行上限；异常、超限或死循环可终止。身份切换、撤权、材料失效和页面销毁须撤销旧交互能力并拒绝迟到消息；撤权或切换身份/范围时销毁旧沙箱及敏感内容。

隔离覆盖运行前后的处理链：若有解析、转译或编译，不得在可信主应用/服务进程执行生成代码、读取秘密或按其指令安装依赖，处理本身有界且可中止。生成代码中的字面量、注释、隐藏节点与派生编译产物也可能含业务材料，沿相同来源/ACL/保留政策管理；错误日志、缓存、截图及导出不能按“只是代码”豁免。人类业务页面、模型输入与沙箱分别取各自允许的最少投影；姓名、电话、详细地址等敏感输入仅在原受权控件处理，不因页面可见自动进入模型或生成代码。

### 10.6 版本、刷新、恢复与降级

流式未完整代码不直接执行；通过结构、完整性及隔离准入检查后才挂载交互版本。事实更新形成新材料/展示修订，旧确认失效；新渲染失败时，仅在当前权限仍有效时可保留明确标记历史/过期、不可执行的旧视图，或退回可信事实摘要。撤权不能以降级名义返回旧敏感数据。

材料、来源、生成/协议版本、输入指纹及适用task/run/step/result关联可追溯，沿原Task/Artifact和审计保留政策保存必要版本，不新建业务状态机。重开历史结果重新鉴权、默认只读；挂载、刷新、重连及恢复历史页面不能自动触发工具、模型或业务提交。展示代码和界面状态不能当作正式业务收据。

代码错误、不兼容、沙箱不可用、资源超限或模型失败时，提供安全文本、受权事实列表及既有人工入口，不能无限白屏或假成功。复制/下载由可信宿主及当前权限控制，不自动导出内部代码、凭据或隐藏资料。展示环境/桥接版本被安全停用后，即使仍有历史读取权也不得重新运行旧代码，须退回当前允许的可信事实呈现。

对话常用操作按下表区分，不能共用含混的“重试”驱动整个业务链：

| 操作 | 允许的行为与边界 |
| --- | --- |
| 停止回复 | 明示停止本轮文字/展示生成或交付；尽力取消生成并阻止其后续新动作，不证明远端停止、未消耗或正式任务取消。若原宿主只支持任务取消，应明确显示“请求取消任务”并走原接口/收据，不把断开流显示为取消成功。 |
| 重新排版 | 对同一当前受权材料产生新展示修订，不重新报价或重放业务工具；若需要新模型调用仍经原Gateway准入、计量及限额，不把排版称为免费本地操作。 |
| 重新生成解释 | 明确发起新的模型生成，沿原请求/调用关联、当前权限/来源/预算和累计资源；不重放已办业务、不覆盖原结果，原派发unknown先核对，不用重生成按钮绕过。 |
| 修改条件重新办理 | 沿原场景创建新输入/选择修订、重新准备及必要确认，保留旧依据；有未明副作用时先读原操作，不通过新对话或新模型重复办理。 |

展示修订与业务材料/输入/批准修订分别识别。只改布局或主题不因展示版本变化自动重新报价、修改业务材料或撤销仍有效的原批准；若改变了用户实际核对的语义、对象或执行效果，仍需按原规则重新核对。历史展示默认只读，既有批准是否可消费始终由原服务端当前授权和材料决定。

### 10.7 验收与适用范围

本次优先适用于租户管理后台右侧工作区。其他端复用业务事实和Action语义，不自动要求小程序、消费者官网或本地Harness执行生成代码；没有已验收隔离能力时沿用安全结构化呈现与人工入口。展示环境具体选型在实现阶段核验，不构成安装框架或替换Runtime的授权。

| 编号 | 验收条件 |
| --- | --- |
| AIN-UI-01 | 同一能力不同回答可形成不同分区/列表/表单；主题、键盘、读屏、长内容和窄屏可用，必要事实清楚，不限定固定卡片模板。新建/列表/重开/归档/删除对话可用，删除不取消正式任务或删除原业务收据。 |
| AIN-UI-02 | 修改数量/租期/地点后正式服务重验重报，旧确认失效；缺项、歧义、资格不足准确返回，不由模型改金额或替选客户/商品。编辑中收到新回复/主题变化/渲染失败不覆盖合法草稿，不逐键创建报价，不用旧金额提交新条件。 |
| AIN-UI-03 | 确认请求绑定合法动作；模型漏报不能绕过必需审批，伪造/过期/重复/跨对象确认被拒；unknown只按原证据核对。沙箱自动填值、合成事件、显示值与回传值不一致或自报人类来源不能取得明确选择/批准证明。 |
| AIN-UI-04 | 实际浏览器证明生成代码无法读宿主凭据、任意联网、远程加载、跨实例通信或自动提交；恶意/无限渲染可终止，宿主确认仍可信可用。解析/编译同样有界且不执行不可信代码，代码/日志/产物含敏感材料时按原ACL及保留清理，安全停用版本不能从历史重开。 |
| AIN-UI-05 | 跨能力/对话/空间、撤权、迟到消息、材料变化及历史重开不串数据或复活执行权，补数据仍鉴权，渲染及重连无新副作用。受理应答丢失及多标签页同轮发送只一份原请求；并发新输入保留未发送草稿。长对话摘要继承来源与撤权限制，不丢人类选择/待答/unknown持久事实，能力版本变化不沿用旧执行权。 |
| AIN-UI-06 | 生成失败有安全降级；展示与确认摘要逐项对应正式事实，区别离线替身、真实浏览器和Core证据，不以截图或模型自评代替。停止回复不伪报任务取消；排版/重生成不重执行业务，模型调用仍计量；纯展示改版与业务材料失效分开，unknown不能借新轮/新对话重做。 |

本节补充原AIN-02/04/07/12/24/26及相关业务场景，不新增原28项分母，也不代表已实现。充分测试可以由AI完成，仍按§18及统一完成定义验收。


## 11. 资料与配置修改（AIN-R11）

客户资料、开业设置及其他获准场景采用“建议→提案→差异确认→正式服务提交”。区分会员共享资料与空间业务数据；修改手机号、身份、企业关系等敏感项沿用原验证流程，不因AI代填省略。

提案与真实业务草稿都须标明存储位置、owner、状态和后续动作。提案创建成功不表示资料已更新；独立版本草稿保存成功不表示发布成功。多人编辑使用 expectedRevision/原对象版本，冲突时展示新的差异并重确认。输入缺失保留为缺失，不自行填写“已审核”等事实。

## 12. 主动经营与自动执行（AIN-R12）

初期主动场景限定为交付临近且资源不足、待处理归还异常、明确的通知/退款失败和开业缺项。触发由正式业务事件或确定性查询产生，AI解释原因、生成候选方案与待办。不要用模型轮询猜测经营事实。

限定场景按下表说明事实、处理边界和结果，不因此新增调度、退款或配置能力：

| 场景 | 异常与方案的正式依据 | 本期处理边界与结果核对 |
| --- | --- | --- |
| 交付临近且资源不足 | 原订单交付时间、当前资源安排和正式可用性/冲突查询；临近窗口及风险条件采用正式政策 | 只建议现有受控能力能办理的资源/交付调整或人工联系方案；替代资源不自动选择，不凭模型认定可调度。执行须有正式工具与批准，按原订单/安排收据核对；无入口时明确人工办理。 |
| 待处理归还异常 | 原归还/检查记录、适用模板及原业务异常状态，不以识别置信度认定事实 | 整理缺失材料和处理候选，交员工或有权人员核实；不判责、免赔或计算赔偿。处理结果以原检查/异常流程记录为准。 |
| 明确的通知或退款失败 | 原发送/退款操作的正式状态及原操作标识；unknown与明确失败分开 | 通知仅在正式服务允许且取得相应授权后办理；原投递未知先核对，不重复发送。退款失败只提示、核对及引导原资金流程，不自主再次退款。以原渠道/业务收据核对，不把已受理说成成功。 |
| 开业缺项 | 正式开业检查、当前分区配置和已实现能力 | 准备普通字段差异/草稿并按原权限确认；证件、账号、密钥及真实连接仍需人工提供或验证，发布另走原审核。复查同一分区的正式检查，不以模型称已修复或旧待办消失判定解决。 |

各场景在开放前须登记事实生产者、触发条件/观察窗口、当前可用工具、允许效果、人工节点、复查条件和处理结果；阈值及生产自动化白名单仍按 AIN-D03 确认，不由 AI 猜定。事实或执行能力缺失时明确不可判断/人工办理，不用本表宣称依赖已交付。已关闭待办不等于异常已解决；实际解决须经当前受权事实复查确认，无法访问或无法判断时不得继续展示旧敏感详情。

事件至少记录 eventId、tenantId、workspaceId（适用时）、资源及版本、类型、发生时间、traceId和必要数据引用。需随业务提交可靠地产生；优先使用已验证的事件/Outbox，缺失时增量建设事务Outbox和有界Worker。消费按至少一次投递设计，使用业务幂等、资源版本和场景去重，不承诺端到端天然恰好一次。

事件乱序或已解决时重新读取当前状态，取消过时建议；自动化不得因自身写入无界循环。任务有冷却、每日次数、收件人范围、金额/数量上限（适用时）、有效期和紧急停用。首次上线为影子模式，仅记录建议；经场景评测和租户启用后，才能执行登记的低风险动作。自动发送通知仍须使用正式发送权限、允许渠道与内容规则，避免重复通知或越权发送。

固定超时取消、对账、计价等已有确定性流程继续由原程序执行。R3不开放无人执行；风险政策变更立刻作用于下一步。人工关闭待办应记录处理结果，不能仅删除卡片后再次重复触发。

## 13. 员工图像与语音辅助（AIN-R13）

员工从授权订单/分配项发起任务，读取对应历史或换货冻结模板。附件必须经正式上传链绑定租户、空间、订单、检查阶段和实际资源；不接受任意URL作为可信证据。

识别输出包含字段code、候选值、原文/图片区域或音频时间段、置信提示、缺失项和待人工核实项。支持编辑、拒绝和重新识别，保留原附件与人工最终值；模型置信度不等于事实或责任已认定。

VIN、车牌、序列号、里程、工时、附件数量等按原格式和范围校验；无法读清时留空。缺领取基线、计量表更换、跨资源照片或读数倒退应走现有异常流程。疑似损坏只形成证据候选，禁止直接增加应收、判定事故时间或替客户确认。

员工端保持弱网草稿和明确同步状态；断网、重复上传、异步结果迟到、切租户/空间后返回均不得串数据。微信授权、录音、相机、上传和真机表现需单独验收，浏览器夹具不替代微信宿主证据。

## 14. 客户多端助手（AIN-R14）

复用客户认证、渠道配置、服务空间切换和本人/企业身份规则。统一后端场景及任务协议，由客户小程序和现有租户预约网站分别渲染；独立APP只维护兼容契约和示例。

首批客户能力为选品澄清、可租方案、正式报价、本人订单解释和办理入口。企业客户仅在已授权的企业关系和用人范围内操作。支付调用现有宿主收银台与回调链，聊天说“我付了”不能改变支付状态；客户取消/退款按正式业务规则和受理结果显示。

匿名访客仅可访问已发布公开目录及帮助，不得枚举客户、内部库存或任务。登录后不可自动把另一个人的匿名任务关联到当前客户；登录迁移需绑定客户端会话与明确选择。助手退出或不可用时，常规预约流程可继续。

## 15. 平台品类治理助手（AIN-R15）

在品类治理正式能力可用后接入：解释模板、从已有定义形成同品类草稿、新增支持范围内的品类方案、推荐字段及已实现能力、调用正式校验与影响预览。模型只能从真实策略/能力目录选择，不生成可执行脚本或把尚未实现的计价模型标成上线。

草稿编辑、发布、可采用资格、空间采用是不同业务动作。发布和采用分别确认并调用各自服务，不能把“平台发布成功”说成“所有租户已升级”。遇到新增必填、唯一性、库存/计价范围收窄和历史依赖，展示原治理工具给出的阻塞和迁移准备项。

不把未合入的工作树实现视为当前部署可用。动态新品类依赖CAT-GOV相应任务；若仅具备内置品类编辑，则显示实际能力并保留后续任务，不能以模拟第五品类完成验收。

## 16. 建议架构、数据与接口（AIN-R16）

建议在现有NestJS应用内新增独立AI模块；保留Core及各业务域为执行者。先实现模型网关、工具目录、上下文/授权、任务Worker与审计，只有实际容量需要时再拆独立服务。已有集成密钥、文件、权限、Job机制先盘点再复用。

建议持久化对象（可在契约设计阶段合并或复用，变更需记录映射）：

| AiStep                             | runId、序号、toolCode/version、actionId、请求指纹、脱敏参数/结果引用、开始结束、租约/版本、重试与业务关联；唯一约束阻止重复执行 |
| AiProposal / AiApproval            | revision、动作清单、对象版本、报价/政策引用、payloadHash、截止时间、确认人/拒绝原因/消费状态；模型不可签发授权              |
| AiPolicy / AiProviderConfig        | tenant或platform范围、场景/角色/空间范围、允许模型和自动化、预算、修订、凭据引用、启停状态                           |

必须有租户/scope与对象关系约束、查询索引、并发唯一约束、乐观修订和迁移回退说明。业务事实引用保持外键或可验证关联；删除聊天不能级联删除订单、资金和审批事实。后台任务身份不通过缺失workspace回退获得范围。

建议API按身份隔离：

| 面       | 路径建议                                                                                                       | 约束                           |
| ------- | ---------------------------------------------------------------------------------------------------------- | ---------------------------- |
| 租户管理后台  | `/api/ai/v1/tasks`、`/:id`、`/:id/events`、`/:id/messages`、`/:id/cancel`、`/proposals/:id/confirm`、`/settings` | 认证用户的当前有效范围；不是万能工具调用代理       |

业务材料、模型结果与复合任务观察同样复用本系统的命名封闭契约：原场景与材料对应，文本、来源和集合有明确上限，明确缺失、过期、失败及待核对语义，不以通用对象或移除未知字段掩盖损坏响应。模型文本、引用和工具候选仅是数据，不能证明授权、审批或业务提交；复合观察由原任务、输入、模型、审批和Core收据各自按当前权限读取，不宣称跨域原子快照，也不因重连启动运行器或重发动作。历史输入/材料指纹只标识原依据，不能拿当前配置或新观察替代；实际业务完成仍由原正式收据证明。纯读取的损坏响应保持不可用，可能已提交的写响应损坏保持待核对并指向原操作观察，不授重试。对话和模型材料按保留政策清理后，合法原业务收据读取不恢复已删除正文。

通用错误至少包含：`AI_DISABLED`、`AI_PROVIDER_UNAVAILABLE`、`AI_BUDGET_EXCEEDED`、`AI_TOOL_UNAVAILABLE`、`AI_SCOPE_CHANGED`、`AI_APPROVAL_EXPIRED`、`AI_PROPOSAL_STALE`、`AI_RESULT_UNKNOWN`及可复用业务错误。状态码和信息必须保证无权限者不能探测对象。请求ID/错误信息不能泄露业务令牌。

## 17. 审计、隐私与可靠性（AIN-R17）

记录可核实的目标、必要输入摘要、来源、方案、工具输入输出引用、模型/提示词/工具版本、授权、执行者、费用和结果；不要求保存或展示模型内部思维链。敏感正文最少保存、加密、按权限访问；调试日志不得收集密钥、身份证件全文、全部客户资料或原始会话令牌。

提示注入、越权、数据外传、恶意附件、任意出网、任务共享、重试、预算并发和模型输出XSS进入专项威胁测试。平台与 BYOK 配置外部供应商均须校验协议、域名、DNS 解析与连接时网络地址及重定向，禁止把 URI 格式合法当作出网安全；未经独立授权的内网 Endpoint 不因“企业/私有模型”名称而放行。附件扫描/解析采取资源限额，不为识别内容执行附件代码。

任务读取和检索的权限与执行同等重要；成员撤权后旧摘要、事件流、下载URL、缓存、向量结果不能继续泄露。留存与删除分别处理对话、附件引用、索引、用量及必须保留的业务审计；保留期限未决定前，不开启生产敏感数据采集，也不能默认永久保留。

**负责人确认的最小保留政策（2026-10-15）**：普通 AI 对话、生成文本及场景准备材料默认保留30天；未绑定任务的 AI 专用临时附件7天清理，不含原订单或检查等业务附件。知识文档与人工确认记忆撤回后立即停止读取、清除可检索索引及缓存；明确删除后，正文、历史版本正文及确认记录中的重复正文在7天内物理清理，最少操作标识与哈希收据保留。审批、预算账本、原业务收据及必要审计沿用业务保留政策，不随对话删除，也不额外留存敏感正文。运行中、unknown或待核对任务暂停关联材料的到期删除，不因TTL重派、退额或释放预算。备份中的已删除内容最长30天淘汰；恢复备份前必须重放删除标记、验证不可读取后才允许恢复访问。清理必须受权、有界、幂等、可恢复并记录失败；共享附件不得误删。政策未配置或备份/删除依赖尚未装配时不宣称删除闭环或生产隐私验收通过。

保留责任必须分开登记：本地正文/索引/缓存由相应数据服务负责，业务收据和财务最少事实由原业务域负责，外部对象与供应商副本由对应适配/运营责任人核验，备份淘汰与恢复屏障由部署运维责任人留证。未指定真实责任人或未装配删除执行者时标明缺项，不以本文代替其承诺。

未决任务的hold须能追溯到实际关联材料、原因和待核对操作，不能因空间内一个无关任务未完成而无限保留其他已到期/已删除正文。暂不能精确关联时如实标为删除实现缺口并限制相关生产采集，既不能删除未知副作用证据，也不能把保守hold报为删除完成。业务审计需保留不代表所有对话正文都需永久保留。

全局、租户、场景三级停用能阻止其适用范围内的下一步模型调用和业务动作；已提交副作用按当前读取 / 善后权限查询并进入核对。服务端模型停用 / 余额不足、本地业务工具政策关闭及安全禁止访问分别处理，范围见 §1.3，不用模型费用开关替代业务授权开关。模型不可用、预算耗尽或Worker失败时，人工经营主链仍可运行。

## 18. 验收矩阵（AIN-R18）

### 测试验收与完成口径

本规则适用于原 AIN-01～AIN-28 和全部 AIN-ENTRY 增量任务。**不要求负责人或其他真人逐项操作、签字或另行进行真人验收。开发 AI 可以完成测试、核验结果、修复问题及复验；任务全部要求满足、测试充分且证据归档后，允许更新为100%，不得仅因缺少真人验收而长期停在75%。**

- 测试须覆盖本任务的完整交付范围及适用的正常、拒绝、权限/范围变化、边界输入、重复请求、未知结果和恢复路径；涉及并发、持久化、金额或外部副作用时，还须验证对应风险。缺实现、未接消费者或可信依赖缺失，不能用局部绿色或默认关闭代替完成。
- 优先复用已有测试、定向冒烟和实际服务组合，不要求为收口新增大量测试脚本。发现问题须修复并复验；适用任务要求独立技术复核时，可由独立 AI 或独立自动化检查完成，不需要真人。模型自评分不能替代业务金额、状态、权限和幂等的确定性断言。
- 原任务明确要求的真实数据库、浏览器、微信宿主/真机、供应商或支付证据仍须实际取得；自动化可以完成这些测试，但离线替身不能冒充实测。真实访问、生产密钥、采购、部署和灰度开放仍按原授权边界办理。
- 原业务页面/服务的程序化操作可以作为参考流程和自动化基线；须注明样本范围、版本、方法及未采集指标，不虚构真人操作、体验、评分或人工接管数据。未采集真人指标本身不阻止任务收口；本任务必需的功能与性能测试仍不可省略。
- 本规则只调整软件开发的测试验收方式，**不取消真实业务中的用户确认、人工审批、资格审核或负责人生产放行**，也不授予 AI 自批、自授权或执行高风险业务的权限。

验收以真实业务状态及权限结果为准，不以模型说“成功”为准。各阶段重复运行固定场景集，保留模型与提示词版本、输入数据、期望、实际状态、耗时、用量、成本和证据。业务金额/状态由确定性断言验证；语言质量可结合人工评审，但不能由另一个模型单独裁定资金正确。

## 18A. 多端入口与业务助手增量需求（AIN-R19）

本节是原28项需求的增量产品与接入约束，不另建 AI 系统，不改变 AIN-01～AIN-28 的分母、状态、依赖和验收口径。所有入口继续复用本专项已经定义的 Gateway、Task/Run/Step、Scope/Authorization、Budget/Usage、Proposal/Approval、Audit、Knowledge/Memory 和 Rental Core；没有正式能力的场景必须保持 `unavailable` 或 `manual_only`。

### 18A.1 多端场景与身份边界

统一支持以下入口，但不要求一次性同时上线：租户管理后台、员工小程序、客户微信小程序、租户消费者预约网站。客户小程序和预约网站共享 Customer Rental Agent 的场景契约，身份、会话、渲染和导航仍按端分别处理。

至少定义三类业务 Agent：

- `operations`：面向租户管理后台，查询订单、客户、资产、库存、经营风险和开业状态，生成建议及受控操作方案。
- `staff`：面向员工履约端，查询当日任务、订单/客户/资产必要信息，辅助交付、归还、检查和资料补全。
- `customer`：面向客户小程序与预约网站，完成需求澄清、公开目录/可用性查询、本人报价、Booking Draft 和预约办理引导。

`platform` 仅作为平台内部受控 audience 预留；在没有明确平台权限、数据范围和正式工具白名单前，不得把它当作普通租户或客户能力开放。每个 audience 都必须由服务端解析并复核 tenant、workspace、location、role、customer/enterprise relation 和 dataScope；客户端、模型文本、URL 参数和历史缓存不能授予范围。

### 18A.2 场景流程与 Rental Core 边界

客户首期采用“AI 生成预约草稿 + 原预约页面确认”，不是“自然语言直接自动下单”：

```text
客户描述需求 → 结构化澄清 → 查询真实商品/可用性/报价 → 生成 Booking Draft
→ 客户明确选择继续预约 → 打开原预约页面并带入已确认条件 → 客户检查并正式提交
```

可带入的字段限于已被用户明确选择、服务器正式默认或 Core 规范化的商品/车型、数量、租赁时间、取还地点、服务、客户资料引用和报价引用。AI 不得生成或改写库存、价格、押金、优惠、退款、订单状态、付款状态、车辆分配、取消/续租/延期资格或调度结果；这些事实继续由 Rental Core 和正式业务流程决定。报价不等于库存锁定，草稿不等于订单、支付或审批成功。

Operations Agent 的结果应优先结构化返回事实、来源、观察时间、风险/阻碍和允许的下一步，例如订单/客户/资产页面入口、方案预览或人工办理出口。Staff Agent 只返回当前员工授权范围内的履约资料和缺失项，不替代检查提交、责任认定或收费裁定。

### 18A.3 结构化 Action 与固定导航注册表

业务执行与导航采用结构化 Action，不能把其参数当代码执行，也不能直接返回 `wx.navigateTo`、`router.push`、脚本、任意 URL 或组件名。首期可使用的 Action Code 包括：`OPEN_ORDER`、`OPEN_CUSTOMER`、`OPEN_PRODUCT`、`OPEN_BOOKING`、`OPEN_PROFILE`、`OPEN_PAYMENT`、`OPEN_DISPATCH`、`CREATE_BOOKING_DRAFT`、`CREATE_NOTIFICATION_DRAFT`；实际可用项必须登记在服务端/客户端版本化注册表中。

每个 Action 至少携带并校验：`contractVersion`、`actionCode`、`audience`、目标资源及其 `resourceVersion`、允许的 `surface`、当前 `scope`、`requiresConfirmation`、`riskLevel`、`expiresAt`、输入指纹，以及适用的 `taskId`/`proposalId`/`quoteId`/`bookingDraftId` 引用。需要副作用的 Action 还必须绑定当前身份、权限复核、幂等键、预算/审批/业务版本和审计关联。客户端只执行“Action Code → 本端固定页面/行为”的映射；未知、过期、跨 audience、跨 scope、篡改参数或不兼容版本一律拒绝并提供人工出口。

同一业务 Action 可以按端映射不同页面，例如 `OPEN_BOOKING` 在小程序打开原预约页，在租户网站打开同站预约页，在后台仅可进入受控的业务查看或人工办理页；Action 本身不携带任意导航地址。§10允许的隔离展示代码属于独立呈现载荷，不是Action、路由或宿主组件执行授权，不能借此放开业务脚本。

### 18A.4 Booking Draft 生命周期与跨端连续性

Booking Draft 是受限的预约输入草稿，不是订单、库存锁、支付意图或审批凭证。其生命周期至少区分：`draft_created`、`user_selected`、`stale`、`expired`、`handed_to_booking_page`、`submitted`、`abandoned`。草稿必须绑定创建者/匿名会话、tenant、发布空间、audience、输入指纹、选择修订、报价/规则/可用性观察版本、过期时间和来源；不得保存支付令牌、完整敏感资料或未授权客户数据。

打开原预约页面前后均需重新检查身份、scope、报价有效期、库存/可用性和对象版本。发生登录、租户/空间切换、客户/企业身份变化、报价过期、库存变化、商品/时间/地点修改或权限撤销时，旧草稿和相关 Action 立即失效并要求重新准备，不静默合并、不自动替换商品、不沿用旧确认。

小程序与预约网站可以共享版本化场景和草稿引用，但不默认共享登录态、任务、缓存或权限。跨端转移必须由服务端签发的一次性/有期限引用完成，并重新绑定当前身份和 scope；匿名访客登录后不自动把匿名草稿归属给另一客户，需明确选择或重新创建。

### 18A.5 风险分级、确认和失败降级

所有端的 Action、场景及工具统一采用 §5 的 R0～R3，不为渠道另设第二套分级：

- `R0`：只读查询、事实展示、无副作用的建议/预览及固定导航；读取本身仍须授权。
- `R1`：正式报价、持久化 Booking Draft/通知草稿/AI提案等已声明副作用；必须区分“草稿/报价已保存”与“业务尚未提交/执行”，不因是准备动作而一概升为R2，也不把保存成功说成建单成功。
- `R2`：建单、普通资料修改、提交检查、获准配置写入或发送通知等 §5 已列动作；仍需具体方案、当前权限、确认和正式提交链，只有原阶段三已登记的低风险政策可授权有限自动执行。
- `R3`：付款等资金处分、退款/免赔/责任裁定、价格/规则/品类发布、权限修改和敏感批量导出；保留明确人工确认与原审核链，不开放无人执行。

取消、延期、调度等未被 §5 逐一列明的具体动作，须按原业务效果在唯一的正式工具/Action注册表中登记风险、权限和批准要求，不能仅凭动作名称或页面将其统一升降级；涉及资金处分、发布或其他R3效果时执行R3约束，未登记或未交付不可执行。各渠道可以进一步禁止某动作或要求更严格的人类确认，但不得降低其原风险与授权要求；导航到支付/退款页面不授予支付/退款执行权。

模型不可用、预算耗尽、工具不可用、未登录、权限变化、网络离线、报价过期、库存变化、Action 无效或业务结果未知时，系统必须保留准确状态并转人工/原页面；不得显示假成功、把请求已提交说成业务已完成、用降级逻辑返回旧敏感事实或自动重派未知副作用。人工页面和传统预约、履约、支付链始终可继续使用。

### 18A.6 隐私、刷新和运营约束

客户不得看到其他客户资料、后台经营报表、内部成本、审核意见、隐藏库存、支付令牌或供应商密钥；员工和管理员也只能在当前授权范围读取。模型输出中的链接、HTML、客户标识、金额和状态必须经过现有白名单/安全呈现规则，不能绕过导航或权限。

所有结构化事实、报价、可用性和 Action 都应带查询时点、来源/版本、有效期或“未加载/未知”标记；“可用”不表示已锁定，“报价已生成”不表示已建单。记录 audience、surface、contractVersion、task/action/proposal/draft 关联、拒绝原因和人工接管结果；按租户和场景设置调用、草稿、Action、失败重试和人工转接的有界限制，避免滥用和无限循环。

### 18A.6A 契约归属、事实优先级与可替换边界

多端增量只增加场景接入，不复制公共任务、授权、预算、审批、Gateway、Core 或客户主数据。Action、Booking Draft、事实投影和错误码的服务端契约由本专项稳定端口及既有 shared 公共契约共同约束；若字段缺失，必须提出契约补丁并保持 `unavailable`，不得在某端私造同名公共 DTO。

输入来源与业务事实权威性分别记录，不使用一条优先级链混排：

- **用户意图与输入：** 用户明确输入/选择说明其希望办理的对象和条件；缺值只可使用该字段已有的正式服务端默认值，并明确展示来源。模型抽取、缓存和客户端回传不能冒充人类已选择或批准；资源ID和输入仍须服务端核验。
- **规范化与资格校验：** Core可按原规则规范化或拒绝输入；影响对象、价款或执行效果的变化应明确展示并按原要求重确认，不能以“规范化”静默替换用户选择。
- **业务事实与最终判断：** 实际金额、库存、资格、订单/付款状态及历史依据，以对应正式服务/受权事实和适用版本为准，不能被用户陈述、默认值、模型推测或确认覆盖。缺失或冲突标明待核对，不自行选一个值冒充事实。

每个输入和可展示事实保留适用的来源、版本与观察时间；确认输入不等于业务允许执行。每次跨服务读取后，执行端仍需复核当前身份、scope、对象版本和能力；旧结果不能因“可选来源”降级而继续可见。

Runtime 或 Provider SDK 的未来替换只能发生在编排/协议适配边界。业务 Action Code、Draft 状态、Task/Proposal 引用、Core 收据、预算单账、权限错误和审计字段不得绑定 LangGraph 节点、SDK 消息对象或供应商专有类型。未验证的 checkpoint 映射、流式取消、重放、迁移和回退标记为待验证，不得以接口存在宣称可无缝切换。

### 18A.6B 草稿、Action 和发布的状态机约束

服务端必须定义允许的状态转移和幂等边界：草稿只能按 `draft_created → user_selected → handed_to_booking_page → submitted` 或进入 `stale/expired/abandoned`；失效状态不得回到可提交状态，重新准备必须产生新的选择修订/输入指纹。`submitted` 仅表示原预约页面已接受正式提交请求，不能代替订单创建、支付或履约成功。

Action 必须在签发、展示、执行前分别进行版本、过期、audience、surface、scope、资源修订和当前权限检查；重复点击复用同一幂等关联或返回原结果，不能创建第二个 Draft、Proposal、订单或资金动作。服务端签发的跨端引用应一次性或短期有效，并在消费后作废；不得用前端保存的 taskId、customerId、URL 或草稿 JSON 恢复授权。

### 18A.6C 发布、关闭和证据等级

每个端/租户/场景必须有明确的默认关闭、能力探测和回退位置，区分入口未开放、新执行停用和历史访问权限：

- **未开放的普通页面入口：** 不自动读取AI数据、不创建轮询、不绑定可执行动作；原订单、预约、履约、支付和人工页面保持可用。启用不得由URL、localStorage、模型文本或客户端自报能力触发。
- **执行停用或准入不足：** 在该入口适用的模型 / 业务政策范围内拒绝新模型调用、新业务执行及自动工作流推进，包括所需预算不足、必需依赖缺失或版本不兼容；不因此把在途操作标成未发送、已回滚或可重派。平台模型余额不得误作 §1.3 本地自付查询的模型准入条件，本地业务政策关闭也不得误改服务端已提交事实。
- **历史查看与原操作善后：** 有单独可信读取/善后宿主且当前访问权限允许时，可显式、有界地查看历史任务、原业务收据，或按原证据及动作权限完成原账结算/核对。不得重新调用模型、产生新的业务动作或授予重派权；普通关闭入口不自动启动该读取或轮询。缺少可信宿主/当前权限，或安全停用明确禁止访问时，拒绝读取而不泄露旧内容。

新执行权限和历史/善后权限分别复核，不能因原执行门关闭就丢失合法核对路径，也不能以善后之名恢复执行。已在途请求仍按unknown/待核对规则收敛，原账不因停用自动退款或释放。

验收证据必须分层记录：契约/静态、离线服务行为、事务/仓储、宿主模拟、真实 Core/数据库、真实浏览器、微信宿主/真机、供应商/支付。低等级证据不得升级为高等级通过。每个入口还需记录延迟和资源上限、失败/拒绝率、人工接管率、重复 Action、草稿转提交率、unknown 收敛率及按租户的成本/配额；保留期限、删除/撤回传播和导出边界沿用现有租户审计与隐私政策，不新增长期缓存。

### 18A.6D 多语言、时间和人工可用性

时间输入必须绑定租户/预约空间时区，向用户展示绝对时间和时区；“明天上午”“周五晚上”等无法唯一解析的表达继续澄清，不使用设备时区或模型猜测。金额沿用 Core 币种和精度，不在 AI 层换算。结构化结果必须可由传统页面和人工人员继续处理，错误、待核对、未提交、已提交请求和业务成功使用不同状态；各端按既有语言、可访问性和安全呈现约定渲染，不能以长文本或图标掩盖关键状态。

除原 AIN-A01～AIN-A32 外，增量需求增加以下验收场景，作为适用原任务的补充证据，不改变原28项完成定义：
