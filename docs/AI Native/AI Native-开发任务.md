### AIN-ENTRY-01：多端 audience 与场景目录

- 登记 `operations`、`staff`、`customer`；`platform` 仅在平台正式授权和工具白名单存在后开放，不能作为普通租户万能入口。
- 明确四端入口：租户管理后台、员工小程序、客户微信小程序、租户消费者预约网站；客户小程序与网站共用后端场景契约，分别处理登录、渲染和导航。
- 服务端解析并复核 tenant、workspace、location、role、customer/enterprise relation、dataScope 和能力/订阅；模型、客户端字段、URL 参数、旧缓存不能授予范围。
- 每个场景登记可用工具、原权限、最大返回量、脱敏、查询时点、成熟度、风险级别、人工出口和停用方式。

### AIN-ENTRY-02：结构化 Action 与固定导航接入

- 建立版本化 Action 注册表，首批允许 `OPEN_ORDER`、`OPEN_CUSTOMER`、`OPEN_PRODUCT`、`OPEN_BOOKING`、`OPEN_PROFILE`、`OPEN_PAYMENT`、`OPEN_DISPATCH`、`CREATE_BOOKING_DRAFT`、`CREATE_NOTIFICATION_DRAFT`。
- Action 至少校验 `contractVersion`、`actionCode`、`audience`、target/resourceVersion、surface、scope、`requiresConfirmation`、`riskLevel`、`expiresAt`、输入指纹和 task/proposal/quote/draft 引用。
- 客户端只做 Action Code 到固定页面/行为的映射；不得借Action执行模型URL、脚本、任意宿主组件名或任意路由。需求§10的隔离展示代码为独立呈现载荷，不是Action执行许可。未知、过期、篡改、跨端、跨 scope 和不兼容版本必须拒绝。

### AIN-ENTRY-03：客户需求澄清与 Booking Draft

- 实现“描述需求→结构化条件→真实商品/可用性/报价→Booking Draft→用户明确继续→原预约页面确认”的装配。
- 草稿只绑定已明确输入、正式默认或 Core 规范化字段；不代替订单、库存锁、支付或审批。
- 草稿持久事实至少包含 audience、会话/创建者、tenant/发布空间、输入指纹、选择修订、报价/规则/可用性观察版本和过期时间；不保存支付令牌或未授权敏感资料。
- 身份、空间、商品、时间、地点、可用性或报价变化时旧草稿立即失效并重新准备，不自动替换商品或合并匿名与登录状态。

### AIN-ENTRY-04：跨端转接和身份切换

- 小程序与预约网站只共享版本化场景/草稿引用，不默认共享会话、任务、缓存或权限；跨端必须使用有期限、一次性或可核验的服务端引用重新绑定当前身份和 scope。
- 匿名访客登录、客户/企业身份切换、租户/空间切换、登出重登时，旧 Action、草稿、异步回调和敏感内容必须隔离或失效。
- 页面和宿主不能通过保存 taskId/customerId 或前端过滤恢复旧授权。

### AIN-ENTRY-05：运营后台结果与人工操作

- Operations Agent 的结果优先提供事实、来源、观察时间、风险/阻碍和已登记的下一步，而非只给长文本；可以跳转订单、客户、商品或调度查看页。
- 只读、预览、需要确认的准备动作和正式业务写入分开；退款、资金处分、调度、通知、建单等 R2/R3 仍走现有权限、Proposal/Approval、预算、幂等和 Core 提交链。
- 没有正式 allowed-action 服务时只返回已核实的人工入口或 `candidates_only`，不把权限码本身当作业务可执行许可。

### AIN-ENTRY-06：员工履约入口

- 员工只读取当前 tenant/workspace/location/role 白名单内的订单、客户、资产和履约资料。
- AI 可以引导交付、归还、检查、拍照、读数和资料补全，但不直接提交检查、不判责、不改收费、不绕现有上传、审批和业务提交入口。
- 弱网、卸载、切空间、权限撤销、识别未知结果和人工更正必须保持草稿/同步/待核对语义，不显示假成功。

### AIN-ENTRY-07：Core 事实和正式报价装配

- 所有库存、可用性、最终报价、押金、优惠、资格、退款、订单和付款事实必须来自 Rental Core/正式只读服务；AI 不重算、不覆写、不把报价当锁定。
- 报价准备输出分项、总额、币种、计价单位、规则/价格/优惠版本、有效期、查询时间、资源占用语义和持久化副作用；缺字段保持缺失/未知。
- 报价或草稿确认不等于建单批准，只有既有固定接口和正式审批/提交链齐备后才可接入下一步；否则交付 `prepared_not_submitted` 或 `unavailable`。

### AIN-ENTRY-08：风险、权限和生命周期降级

- 风险分级只采用需求 §5及§18A.5：R0只读/导航/无副作用建议，R1正式报价与持久草稿/提案，R2建单/普通资料修改/检查提交/获准配置写入/通知发送，R3资金处分/退款/责任裁定/规则价格品类发布/权限修改等。取消、延期、调度按原业务效果在唯一注册表中明确，不按渠道重新分级；未登记不可执行，渠道限制只能收紧不能降权。
- AI 不可用、预算耗尽、工具 unavailable、未登录、权限变化、离线、报价过期、库存变化、Action 无效或结果 unknown 时，转原页面/人工办理，禁止假成功和自动重派未知副作用。
- R1～R3分别返回草稿/报价保存、请求受理、业务完成或待核对等真实状态，不一概标为未执行；准备结果不能冒充业务成功。R2/R3在执行前重新核查身份、scope、对象/报价版本、能力、预算和审批，R3保留明确人工确认及原审核链。

### AIN-ENTRY-09：隐私、刷新和结构化显示

- 不向客户泄露其他客户、内部成本、审核意见、隐藏库存、支付令牌或密钥；员工/管理员也仅见当前授权范围。
- Action、事实、报价和可用性带查询时点、来源/版本、有效期或未知标记；模型文字不能覆盖确定性金额、状态、资格和 Core 结果。
- 模型链接、HTML、控制字符和导航参数走既有安全呈现/白名单；不通过富文本、任意 URL 或前端隐藏绕过服务端授权。

### AIN-ENTRY-10：固定入口与人工兼容

- 将入口接入现有显式组合、任务/事件和页面宿主，不注册第二套 HTTP、Worker、Runtime 或客户端路由系统。
- 任何端关闭 AI、缺后端能力或失去权限时，传统订单、预约、履约、支付和人工流程保持可用。
- 入口交付需列明真实页面/宿主装配、默认关闭位置、Action 映射、可用工具、人工出口和未接通依赖。

### AIN-ENTRY-11：组合快检和证据等级

- 复用真实业务服务和现有离线夹具，按 audience 各选正常、缺依赖、权限变化、过期/unknown、重复点击和迟到响应案例；不复制产品逻辑到夹具。
- 证据分开记录为静态/类型、服务行为、离线宿主模拟、真实 Core/数据库、浏览器、微信宿主/真机和供应商；低等级证据不得升级为高等级结论。
- 只做边界内定向快检，失败保留首轮证据并修实际缺陷；不以新增脚本数替代功能实现。

### AIN-ENTRY-12：交接与未来替换资料

- 每片留下稳定输入/输出、生产者/消费者、Action/草稿状态、持久化事实、授权/预算/审批/Core 依赖、当前耦合和未验项。
- 未来替换 Runtime 或 Provider SDK 时只替换编排/适配边界；不得改变业务 Action、Task、Proposal、Core 收据和预算单账语义。未验证的迁移、checkpoint 映射和回退条件标为待验证。
- 本增量队列清空不等于原 AIN-01～AIN-28 结项；主线须按原任务和需求文档完成独立验收。

### AIN-ENTRY-13：稳定契约与事实来源优先级

- 冻结 Action、Booking Draft、事实投影、错误和证据等级的生产者/消费者；缺字段时提出公共契约补丁并保持 `unavailable`，不造私有同名 DTO。
- 对每个输入记录“用户明确输入/选择、服务端正式默认、Core 规范化、受权事实、模型候选”的来源；模型、缓存、客户端回传不能升级为确认输入、权限或业务事实。
- 按需求§18A.6A分离意图、默认/规范化和权威事实：用户选择不覆盖Core金额、库存、资格或付款状态；默认值须有正式字段依据，规范化改变办理效果时重确认，冲突/缺失保持待核对。不以来源排列决定谁能覆盖业务事实。
- Runtime/Provider SDK 类型只留适配边界；Task、Proposal、Core 收据、预算单账、Action 和 Draft 状态不绑定具体框架或供应商对象。

### AIN-ENTRY-14：Booking Draft 与 Action 状态转移

- 实现并验证 Draft 的允许状态转移、失效终态、选择修订、输入指纹、过期和提交语义；`submitted` 不得解释为订单/支付/履约成功。
- Action 在签发、展示、执行前分别复核版本、过期、audience、surface、scope、资源修订和当前权限；重复点击使用幂等关联，不创建第二订单、Proposal、Draft 或资金动作。
- 跨端引用必须由服务端签发、短期/一次性消费并重新绑定身份和 scope；不得用前端 taskId/customerId、URL 或缓存恢复授权。

### AIN-ENTRY-15：端/租户发布、停用和传统路径

- 为每个端、租户和场景登记默认关闭位置、能力探测、停用行为、人工出口和回退页面；未开放的普通页面入口零自动AI读取、零轮询、零动作。执行停用或准入不足拒绝新模型调用/业务执行，但不将原操作视为未发生。
- 按需求§18A.6C另行装配显式、有界的历史读取和原操作善后：仅在当前独立读取/善后权限及可信宿主齐备时可用，不触发新模型/新业务动作，不授予重派权；安全停用禁止访问或缺权限时仍拒绝，不借历史模式回显旧敏感内容。
- 禁止 URL、localStorage、模型文本和客户端自报能力启用入口；执行停用后拒绝新执行请求，历史读取/善后另按当前权限核验，在途未知按原规则核对，不自动重派。
- 验证传统订单、预约、履约、支付和人工路径不依赖 AI 入口，AI 失败不阻塞原业务。

### AIN-ENTRY-16：多端事实显示、时间与可访问性

- 结构化结果分开显示错误、待核对、未提交、已提交请求和业务成功；金额、币种、状态和资格只读 Core/正式事实，不由文本重算或覆盖。
- 时间按租户/预约空间时区解析并展示绝对时间；无法唯一解析的相对时间继续澄清，不用设备时区猜测。沿用 Core 金额精度，不在 AI 层换算。
- 按既有语言、安全呈现、键盘/读屏、系统字号和长文本约定装配；关键状态不能只靠颜色、图标或长文本表达，人工人员可以接续处理。

### AIN-ENTRY-17：证据、审计和隐私生命周期

- 每个入口分别记录契约/静态、离线服务、事务/仓储、宿主模拟、真实 Core/数据库、浏览器、微信宿主/真机和供应商证据，不跨等级宣称通过。
- 记录 audience、surface、contractVersion、task/action/proposal/draft、拒绝原因、人工接管、延迟/资源上限、重复 Action、unknown 收敛和按租户成本；与现有审计关联，不重复建设统计账本。
- 沿用现有租户审计/隐私保留、删除、撤回传播和导出边界；不得新增长期客户端缓存，不保存支付令牌、完整敏感资料或未授权客户数据。

### AIN-ENTRY-18：组合快检与交接出口

- 每个完整功能片只做一次针对性正常/关键拒绝冒烟和必要类型检查；失败修复后复验受影响范围，不以新增测试脚本数量替代功能实现。
- 交付固定入口、生产者/消费者、状态转移、授权/预算/审批/Core 依赖、默认关闭位置、回退路径、实际证据和未验项；缺依赖给出方法/字段/文件级补丁需求。
- 队列清空仍不等于原 AIN-01～AIN-28 结项；真实 Core、数据库、浏览器、微信宿主和供应商证据必须单独验收。

### 3.1 百分比口径

百分比是主线已核实研发里程碑的覆盖率，不是工时、代码量、全部需求覆盖率或上线就绪度。沿用原有四个固定门槛，每个25%：

- **G1：** 本任务的正式契约、权威输入/事实或验收基线已形成；只写任务计划不计。
- **G2：** 至少一条主要功能路径在原服务中实现，不是空端口或仅有测试替身。
- **G3：** 主消费者、公开发布或原宿主已接回实际生产代码；显式默认关闭的组合可计代码装配，但不是生产启用，也不表示所有变体齐备。
- **G4：** 本任务全文功能及实际生产装配齐全，必要模拟冒烟和类型检查通过，发现的问题完成修复、受影响范围复验及证据归档；原要求的独立技术复核由独立AI/自动化检查完成。真实数据库、浏览器、微信宿主/真机、供应商及其他外部实测由负责人自行操作，不再作为本轮研发100%的前置。只有G1～G4全满足才100%；缺实现或只接接口不能靠替身补齐，模拟也不得记为真实能力、真实费用或生产启用。

0%=尚无已核实门槛，25%=G1，50%=G1/G2，75%=G1/G2/G3。部分实现、仅作者报告或证据待核实不多计。整体为28项等权平均，不据此推算剩余工期；ENTRY增量18项另算。未提交或尚未核查的辅助成果不提前计分。

百分比变化须能在开发情况记录中追溯对应门槛、固定提交、消费者和验证边界。不因测试数、提交数或文档整理加分，不缩小原需求抬高比例。未跨门槛时保持百分比不变，只在实施记录更新成果与余项，不在此追加说明。归属、派工和交接只在当前协作接续维护。

## 4. 任务交付细则

### AIN-01 实现基线、业务工具成熟度和人工流程盘点

- 逐一核对正式分支、目标工作树、部署版本、Core与品类治理提交；记录现有AI配置的模拟行为，不能把未合入代码列为已部署能力。
- 为计划工具建立清单：实际服务入口、原权限、scope、输入/输出、事务、副作用、幂等、实际验证和缺口，登记`unavailable / preview_only / executable`的判定依据。
- 建立四品类人工参考案例：选品、资格、计价、取还、报价、开单、检查、结算、变更解释；采集已实现范围，不补造数据口径。
- 交付当前事实清单、原业务参考流程及程序化实测基线、依赖/缺陷归属和AI工具初始目录；不要求先取得真人操作样本。不得直接修改其他专项规则；缺口按原专项关联。
- 验收：入口可追到代码/契约和证据；未验收能力明确降级；AIN-A27/A28已有可重复基线。

### AIN-02 共用契约、身份范围、错误与事件协议冻结

- 冻结工具注册schema、认证后的执行上下文、任务/步骤状态转换表、提案/审批、结构化卡片、用量与知识引用契约。
- 后台动态展示按需求§10另行明确载荷、正式事实绑定、可编辑字段、确认请求、沙箱消息桥及资源上限合同；以同一版本关联输入、材料、Action和原收据，代码不是授权。接口冻结包含生产者/消费者、兼容回退和拒绝未知版本规则。
- 明确scope判别联合类型，tenant/platform对象不强塞workspace；请求不能自授actor或audience；输入未知字段拒绝。
- 将最终路径、HTTP方法、权限码、DTO、分页/游标、幂等请求、错误码写入shared/OpenAPI；对SSE和轮询提供同一事件模型。定义取消、未知结果、部分完成的确切语义。业务材料、模型结果及复合任务观察沿同一命名封闭契约，场景与材料相符；原task/run/input、审批、Core收据分别受权，复合读取不宣称原子快照、不启动执行，模型文本/引用/候选不充当批准或业务提交证据。
- 为后台/平台/员工/客户给出成功、拒绝、失效、断线和旧协议的契约夹具；冻结版本、生产者和消费者，规定兼容期/升级方式。
- 验收：契约校验与消费者编译通过；任何一端不维护私有同名DTO；角色与数据范围负例可测试；跨AI已确认冻结记录。

### AIN-03 任务/提案/用量/知识持久化及迁移

- 按需求§16盘点已有对象，选择复用/新增并记录字段映射；任务与run分离，审批与业务事实分别保存。
- 实现scope、owner、状态revision、actionId、请求指纹、关联业务对象、预算预留、知识版本及必要索引/唯一约束；不依赖仅应用内变量去重。
- 迁移定义字段备注、时间/币种/用量精度、敏感字段策略、历史数据默认值和安全回退。迁移文件由唯一认领人排序整合。
- AI 配置增加 `platform_managed / tenant_managed`；新租户默认平台，旧无 mode 的自定义配置按 BYOK 兼容读取，不丢加密密钥、协议、URL、模型。模式切换保留原自定义配置；损坏/不完整旧配置不可补造就绪。验证空库、旧配置升级、重复迁移、修订冲突及兼容回退。
- 交付受限仓储接口与迁移测试；验证跨租户关系拒绝、并发唯一性、删除聊天不删除业务事实，以及失败迁移后的恢复方式。
- 验收：只在预检查不存在的新`rental_os_e2e_*`库执行；空库与支持的升级路径真实通过并清理自身资源。不得操作共享库。

### AIN-04 业务共用授权入口与执行上下文

- 将适用业务权限检查放到HTTP、AI工具和Worker都可调用的应用入口；保持既有路由认证及行为，不复制易漂移的鉴权分支。
- 服务端解析tenant/workspace/audience/成员/角色/dataScope/locationScope；读历史、来源、下载与事件流同样检查。内部调用禁止回落到初始化空间。
- 每步重验撤权、冻结、订阅与政策；任务owner离职或自动化政策撤销后停止新动作，保留合法人工善后。
- 自动主体独立建模，其能力不得超出租户授权政策；客户端令牌不得进入后台/平台工具。
- 验收：AIN-A02～A04与原HTTP权限等价回归；覆盖同租户不同空间、共享会员非共享订单、地点缩权和任务恢复后撤权。

### AIN-05 真实模型网关、能力声明与凭据管理

**重点施工要求：当前模型协议开发必须为后续接入成熟开源 Provider SDK 做准备，与 Runtime 可替换性同等重视，但两者独立实施。** 当前继续复用已有协议实现，不以此要求启动 SDK 安装、迁移或全仓重构。

- 将协议编码、响应解析、流事件和 SDK 专有类型限制在现有适配层；业务场景、Runtime、公开 DTO 和预算服务不直接依赖具体 SDK，复用现有 ModelAdapter、传输端口及显式组合入口。

- 在本线切片记录中同步维护请求/响应字段、终态、错误、usage、工具标识及取消映射，受控传输注入位置、重试所有者、实际请求次数、兼容测试入口、耦合点与未来替换/回退步骤。接口变化时更新；不只写“以后可接 SDK”。

- 保持平台/BYOK 配置与凭据修订、能力准入、受控出网、唯一 dispatch 和预算单账；SDK 不得隐式使用环境密钥、全局 fetch、云代理、媒体下载、遥测、自动工具循环或未批准的重试/模型回退。

- 当前触及的代码保留可验证的请求/终态/用量证据和有限快检；实际采用时以锁定发布包验证导入、许可、运行时兼容和旧新契约差分。SDK 缺值补零、生成 ID、流内错误等行为不得改变原事实与 unknown/reconcile 语义；结果未知不切换适配器重发，不双发真实模型做对照。

- Provider SDK 可替换性落实到原 AIN-02/05/11/24 的接口、单账和验证交付，不新增正式任务或调整28项状态；已有代码与测试实际保留，后续启用与回退另行确认。

- 建立统一 Gateway → Provider Router → 平台/租户配置 → Provider Adapter；保留已有受控协议，Agent 仅提交场景与能力需求，不直接读供应商连接配置或 SDK。绑定实际配置来源、修订和模型；平台缺配置如实不可用。

- 能力检测至少覆盖 Text、Streaming、Tool Calling、Structured Output、Vision、Embedding、Reasoning，分支持/不支持/未验证及 mock/live；连接成功不等于能力支持。必需能力缺失或未验证在调用前拒绝，可选能力不授予额外权限。首期不实现复杂多模型路由或自动故障转移。

- 替换或衔接现有模拟连接测试，明确mock/真实；服务端密钥加密引用、轮换、掩码、出网限制及重定向校验。

- 实现超时、取消、限流、供应商错误映射、允许模型选择与用量回传；降级只能走预先批准的数据范围和能力。

- 复用故障夹具，对实际适配器做定向模拟冒烟，明确运输与存储替身；真实连接由负责人实测。缺凭据不阻塞研发验收，协议实现、主消费者和错误/用量处理仍须齐全。

- 验收：两轨均经过相同网关及安全/预算入口；配置修订变化、跨租户凭据和未支持协议拒绝；真实认证失败/超时/能力不足不报成功。已实现协议的真实连接、必需能力及工具往返/用量有可核对证据，mock 不替代，日志不泄密。

### AIN-06 持久化任务运行器、步骤恢复和接管

- 实现有限步骤的规划/执行循环和需求状态机；工具集合由服务端下发，澄清与授权事件分开。
- 持久化领取、租约、fencing及版本控制；崩溃后恢复同一actionId，过期worker不得继续写入。不得在模型等待期间占用业务事务。
- 重试前验证已提交业务结果；未知外部结果保持待核对，取消只停止未发出的动作；部分成功保留逐步结果和人工接管入口。
- 实现步骤/并发/时间/输出上限，接入预算检查接口；AIN-11未齐备时不得生产开放。任务事件游标可重连，落库事实先于成功事件。

### AIN-07 提案确认、授权绑定、重校验与幂等

- 实现不可变方案revision、规范化payloadHash、对象/报价/政策版本、确认人/scope/期限、拒绝及单次消费；批准动作不是模型工具。

- 提交点重验权限、价格、库存、资格、对象版本及取消状态；效果变化产生新提案，不能静默改商品或金额。

- 验收：篡改/过期/跨人/跨范围确认拒绝；重复请求返回同一事实；并发变更与故障恢复真库测试通过。

### AIN-08 经营只读工具与权威事实查询

- 封装商品、可用性、客户候选、订单事实/快照、开业检查、经营风险等最小工具；先核验现有入口，不建立任意SQL问答。
- 每工具落实schema、权限、成熟度、最大返回量、脱敏和查询时点；未交付的场景返回可解释不可用。
- 历史规则/价格/检查模板按订单适用依据读取；当前库存不可被当作历史利用率，缺成本不输出利润事实。
- 为模型提供简洁、可引用、可核对的数据，工具结果自然语言视为不可信内容。
- 验收：四品类实际差异由定义/能力驱动；越权资源、缺失历史、同名客户、无结果等用例通过。

### AIN-09 Core报价工具与四品类输入规范

- 将自然语言候选转换为待确认参数：商品/数量、客户或企业身份、开始结束时间/时区、计价与履约方式、地点；枚举由服务器解析，不开放不适用品类选项。
- 调用Core正式计价，不允许模型覆写计算结果；确认报价是否持久化并在工具风险说明标明。
- 输出分项、总额、币种、单位、规则/价格/优惠版本、有效期、查询时点及是否占用资源；报价与库存锁定不可混淆。
- 提供结构化歧义、缺项、缺货、资格、过期与当前不支持的返回值，允许用户更改后重新报价。
- 验收：四品类相同输入与人工入口报价完全一致；相对日期/时区/数量边界有确定性断言。

### AIN-10 知识文档、权限检索、来源及结构化记忆

- 复用文件上传，支持批准文档的解析、版本、生效、撤回、失败重试；先实现明确格式清单和大小/资源限制，未知格式拒绝。

### AIN-11 平台/租户AI设置、权益、预算与计量

- SaaS 管理员维护平台供应商、模型、凭据、费率、能力、限流及停用。租户默认平台 AI，只申请金额，由 SaaS 审批增加总额度，租户管理员在总额内分配空间上限；不填写供应商费率、内部场景编号或计价版本。BYOK 仅填写受控协议、Base URL、模型和写入式 Key，由供应商直接计费，平台仅记录实际 Token/调用，不扣平台金额。两轨保留原权限、场景政策、累计资源及唯一调用账本。
- 模式使用 `platform_managed / tenant_managed`；旧自定义配置保留，切平台不自动删除密钥。保存、读视图、内部凭据引用分开；修订/CAS 冲突和轮换后旧任务重校验。BYOK URL 经过与平台相同的 DNS/连接地址/重定向策略，不能用 schema 格式验证冒充出网安全。
- 场景code、提示词/模型/工具集合及政策采用版本化配置，变更有草稿差异、评测与发布/回退记录；租户只能调整明确开放字段，不能用提示词覆盖系统授权。首期不建设通用可视化Agent编排器。

- 验收：事务回滚不发事件，提交后宕机不漏可恢复事件；重复/乱序/worker接管不重复副作用，有真库故障证据。

### AIN-24 攻击/越权评测、业务评测与审计隐私

- AIN-02后即建立测试集和威胁模型，随每场景落地持续验证；记录模型/提示词/工具/数据版本，确定性业务断言与语言质量评测分开。语言评测可使用独立AI或可重复自动评测，不以真人评分为前置，也不以模型自评分代替业务正确性断言。
- 覆盖越权、提示注入、任意出网、恶意附件、XSS、过量读取、来源/缓存泄漏、审批伪造、预算竞态及任务恢复提权。

- 审计只存可核对输入摘要/计划/工具/授权/结果，不保存模型内部思维链；实现正文脱敏、敏感访问审计和分类留存/删除传播。
