## 1. 产品定位

Rental OS 是面向摄影设备、露营装备、车辆载具和工程设备等品类的多租户 SaaS 租赁平台。

- “SaaS 租户”是使用系统经营租赁业务的商户，不是租用设备的客户。
- “租赁客户”是向 SaaS 租户租用设备的个人或企业。
- 一个 SaaS 租户可建立多个经营空间；每个经营空间只经营一种设备品类，但可经营该品类下多个商品、资产、耗材和套装。
- 同一租户的客户主档共享；商品、资产、库存、地点、定价、订单、权益和经营报表按经营空间隔离。
- 平台提供一套通用租赁内核；车辆调度、TBox、工程资质、智能柜和物流等作为品类能力按需启用。
- 当前交付营运管理端和后台 API；小程序与 App 暂不开发页面，只保留独立、可版本化的客户端 API 边界。
- 旧门市租赁模块、页面、接口和数据仅作需求与实现参考；新平台不承诺兼容、迁移、投影或对账，任何新业务事实只进入 Rental Core 与通用模块。
- 车辆载具不是兼容品类，而是与摄影设备、露营装备、工程设备平级的正式品类；通用能力使用同一 Rental Core 模型，车辆专属能力通过 capability 在新模块中建设。

## 2. 角色与数据边界

| 角色 | 职责 | 数据范围 |
| --- | --- | --- |
| SaaS 平台管理员 | 创建租户、治理经营空间开通、冻结或停用租户、查看平台审计 | 仅平台管理面，不自动获得租户业务数据权限 |
| 租户管理员 | 配置本租户经营空间、组织、账号和权限，可进入本租户全部经营空间 | 当前 SaaS 租户及其全部经营空间 |
| 经营空间管理员 | 配置所在空间的品类规则、价格、营销、通知和业务数据 | 被授权的经营空间 |
| 租户运营人员 | 管理商品、资产、库存、地点、客户、订单和履约 | 被授权的经营空间、角色与组织数据范围 |
| 租赁客户 | 注册、获取报价、下单、支付、领取和归还 | 本租户共享客户身份及自己在目标经营空间的订单与权益 |

必须满足：

- 请求中的租户身份只能来自已验证会话，不能信任客户端提交的 `tenantId`。
- 租户业务请求中的当前经营空间必须来自服务端验证过的会话上下文，不能信任客户端提交的 `workspaceId`。
- 缺少租户身份时必须拒绝访问，不得回退到演示租户。
- 平台管理员和租户管理员的权限模型必须分离。
- SaaS 平台路由不得出现在普通租户菜单中，普通租户也不得通过直接 URL 或 API 访问；SaaS 平台管理员只进入平台管理路由，不自动进入租户营运路由。
- 同一客户在不同 SaaS 租户下的数据、权益和优惠券相互隔离。
- 同一租户内共享客户主档；订单、优惠券、积分、会员等级和营销余额默认按经营空间隔离。
- 租户冻结或停用后，其账号会话立即失效；历史订单、资金和审计数据不得物理删除。

## 3. 经营品类模型

经营品类在经营空间创建时确定。经营空间产生商品、资产或订单后，不允许通过普通设置直接切换品类；变更品类必须新建经营空间或执行显式数据迁移。

层级模型：

```text
SaaS 租户
├─ 经营空间 A（唯一品类：摄影设备）
├─ 经营空间 B（唯一品类：露营装备）
└─ 租户账号通过成员关系进入一个或多个经营空间
```

- 经营空间是业务隔离边界，不替代 SaaS 租户；所有经营事实同时包含 `tenantId` 和 `workspaceId`。
- 租户管理员默认可进入本租户全部经营空间；普通账号只能进入明确授权且启用的经营空间，并可在不同空间拥有不同角色和数据范围。
- 一个业务会话只能有一个当前经营空间。右上角切换空间时，服务端必须重新校验成员资格并刷新会话上下文。
- 切换后必须取消旧请求、清空旧空间业务缓存并重新加载菜单、权限、品类和 capability；目标页面不适用于新空间时返回该空间工作台。
- 当前阶段不建设跨空间订单、收入、库存或客户消费汇总；未来汇总只能基于明确的租户级查询权限实现。

| 品类 | 典型库存 | 主要资产字段 | 使用量 | 履约地点 | 专属能力示例 |
| --- | --- | --- | --- | --- | --- |
| 摄影设备 `camera` | 序列化资产、套装 | 厂商、型号、序列号、快门数、镜头卡口、套装组件 | 快门数、使用时长 | 自营门店、合作商、仓库、寄送点 | 套装拆分、配件清点、损坏免赔 |
| 露营装备 `camping` | 数量库存、套装 | 厂商、型号、规格、尺码、容量、清洁等级 | 天数、损耗等级 | 门店、仓库、自提点、合作商 | 数量预占、套装缺件、清洁费 |
| 车辆载具 `vehicle` | 序列化资产 | 厂商、车型、车牌、VIN、里程、能源类型 | 里程、租期 | 车行门店、取还车点、停车场 | 调度、异地还车、TBox、驾驶资质 |
| 工程设备 `construction` | 序列化或数量库存 | 厂商、型号、设备编号、工时、吨位、检验证照 | 工时、班次 | 设备基地、项目现场、交付点 | 操作资质、运输、维保和安全检查 |

品类定义必须同时决定：

- 业务术语和动态字段 schema；
- 序列化、数量和套装库存能力；
- 可使用的计价单位、使用量指标和押金规则；
- 领取、归还和检查模板；
- 菜单、页面、API 与集成 capability；
- 报表指标和异常规则。

Rental Core 的扩展结构必须保持为：

```text
Rental Core
├─ 通用商品、资产、库存
├─ 通用报价、订单、预占、履约
├─ 品类定义注册
├─ 计费策略注册
└─ Capability 扩展模块
```

新增品类和计费模型必须满足以下兼容规则：

- 新品类通过新增品类定义接入，定义业务术语、字段、库存模式、地点、检查模板、默认规则、支持的计费单位和 capability；不得在通用报价、订单、库存或履约主流程散落品类编码分支。
- 新计费模型通过独立计费策略接入，由统一报价入口调用；策略负责计费单位数量与金额计算，既有策略不因新增模型而修改。
- 品类独特功能通过 capability 模块建设。车辆的调度、驾驶资质、TBox、里程和异地还车属于 vehicle capability；其他品类可拥有自己的检查、清点、清洁、缺件、运输、维保等模块。
- 新增品类可以新增代码和数据库迁移，但必须是增量扩展，不要求运行时无代码配置；扩展不得改变既有品类的定义、报价结果、订单状态机和数据边界。
- 启动和自动测试必须校验：品类引用的计费策略与 capability 均已注册、默认值属于品类支持范围、品类编码不重复。

前端动态文案不能代替后端数据模型。页面隐藏不是权限控制，后端必须按当前经营空间的品类、capability 和成员权限再次校验。

## 4. 功能需求

### 4.1 SaaS 租户、经营空间与组织权限

- 平台管理员可创建、编辑、冻结、恢复和停用 SaaS 租户。
- 平台管理员可在平台管理面查看目标租户的全部经营空间，并新增空间或编辑空间名称与状态；空间品类创建后不可直接修改，平台治理空间不等于获得空间内经营数据权限。
- 初始化租户必须在同一事务内创建租户档案、首个默认经营空间及其唯一经营品类、根组织、首个履约组织、默认角色、权限、首个管理员、编号规则和审计记录。
- 初始化失败必须整体回滚；临时密码只在初始化响应中返回一次，并强制首次登录修改。
- 租户管理员可新增、编辑、冻结和停用经营空间；新增空间必须原子创建空间档案、品类配置、默认角色、编号规则和审计记录。
- 租户可维护组织、账号、经营空间成员关系、角色、按钮权限和数据范围；同一账号可进入多个经营空间。
- 资源查询与写入必须在数据库层同时附带租户、经营空间及数据范围条件；租户共享主档除外，但仍必须附带 `tenantId`。

### 4.2 商品、资产与库存

- 商品组描述可租产品及其品类字段、库存模式、默认检查模板和定价引用。
- 序列化资产必须独立追踪资产编号、序列号、状态、所在地点、使用量、维保和事故。
- 数量库存必须按地点记录可用、预占、在租、维修和报损数量。
- 套装必须维护组成、数量、可替代组和拆分规则。
- 套装替代组必须有且只有一个默认组成，并至少有一个替代候选；订单确认后、配货前可在同组内替换，替换时必须重新校验目标库存。
- 配货必须记录实际分配的商品组和资产或数量，不能只保留套装父商品；部分归还只释放本次归还的实际组成与数量，剩余部分继续在租。
- 最后一批归还必须进入整单归还或归还检查，以统一计算逾期、缺件、损坏和清洁等异常费用。
- 资产状态变化必须写流水并影响可用性；停用、维修或已占用资产不得再次分配。
- 商品与资产字段由品类 schema 驱动，服务端校验必填项、类型和唯一约束。

### 4.3 经营主体与履约地点

- 经营空间可维护自营经营主体和合作商，并配置结算方式和启停状态。
- 地点统一抽象为履约地点，可表示门店、仓库、自提点、寄送点、停车场、项目现场或智能柜。
- 地点可配置支持的领取、归还、配送、跨点归还和营业能力。
- 订单必须保存创建时的主体、地点和履约方式快照，后续主档变更不能篡改历史订单。

### 4.4 定价、优惠与增值服务

服务端是最终报价事实源。前端只提交商品、数量、租期、地点、客户、优惠券和服务选择，不提交最终应付金额。

报价公式：

`最终应付 = 基础租金 + 使用量费用 + 履约费用 + 增值服务 + 异常费用 - 优惠方案 - 优惠券`

同时独立计算：

- 应付押金；
- 预授权金额；
- 已支付、待支付和可退金额。

定价必须支持：

- 小时、自然日、24 小时、周、月、班次和使用量等计价单位；
- 最小租期、进位、阶梯价、封顶价和超额使用费；
- 工作日、周末、法定节假日和特殊日期价格；
- 商品、套装、地点、会员等级和客户类型适用范围；
- 固定押金、租金倍数押金、预授权或免押；
- 发布版本、有效期、优先级、冲突校验和报价快照。

优惠与服务必须分离：

- 优惠方案按条件自动计算折扣；
- 优惠券包含领取、锁定、核销、释放、过期和作废状态；
- 增值服务独立计价并保存条款快照，例如保险、配送、清洁、操作员和损坏免赔；
- 优惠不得使不允许为负的费用项变成负数。

### 4.5 营业日历

- 经营空间可设置每周工作日、周末、临时营业、临时关闭和特殊日期。
- 系统支持导入带来源、发布日期和版本的中国大陆法定节假日数据。
- 官方日历导入后必须人工发布，经营空间可在本空间范围覆盖。
- 报价必须保存命中的日历版本和日期类型，跨年度订单可复算。

### 4.6 租赁规则

经营空间可按品类配置并发布规则版本：

- 支付时点、支付比例、押金、预授权发起和释放；
- 待支付订单保留时间；
- 领取、归还、配送和跨地点履约；
- 取消、爽约、提前归还和延期；
- 超时宽限、逾期费用、异常扣款和人工复核；
- 身份、驾驶、操作、企业或其他资质；
- 损坏、缺件、清洁、维修、停运和免赔。

订单创建时必须保存规则快照。取消、逾期和损坏费用只能由服务端依据订单快照计算，并进入最终应付和审计链。

### 4.7 报价与订单

标准流程：

`报价草稿 → 有效报价 → 创建订单 → 待确认/待支付 → 已确认 → 预占 → 配货/分配 → 已领取 → 已归还 → 待结算 → 已完成`

异常终态包括取消、爽约和关闭。

- 一个订单支持多行、多数量、序列化资产、数量库存和套装。
- 报价必须有有效期且只能按约定次数使用；订单保存价格、规则、日历、优惠和服务快照。
- 确认订单时锁定库存与优惠券；取消或失败时释放资源。
- 配货将商品需求分配到具体资产、地点库存或套装组件。
- 领取和归还按品类检查模板执行；异常进入费用、维修、报损或人工复核。
- 关键动作必须幂等，并写状态事件、操作者、原因和审计记录。

### 4.8 会员、注册与邀请奖励

- 经营空间可配置新会员注册、实名认证和首单完成赠礼。
- 邀请关系必须记录邀请人和被邀请人；双方奖励可独立配置触发点和金额。
- 奖励支持积分、营销余额和优惠券；营销余额不是可提现或储值资金账户。
- 奖励发放必须幂等、可撤销、可审计，并受每人上限、活动预算和防刷规则约束。
- 客户基础身份、联系方式、企业资料和基础实名认证在 SaaS 租户内共享；品类资质保存为共享客户资料，但按目标经营空间的品类规则判断适用性。
- 会员等级、权益账户、优惠券和奖励流水默认按 SaaS 租户及经营空间双重隔离，不自动跨空间使用。

### 4.9 通知模板

- 经营空间可按订单确认、待支付、领取提醒、逾期、归还、取消、退款、审核、奖励和资产异常等事件配置通知。
- 模板必须定义渠道、变量 schema、版本、启停状态和适用事件。
- 发送记录保存模板版本、脱敏目标、状态、失败原因和业务对象。
- 真实短信、邮件、微信和 App Push 通过 provider adapter 接入，必须支持幂等、重试和回执。

### 4.10 报表、审计与平台治理

- 经营空间报表至少覆盖订单、收入、库存/资产利用率、地点经营、客户、优惠和异常。
- 当前阶段报表和导出只能查询当前经营空间，必须使用会话中的租户、经营空间和数据范围，不能接受客户端覆盖。
- 跨经营空间汇总报表暂不开发；数据模型需保留未来按租户汇总的可能性，但不得提前开放绕过空间权限的查询。
- 平台审计与租户业务审计分开；关键配置发布、订单动作、费用变化和权限变化必须可追溯。
- 导出、附件、打印、异步任务和外部 adapter 不单独扩成泛化后台，只围绕已确认业务场景提供能力。

### 4.11 小程序与 App API

- 客户端 API 必须与后台运营 API 分开版本、认证和权限。
- 客户端必须明确目标经营空间；服务端按目标空间状态、品类和客户关系校验，不能把后台当前空间会话直接复用为客户授权。
- 必须支持客户注册登录、商品查询、可用性、报价、下单、订单查询、优惠券、通知和履约信息。
- 发布前必须补齐客户身份认证、签名、限流、幂等、回调验签和字段级 OpenAPI 契约。
- 当前后台运营 token API 不得直接暴露给小程序或 App。

## 5. 非功能要求

- **租户与空间隔离**：经营业务事实同时包含 `tenantId` 和 `workspaceId`，数据库查询默认 fail-closed；租户共享客户主档只按 `tenantId` 共享。
- **一致性**：订单、库存、优惠券和价格事实的关键写入使用数据库事务。
- **并发**：库存预占和优惠券锁定必须防止超卖与重复核销。
- **幂等**：支付、回调、订单状态动作、奖励和通知均需业务幂等键。
- **可追溯**：金额、规则、日历、服务和优惠保存版本快照。
- **安全**：密码只保存强哈希；仓库和文档不得保存真实或测试明文凭据。
- **历史参考**：`/store-rental/*` 不属于新平台产品接口；不得作为新页面、数据迁移、兼容 facade 或验收依据。新业务统一进入 `/rental/v1/*`。
- **可恢复**：数据库迁移必须同时验证空库部署和已有库升级，不允许静默丢数据。

## 6. 核心验收

| 场景 | 验收结果 |
| --- | --- |
| 租户隔离 | 两个 SaaS 租户不能通过列表、详情、导出、动作或并发请求访问对方数据；缺少租户身份直接拒绝 |
| 经营空间切换 | 同一账号可切换被授权空间；未授权或停用空间被拒绝；切换后菜单、品类、权限和缓存立即更新 |
| 空间隔离 | 同一租户的两个经营空间不能读取或修改对方的商品、资产、库存、地点、定价、订单、权益和报表数据 |
| 客户共享 | 同一客户在同租户不同空间复用唯一客户主档；订单和权益仍归属各自经营空间 |
| 品类一致性 | 摄影、露营、车辆和工程经营空间分别获得正确字段、库存、地点、定价、检查和菜单能力 |
| 服务端报价 | 相同输入可复算；订单可追溯价格、规则、日历、优惠和服务来源 |
| 库存一致性 | 并发确认不会超卖；取消、失败和归还正确释放资产、数量和套装组件 |
| 优惠与权益 | 优惠券锁定/核销/释放正确；注册和邀请奖励幂等且按租户与经营空间入账 |
| 订单履约 | 多行订单可完成确认、配货、领取、归还、异常费用和结算闭环 |
| 数据恢复 | MySQL 模式重启后订单、占用、费用、权益和审计不丢失 |
| 迁移安全 | 空库可全量部署；已有库升级前后的业务记录数量和关键字段一致 |
