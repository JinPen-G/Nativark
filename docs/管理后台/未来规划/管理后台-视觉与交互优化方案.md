# 管理后台视觉与交互优化方案

版本：v0.2。编制及更新日期：2026-10-16。

本文保留方案编制时点的设计建议；后续已采用的公共约定见[界面规范](../../公共技术资料/界面规范/管理后台-界面规范.md)，实施证据见[开发记录](../管理后台-开发记录.md)，不在未来方案中另写施工进度。

文档性质：供负责人评审的设计方案。参考方向和首轮样板已在对话中确认，具体设计、效果选型和新增交互能力仍以本方案评审为准；形成文档不等于授权开发、安装依赖或全站推广。

适用范围：租户管理后台全部角色，以及 SaaS 平台管理端。四个经营空间共用视觉与交互规则，业务术语、可用能力和权限仍由各自正式定义决定。

## 1. 目标与边界

### 1.1 要解决的问题

保留 UIArc 组件，把后台从“菜单、数据表和长表单的集合”调整为清楚、自然、有响应的业务工作空间。

- 浏览时，用户不必面对每个功能都一样的表格；可以直观看到对象、差异、状态和需要处理的事情。
- 操作时，不必默认展开全部输入框；先理解当前内容，需要时再编辑相关部分。
- 页面切换、内容出现、加载与操作结果具有连续感，不突然跳变、不靠动画增加等待。
- 错误在对应任务和字段附近解释，重要失败不依赖顶部或右下角短暂消息。
- 新用户知道从哪里开始，熟练用户可以直接操作；不用 AI Native 也能正常完成工作。
- 样板最终提炼为共享排版、交互和动效约定，不逐页自由发挥。

“现代化”不是背景视频、渐变、玻璃和弹跳越多越好，也不是继续沿用传统后台模板只换圆角。目标是产品感、信息组织和实际操作体验同时改善。

### 1.2 本轮明确不做

- 不替换现有 UIArc 基础组件，不修改其原始样式、弹簧或动画路径来仿造其他效果。
- 不改订单、会员、资金、库存、价格、规则发布等业务判断和接口语义。
- 不启动跨页面配置任务引擎、统一暂存/一键生效机制、低代码平台或 CRM/TMS 通用底座。
- 不重做表格本体的外观、列结构、排序和行级动画；订单表格继续作为现有承载体。
- 不强制所有页面卡片化、向导化，也不为每页增加表格/卡片/看板切换。
- 不新增自动保存到服务器、批量操作、拖拽业务状态、撤销交易等能力来包装视觉效果。
- 不安装 Taste Skill、Impeccable、Animate UI 或 Solid Glass，不下载付费素材、不登录外部服务。本方案列出候选和准入要求，实际引入另行确认。
- 不创建独立演示站，不代替负责人登录或操作浏览器。本轮只形成文档。

前面三个案例共同构成具体视觉参考；Impeccable/Taste 是设计方法，Animate UI 是区域动效候选，Solid Glass 是材质设计参考。它们不是七套可同时启用的主题，也不是同一种成熟程度的成品。

MotionSites 对上述案例提供公开预览和结构化提示词，不能称为已取得完整后台源码。Modern HR Dashboard 标注付费；Task Engine 和 Aurora Onboard 也需按各自条目核实访问与使用许可。本轮不绕过许可、不购买或复制受限内容。

本方案不以 Fluent、Carbon、SAP Fiori 作为主视觉方向。用户已明确希望参考更有当代产品感的具体作品，而非传统企业后台外观。

### 2.3 统一方式

1. UIArc 原组件负责控件本身的质感；不把其他来源的按压、滑块、阴影再覆盖到它上面。
2. Modern HR Dashboard 作为页面编排的主要方向，Task Engine 补充工作区域的组织参考；按当前真实数据和操作重构，不像素照搬营销展示。
3. Aurora Onboard 保留为后续登录/进入体验参考，不因列入方案就重做已有登录页。
4. Impeccable/Taste 作为审查辅助，服从既有品牌、组件、业务和本方案，不能反过来改写这些边界。
5. 新增区域级动效只从审核过的有限清单选择，通过共享入口使用；不每页再挑一套动画库。
6. Solid Glass 补充浮层与内容容器的表面层次，不能接管 UIArc 控件及原动效。先明确材质边界和 token 映射，再评审样板，不把整张主题样式表全局导入。

## 4. 全局视觉与排版

### 4.1 阅读层级

一个页面先让用户理解“在哪里、当前有什么、可以做什么”，再进入细节。

| 层级 | 内容 | 表现方式 |
| --- | --- | --- |
| 页面定位 | 当前功能、简短用途、主要动作 | 复用统一 PageHeader，不重复增加品牌宣传式大标题 |
| 工作上下文 | 视图分类、筛选、当前条件、必要状态 | 与操作内容靠近，不挤占标题 |
| 主要内容 | 订单、方案、设置摘要、待办 | 按业务选择清单、表格、分栏、对比等 |
| 辅助信息 | 解释、历史、少用操作 | 分组、折叠、侧窗或原有说明入口；必要警告不能藏起来 |

每个操作区域应有清晰主操作；多个独立模块可以各有主操作，不机械限制整页只有一个。危险操作保持单独辨识，不伪装成普通装饰按钮。

### 4.2 容器与密度

- 通过对齐、留白、分组标题和分隔建立层级，不给每组字段都额外套卡片。
- 用卡片表达独立对象、可比较方案或独立任务，不把表格每一行原封不动塞进卡片。
- 订单等高频查询保持紧凑；规则、说明和资料编辑适当舒展。统一的是密度档位，不是所有控件强制等高。
- 输入、选择、搜索遵循原组件设计和明确的尺寸语义；同一工具条对齐，不用全局高度覆盖破坏原组件。
- 内容有长短时自然布局，不用拉高所有容器制造大片空白；固定高度只用于明确需要稳定尺寸的场景。
- 圆角、字体、阴影、颜色和间距从共享 token 读取；本方案不另定一组逐页像素值。

### 4.3 品牌、主题与适配

- 保留当前后台主色配置、租户分组圆角及历史回退；当前代码为账号后台主色与租户客户端品牌色独立。早先“跟随租户主题色”的诉求与现状不同，本轮不借视觉方案改变归属或宣称已满足。不强加参考案例的黄、紫或深色。
- 品牌色用于主要动作、当前选中与焦点；状态色继续表示业务状态，不能一并染成品牌色。
- 深浅色分别检查文本、辅助说明、禁用、错误和弹层层级，不是简单反相。
- 不新增单页字体和图标库；图标不能成为每个标题前重复的彩色装饰块。
- 保留中英文与长文本适配，不能用截断掩盖关键状态和错误。
- 保留已确认的导航响应方式：宽屏正常展开，中等桌面宽度收起为图标，移动尺寸才隐藏；不借改版重置为同一种行为。
- 双栏在空间不足时合理转为单栏或沿用现有详情入口，不强塞窄屏；交互内容、焦点和操作不能丢失。

### 4.4 Solid Glass：浮层与内容容器的材质方案

负责人已确认浮层和内容容器都纳入考虑，但具体强度和落点尚待样板评审。Solid Glass 不是新增整套皮肤：布局仍沿前三个案例，控件和原动效仍归 UIArc；此处只补充共享表面层次。

上游将材质分为 panel、card、popover 三种厚度，层越浮起越厚实；质感主要来自边缘高光、细线与阴影，而不是大面积折射。以下是本项目的应用建议，并非上游已提供的后台业务方案。[材质依据](https://github.com/deeplethe/solid-glass/blob/main/content/docs/material.mdx)

| 场景 | 建议材质与处理 | 必须保持 |
| --- | --- | --- |
| 页面工作区 | 稳定中性底面，保持清楚的内容承载 | 不整页透明，不加动态背景 |
| 设置摘要、会员方案摘要等内容容器 | 评审轻量 panel/card 层次，区别主次和独立对象 | 不重新把每组字段套进玻璃卡片 |
| 帮助、账号菜单、下拉、抽屉表面 | 评审较厚、较不透的浮层材质 | 原控件的尺寸、焦点、圆角、按压与开合效果不变；公开适配点不支持时保持原样 |
| 密集文字、资料编辑、错误与重要状态 | 优先不透或近不透的承载面 | 清晰度优先，警告不能混进装饰 |
| 订单表格 | 本轮不处理 | 表头、行、固定列、悬停与行内控件不套新材质 |

兼容策略：

- 原主题源码面向 shadcn/Tailwind，包含全局变量、选择器和深色 class 约定；不能直接导入覆盖 UIArc 的同名 background/accent/radius。只在现有后台主题/适配层评审所需表面语义，使用受限作用域，不另建第三套基础控件。[主题源码](https://github.com/deeplethe/solid-glass/blob/main/src/solid-glass.css)
- 新材质如确需增量 token，仅补充现有体系缺失的表面厚度、边缘和阴影语义；复用当前字体、颜色和圆角来源。具体名称与数值在实施选型时固定，不让页面自由填写 blur、透明度或阴影。
- 不叠加按钮/输入/页签的双边框、双阴影、双焦点环；如果必须改变原组件效果才能成立，该处不启用材质，不能反过来修改 vendor。
- 深浅色分别评审；遵循系统减少透明效果偏好，提供不支持 backdrop-filter 或性能不适宜时的不透替代。不能把减少动态效果与减少透明效果混为同一开关。
- 有模糊的容器要核对层叠上下文、弹层定位和滚动性能；避免整个长页面、所有嵌套面板同时模糊。没有真实浏览器体验前不宣称已经协调。
- Solid Glass 自有的“运行才动”状态语言仅作材质系统背景，不取代本方案的导航、路由和交互动效；UIArc 原交互仍保持。其 AI/Agent blocks 本轮不接入，不扩展已搁置的引擎。

## 5. 展示与编辑模式库

这些是少量可复用模式，不是每页必须开启的视图菜单。每页先选择一个默认方式，再判断是否真的需要辅助方式。

| 模式 | 用于解决什么问题 | 适用边界 |
| --- | --- | --- |
| 表格 | 精确查询、同字段密集比较、流水与批量核对 | 金融和操作明细继续保留；本轮不重做表格本体 |
| 分组清单 | 快速扫描对象、用途和状态 | 营销方案、模板、设置项，不强制画表格网格 |
| 主从分栏 | 连续查看多个对象，保留列表上下文 | 需已有详情与权限接口；不默认新增双份详情逻辑 |
| 方案摘要与对比 | 识别方案差别 | 比较共同权益及适用范围，不凭空增加价格、销量和推荐档位 |
| 图文目录/画廊 | 通过真实图片或内容预览识别对象 | 适用于商品、品牌素材；无图片不制造大片空位 |
| 看板 | 按业务阶段处理工作 | 不是所有状态都适合列；拖拽状态变更须另行确认 |
| 日历/时间轴 | 理解排期和持续时间 | 必须有真实时间数据、时区和权限；不因有日期就加日历 |
| 任务工作台 | 确定下一项工作 | 依赖既有待办和状态，不伪造优先级、紧急度或完成度 |
| 设置摘要＋展开编辑 | 浏览当前配置，减少满屏输入框 | 保留现有保存/发布边界，不把“保存草稿”改称“已生效” |
| 编辑与预览并排 | 理解内容修改的展示效果 | 预览明确标识；缺真实渲染器时不冒充客户端像素级预览 |

编辑遵循四条原则：默认先看内容、只编辑相关分组、有关联约束的字段一起处理、保存前能理解修改结果。低风险独立字段才考虑就地编辑；资金、权限、规则版本不默认失焦即提交。

## 7. 首轮三个样板

以下是实施前的设计目标，不是新需求编号或施工任务表。

### 7.1 订单管理：把查找过程组织好，不动表格本体

推荐顺序：统一页头与新建操作 → 分配分类 → 搜索/租期/状态 → 待审费用筛选及口径 → 当前结果与现有表格。

- 保留当前分配分类、搜索、日期、状态和待审费用条件，不删功能来制造简洁感。
- 搜索继续遵循现有提交时机，不擅自改成每个字符都请求；筛选变化回第一页。
- 待审费用计数目前是当前空间总数，不随列表条件变化，必须解释口径，不能摆成筛选结果数。
- 现有 keepPreviousData 保留；刷新时说明正在更新，不闪空白，也不能让旧数据看起来已经对应新条件。
- 同步调整工具条分组、对齐、换行和必要说明，避免分类、附加条件和普通筛选三套控件各占一块空白。
- 页面入场可使用一个共享 Fade；后续筛选/翻页不重复播放整页入场，不给每一行追加动画。
- 快速预览只列为候选增量，首轮可继续使用原详情跳转。不得为预览复制客户敏感数据或绕过订单权限。
- 表格列、固定列、排序关闭状态、金额/币种、续租后归还时间、分页与服务端查询全部保持。
- Solid Glass 只评审表格外工作区及辅助浮层的表面层次，不改变表格本体和原筛选控件。

### 7.2 品类与业务规则：摘要可读，编辑有边界

推荐顺序：统一页头 → 现有权限 Tab → 当前分区摘要/版本状态 → 分组编辑 → 本分区操作及反馈。

- 保留“品类与租赁方式、业务规则、营业日历、会员奖励规则、通知模板”的现有权限派生逻辑。
- 不是进入就把全部分区表单摊开；优先呈现当前值、适用范围和需要注意的说明，再进入相关编辑组。
- 字段间存在约束时共同编辑，不把依赖字段分成若干个互相独立的即时提交。
- 每个 Tab 保持独立的保存与发布机制；不新增“一键发布全部”，不重建已暂停的关联配置机制。
- 展开编辑可以候选使用原 Auto Height；原 Tab 滑块、按钮和抽屉继续使用 UIArc 效果。
- 错误汇总位于本分区操作区域，能打开并定位真实出错字段；切换 Tab 前的未保存处理须先核对现有表单保活/销毁行为。
- 未建立可靠跨页面草稿前，只能说明本次会话的未保存状态，不能写“已自动保存、下次继续”。
- Solid Glass 用于摘要与编辑承载面的轻重区分；主要填写面保持可读，不额外给每个字段包玻璃卡片。

### 7.3 会员方案：让人先理解权益，再编辑字段

默认建议：按个人/企业等现有目标类型组织紧凑的方案摘要。方案对比是辅助候选，不强制所有方案并排，不硬套三档价格卡。

每个方案摘要应清楚表达：名称、目标会员、等级排序、权益概述、适用范围、当前版本状态及实际可执行操作。草稿与已发布版本分开表达，不只显示一个模糊的“正常”。

- 主要阅读区域用于权益，不把编码、内部 ID 和所有按钮放成同等视觉权重。
- 编辑沿用原业务表单，基础资料、权益、范围和叠加规则按组组织。新增权益后定位到新条目，不使整页抖动。
- 展开更多权益可采用共享展开效果；若现有 UIArc Accordion 已满足，不再套一层 Auto Height。
- 草稿保存、发布、停用、基于历史生成新草稿保持不同动作；界面不得把恢复历史写成覆盖已发布版本。
- 方案对比只比较字段和已支持的权益；缺少资料明确表示，不能算出不存在的性价比或推荐评分。
- 数量较多时保持搜索、分页和分组；不要求一屏展示全部方案。若改用非表格展示，应保留原数据访问与查询能力。
- 不做购买套餐、营销宣传海报、销量排行榜，不改变租户统一会员及权益范围。
- Solid Glass 可用于方案摘要的低强度材质层次；展开编辑仍沿原控件，不引入悬浮海报或夸张反光。

## 8. 动效方案与原源码边界

### 8.1 动效选择表

| 场景 | 首选来源 | 建议使用方式 | 禁止/限制 |
| --- | --- | --- | --- |
| 按钮、Tab、分段、菜单、抽屉、确认动作 | 当前 UIArc 组件 | 原效果原参数，修宿主干扰而非改动画 | 不叠 Animate UI，不重写共享滑块 |
| 路由主体首次进入 | Animate UI Fade 候选 | 只作用于主要内容，导航保持稳定 | 需核对原组件是否支持目标生命周期；不能把进入效果冒称完整路由退出能力 |
| 局部新内容到达 | Animate UI Slide/Fade 候选 | 仅有明确来源和方向关系的工作区域 | 不全站默认大距离滑动；不逐个表格行播放 |
| 条件字段、设置编辑区展开 | 原 UIArc Disclosure/Accordion 优先；不足时 Auto Height | 只选一个负责高度的组件 | 不给固定高度登录区解锁高度，不嵌套高度动画 |
| 加载与数据替换 | 当前共享加载/QueryState 入口 | 保持结构和状态连续，必要时局部轻量接替 | 不伪造百分比、设置人为等待或全屏反复闪白 |
| 保存/执行结果 | 原 SaveButton/ActionButton 及就地状态 | 等待真实 Promise，失败保留内容 | 不用定时器模拟成功，不让失败被 catch 后当成功 |
| 错误出现/定位 | 当前字段反馈与共享错误区 | 明确文字＋必要聚焦/短暂强调 | 不依赖抖动、闪烁或单一颜色；不打断正在输入 |
| 深浅色切换 | 现有主题切换实现 | 保留当前默认与既有可选效果 | 不让路由层过渡同时参与主题扫屏 |
| 空态和成功页 | 原有共享状态组件 | 内容简洁，出现一次，保留明确操作 | 不加循环庆祝、强制声音和品牌宣传动画 |

“候选”不代表已经安装或选定原参数。UIArc 原组件效果与宿主新增效果分层管理；不存在的交互不能用效果库补成假业务能力。

### 8.2 原源码接入规则

1. 实施前读取候选原源码、许可、依赖、API、默认动效及 reduced-motion 行为，确认能用于当前 React/Motion 环境；不能只看预览就复制。
2. 能直接复用就复用原实现，业务适配放外层；不凭印象手写一个“差不多”的 Fade/Slide。必要配置只能使用原公开 API，并记录原因。
3. 下载文件、上游版本/固定提交或内容哈希、许可和引用位置形成来源记录；不把只改清单哈希当作恢复原效果。
4. 如遇真实 bug，先证明是上游问题还是 transform/filter、滚动、overflow、z-index、全局 CSS、重复动画或布局变化造成；优先修宿主。
5. 必须修改上游时单独说明差异、原因与回退方式，经确认后最小修改，不静默改原版观感。
6. 不用全局 CSS 覆盖所有 transition/transform，不在新父容器上对原 UIArc 交互重复施加布局动画。

### 8.3 防止“又做得不统一”

拟在现有后台适配层内维护一份小型动效注册清单，不建设通用流程引擎。语义可采用“页面进入、内容到达、区域展开、结果反馈”，具体名称待实施时与现有导出核对。

每个条目记录：来源、用途、允许公开参数、上游默认值、使用场景、减少动态效果的替代方式、兼容限制和消费者。页面只能引用条目，不自行创建时长、曲线、位移、弹簧或动画包。

不另造第二套数值 token：优先复用现有 UIArc Motion/CSS tokens；Animate UI 独有配置集中保留其原默认或已评审的公开设置。语义入口统一不等于强行把两个库所有弹簧调成同一个值。

同一时刻一个区域只有一个主要动效负责人。导航、内容、弹层分别拥有稳定边界；筛选更新不重挂整个工作区，切换租户/空间则必须保持原重挂与清缓存隔离。

### 8.4 舒适度、性能和稳定性

- 不锁住普通导航等待动画完成，不增加为了看效果的延迟；请求动作的防重仍由真实异步状态与服务端共同控制。
- 支持系统减少动态效果设置；若上游没有适当处理，在外层提供静态渲染分支，不改 vendor 动画。字段和错误仍可被理解与访问。
- 大部分新增过渡优先不改变布局；原 Auto Height 的布局开销只在局部使用，避免大量区域同时测量。
- 中文/英文切换、错误出现、浏览器缩放、窄窗口、重复切换和长内容都不能让滑块走弯、容器裁切或内容重叠。
- 不在所有内容区常驻 filter/transform；有原版效果要求时，核查其层叠上下文、浮层定位与裁切。
- 音效沿用现有全局机制与用户设置，新效果组件不再重复播放；重要状态不能只用声音表示。

## 9. 填写、提醒和轻量引导

### 9.1 填写过程

- 标签说明字段是什么，必要帮助解释为什么需要及如何填写；必须知道的信息不只藏进 Tooltip。
- 第一次输入不过早满屏报红；离开字段或明确提交时校验，已经报错后随修改及时更新。具体时机沿字段业务规则统一确定。
- 长表单按含义分组，短表单直接完成，只有真实先后依赖才分步骤；不把所有输入变成聊天或一题一屏。
- 提交校验失败时保留值，展开相应区域，再定位字段。错误在不可见 Tab 时先打开正确 Tab；不要只滚动到仍被隐藏的 DOM。
- 浏览时显示已保存内容，编辑中显示未保存状态；不得将本地未提交数据标成草稿已入库。
- 涉及权限、金额、收款、发布、库存状态的操作，沿原正式动作完成，不采用失焦自动提交。

### 9.2 反馈分级

| 状态 | 主要反馈位置 | 持续与恢复 |
| --- | --- | --- |
| 字段错误 | 字段附近 | 修改后重新校验，明确修正方法 |
| 多字段校验失败 | 当前表单操作区附近＋错误汇总 | 保留到修正，可定位具体字段 |
| 业务阻断 | 对应商品、规则、权限或报价区域 | 显示服务端原因及真实可用动作 |
| 网络/服务失败 | 当前任务区域 | 保留内容；只读读取可重试，写入须按结果状态决定 |
| 操作中 | 原操作按钮＋相关区域 | 不清空界面，不伪造完成进度 |
| 普通成功 | 原按钮或原操作区，可辅以轻量消息 | 不用强制弹窗，只有真实成功才展示 |
| 结果未知 | 原任务区域的持续状态 | 提供核对入口，不把超时认作失败后盲目重发 |
| 权限不足 | 对应入口/操作处 | 解释限制；不泄漏无权访问的数据或指引越权 |

页面级反馈通过共享入口统一，不能每页再决定是顶部 message、右下角 Toast 还是居中弹窗。同一错误不同时触发字段、汇总、Toast 三次重复播报；屏幕阅读器 live 区域与焦点管理需要一并检查。

### 9.3 轻量进入引导

- 首次进入陌生功能时，用简短用途说明、真实空态与明确起点提供帮助；熟练用户可跳过，不强制全屏菜单教学。
- 已有开业配置沿现有 readiness 组织；不要把本次视觉方案扩展为新的依赖图和联合发布机制。
- 空态区分确实无记录、筛选无结果、无权限、读取失败与尚未配置；每种只展示实际可用动作。
- 不可用按钮说明真实原因；必要说明必须支持键盘/触屏读取，不只依赖 hover。
- 真正的跨会话引导完成记录、草稿恢复和协作接手涉及持久化，需要另行确认，不用 localStorage 假装服务端能力。

| 层次 | 复用职责 | 不承担的职责 |

## 12. 样板验收检查表

以下为拟定检查项，不代表已执行或已通过。

### 12.1 视觉与交互

- [ ] 三个样板共用标题、间距、操作层级和反馈方式，但没有被硬套成同一版式。
- [ ] 页面重要信息无需逐字段阅读才能理解，次要内容能找到且没有被错误隐藏。
- [ ] 无卡片套卡片、大片被等高撑出的空白、控制高度混乱和重复操作入口。
- [ ] 中英文、深浅色、租户主题与不同圆角配置协调；长内容不遮挡关键操作。
- [ ] Solid Glass 材质仅在确认的浮层/内容容器作用，原控件效果与表格保持；减少透明效果和不支持模糊时可清楚阅读。
- [ ] 桌面窄窗保持既有收缩导航，移动尺寸沿用隐藏导航；内容与弹层均可操作。

### 12.2 动效

- [ ] 新效果有确定来源和共享入口，UIArc 原控件未被覆盖或双重动画。
- [ ] Tab、下拉、抽屉和主题切换与页面动效不冲突，浮层不被按钮或祖先容器遮挡。
- [ ] 首次进入、局部更新、翻页和后台刷新有所区分，不重复播放整页入场。
- [ ] 快速连续操作不会拐弯、闪白、丢焦点、滚动跳位或改变已约定固定高度。
- [ ] 减少动态效果时仍清楚表达状态，不靠动画隐藏必要业务信息。

### 12.3 业务保持

- [ ] 订单服务端分页、所有筛选、费用计数口径、续租时间、金额币种与权限保持；排序不被重新加回。

- [ ] 会员方案权益、适用范围、草稿、发布、历史与授予快照语义保持，未新增虚构售价或已生效权益。
- [ ] 表单校验失败保留内容并可定位；异步失败不显示成功，结果未知不盲目重复提交。
- [ ] 租户/空间切换继续清理旧数据，方案与会员共享不等于跨空间订单可见。

### 12.4 验证证据

- [ ] 先检查已有脚本实际行为，再选择必要的定向回归和类型/构建检查；不新建大批测试或预览工程。
