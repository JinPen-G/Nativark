# 管理后台整体审查报告

> 日期：2026-10-30。审查基线：`main@896bb7123c7d06240e9b395f3ea52858e97038b0`。
> 方法：三个独立子智能体分别审查 AI Native、Rental Core、其余后台；三份报告完成后，由主会话核对调用链、事务边界、权限来源和反证。本报告是固定基线的问题报告，不是生产事故认定、发布许可或原开发任务百分比更新。

## 一、结论与边界

二次复核保留 **63 项源码可确认缺陷：48 项 P1、15 项 P2**。其中 Rental Core 35 项（27 P1 / 8 P2）、其余后台 22 项（17 P1 / 5 P2）、AI Native 6 项（4 P1 / 2 P2）。P1 表示应优先修复的权限、资金、实物安全或主要流程断点；P2 表示重要的恢复、一致性或可用性问题。没有足够证据认定生产已经发生损失，也没有将任何项目标为无条件 P0。

最优先的风险是：租户账号/角色管理的提权旁路；支付、退款结果不明时允许再次发起；换货或部分归还后异常实物提前恢复可租；换货追溯改价、早退重复核减；企业债权和订单收款不勾稽。

## 三、权限、身份与后台集成（OTHER）

### OTHER-001 · P1 · 租户参数管理可改全平台登录安全基线
- **触发与影响：** 具有 `system:params:manage` 的租户账号写 `/platform/security-baseline`，服务固定写平台主体；认证前登录/锁定策略随后读同一份配置，影响其他租户。SaaS 路由白名单反而未包含此入口。
- **证据：** [Guard:377](../../apps/api/src/common/api-auth.guard.ts#L377)、[Controller:484](../../apps/api/src/modules/platform/platform.controller.ts#L484)、[Service:760](../../apps/api/src/modules/platform/platform.service.ts#L760)。Controller 不传可信主体，Service 仅接展示用 operator。
- **处理：** 平台全局基线写入限定 SaaS 当前身份及相应权限；服务层再次校验，不信 body.operator。区分租户可读的有效策略和平台管理入口。
- **验证/恢复：** 租户参数管理员、租户全权管理员均不得写全局基线；授权 SaaS 成功。存量配置与操作日志另行核对，不直接恢复为猜测的默认值。

### OTHER-002 · P1 · 普通账号管理员可重置或停用租户管理员
- **触发与影响：** 具 user:manage、全租户数据/地点范围但不是租户管理员的操作者，对管理员调用专用重置口令/停用接口；返回一次性口令可接管账号。统一 saveUser 有特权保护，但专用动作绕过。
- **证据：** [Service:2330](../../apps/api/src/modules/platform/platform.service.ts#L2330)、[Repository:1344](../../apps/api/src/modules/platform/platform.repository.ts#L1344)。这里只校验目标 tenant，未检查目标基础或角色派生管理员身份。
- **处理：** 同一授权事务内复验当前操作者、目标及管理员角色；原会话撤销仍保留。不能只在 UI 禁用按钮。
- **验证/恢复：** 覆盖基础管理员、固定全权角色、空间派生管理员、自改资料与普通账号；核查历史重置日志需另获授权。

### OTHER-003 · P1 · 旧空间成员写入口绕过固定全权角色保护
- **触发与影响：** 普通 user:manage 全范围账号使用 `PUT /platform/workspaces/:id/members` 给自己设置同租户固定全权角色，后续权限解析获得 `*`。
- **证据：** [Repository:526](../../apps/api/src/modules/platform/platform.repository.ts#L526)。同租户与空间状态校验存在，但只查 role 存在，未调用统一用户授权路径的固定角色保护。
- **处理：** 路由复用统一授权事务；同时保护既有管理员目标和将要授予的角色，不单独复制弱化逻辑。
- **验证/恢复：** 单成员与批量用户 access 两入口应得相同拒绝；普通角色合法授权仍可用。存量空间管理员关系列为审计对象，不自动删除。

### OTHER-004 · P1 · 角色集合写入错误接受用户管理权及通配权限
- **触发与影响：** `/platform/roles` 对 POST 也采用 user:manage OR role:manage；DTO 可携既有 id，saveRole upsert 修改已有角色。buttonPermissions 接受任意字符串并进入 effective permissions，包含 `*`。
- **证据：** [Guard:432](../../apps/api/src/common/api-auth.guard.ts#L432)、[Service:2200](../../apps/api/src/modules/platform/platform.service.ts#L2200)、[Repository:989](../../apps/api/src/modules/platform/platform.repository.ts#L989)。全租户数据范围检查不能代替角色管理权限。
- **处理：** GET 与写权限分离，全部角色写须 role:manage；创建/更新语义明确；登记权限白名单、按钮权限分类及固定全权角色边界统一校验。
- **验证/恢复：** user-only POST/携旧 id/`*`/未知权限被拒，合法角色编辑保留。核查异常权限配置，不凭角色名称批量删权。

### OTHER-005 · P1 · 角色与权限集合分步写，失败或并发破坏整体替换
- **触发与影响：** role upsert 后权限 deleteMany、createMany 分离；插入失败遗留新 metadata/空权限；两个保存交错可留下两个配置的权限并集。
- **证据：** [Repository:1001](../../apps/api/src/modules/platform/platform.repository.ts#L1001)、[Repository:1043](../../apps/api/src/modules/platform/platform.repository.ts#L1043)、[Repository:2180](../../apps/api/src/modules/platform/platform.repository.ts#L2180)。skipDuplicates 不能提供原子替换。
- **处理：** metadata、权限、按钮及适用范围在同事务、同角色锁/CAS 下替换；保存失败全部回滚，统一读取同版本结果。
- **验证/恢复：** 删除后注入失败、两个不同集合并发、旧版本写入。存量需按批准配置核对，不能取并集作为期望权限。

### OTHER-006 · P1 · 退出先清凭据导致服务端会话撤销请求失去认证
- **触发与影响：** logout fire-and-forget 后立即清 storage；异步 Axios request interceptor 才取 token，撤销请求不带认证，被 Guard 拒绝。浏览器退出了，但原 access/refresh 会话仍有效。
- **证据：** [authStore:206](../../apps/admin/src/features/auth/authStore.ts#L206)、[http:71](../../apps/admin/src/api/http.ts#L71)。服务端并非匿名撤销入口。
- **处理：** 捕获旧会话凭据，撤销使用独立明确请求，不被清缓存/新 session 的 abort 覆盖；本地退出与撤销失败分别表达。
- **验证/恢复：** 延迟 interceptor、立即重登录、撤销失败/超时，确认旧会话凭据只发往固定原认证端点。

### OTHER-007 · P1 · 切空间后旧 token 请求被解释为新空间
- **触发与影响：** 服务端先改变 session.currentWorkspaceId，切换响应尚未返回时旧标签页仍发送 A 空间表单；Auth 忽略 token.wid，按 session 当前 B 解释，可能在 B 新建业务。
- **证据：** [Auth:336](../../apps/api/src/modules/auth/auth.service.ts#L336)、[authStore:136](../../apps/admin/src/features/auth/authStore.ts#L136)。前端 epoch 只能拦本页迟到响应，不能绑定服务端请求语义。
- **处理：** access token 与 session 当前空间及切换代次一致，不一致拒绝；客户端 expected scope 仅作一致性条件，不能自授权。
- **验证/恢复：** 双标签、切换响应丢失、旧 token 延迟写；确保旧请求拒绝而非自动转入 B。

### OTHER-008 · P1 · 共享客户详情夹带未授权空间经营数据
- **触发与影响：** 租户会员主档路由允许无有效空间成员身份，使用 tenantUser；客户 profile 只要求 workspaceId 非空便查订单、余额等，可能沿基础 all 数据范围返回经营信息，也未独立要求订单/财务读取权限。
- **证据：** [Guard:935](../../apps/api/src/common/api-auth.guard.ts#L935)、[Platform:1614](../../apps/api/src/modules/platform/platform.service.ts#L1614)、[CustomerOperations:903](../../apps/api/src/modules/platform/customer-operations.service.ts#L903)。
- **处理：** 租户共享主档与空间经营投影分开；后者解析有效 workspaceUser，再按订单/资金权限、own/location 限定，缺权返回 restricted 而非零。
- **验证/恢复：** 冻结/已退出空间、只有 member:view、不同空间角色及 own 用户；共享主档正常可读不受误伤。

### OTHER-009 · P1 · 企业授信流水/回款核销跨越原空间财务权限
- **触发与影响：** 企业 view/manage 用户读全部 tenant+customer 流水或登记回款，FIFO 分配进入无权空间订单；共享企业主档变成跨空间资金授权。
- **证据：** [Platform:2541](../../apps/api/src/modules/platform/platform.service.ts#L2541)、[CorporateSettlement:713](../../apps/api/src/modules/platform/customer-corporate-settlement.service.ts#L713)、[Guard:465](../../apps/api/src/common/api-auth.guard.ts#L465)。与 Core 原候选 C10 合并。
- **处理：** 企业总授信配置与经营债权/回款投影分离；核销只含经当前主体授权的原账单/订单/空间，不能自行引入跨空间结算产品规则。
- **验证/恢复：** 企业管理有权而空间财务无权、selected location、own；历史核销审计另行授权。

### OTHER-010 · P1 · 支付对账批次绕过地点和本人数据范围
- **触发与影响：** 受限财务账号通过对账列表、文件导入、批次详情/核对接触或处理同空间其他地点/他人订单。
- **证据：** [Payment:886](../../apps/api/src/modules/integrations/payment.runtime.service.ts#L886)、[ReconciliationFile:269](../../apps/api/src/modules/integrations/payment-reconciliation-file.service.ts#L269)、[Guard:1248](../../apps/api/src/common/api-auth.guard.ts#L1248)。仅 tenant/workspace 过滤，不是完整 scope。

- **验证/恢复：** 混合授权订单批次、猜测 batchId、受限 bulk reconcile，确保没有部分越权写。

### OTHER-011 · P1 · 通用文件读取/签名绕过业务对象 ACL

### OTHER-012 · P1 · 本地过期/关单不明及入账失败释放再次支付名额
- **触发与影响：** pending 到本地 TTL 即 closed；远端关单异常/部分业务错误被吞，原支付停止查询却可新建支付。第三方已付但本地 funding_failed 也不在新单占用状态集合中，未修复入账前可再次收款。
- **证据：** [Payment:540](../../apps/api/src/modules/integrations/payment.runtime.service.ts#L540)、[Payment:958](../../apps/api/src/modules/integrations/payment.runtime.service.ts#L958)、[Payment:1070](../../apps/api/src/modules/integrations/payment.runtime.service.ts#L1070)、[Payment:2232](../../apps/api/src/modules/integrations/payment.runtime.service.ts#L2232)。Core 原候选 C09 的同根因部分合并于此。
- **处理：** 原支付可信终态才释放；过期/close unknown/已付款待入账保留阻挡与原键核对，分类业务拒绝，不把 TTL 或查询错误当未支付。
- **验证/恢复：** 原单付款与关单竞态、close 超时/404、到账后资金落库失败；已错误 closed 的单据需按原商户单号核对，不能批量重发。

### OTHER-013 · P1 · 退款查询错误被当确定失败，释放原未知退款金额
- **触发与影响：** 退款可能已提交，refresh query 的 401/403/404 进入发起失败分类器，改 failed；额度统计排除 failed，允许再次退款。时间久未查到记录也不足以证明原商户未退款。
- **证据：** [Payment:261](../../apps/api/src/modules/integrations/payment.runtime.service.ts#L261)、[Payment:748](../../apps/api/src/modules/integrations/payment.runtime.service.ts#L748)、[Payment:821](../../apps/api/src/modules/integrations/payment.runtime.service.ts#L821)。
- **处理：** 分离“发起前明确拒绝”和“查询失败”；查询认证、网络、记录缺失保留 unknown/原占用，只有原操作可信失败证据释放。
- **验证/恢复：** 成功提交后断线、查询 key 已轮换、404、超 24h 无记录、重复 refresh；存量 failed 先原商户核对，禁止自动补发。

### OTHER-014 · P1 · 支付创建成功后的日志失败把真实交易降为 failed
- **触发与影响：** 供应商已建支付单、checkout 已持久化，随后 log 写失败，被覆盖 provider/save/log 的同一个 catch 当普通非 unknown 错误处理，改 failed，后续可再次建单。
- **证据：** [Payment:594](../../apps/api/src/modules/integrations/payment.runtime.service.ts#L594)、[Payment:245](../../apps/api/src/modules/integrations/payment.runtime.service.ts#L245)。
- **处理：** 显式外发提交边界和原交易状态机；外部结果/本地收据与辅助日志分别处理。外发后的本地异常不能证明供应商拒绝。
- **验证/恢复：** provider 成功后在 response 保存、日志两个位置注入失败；原商户号始终可恢复且不能让出新收款名额。

### OTHER-015 · P1 · 集成配置原位换商户/存储位置，存量操作失去原配置关联
- **触发与影响：** 保持 enabled 修改商户、bucket、endpoint、key；旧支付/退款按新配置查，旧文件 key 与新 bucket 拼接，删除新位置返回 404 后可能误称旧对象已删。
- **证据：** [Integration:312](../../apps/api/src/modules/integrations/tenant-integration.service.ts#L312)、[FileRuntime](../../apps/api/src/modules/integrations/file-storage.runtime.service.ts)、[PaymentRuntime](../../apps/api/src/modules/integrations/payment.runtime.service.ts)。依赖保护主要在 enabled→disabled，原记录缺不可变身份/位置 revision。
- **处理：** 原操作绑定配置版本及商户/存储定位；短期有存量依赖时拒改身份/位置字段，凭据轮换与商户替换分别处理。
