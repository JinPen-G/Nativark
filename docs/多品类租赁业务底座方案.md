## 版本记录

| 版本 | 日期 | 作者/编辑 | 变更摘要 | 依据 |
| --- | --- | --- | --- | --- |
| v0.1 | 2026-08-13 | Codex | 统一后台信息架构，定义品类、资产、履约地点、定价营销、规则、日历、会员与通知底座，并给出分阶段开发与验收方案 | 项目当前 React/NestJS/Prisma 实现、`Rental Core v0.1`、现有平台规则与本轮九项需求 |

## 1. 结论先行

本轮需要先修正两个基础问题，再继续增加业务页面：

1. 路由、菜单、权限和品类能力必须由同一份注册表驱动。当前路由与菜单分别维护，新增页面后容易出现菜单可见但路由无权、菜单命名与面包屑不一致等问题。
2. 经营品类不能只负责替换“车/器材/设备”等文案。它必须定义可用库存模式、资产字段、履约方式、计价单位、押金与预授权能力、检查规则和可配置模块。

同时需要明确三个边界：

- SaaS 租户是 Rental OS 的经营主体；租用设备的个人或企业是客户，二者不能混用。
- 品类模板定义“允许做什么”，租户配置定义“本租户怎么做”，订单快照记录“这笔交易实际按什么做”。三者不能合并成一张配置表。
- 小程序与 App 首期只保留稳定 API，不在本阶段开发客户端页面；后台必须先具备可维护、可审计、可版本化的配置能力。

## 2. 目标后台信息架构

### 2.1 SaaS 租户后台

| 一级菜单 | 二级菜单 | 说明 | 显示条件 |
| --- | --- | --- | --- |
| 运营概览 | 经营看板 | 订单、收入、库存、履约和风险概览 | 报表查看权限 |
| 租赁交易 | 新建订单、订单管理、合同与单据 | 报价、下单、支付、预占、履约、取消、退款 | 订单权限 |
| 商品与资产 | 商品目录、资产与库存、履约地点 | 商品型号/套装、序列化资产/数量库存、门店/仓库/合作商 | 对应库存与地点权限 |
| 定价与营销 | 基础定价、优惠方案、优惠券、增值服务 | 服务端报价的四类输入 | 价格/营销权限及品类模块 |
| 客户与财务 | 客户与企业、会员、财务结算 | 客户档案、等级、账务、发票、退款 | 客户/财务权限 |
| 运营与分析 | 履约调度、资产运维、资产生命周期、经营报表 | 调拨、维保、IoT、检查、分析 | `dispatch`、`iot` 等 capability + 权限 |
| 经营设置 | 品类与业务、租赁规则、营业日历、会员激励、通知模板 | 租户级版本化业务配置 | 租户配置权限及品类模块 |

### 2.2 SaaS 平台后台

平台管理员只管理 SaaS 租户、品类模板、平台组织权限、平台参数、运维和治理。平台管理员不应直接进入某个租户的订单、价格或会员配置；如未来需要代运营，应使用有审计记录的“进入租户”机制。

### 2.3 路由可见性规则

```text
可访问 = 已登录
      AND 用户拥有 permission
      AND 当前租户品类支持 module/capability
      AND 租户状态允许操作
```

前端隐藏菜单只改善体验，不构成数据隔离。API 仍必须按 `tenantId`、permission 和 capability 进行校验。

## 3. 品类模型

### 3.1 分层

| 层级 | 主要对象 | 职责 |
| --- | --- | --- |
| 平台品类目录 | `RentalCategoryDefinition` | 定义库存模式、术语、资产字段、地点类型、租赁方式、计价方式、可配置模块和默认能力 |
| 租户品类档案 | `TenantRentalProfile` | 锁定一个经营品类，选择模板允许范围内的 capability 与术语覆盖 |
| 租户经营设置 | `TenantRentalBusinessSettings` | 支付、押金/预授权、超时、节假日、会员、通知等可版本化配置 |
| 商品/资产数据 | `RentalItemGroup`、`RentalAsset`、`RentalStockBalance` | 保存商品型号和具体资产/数量库存；字段受品类 schema 校验 |
| 交易快照 | 报价、订单、费用、规则、优惠快照 | 下单时固化，后续修改配置不能回写历史订单 |

### 3.2 四类品类基线

| 品类 | 库存 | 常用计价 | 资产差异 | 履约地点/方式 | 典型规则 |
| --- | --- | --- | --- | --- | --- |
| 车辆载具 | 序列化、少量套装 | 小时、24 小时、日、周、月、里程 | 商品组：厂商、车系、款型、能源；资产：车牌、VIN、登记信息、里程、油电 | 运营商/车行、门店、取还点；门店取还、异店还车、配送 | 驾驶资质、预授权、超时、超里程、油电差、事故、违章 |
| 摄影设备 | 序列化、数量、套装 | 小时、24 小时、日、周、套餐 | 商品组：厂商、型号、卡口、传感器；资产：SN、快门数、成色、校准 | 自营/合作商、门店、仓库、自提柜；自提、寄送、上门 | 高价值押金、损坏免赔、配件清单、快门增量、逾期 |
| 露营设备 | 数量、套装，贵重品序列化 | 日、夜、周末套餐、套 | 商品组：品牌、人数、季节、材质；资产/库存：批次、清洁状态、缺件 | 门店、仓库、合作营地；自提、配送 | 清洁费、缺件、耗材、天气取消、逾期 |
| 工程设备 | 序列化、数量、套装/属具 | 小时、班次、日、周、月、工时 | 商品组：厂商、型号、功率、额定载荷；资产：出厂号、工时、年检、属具 | 运营商、仓库、项目现场；配送、现场交付 | 操作资质、运输、预授权/保证金、超工时、停机、现场交接 |

## 4. 商品与资产模型

### 4.1 共同结构

- 商品型号/标的分组保存：品牌、型号、规格、租赁单位、库存模式、套装组成和适用计价计划。
- 资产实例保存：资产编号、序列号、所属商品型号、当前位置、运营状态、使用量与品类专属属性。
- 数量库存保存：地点、在手、预占、维护/清洁、可用数量；后续补库存流水和批次。

品牌和型号是车辆、摄影和工程设备都需要的共同字段，不应因为品类不同而创建多套资产主表。车牌、VIN、快门数、工程工时等由品类字段 schema 扩展。

### 4.2 字段作用域

| 作用域 | 示例 | 说明 |
| --- | --- | --- |
| `item_group` | 厂商、型号、卡口、能源类型、额定载荷 | 同一型号共享，不能重复录入每一件资产 |
| `asset` | 车牌、VIN、SN、快门数、出厂号、当前工时 | 每一独立资产不同 |
| `transaction` | 交付里程、归还快门数、缺件、油电量 | 属于订单履约记录，不回写为静态型号字段 |

## 5. 履约组织与地点

“车行”“摄影合作商”在平台模型中都是经营/履约组织，不应建立品类专属表。建议结构：

```text
FulfillmentOperator（自营主体/合作商/供应商）
  └─ FulfillmentLocation（门店/仓库/取还点/自提柜/项目现场/配送中心）
       └─ capabilities（pickup/return/storage/delivery/inspection）
```

地点类型由品类模板给出允许集合，租户选择实际启用类型。订单必须分别保存领取地点和归还地点，为异地归还、配送和项目现场交付保留空间。

## 6. 定价、优惠与增值服务

### 6.1 服务端报价链路

```text
基础定价
→ 日历调整（工作日/周末/法定节假日/租户特殊日）
→ 优惠方案（自动满足条件）
→ 优惠券（用户主动使用，校验领取与核销）
→ 会员权益
→ 增值服务
→ 押金/预授权
→ 税费、舍入
→ 报价快照与订单费用明细
```

前端提交的单价只能作为询价输入或人工改价建议，不能成为最终订单价格。最终价格必须由服务端报价并生成版本快照。

### 6.2 对象边界

| 对象 | 作用 | 关键字段 |
| --- | --- | --- |
| 基础定价计划 | 定义商品在计价单位下的基础价格 | 品类、商品范围、计价单位、阶梯、使用量、押金、有效期、版本 |
| 优惠方案 | 自动计算折扣 | 适用客户/商品/日期/租期、折扣类型、叠加规则、优先级、上限 |
| 优惠券模板 | 定义可领取凭证 | 门槛、面额/折扣、发行量、每人限领、有效期、适用范围 |
| 用户优惠券 | 领取与核销事实 | 客户、模板、状态、领取/锁定/核销/退回时间、关联订单 |
| 增值服务 | 可选服务或保障 | 价格、计费单位、数量限制、适用品类/商品、保障额度、条款版本 |

损坏免赔不是“随便打折”，而是带保障范围、免赔额、赔付上限和除外责任的增值服务；需要在订单中保存条款版本。

## 7. 租赁业务规则

租户规则由通用规则和品类适配规则组成：

| 规则域 | 通用设置 | 品类差异 |
| --- | --- | --- |
| 支付 | 下单付/确认付/取件付、全额/部分、待支付保留时间 | 工程设备可线下账期；高价值摄影可要求全额 |
| 押金 | 无、固定、价格倍数、按商品累加 | 车辆常用预授权；工程设备可保证金；露营可低额押金 |
| 预授权 | 是否启用、发起时间、释放条件、失败策略 | 只有支付通道和品类模板都支持时才可开启 |
| 领取归还 | 是否需要检查、照片/视频/读数、允许异地归还 | 车辆里程油电、摄影配件与快门、工程工时与安全点检 |
| 超时 | 宽限期、按小时/周期/倍数收费、封顶、人工审核 | 车辆和摄影通常严格；工程设备可按班次/停机处理 |
| 取消 | 免费取消窗口、阶梯费、天气/不可抗力 | 露营可有天气策略；工程设备需计运输准备成本 |
| 资质 | 是否必需、类型、有效期、审核 | 车辆驾照；工程操作证；高价值摄影可做信用审核 |

每次规则变更生成新版本；报价和订单保存采用的规则版本及关键计算结果。

## 8. 营业日历

日历优先级：订单指定特殊价 > 租户特殊日期 > 法定节假日数据 > 周规则 > 普通工作日。

中国大陆法定节假日不能仅靠“周六周日算法”推断，调休会每年变化。目标实现：

1. 平台维护年度官方日历数据集，记录来源、发布日期、导入人和版本。
2. 租户选择同步某年度，并允许增加本租户特殊营业日/停业日/旺季日。
3. 自动同步失败时保留上一个已发布版本，不静默覆盖。
4. 订单报价保存命中的日期类型和日历版本。

本阶段只建立数据结构和手工特殊日期入口；自动抓取需另行接入可信的国务院办公厅年度放假通知源并做人工发布审核。

## 9. 会员激励与通知

### 9.1 会员激励

- 注册赠礼：开关、奖励类型（余额/积分/优惠券）、数量、有效期、实名/首单条件。
- 邀请奖励：邀请人和被邀请人可分别配置；明确触发点为注册、实名或首单完成。
- 必须有幂等业务键、防刷限制、奖励流水和撤销原因，不能只在会员余额上直接加数。

### 9.2 通知模板

模板由事件、渠道、接收人、标题、正文、变量 schema、状态和版本组成。首批事件：注册、邀请达成、订单创建/确认/取消、待支付、领取提醒、归还提醒、逾期、退款、资质审核、资产异常。

租户只能编辑模板允许的文案和渠道，不得创建未注册的系统事件或任意变量。发送日志、重试和供应商回执属于通知基础设施，不与模板编辑混在一起。

## 10. API 与客户端边界

| 范围 | 本阶段 |
| --- | --- |
| 后台管理 | 完整路由、菜单、品类与经营设置入口；逐步迁移定价、优惠、资产、地点 CRUD |
| 小程序/App | 保留登录、品类元数据、目录、报价、下单、订单、优惠券、通知偏好 API 设计；暂不开发页面 |
| 服务端 | 所有写操作按租户隔离；价格、优惠、日历、规则在服务端计算和快照 |
| 兼容层 | 旧车辆 API 只能作为迁移适配器；新通用页面不得继续新增车辆专属字段依赖 |

## 11. 开发分期

### P0：本轮底座

- 收口导航、路由、权限与 capability 元数据。
- 丰富四类品类目录：计价单位、租赁方式、地点类型、资产字段、设置模块。
- 新增租户经营设置读写契约和后台“品类与业务”页面。
- 登录上下文携带 capability，菜单与路由同时判断 permission/capability。
- 消除 API 服务与 seed 的品类定义重复。

### P1：通用商品、资产与地点

- 将后台商品、资产、地点页面切到 Rental Core 持久化模型。
- 实现 schema 驱动字段、履约组织/地点、数量库存流水、套装兼容/替代。
- 清理页面对 `VehicleGroup`、车牌、VIN、里程、车位的直接依赖。

### P2：定价与报价

- 基础定价计划、日历调整、服务端报价、费用行和订单价格快照。
- 禁止客户端决定最终 `unitPrice`。

### P3：优惠和服务

- 优惠方案、优惠券模板/领取/锁定/核销/退回、会员权益叠加规则。
- 增值服务与保障条款版本。

### P4：规则、日历、会员与通知

- 规则版本、官方日历导入与租户覆盖、奖励流水、通知事件注册表和发送日志。

### P5：客户端 API 稳定化

- 发布小程序/App OpenAPI；补幂等、签名、限流、错误码、回调和契约测试。

## 12. 验收标准

- 菜单名称、路由、面包屑、权限码来自统一注册表；不存在两份手工列表。
- `demo` 登录后只能看到摄影设备支持的能力，车辆专属 IoT/驾照功能不出现；SaaS 平台管理员只见平台菜单。
- 四个品类均返回完整业务模型，字段能明确区分 `item_group`、`asset`、`transaction`。
- 租户只能在品类允许范围内开启计价、履约和 capability；越权保存由 API 拒绝。
- 订单最终价格来自服务端报价快照；配置修改不影响历史订单。
- 官方日历数据有来源、版本和发布状态；租户覆盖不破坏原始数据。
- 注册/邀请奖励有流水与幂等键；优惠券有锁定、核销和退回状态机。
- 通知模板变量经 schema 校验，发送日志可追踪模板版本和供应商回执。

## 13. v0.1 实施结果与未完成边界

### 已完成

- 后台菜单、路由、权限和 capability 元数据收口到统一注册表，路由守卫与菜单使用同一事实源。
- 四个经营品类补齐计价单位、履约方式、地点类型、资产字段、预授权/资质能力、增值服务预设和配置模块。
- 登录及会话恢复上下文携带 capability；调度、IoT 等菜单与对应 API 同时受权限与品类能力控制。
- 新增租户经营设置 API 和后台页面，支持品类约束下的计价单位、履约方式、支付/押金/预授权、逾期、日历、会员激励和通知事件设置。
- 商品目录、资产与库存、履约地点页面已从旧车辆兼容接口切换到 Rental Core 通用接口，并按品类 schema 显示字段。
- 新增优惠券模板 API 与后台页面，支持固定减免/百分比、门槛、封顶、发行量、每客限领、有效期和适用商品。
- Prisma schema/迁移已为品类业务模型和履约经营主体快照预留持久化字段；seed 改为复用共享品类目录。

### 尚未完成，不能视为已有生产能力

- Rental Core 的商品、资产、地点、经营设置和订单运行态仍是进程内存储，Prisma 表尚未接入服务仓储；重启会丢失运行时修改。
- 现有基础定价、优惠方案和增值服务仍使用旧车辆租赁内核；菜单已拆分，但尚未迁移到通用品类价格模型。
- 优惠券模板已完成内存版；用户领取、锁定、核销和退回状态机尚未开发。
- 订单仍接受调用方提交 `unitPrice`，服务端报价和价格/规则/日历快照尚未开发。
- 中国大陆官方节假日自动导入、奖励流水与防刷、通知模板变量 schema 和发送日志尚未开发。
- 履约经营主体目前以地点快照保存，尚未拆成独立合作商/供应商主档。
