## 1. 适用范围

本文只说明本地与部署环境的 MySQL 初始化、迁移、Seed、备份和验证。业务需求见 `多品类租赁平台需求说明.md`，开发优先级见 `多品类租赁平台开发任务.md`。

当前数据结构同时包含：

- SaaS 平台、租户、组织、账号、角色和权限；
- `vehicle` 品类兼容域的车辆、客户、订单、费用、调度和报表表；
- Rental Core 的品类、商品、资产、库存、订单、预占、检查和商业配置表；
- `rental_core_state_snapshots` 与 `rental_business_state_snapshots` 聚合快照。

聚合快照是 v0.1 的恢复机制，不代表订单、库存、价格和权益已经完成生产级规范化持久化。

## 2. 环境配置

从模板创建本地配置：

```powershell
Copy-Item .env.example .env
```

必须配置的变量：

| 变量 | 用途 |
| --- | --- |
| `DATABASE_URL` | MySQL 连接，只通过环境或秘密管理注入 |
| `PLATFORM_DATA_SOURCE` | `mysql` 或显式测试用 `memory` |
| `STORE_RENTAL_DATA_SOURCE` | 车辆兼容域数据源 |
| `INFRA_DATA_SOURCE` | 文件、通知、任务等基础设施数据源 |
| `AUTH_TOKEN_SECRET` | 认证签名密钥，生产环境必须单独设置 |
| `DATABASE_CONNECT_ON_START` | 是否在 API 启动时验证数据库连接 |
| `REDIS_URL` | Redis 连接，当前主要为预留能力 |

不得把账号、密码、token、私钥或真实客户数据写入本文、README、Git 示例或测试输出。

## 3. 本地启动

启动 MySQL 和 Redis：

```powershell
docker compose up -d mysql redis
```

安装依赖并生成 Prisma Client：

```powershell
npm install
npm run db:generate
npm run db:validate
```

启动应用：

```powershell
npm run dev
```

API 默认地址为 `http://localhost:3000/api`，管理端默认地址为 `http://localhost:5175`。

## 4. 迁移

### 本地开发

只有在新增或修改 Prisma 模型、并准备生成新 migration 时使用：

```powershell
npm run db:migrate -- --name <migration_name>
```

根脚本会加载项目根目录 `.env`。不要用 `migrate dev` 作为部署命令。

### 部署环境

部署环境由流水线安全注入 `DATABASE_URL` 后执行：

```powershell
npm exec -w @store-rental/api -- prisma migrate deploy
```

### 迁移安全规则

- 已共享或已应用的 migration 默认不可修改。
- 如果要重建预发布基线，必须先确认所有数据库可销毁，并在开发任务中记录决定、影响和恢复方案。
- 禁止使用无数据迁移方案的 `DROP TABLE`、`DROP COLUMN` 或批量覆盖。
- 字段重命名采用“新增字段 → 回填 → 双读/切读 → 移除旧字段”的兼容过程。
- 每次迁移同时验证空库全量部署和已有库增量升级。
- 升级验证至少比较迁移前后的记录数、租户归属、金额、订单状态、库存占用和审计记录。

## 5. Seed

本地演示数据：

```powershell
npm run db:seed
npm run db:seed:reports
```

规则：

- Seed 仅用于本地和测试环境，生产环境禁止执行。
- Seed 必须幂等，重复执行不能产生重复租户、商品、资产、订单或报表记录。
- `demo` 应提供摄影设备样本，`demo2` 应提供露营装备样本；车辆样本使用独立车辆品类租户。
- 品类、商品字段和样本数据必须一致，不能把摄影 fixture 暴露给露营租户。
- 演示账号的临时凭据只通过初始化流程或本地安全配置获得，不写入仓库文档。

## 6. 备份与恢复

备份本地 MySQL：

```powershell
npm run ops:mysql:backup
```

恢复到明确指定的本地数据库：

```powershell
npm run ops:mysql:restore -- -InputFile <backup-file>
```

恢复前必须确认目标数据库；生产恢复需单独审批、备份当前状态并验证恢复后的 migration、租户数量和关键业务记录。

## 7. 验证

静态和内存底座验证：

```powershell
npm run test:rental-foundation
npm run build
git diff --check
```

`db:validate` 只验证 Prisma schema，不连接数据库，也不证明 migration、Seed 或持久化正确。

数据库任务必须额外验证：

1. 专用空测试库执行全部 migration；
2. 两个 Seed 各执行两次；
3. 登录并初始化不同品类 SaaS 租户；
4. 完成报价、下单、确认、配货、领取、归还和异常费用；
5. 重启 API 后重新读取订单、占用、权益和审计；
6. 并发请求验证租户上下文不串线；
7. 在带旧通知数据的数据库执行升级并确认数据保留；
8. 只清理专用测试数据库，不清理开发库。

## 8. 数据源边界

- `memory` 只允许测试或明确的演示场景使用，不能作为租户隔离、事务或重启恢复证明。
- `mysql` 是平台和生产业务目标数据源。
- 请求身份缺失时不得使用演示租户兜底。
- Rental Core 的规范化事实表、事务和并发控制任务见开发台账 `RC-01` 至 `RC-04`。
