## 1. 适用范围

本文只说明本地与部署环境的 MySQL 初始化、迁移、Seed、备份和验证。业务需求见 `多品类租赁平台需求说明.md`，开发优先级见 `多品类租赁平台开发任务.md`。

截至 v2.5，当前已落库的数据结构包含：

- SaaS 平台、租户、组织、账号、角色和权限；
- 历史门市租赁的车辆、客户、订单、费用、调度和报表表（仅作参考，不属于新平台事实源）；
- Rental Core 的品类、商品、资产、库存、订单、预占、检查和商业配置表；
- `rental_core_state_snapshots` 与 `rental_business_state_snapshots` 聚合快照。
- `rental_attribute_unique_values` 动态属性唯一声明表，用于在经营空间内原子约束资产 schema 的唯一字段。
- `rental_allocations.itemGroupId` 保存实际分配商品，`rental_reservations.releasedQuantity` 保存部分归还后的累计释放数量。

经营空间、空间成员和经营事实 `workspaceId` 已按 `SPACE-01` 至 `SPACE-03` 落库；所有新经营事实仍必须同时保持 `tenantId` 与 `workspaceId` 边界。

聚合快照仅作为恢复副本；订单、库存、价格和权益等规范化表是当前业务事实源，新增实现不得重新依赖快照作为主读写路径。

## 2. 环境配置

从模板创建本地配置：

```powershell
Copy-Item .env.example .env
```

必须配置的变量：

| 变量 | 用途 |
| --- | --- |
| `DATABASE_URL` | MySQL 连接，只通过环境或秘密管理注入 |
| `PLATFORM_DATA_SOURCE` | `mysql` 或显式测试用 `memory` |
| `STORE_RENTAL_DATA_SOURCE` | 历史门市租赁参考模块数据源；新平台功能不得依赖 |
| `INFRA_DATA_SOURCE` | 文件、通知、任务等基础设施数据源 |
| `AUTH_TOKEN_SECRET` | 认证签名密钥，生产环境必须单独设置 |
| `DATABASE_CONNECT_ON_START` | 是否在 API 启动时验证数据库连接 |
| `REDIS_URL` | Redis 连接，当前主要为预留能力 |

不得把账号、密码、token、私钥或真实客户数据写入本文、README、Git 示例或测试输出。

## 3. 本地启动

启动 MySQL 和 Redis：

```powershell
docker compose up -d mysql redis
```

安装依赖并生成 Prisma Client：

```powershell
npm install
npm run db:generate
npm run db:validate
```

启动应用：

```powershell
npm run dev
```

API 默认地址为 `http://localhost:3000/api`，管理端默认地址为 `http://localhost:5175`。

## 4. 迁移

### 本地开发

只有在新增或修改 Prisma 模型、并准备生成新 migration 时使用：

```powershell
npm run db:migrate -- --name <migration_name>
```

根脚本会加载项目根目录 `.env`。不要用 `migrate dev` 作为部署命令。

### 部署环境

部署环境由流水线安全注入 `DATABASE_URL` 后执行：

```powershell
npm exec -w @store-rental/api -- prisma migrate deploy
```

### 迁移安全规则

- 已共享或已应用的 migration 默认不可修改。
- 如果要重建预发布基线，必须先确认所有数据库可销毁，并在开发任务中记录决定、影响和恢复方案。
- 禁止使用无数据迁移方案的 `DROP TABLE`、`DROP COLUMN` 或批量覆盖。
- 字段重命名采用“新增字段 → 回填 → 双读/切读 → 移除旧字段”的兼容过程。
- 经营空间改造采用“创建空间主档与成员关系 → 每个现有租户创建默认空间 → 将全部现有账号及角色关系回填到默认空间 → 回填经营事实 `workspaceId` → 双重范围校验 → 收紧约束”的兼容过程。
- 回填必须依据现有 `tenantId` 和租户唯一品类确定默认空间，不得按商品名称、页面文案或车辆字段猜测；任何旧行无法唯一归属时停止迁移并报告。
- 每次迁移同时验证空库全量部署和已有库增量升级。
- 升级验证至少比较迁移前后的记录数、租户与经营空间归属、金额、订单状态、库存占用、客户关联和审计记录。
- 当前品类编码由 Prisma 枚举约束。新增品类必须创建新的增量 migration 扩展枚举，并同步共享品类定义、Seed 与 E2E；不得修改已应用 migration，也不得复用旧门市品类或根据名称猜测映射。
- 为 JSON 动态字段增加 `unique` 时，迁移必须将已有非空值按服务端相同规则归一化并回填唯一声明；若历史数据冲突必须停止升级并先治理数据，不得跳过或静默覆盖。写主记录与唯一声明必须处于同一事务，并以并发 E2E 验证冲突返回 409。
- 实际分配商品只在可准确推导时回填：序列化分配按资产商品组回填，非套装数量分配按订单行回填；历史套装数量分配无法确定真实组成时必须保留空值，不能猜测，并由业务层限制为整单归还。

## 5. Seed

本地演示数据：

```powershell
npm run db:seed
npm run db:seed:reports
```

规则：

- Seed 仅用于本地和测试环境，生产环境禁止执行。
- Seed 必须幂等，重复执行不能产生重复租户、商品、资产、订单或报表记录。
- `demo` 必须包含摄影、露营、车辆和工程设备四个启用经营空间；同一租户下的演示账号均具有四个空间的成员资格，可直接切换测试。`demo2` 保留为独立租户，用于跨租户隔离验收。
- 品类、商品字段和样本数据必须一致，不能把摄影 fixture 暴露给露营租户。
- 各品类样本通过独立样本注册表生成；未注册样本的新品类允许初始化为空目录，不得回退到摄影、露营或车辆样本。
- 同租户两个经营空间共享一个客户主档样本，但订单、优惠券、积分和会员权益分别归属各自空间。
- 演示账号的临时凭据只通过初始化流程或本地安全配置获得，不写入仓库文档。

## 6. 备份与恢复

备份本地 MySQL：

```powershell
npm run ops:mysql:backup
```

恢复到明确指定的本地数据库：

```powershell
npm run ops:mysql:restore -- -InputFile <backup-file>
```

恢复前必须确认目标数据库；生产恢复需单独审批、备份当前状态并验证恢复后的 migration、租户数量和关键业务记录。

## 7. 验证

静态和内存底座验证：

```powershell
npm run test:rental-foundation
npm run build
git diff --check
```

`db:validate` 只验证 Prisma schema，不连接数据库，也不证明 migration、Seed 或持久化正确。

数据库任务必须额外验证：

1. 专用空测试库执行全部 migration；
2. 两个 Seed 各执行两次；
3. 登录并初始化包含多个经营空间的 SaaS 租户；
4. 同一管理员依次切换摄影、露营、车辆和工程设备空间，验证成员权限、会话更新、品类样本和缓存隔离；
5. 验证共享客户主档在两个空间可复用，而订单和权益不能跨空间访问；
6. 完成报价、下单、确认、套装替代、配货、领取、部分归还、整单归还和异常费用；
7. 重启 API 后重新读取订单、占用、权益和审计；
8. 并发请求验证租户和经营空间上下文不串线；
9. 在带旧业务和通知数据的数据库执行升级并确认默认空间回填与数据保留；
10. 只清理专用测试数据库，不清理开发库。

## 8. 数据源边界

- `memory` 只允许测试或明确的演示场景使用，不能作为租户隔离、事务或重启恢复证明。
- `mysql` 是平台和生产业务目标数据源。
- 请求身份缺失时不得使用演示租户兜底。
- Rental Core 的规范化事实表、事务和并发控制任务见开发台账 `RC-01` 至 `RC-04`。
