## 1. 不可偏离边界

### 本期只做

- 营运端门市租赁平台。
- SaaS 架构保留，至少支持 1-2 个租户。
- MySQL 真实落库；内存模式只作为开发 fallback。
- 平台底座、会员、企业客户、站点、车辆、定价、订单、调度、财务、报表。
- 企业端、用户 H5 只预留接口边界，不开发完整产品。

### 本期不做

- 工作台。
- 排班表。
- 战情室。
- 分时租赁业务逻辑。
- 渠道团票。
- 无 PRD/原型依据的通用后台扩张。

### 高风险入口

通知中心、附件与打印、异步任务、外部接入与任务日志、安全基线已恢复历史入口，但后续只能围绕明确业务页面接入，不允许扩成泛化后台。

1. **仓库收口**：工作区垃圾与失效 worktree 已清理；后续提交当前 React 替换与文档变更。

## 6. 接手开发流程

### 多分支开发规则

- 旧分支 `codex/foundation-platform`、`codex/infra-adapters`、`codex/integration-store-rental-mvp`、`codex/fleet-ops`、`codex/pricing-marketing`、`codex/customer-finance`、`codex/order-fulfillment`、`codex/dispatch-exception`、`codex/reports-ops` 只作为历史记录，不再派发新任务。
- 新开发必须基于最新 `main` 新建分支，且一个分支只对应一个清晰任务域。
- 当前建议只保留 4 个活跃分支：
  - `codex/master-data-foundation`：平台底座、系统参数、权限、会员、企业客户、站点、车辆、MySQL 回归。
  - `codex/order-finance-flow`：新建订单、取车、还车、费用、预授权、发票、月结、异常订单闭环。
  - `codex/pricing-dispatch`：租赁规则、基础定价、动态调价、行销方案、调度、车辆占用联动。
  - `codex/reports-tests`：报表、导出、演示 seed、关键流程测试、MySQL E2E。
- 各分支开发前必须先确认 `main` 是最新基线，不允许从旧历史分支继续开发。
- 分支 agent 只负责在自己的分支开发、验证和提交，不允许自行合并到 `main`。
- 合并回 `main` 必须由主线程统一执行：先审计 PRD/原型依据，再处理冲突，再跑 build、contract、Prisma 校验，确认无偏离后才能合并。

### 开发步骤

1. 选任务 ID。
2. 读本文中该任务的目标、方向、必看 PRD/原型。
3. 读对应代码：前端页面、API client、后端 controller/service/repository、shared DTO、Prisma schema。
4. 开发前确认是否会影响订单状态、车辆占用、费用、资金、权限、审计、通知。
5. 前后端同步开发，MySQL 和内存模式都不能破。
6. 验证：至少跑 `npm run build`、`npm run contract:validate`、`npx prisma validate --schema apps/api/prisma/schema.prisma`，涉及报表跑 `npm run test:reports`。
7. 更新本文对应任务状态和下一步，不写自动检查流水账。

## 7. 台账更新规范

- 开发过程流水、检查总结、定时任务记录、阶段复盘只能写入 `docs/门店租赁开发日志.md`，不得写入本文件。

本文件是开发任务台账，不是运行日志、日报、交付报告、聊天记录或自动任务输出。任何 AI 开发后只能按下面规则更新，禁止在本文末尾追加大段流水账。

### 允许更新的位置

只允许更新以下位置：

1. `0. 当前真实状态`：只在最新提交、验证结果、未收口项发生变化时更新。
2. `3. 当前成熟度`：只更新对应模块的状态、当前进度、主要缺口。
3. `5. 任务清单`：只更新本次实际开发过的任务行。
4. `4. 下一轮总优先级`：只有优先级真正变化时才调整顺序。

除非用户明确要求，不允许新增新的日报章节、检查章节、交付章节、总结章节。

### 单个任务怎么更新

开发完成后，找到对应任务 ID 的表格行，只改这几个字段含义：

- `状态`：只能是 `Done`、`In Progress`、`Pending`、`Reserved`。
- `开发目标`：一般不改，除非用户确认目标变化。
- `开发方向`：补充真实实现范围，不写空话。
- `必看 PRD/原型`：发现新的必读资料时追加文件名。
- `验收`：写本任务下一步验收口径或已通过的关键验收。

状态含义：

- `Done`：本任务在 MVP 范围内前端、后端、MySQL、权限、审计、基本验证都完成；没有明确未完成项。
- `In Progress`：已有实现，但仍缺规则、MySQL、权限、异常流程、测试或真实接入。
- `Pending`：未开发。
- `Reserved`：本期只预留接口或边界，不开发完整能力。

### 必须写清楚的内容

每次更新任务行时，必须体现：

- 做了哪个页面、接口、表、DTO 或脚本。
- 对应哪个 PRD 或原型。
- 是否真实落 MySQL。
- 是否只是 mock/预留。
- 还缺什么，下一步是什么。

推荐格式：

`已完成 xxx 页面/接口/表，依据 xxx PRD 和 xxx.html；MySQL 模式已/未接入；当前仍缺 xxx，下一步 xxx。`

### 禁止写入的垃圾信息

严禁在本文写入：

- “定时任务第几次触发”。
- “持续开发承诺”。
- “开发完成时间”。
- “所有任务已全部完成/全部深化完成”这类未经逐项验收的结论。
- 构建产物体积、模块数量、耗时等流水账。
- 大段夸奖、总结、口号、交付清单、用户手册、部署教程。
- 与门市租赁开发无关的泛化后台规划。
- 自动生成的重复检查记录。

构建和验证结果只允许写在 `0. 当前真实状态` 的一行里，例如：

`最新验证：build/contract/prisma/test:reports 通过；未跑 MySQL E2E。`

### 新增任务规则

只有满足以下任一条件才能新增任务：

- 用户明确要求新增。
- PRD 或原型中存在明确页面、流程或字段，当前台账没有覆盖。
- 为完成现有任务必须新增底层支撑，例如一键重置、E2E、数据权限。

新增任务必须放进合适阶段和模块表格中，不能在文件末尾追加零散段落。

新增任务必须写清：

- 任务 ID。
- 开发目标。
- 开发方向。
- 必看 PRD/原型。
- 验收口径。
- 防偏离说明。

### 完成后提交前检查

更新台账后必须检查：

- 本文没有新增重复章节。
- 本文没有自动检查流水账。
- 本文没有泛化交付文档内容。
- 搜索“定时任务、持续开发承诺、交付准备最终完成、所有任务完成”等词时，除本节禁写示例外，不应在其他章节命中。
- `git diff --check` 通过。

## 8. 合并前防偏离清单

- 是否改了 PRD、原型或业务知识库？如果是，停止。
- 是否新增了工作台、排班、战情室、分时租赁、渠道团票？如果是，停止。
- 是否只做了前端页面，没有后端/API/MySQL？如果是，不能标完成。
- 是否新增独立通知/附件/异步/外部接入/安全页面能力？必须有业务依据。
- 是否影响订单状态、车辆占用、费用、资金、权限、审计、通知？必须回归。
- 是否有 mock/provider？必须标注为 MVP 预留，不得宣传为真实接入。
- 是否跑过构建、契约、Prisma 校验？没有就不能合并。
