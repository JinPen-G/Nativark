- [平台服务/仓储](../../../apps/api/src/modules/platform/platform.repository.ts)锁定实际Tenant、User、AuthSession、空间成员、账号角色关系、角色/权限关系及权限行，按原User与空间角色替换规则映射当前权限；所有读取使用传入事务，不使用根Prisma。成员数据范围和地点范围优先，停用角色、坏地点JSON、冻结租户、强制改密、撤销/到期/切空间或受众不一致均拒绝；内存演示身份不能替代持久化授权。
- 锁序为人员租户→账号→原会话→成员→账号角色关系→按ID角色/权限关系→按ID权限，之后商业目录→品类身份/政策→空间业务锁。现有撤权写入更新/删除相同行，已提交撤权在获得锁后重读；锁先获准者与后续撤权按数据库事务排序，不宣称正在等待的撤权已提交。真实MySQL等待、死锁与容量未执行。

- [内部采用阶段](../../../apps/api/src/modules/rental-core/category-adoption-transaction-phase.ts)在商业/业务锁之前取得相同人员授权，绑定及审计写入后再次复验；缺原认证或执行器时在业务读取前拒绝。该阶段仍无正式应用入口，业务兼容仍为`complete:false`；采用原键/指纹/原审计回读与最终完整业务闸门继续实施。
