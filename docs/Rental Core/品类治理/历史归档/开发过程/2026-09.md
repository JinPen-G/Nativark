## 实施与部署原始证据（2026-09-30，非当前复验）

下列旧现状、命令、库和“下一步”仅说明当时。不得用旧许可执行生成、迁移或连库，不以本次归并认定已部署。

### 现状和迁移入口

| 入口 | 当前来源 | 目标入口 / 风险 |
| --- | --- | --- |
| 租户及空间创建 | `platform.service` 固定四品类枚举、`platform.repository` 字符串映射 | 从发布版本与开通/采用政策解析；创建事务内绑定版本，不能落空壳 |
| 核心报价和建档 | `rental-core.service` 进程内 `RENTAL_CATEGORY_DEFINITIONS` | 以空间绑定版本读取；旧报价/订单以自身引用和快照执行 |
| 能力治理与 Hook | `workspace-capability.service`、`capability-hook.runtime` 再读静态必选能力；仓库另读品类表默认值 | 与核心共用解析服务；代码只登记真实实现和硬前提，避免双口径 |
| 后台导航及资料 | `navigation.tsx`、`WorkspaceSwitcher`、会员资料页及建单页含固定映射 | 安全元数据驱动；图标提供受控通用回退 |
| 客户及员工端 | shared/client 与 API 元数据、端侧可能含四品类映射 | 消费授权空间的安全投影；不暴露治理正文和内部规则 |
| 数据模型 | Prisma `RentalCategoryCode` 为四值 enum，品类身份表持可变 JSON，空间仅有 `categoryCode`；另有 10 余处品类 enum 字段 | 先增兼容版本结构及引用，最后独立迁移动态编码与各事实字段；不得一步放开新编码 |
| Seed | `seed.ts` upsert 对既有定义执行 `update: category` | 改为只补缺身份/内置版本；演示事实与正式模板分离 |

共享 `core.ts` 的 `RentalCategoryCode`、静态定义、能力白名单和 `workspace-names.ts` 仍是四项；项目中 API/shared/admin 共 27 个文件含固定枚举或定义引用。不能仅更改平台列表 API 就声称新品类可营运。

### 基线证据与限制

- `npm run test:category-core` 在重新生成 Prisma Client 后通过：品类核心对齐，以及四品类的目录、定价分组、地点、价格、报价和规则契约。
- 首次运行因隔离工作树旧 Prisma Client 缺 `organizationId`、优惠券日期字段而在 TypeScript 编译阶段失败；`npm run db:generate` 后复跑通过。此为生成产物失配，不是业务差异。
- 该专项未覆盖本任务要求的每个品类的真实资产预占、取消、续租含缓冲、交接、结算和权限全链路。后续逐场景补真库/浏览器证据；不能将现有静态契约检查称为全部四品类经营验收。
- 后续已在**临时专用克隆库**执行迁移及对照，见下节。该结果不代表共享库已部署，更不是生产验收。

#### 专用库复核（2026-09-30）

- 从当前 `rental_os` 只读复制；源库 167 条迁移，克隆部署后 169 条（品类版本结构与旧外键名对齐各一条）。4 个品类及 6 个空间均获得旧库快照绑定；`Tenant=4`、订单 27、报价 30、客户主档 9，迁移前后数量一致。重复 `migrate deploy` 无新增迁移。显式运行定义对账建立 4 个 `builtin_runtime` 版本；重复对账无正文改动。Seed 连续运行两次，版本与原品类正文摘要保持不变。临时库及授权已清理。
- 发现四个数据库品类行与当前实际运行的 `RENTAL_CATEGORY_DEFINITIONS` 均有差异：名称在库中呈问号，术语、属性结构与业务模型不同；车辆的数据库 `defaultCapabilities` 比运行定义少 `delivery`。版本号相同也不能视作正文相同。因此迁移先保存旧库快照为 `legacy_baseline`，再由显式、幂等的运行定义核对步骤建立 4 个 `builtin_runtime` 发布版本，并将 6 个空间从旧库快照绑定到运行版本；**不覆盖旧品类行，不把运行版本声称为历史订单依据**。
- Prisma 结构比较另显示 `customer_corporate_credit_ledger` 和 `rental_offline_payment_registrations` 两张旧表的三处外键**名称**漂移。另立增量迁移仅对齐外键名，引用列及删除行为不变；克隆库复核未发现 schema 差异。此迁移不涉及业务字段或数据搬移。
- `npm run test:rental-core` 等更宽的基线另列验证；真实 MySQL 全经营链及宿主验收仍未由上述迁移演练证明。

### 部署检查中的原已验与未验

- 已验证：独立克隆库增量迁移、重复部署、Seed 幂等、结构无 drift、业务行数保持、版本引用外键、唯一声明并发、过期采用修订号报价拒绝。
- 尚未验证：目标环境备份恢复、共享库部署、多实例新旧版本并存门禁、不兼容旧实例重新接入阻断、第五品类后台任务及全端链路、兼容程序回退。
- 测试库恢复/清理结果不等于生产灾难恢复。以上待验收项保留在专项任务中，不标记完成。
