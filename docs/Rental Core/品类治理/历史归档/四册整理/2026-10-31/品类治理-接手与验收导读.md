# 品类治理接手与验收导读

版本：v1.0；日期：2026-10-31。

> 本册解释既有跨文件入口及验收路径，不另建任务或替代[需求v1.3](品类治理-需求.md)、[任务v1.6](品类治理-开发任务.md)。当前施工状态见[接续](品类治理-协作接续.md)，已做/剩余及历史证据见[记录](品类治理-开发记录.md)。接口存在不等于完整链路或获准执行；当前只有准备的路径不能当正式采用。

## 1. 先辨层级与版本

- 新增服装等租赁类型：本专项，仍使用Rental订单/库存/履约。
- 接CRM/TMS等另一领域：独立[平台Core接入专项](../../平台底座/Core接入/平台Core接入-需求.md)，不能当Rental新枚举或Hook。
- 品类正文发布不改空间；政策修订不改正文；空间采用不改Core实现；程序回退不等于采用旧品类或恢复数据库。
- 原[项目指南§5.1](../../公共技术资料/开发指南/项目-开发指南.md#51-品类与动态字段)仍描述固定注册/迁移路径；本需求§1.4已明确动态组合能力完成后的目标替代。不能照旧指南给第五品类验收临时补枚举，也不能因目标已写就宣称当前动态创建可用。

## 3. 恢复实施前的核对顺序

1. 核对[根规则](../../../AGENTS.md)、当前工作树/权限/并行作者和原任务依赖，不采用旧接续里的启动命令作授权。
2. 先核实原01～04基础与历史保护，再按05～08完成治理/采用。不要因为有准备弹窗便从“补一个采用按钮”开始。
3. 对正式采用，列全最终检查：当前人类权限、目标政策、来源绑定/准备/实体修订、准备后新增实体、唯一声明、库存/价格/规则/检查/能力/商业权益；固定锁顺序和同事务生效集合。
4. 09～12动态编码/多端接通后，13在同一冻结构建里通过后台创建两个新编码，不能现场改Seed/注册表；14独立复核与资料收口。
5. 平台Core解耦若同时推进，以固定接入合同协调，Rental品类业务留本专项；不重写其状态或借通用合同跳过当前门禁。

## 4. 有限验证与证据模板

已有验证定位入口包括[根命令清单](../../../package.json)、[品类治理测试](../../../tests/category-governance.test.cjs)、[版本解析测试](../../../tests/category-version-resolver.test.cjs)、[版本迁移测试](../../../tests/category-version-migration-db.test.cjs)、[四品类基线](../../../tests/rental-four-category-acceptance.test.cjs)、[能力Hook测试](../../../tests/capability-hook-runtime.test.cjs)。必须先读脚本及前置：其中有构建、环境或真库依赖，不能按名称认定离线并直接执行。

每个完整阶段在开发记录写明：

| 证据栏目 | 要求 |
| --- | --- |
| 原任务/验收 | CAT-GOV与CAT-A对应编号，不新增平行统计 |
| 固定对象 | 工作树/提交或明确WIP、合同/结构/能力版本、构建标识 |
| 真实消费 | 角色/入口/当前授权、输入、正式服务、提交点与原结果 |
| 正反例 | 正常业务、越权、陈旧修订、并发/重复、失败/失应答恢复 |
| 验证层级 | 静态/类型、离线、真库、浏览器、微信Host、多实例、供应商分别列 |
| 命令/结果 | 实际执行命令、退出码、日志/fixture位置；未运行不写通过 |
| 剩余/回退 | 缺实现与缺证据分开，最低回退及旧事实保留，不清理未知WIP |

只测静态或替身不能完成A17原子采用、A18真库唯一性、A21程序兼容回退或A14/A22后台动态经营。预览关闭不等于安全验收完成，`preparedOnly`不等于`adopted`，字段配置不等于行业算法上线。
