#### 专用库复核（2026-09-30）

- 从当前 `rental_os` 只读复制；源库 167 条迁移，克隆部署后 169 条（品类版本结构与旧外键名对齐各一条）。4 个品类及 6 个空间均获得旧库快照绑定；`Tenant=4`、订单 27、报价 30、客户主档 9，迁移前后数量一致。重复 `migrate deploy` 无新增迁移。显式运行定义对账建立 4 个 `builtin_runtime` 版本；重复对账无正文改动。Seed 连续运行两次，版本与原品类正文摘要保持不变。临时库及授权已清理。
- 发现四个数据库品类行与当前实际运行的 `RENTAL_CATEGORY_DEFINITIONS` 均有差异：名称在库中呈问号，术语、属性结构与业务模型不同；车辆的数据库 `defaultCapabilities` 比运行定义少 `delivery`。版本号相同也不能视作正文相同。因此迁移先保存旧库快照为 `legacy_baseline`，再由显式、幂等的运行定义核对步骤建立 4 个 `builtin_runtime` 发布版本，并将 6 个空间从旧库快照绑定到运行版本；**不覆盖旧品类行，不把运行版本声称为历史订单依据**。
- Prisma 结构比较另显示 `customer_corporate_credit_ledger` 和 `rental_offline_payment_registrations` 两张旧表的三处外键**名称**漂移。另立增量迁移仅对齐外键名，引用列及删除行为不变；克隆库复核未发现 schema 差异。此迁移不涉及业务字段或数据搬移。
- `npm run test:rental-core` 等更宽的基线另列验证；真实 MySQL 全经营链及宿主验收仍未由上述迁移演练证明。
