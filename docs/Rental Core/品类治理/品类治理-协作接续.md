### 5.3 恢复实施前的核对顺序

1. 核对[根规则](../../../AGENTS.md)、当前工作树/权限/并行作者和原任务依赖，不采用旧接续里的启动命令作授权。
2. 先核实01～04基础、能力合同/条件粒度和历史保护；05～07提供模板/治理，新空间路径按09～12推进，存量08独立收口。当前尚未接通的链路不能按页面存在视为可用。
3. 对存量采用，先解决分批累计/回读/撤回与规模边界，再列全最终检查：当前人类权限、目标政策、来源绑定/准备/实体修订、准备后新增实体、唯一声明、库存/价格/规则/检查/能力/商业权益；固定锁顺序和同事务生效集合。
4. 13可先记录新空间场景，完整验收须08及09～12齐备，在同一冻结构建验证两个新编码和两组不同执行组合，不能现场改Seed/注册表；14再独立复核与资料收口。
5. 平台Core解耦若同时推进，以固定接入合同协调，Rental品类业务留本专项；不重写其状态或借通用合同跳过当前门禁。

验收定位与证据模板统一见[开发任务](品类治理-开发任务.md#acceptance-evidence)。入口存在不等于链路接通，不使用旧记录的环境许可。
