## 4. 第一阶段：统一基础

### CAT-GOV-01：实施清单与四品类行为基线

状态：`In Progress`。依赖：负责人启动专项开发。

- 逐模块列出品类定义读取、固定枚举/映射、默认配置、能力必选/适用判断、元数据缓存、字段渲染及订单历史执行入口。
- 固定首批可组合能力与模板清单：逐项关联真实实现/版本、库存和资料前提、执行环节、依赖/冲突、条件适用及各端支持；标清须先完成的通用化改造。依需求§1.6标注Core业务、公共服务及宿主接点，不把平台管理员页面移入公共业务内核。
- 核对数据库实际结构、迁移链、现有品类数据与静态定义差异；记录无证据字段，不静默覆盖任一来源。
- 形成迁移与兼容设计：品类版本/空间绑定、legacy 处理、动态编码、发布/采用事务、现有规则与价格版本的边界。
- 明确独立暂存的批次保存/回读/撤回、集合修订、累计规模、分页及最终事务限制；允许部分准备且不提前写入经营事实。区分展示调整、兼容扩展及影响存量的检查范围，同步两条采用路径的政策、部署顺序及最低回退版本。
- 建立四品类代表性基线：型号资产、报价明细、预占分配、取消、续租含缓冲、取还检查、结算及权限。只承诺已实现路径，缺项回原任务处理。
- 基线结果、必要差异、冻结清单及验证证据写入既有开发记录，任务只引用固定依据，不另建附件台账或交付说明册。

验收：可逐项追踪旧读取入口到目标服务；迁移对象、数据风险、现有能力限制与测试范围明确。仅规划不伪装成数据库演练通过。对应 CAT-A01、A02、A16。

### CAT-GOV-02：品类版本与空间绑定数据基础

状态：`In Progress`。依赖：CAT-GOV-01。

- 复用品类身份表，增加草稿/不可变发布版本、结构版本、来源及发布/采用审计模型；空间增加版本引用和采用修订号。
- 明确品类新开通范围、各发布版本的新建/升级/恢复采用资格及默认推荐引用；可调整的资格政策独立修订和审计，不改已发布正文。建立受控预备数据的存储/请求契约，记录目标版本和来源修订，不作为活动配置。
- 预备集合支持实体/字段稳定引用、分批累计、明确撤回和操作回读；批次、集合、来源绑定及实体修订分别有防冲突依据。保存部分准备不要求全空间已经满足目标版，准备完成状态由独立完整性检查产生。
- 首阶段保持四品类编码可用，不为了建版本层一次性开放动态品类；动态标识迁移在 09 中完成。
- 对可证明的当前空间配置进行确定性初始版本绑定；不把当前定义强行回填为历史订单曾采用的版本。
- 增量迁移先兼容结构，再回填核对，再收紧约束；保留历史业务数据，不修改已应用迁移、不 `reset` 或清库。
- 形成符合需求第 7.4 节的部署/恢复清单：结构兼容、读执行程序升级、API/后台任务实例核验、动态写入开放分步进行。基础阶段不开放新编码；不能把数据库已迁移等同于全部程序可承接新数据。
- 新空间初始化在原事务内绑定明确的发布版本；失败不能留下空间空壳。
- Seed 只补缺失身份/内置版本，不覆盖已有发布内容；正式模板与演示样本分开。

验收：专用克隆库迁移前后编码、关系和事实数量核对一致；重复执行初始化不覆盖配置；外键、不可变版本和冲突写入验证通过。共享库部署须另有明确授权。对应 CAT-A02、A04、A07。

### CAT-GOV-03：统一解析与配置合法性

状态：`In Progress`。依赖：CAT-GOV-02。

- 建立统一品类解析服务，按空间当前绑定或业务明确版本读取；接入初始化、型号/资产字段校验、报价、能力治理/Hook 和安全元数据投影。
- 将支持范围、默认值、覆盖政策和硬约束分开，定义缺省、空值及清空语义；不做任意深合并或表达式引擎。
- 代码只注册执行实现及结构/兼容限制，不再静态决定同一空间的品类业务政策。
- 分开校验全品类适用能力、专用白名单及单位/结构型计价条件，不能将 `shared` 标签或复制来源当作准入依据；需要通用化的兼容改造单列并纳入 09/13 验证。
- 在原注册表、解析服务及执行端口补齐需求§4.3.1的能力合同；通用能力使用代码支持的业务前提，专用能力保留限制，不增加通用脚本/条件引擎。统一输出字段、依赖、缺项和受控处理入口，供模板引导与真实执行消费。
- 按需求§4.3.2从可信商品/订单行及操作上下文判断条件必选，区分空间基础与商品/交易触发后的要求；未触发不误拦，触发后缺项不能靠客户端漏传绕过。业务判定留Core，当前权限继续复验。
- 复用资产唯一值声明的事务机制，补齐型号动态属性和全部已支持写入口；定义空间/实体/字段/规范化值的唯一口径，覆盖改值时旧声明释放与新声明建立。为 08 提供目标版本校验和非唯一转唯一的存量冲突/声明准备能力，不提前使预备约束生效。
- 缓存按不可变版本组织，采用后读取权威空间绑定；事务提交前不发布缓存，多实例/重启一致。
- 明确错误与失败恢复；未知品类/版本拒绝相关新业务，不回退另一品类。只允许有登记依据的 legacy 路径。

验收：修改合法草稿不影响运行；不同进程读取同空间同版本一致；必选、依赖、互斥、默认单位、未知字段和超大配置的正负例通过；型号与资产唯一写入分别有事务及并发证据，目标版本校验不放松当前保存校验。对应 CAT-A01、A05～A07、A10、A18；为 A17、A22 提供基础。

### CAT-GOV-04：报价、订单与执行版本保护

状态：`In Progress`。依赖：CAT-GOV-03。

- 报价固化品类版本引用与必要政策/检查快照；建单复制有效报价依据，不重读最新品类。
- 复核续租、换货、取还、异常和结算，按需求第 6.3.1 节逐动作固定取值矩阵：独立续租的新增时段按申请时适用价格/日历/规则，原价补差按原依据，换货按明确选择的价格基准；不把历史保护改成所有后续动作只能取原价。
- 后续变更保存实际使用的品类政策、实现及价格/规则/日历引用或必要快照；按对应商品、时段及变更事实执行检查与结算，不将替换商品的新检查要求套回原商品。验证新版已移除旧单单位/能力时的兼容成功和缺依据明确拒绝，不静默切单位/算法。
- 保存条件能力的实际适用依据和必要字段/执行快照；同一空间不同商品按自身条件执行，不把新版本的商品适用规则套回旧单。
- 区分模板版本与实际能力/策略版本，检查在途依赖；旧配置对应实现不可被新发版直接删掉。
- 权限、撤权和当前安全校验仍执行，不能将历史快照当永久操作授权。
- 为无法证明历史定义的存量建立显式兼容及诊断，不重算历史金额、不伪造版本证据。

验收：品类升级后旧报价建单及后续动作按需求第 6.3.1 节取值，不追改原事实；现价变化按约定影响独立续租或替换商品，不影响原价补差；保留旧实现，模拟缺失依赖时明确阻断发布或提供登记兼容，不能静默改算法。四品类基线复跑。对应 CAT-A09、A10、A16、A19。

## 5. 第二阶段：平台管理闭环

### CAT-GOV-05：平台 API、权限与发布服务

状态：`In Progress`。依赖：CAT-GOV-03、04。


- 平台命名空间提供列表、新建、复制、草稿分区 PATCH、校验、预览、影响分析、发布、开通范围和审计接口；能力目录只读真实实现。
- 上述服务、仓储及领域合同属于Rental Core；平台提供可信身份与公共能力，宿主按PCH接点装配。模板复制保存独立品类草稿与来源，不建立随来源自动变化的继承链；新空间绑定与已有空间采用分路，均有正式类型、授权和原操作回读。
- SaaS audience 与查看/编辑/发布/停止新开通/审计权限分别检查，拒绝租户 `*` 越权。
- 已发布正文不可改；草稿修订号防覆盖，发布带幂等/并发保护，审计与发布同事务落库。
- 分别维护品类新开通范围、版本新建/升级/恢复采用资格及默认推荐版本；资格政策单独带修订与审计，不修改已发布正文。候选列表和直接指定版本的请求使用同一资格校验，资格或范围调整与创建/采用并发时在提交点复核。
- 发布检查字段结构、支持范围、依赖、互斥、已有算法及能力的适用性；不能由请求把实现状态标记为已上线。
- 元数据/影响结果只提供治理必要信息，不返回客户、订单资金或服务密钥；同步 DTO、shared、OpenAPI 与权限表。
- 阶段二优先交付已有品类的版本维护接口；新品类创建契约可以先定义，但其正式持久化和开放依赖 09，不以无法通过当前枚举校验的接口宣称可用。

- 采用在事务内复核期望版本、采用资格、实体修订及全部受影响数据，包括准备后新增的记录；资料补丁、唯一声明、必要配置引用、绑定及审计原子生效。并发报价固定读一个完整组合，失败保留旧版与可修正输入，重试不重复初始化或应用补丁。

## 9. 实施与部署约束

原设计与部署检查于2026-10-31归并，本版按2026-11-09批准的方案补齐组合、分批暂存和两路径约束；不沿用旧现场或启动许可。原14任务/22验收身份保留，历史扫描及克隆库结果见开发记录链接的月度归档。

### 9.1 已有设计决策

1. 复用 `rental_category_definitions` 作为稳定身份；新建草稿/发布版本和独立可修订的开通、版本采用政策。空间保存当前版本 ID 与采用修订号。发布正文不可更新；政策变化不回写正文，也不追改当前绑定。
2. 候选资料继续采用**独立暂存**，扩展为受控批次和可累计集合：按空间、目标版本、来源绑定及实体原修订保存结构化补丁，实体/字段稳定引用更新，显式撤回；部分保存与完整性检查分开。单批/累计大小、分页、最终事务规模及回读合同在01/02固定，08/13验证；当前经营接口仍执行当前版校验。最终采用在同一事务中锁定并复核资格、修订、全部受影响事实及唯一性/价格/规则依赖，原子提交资料、必要声明、配置引用、绑定和审计；失败保留暂存。价格/规则仍走各自草稿与发布。
   最终事务的代码安全范围固定为型号/资产合计10000条、每配置领域10000条且配置合计50000条、候选JSON合计16MiB；采用正文/准备集合保留原更小限制，不放大单批。范围从同事务当前数据读取，超限保留原事实与暂存。该范围是离线实现上限，真库承载及生产开放仍须原验收证明。采用请求固定来源/准备/目标政策修订、原键及明确原因，原结果按原审计回读；后续政策或绑定变化不抹去已提交收据。应用事务最大等待10秒、执行30秒；超时不证明未提交，不自动重跑。
3. 先添加兼容结构，确认旧程序可读写，再回填可证实的当前空间绑定。存量报价和订单没有历史版本证据的标记 `legacy`，保留原价格/规则/检查快照，不伪称曾采用当前版本。之后升级所有 API 与后台任务读路径，最后再迁移 enum 与开放动态写入。
4. 品类新开通政策与各版本的新建/升级/恢复资格分别校验。推荐版本是显式引用，不能取最新代替；停止新开通不禁止既有空间履约。恢复旧版也须兼容检查，不能删除升级后字段以求通过。
5. 动态写入开关默认关闭。记录最低兼容程序版本，并在所有 API/后台任务实例通过兼容性检查后才开放。产生动态事实后不得接入只识别四品类的旧程序；关闭开关不是数据回滚。数据库灾难恢复另需授权和资金事实核对。
6. 租户价格版本、规则版本和营业日历独立于品类模板：旧报价建单复制原快照；独立续租新增时段读申请时现价，原价补差读原依据，换货读所选价格基准，各自记录变更依据。不可拿“历史保护”一概冻结后续现价。
7. 组合合同在现有Rental注册表、解析及执行端口扩展，统一驱动模板引导、业务校验和安全元数据；品类独立版本固定来源。条件由可信商品/操作事实求值，声明、实现、实例启用和条件触发分别校验；不把shared标签当准入，不新增平台通用规则引擎。
8. 原[差异比较](../../../apps/api/src/modules/rental-core/category-definition-diff.ts)可作为分级入口，按受影响字段/能力规划准备及声明变更；最终仍复核并发新增/修改，不能只信准备时快照。仅展示变化不无差别重建全空间唯一声明。具体锁顺序、承载上限和失败恢复由08在现有事务边界内落实。
9. Rental提供治理服务、数据及前端贡献；底座只经正式公共接点提供身份/权益/挂载等服务。现有[治理服务](../../../apps/api/src/modules/rental-core/category-governance.service.ts)、[解析服务](../../../apps/api/src/modules/rental-core/rental-category-resolver.service.ts)和[空间能力服务](../../../apps/api/src/modules/rental-core/workspace-capability.service.ts)是复用入口；这些路径是当前实现位置，不代表拆分已经完成或必须新建某个包。

条件只采用库存形态、履约方式、型号枚举/布尔属性的交集，最多32项；单次条件事实最多1000个型号，按组预约包含服务端冻结的成员，套装包含必需组成。分类缺失明确拒绝；不含任意表达式。快照固定版本、政策摘要、履约方式、根商品、必需组成及匹配结果；保存前在原空间事务锁内重读事实。检查投影可以缩小至取消后或本批商品，新增/替换商品必须有动作自身依据。报价、订单和变更的快照不可改写；缺历史依据不以当前属性补造。

后台条件编辑与检查关联分别归原页签。选择所需检查项只提示跨页缺项，未经明确操作不保存其他页签。目录的已实现状态来自实际注册版本，结构合法与真实渠道/宿主验收分开。

已有空间采用按同空间当前型号事实与启用履约方式复用同一条件 matcher，触发者加入实际必选，分类缺失不能当未触发；空间集合与单次报价快照保留各自上限。预备可以明确选择目标必选或条件声明的新实例，但不自动选择/激活，不借准备恢复暂停/停用实例。商业行锁先覆盖可能依赖的上界，提交前按实际候选必选和启用实例读取同事务期限/权益，实际依赖超界拒绝。未触发且未启用的条件不自动成为商业义务；显式启用的实例仍按其真实依赖验证。

事务内人员授权沿原[Auth](../../../apps/api/src/modules/auth/auth.service.ts)与[平台身份仓储](../../../apps/api/src/modules/platform/platform.repository.ts)映射，租赁采用权限及全空间范围由[Core授权接点](../../../apps/api/src/modules/rental-core/category-adoption-access.ts)核对。仅原Guard验证的运营会话提供会话ID/访问到期证据，不存原令牌、不接受请求体空间或自由操作人作为授权。固定锁序为租户→账号→原会话→空间成员→账号角色关系→按ID角色/权限关系→按ID权限，再进入商业目录→品类身份/政策→空间业务锁；授权变更复用这些实际行，缺持久化身份拒绝。准备保存/分页/预览/候选及原批次收据读取同事务复验；返回前再次核对原会话、到期、当前角色及全空间/地点范围。并发写冲突返回可核对结果并保留原键，不自动重跑；原收据仍按当前权限与原操作人读取，不因目标资格收窄而改写或消失。此接点不授予完整采用，不替代最终业务/批次/政策兼容闸门。

条件能力的检查就绪同时核对目标声明和实际登记的执行合同，并从同事务启用的租户取还模板应用[原快照字段投影](../../../apps/api/src/modules/rental-core/rental-inspection-template-snapshot.ts)，再复用[Hook检查准入](../../../apps/api/src/modules/rental-core/capability-hook.runtime.ts)。条件未触发者不增加该检查义务；触发者缺任一所需阶段/字段、字段类型不一致或缺可信合同执行器即拒绝。投影不回写模板、不自动补新增必填字段、不改旧单快照；所需模板继续通过租户原检查配置明确准备。

明确采用的[应用入口](../../../apps/api/src/modules/rental-core/category-adoption.application.ts)拥有事务与原键收据，[最终配置检查](../../../apps/api/src/modules/rental-core/category-adoption-final-compatibility.ts)拥有受权配置的读取/结构/范围证据，原实体/能力阶段只写获准候选。人员、商业、政策/来源/准备/实体及配置均在同事务复核，绑定/审计/原收据共同提交；完整配置检查与经营就绪、宿主、部署验收分别表达。原收据必须与原审计、指纹及目标身份一致；回读不依赖当前目标资格或当前绑定，不自动重新执行。当前非生产采用测试开关默认关闭，不承担全实例兼容或生产开放授权。

### 9.1.2 模板创建与原操作合同

首批蓝图为`serialized`、`quantity`、`kit`，修订`rental-template-1`，由[Core模板](../../../apps/api/src/modules/rental-core/category-creation-templates.ts)输出。仅组合原单件/数量/套装库存、既有计价单位和取还流程；套装蓝图沿§9.1.1的条件交接合同。蓝图不保存价格、商户目录或演示库存，数量蓝图不新增无用途的单件资产字段。

创建选择一个蓝图或一个不可变发布来源，选择范围须为其支持范围的合法子集，基础库存/取还能力不得删除。新编码与发布正文独立；复制来源可属于其他品类，但仅用于新身份的来源与差异比较，不允许已有空间换品类。平台查看/编辑权限及SaaS身份仍独立检查。

预览返回完整草稿、实际依赖错误、将移除的来源能力和正文指纹；最终创建复核该指纹与执行合同，身份、初始草稿及创建审计同事务写入，初始开通政策为未开放，创建不发布或启用经营。原操作按平台人员及操作键索引，原输入指纹与原结果固定；重复返回原结果，失应答读取原收据，unknown不能换键重做。后续编辑后的详情与原创建收据分开读取。

现有预览总闸门及动态创建开关默认关闭；`RENTAL_CATEGORY_DYNAMIC_CREATION`只用于本阶段非生产预览路径，不授予生产开放、数据库或部署许可。最终开放继续执行§9.2的多实例、迁移与对应路径验收，不把单进程开关当作完整兼容门。

### 9.1.3 新租户与空间选版接点

新租户的`categoryVersionId`可明确选择合格发布版；省略沿原推荐兼容，空值不冒充合法版本。经营空间既有同名字段复用，不在前端只提交品类而丢弃选版。初始化仍在原租户/空间事务内，Core拥有档案、默认空间绑定、配置及采用审计，平台宿主协调身份/角色与Core回调；缺Core或持久化解析器拒绝正式事务初始化。

默认空间首次建立核对目标create资格；已存在只读其权威绑定，不要求当前推荐仍存在，不通过初始化改版。选择来源、配置正文、空间绑定及实际操作人保持一致，外层事务返回后才预热进程缓存。初始化不授予原来没有的成员或经营权限。

候选读取由Core按品类新开通和版本create资格筛选；新租户只取全部允许的范围，已有租户可取其试点范围。推荐与可选版本分开。HTTP投影只返回稳定编码、名称、版本ID/标签、推荐标记和默认空间名，结构版本1，单页100项并标明还有更多，名称/编码/版本支持服务端搜索；选择不代替提交时复核。

原明确内存演示路径单独标记`builtin_demo`，不编造发布ID；缺发布目录或查询失败不回落演示目录。生产拒绝该来源，客户/员工端另按原任务接入安全投影，不能据此开放其新动作。

唯一性声明差异计划从锁定的来源正文、目标正文及真实候选资料求出范围/字段集合。新增/退役唯一声明、类型变化或规范化值变化纳入集合，完整释放集合内旧声明再建立目标声明，以支持值互换；未受影响范围/字段保持原声明 ID，文案、可见性和等价规范化值不重建。候选完整性与碰撞先验证，实体补丁、声明、绑定和采用审计仍由同一最终事务提交。内部实体阶段不授权采用、不替代最终兼容/规模检查。

#### 9.1.4 订阅身份与端侧字段投影

订阅目录/意向复用 Core 已发布身份的编码/名称投影；租户候选受新开通范围、试点及既有空间过滤，历史 pending 收据不因当前目录变化被重写。新写入在原事务验证动态编码，公共 DTO/OpenAPI 与客户端消费同一出口。

客户目录字段使用 `RentalAttributeDefinition.clientVisible`；只允许型号字段声明布尔值，新编码缺声明默认内部。四个内置编码未声明时沿 Core 内受控技术规格清单兼容；显式 false 覆盖兼容。HTTP 只投影合法标量与标签，`categoryMetadata.structureVersion=1` 提供明确绑定 ID、定义版本及只读名称/图标/字段/单位/选项，不返回规则与输入授权。读取前后核对权威采用版本/修订，变化拒绝混版结果。现有内置发布正文保持原文，不通过 Seed 覆盖加入可见性。

客户小程序只消费类型出口，按会话版本拒绝迟到目录和未知展示结构；预约网站复用 Shared 目录类型、标签、Core 单位和受控图标。缺价格、押金或时段库存保持缺失/unknown，真实金额由原报价链提供。员工端每次实际刷新读取当前空间定义，缺定义及不支持的检查控件明确阻断；原订单检查快照和布尔 false 保留。此契约不创建 APP 工程，也不代表真实宿主通过。

### 9.2 部署与恢复检查

#### 9.2.1 迁移前

- 确认数据库、程序分支、提交、API/任务实例清单及维护窗口，记录批准人。不得从目录名称推断数据库目标。
- 保存备份及校验值，验证备份能恢复到独立库。记录业务事实数量、迁移账本、结构差异和品类定义差异；含有乱码或不同定义的既有版本不得被 Seed 覆盖。
- 检查发布、采用、动态编码入口处于关闭状态。未交付的接口不能用直接修改数据库替代。
- 明确租户经营数据的写入归属，不对其他工作树的专用库或共享库运行测试 Seed。

#### 9.2.2 兼容结构阶段

- 只以已审核的增量迁移部署版本、政策、预备资料、审计及空间引用；禁止 `migrate dev`、重置库或修改已应用迁移。
- 报价/订单引用保持可空；既有订单没有来源证据时仍为空，不虚构当前品类版本作为历史依据。
- 对确定性可证明的空间定义形成初始绑定。非确定性差异先记录并阻断相关新业务，再通过授权的对账处理；不能静默选用最新内置模板。
- 再次部署应无操作，`migrate diff` 应无结构差异；核对业务行数和关联事实，而不是要求迁移账本数量不增长。

#### 9.2.3 程序切换及开放门槛

- API、定时任务、后台作业和消费者逐实例记录运行提交、支持的正文结构版本、动态编码读取能力和能力实现版本。实例清单遗漏一项就不能开放。
- 部署时先保持动态写入关闭，验证所有实例可读取现有四品类、历史空引用和新绑定；验证权限撤销仍按当前安全规则生效。
- 新空间路径须具备平台发布、动态编码、原子初始化/绑定、原就绪与授权、多实例兼容及所开放端业务证据；存量升级路径另须08的准备/最终采用/恢复证据。对应路径通过后才可按目标环境授权开放，不因新空间通过自动开放旧空间升级；完整专项继续要求全部验收。
- 后续新实例加入必须满足同一兼容条件，不允许不兼容旧程序重新接入。仅刷新单进程缓存不算验收。

#### 9.2.4 三种不同的恢复

| 情况 | 允许处理 | 禁止处理 |
| --- | --- | --- |
| 品类配置需要恢复 | 经目标旧版资格和存量资料兼容检查，明确采用旧发布版本，形成新采用审计 | 改写已发布正文、直接改空间引用、删新业务事实 |
| 程序故障需要回退 | 回退到能读取所有已产生编码、结构与历史执行依赖的程序版本，逐实例验证 | 将“关闭新增入口”当成旧程序已兼容，回退到只认四品类的构建 |
| 数据库灾难恢复 | 单独授权恢复方案，先独立库恢复并核对资金/库存/订单新增事实，制定补偿与切换计划 | 倒放迁移、删除新品类/订单或不核对新增交易就覆盖现库 |

最低可回退程序版本目前**未确定**：动态编码改造和历史执行兼容仍未交付，不能把当前阶段提交写成最终回退基线。发布说明必须在 CAT-GOV-09/13/14 验收后补齐具体提交和依赖。
