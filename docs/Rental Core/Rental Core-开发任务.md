# RentalCore 业务闭环专项开发任务

更新日期：2026-10-18（文档口径补充，原待办编号、状态、范围及安排不变）。范围：摄影设备、露营装备、车辆载具、工程设备共同的租赁核心；不以品类分支复制一套订单和资金实现。

规则核对区分法律强制要求、租户合法合同与租赁商自身政策。中国大陆法规不得直接宣称适用于香港或其他司法辖区；地区规则映射与合同法律审查仍待验收。

本文件保留原12项进行中、未完成与待验收工作；状态为2026-10-18原口径，未提供可靠百分比，不在本次整理估分。正式依据见[需求](<Rental Core-需求.md>)，阶段证据见[开发记录](<Rental Core-开发记录.md>)，当前归属见[协作接续](<Rental Core-协作接续.md>)；[原统一历史归档](../历史归档/整理前快照-20261016/docs/归档/多品类租赁平台已完成任务归档.md)保留旧来源。代码构建、模拟测试通过不代表真实数据库、支付通道或设备验收通过。

## 验收约束

- 沿用[平台需求](../管理后台/管理后台-需求.md)§1.4历史/当前准入矩阵、§4.9.2外部副作用和资金证据、§6.3场景交付及§7.2行业地区参数；这些说明细化本表原范围，不新增任务或提前启用未完能力。
- 原任务“待验收”不得解释为实现已齐全。实际缺实现、缺装配/可信依赖、已知缺陷与待真库/宿主/供应商证据，分别维护在[平台开发记录](../管理后台/管理后台-开发记录.md#当前业务闭环缺口分类2026-10-18)，不把审查修复流水追加到本表。
- CLOSE-MONEY-VERIFY与CLOSE-GUARANTEE分别核对真实资金来源、原操作unknown、远端成功后的本地恢复和保证金事实；CLOSE-CORP-VERIFY与原CORP-SETTLE-01共同核对旧单结算方式、币种、额度并发和逾期准入，不以普通现金订单代替账期证据。

- 权限、租户、经营空间、地点和人员可见范围贯穿读写、回放、查询与导出。
- 订单、库存、服务容量、企业应收、资金事件在正确事务边界下保持一致；外部支付采用可恢复的状态与对账，不假设跨系统原子提交。
- 每项至少覆盖正常流程、失败/重试、重复提交、并发和客户争议；需人工审批时明确待办与阻断条件。
- 真实数据库和支付验收必须明确使用的独立环境与证据，不以模拟测试代替。

## 实施接点与原任务映射

本节补齐原任务的阅读和验证路径，不新增范围、依赖、顺序或完成门槛。入口需要继续沿当前调用方与原事务追踪，不能仅凭文件存在宣称接通。

| 原任务 | 实施核对 | 直接消费者与验证出口 |
| --- | --- | --- |
| MONEY、GUARANTEE | 原支付/退款/预授权操作→外部适配→回调/查询→订单资金事件→原收据；远端成功与本地提交恢复分开 | 后台资金/凭证、客户本人支付状态；取消后到账、并发/分笔退款、unknown与原商户关联 |
| CORP | 企业债权/回款及allocation→订单应收/资金上下文→结算门；锁与账务原子边界一致 | 企业账务与订单付款/结算；原payment不再与allocation合计收入，FIFO/历史债权/并发核销 |
| USAGE、WAIVER、INSPECTION | 冻结费率/保障/检查依据→分配项及基线→归还/异常→裁定/客户响应→补退；原修订/冲销不覆盖 | 后台与员工交接、客户费用确认；多批/续租/换货、上限与事故证据、连续申诉/并发 |
| NONRETURN、OFFRENT、VEHICLE-AFTER | 特殊责任/证据→资源状态及应收/保证金处置→客户争议→补退/结案 | 对应正式业务动作和通知入口；不得借普通归还、当前配置或手动终态绕过 |
| SAFETY、QUARANTINE | 当前主体/资格→具体资源/有效期→检查/异常→独立隔离/缓冲→正式恢复 | 配货/领取/归还/维修；混合库存、多预占/同资源多异常及撤权矩阵 |
| NOTICE | 原通知任务/消息→供应商受理/回执→订单可信时点→失败/unknown核对及补录 | 工作待办和客户渠道；冷启动、多实例、关闭/限流及禁止生产模拟 |
