# 管理端界面设计规范

> 本文记录 `apps/admin` **当前已实现**的界面规范，不是未来设想。
> 设计语言与组件一律采用 **Ant Design v6**，不自建组件库、不引入第二套设计体系。
>
> 文中标注「**机器校验**」的条目由 `scripts/validate-react-admin.cjs` 逐条断言，
> 改动破坏后 `npm run test:admin` 会失败。其余条目是代码中的既成约定，改动前请先读本文。

## 1. 技术基线

| 项 | 版本 / 取值 |
| --- | --- |
| Ant Design | `6.6.0` |
| React | `19.2` |
| 路由 | `react-router-dom` 7 |
| 数据获取 | `@tanstack/react-query` 5 |
| 全局状态 | `zustand` 5 |
| 构建 | Vite 8 |

根组件固定这三项配置（`app/App.tsx`）：

```tsx
<ConfigProvider locale={zhCN} variant="outlined" theme={createThemeConfig(mode)}>
```

- `locale={zhCN}`：界面语言为简体中文，日期、分页、空态文案都走 antd 官方中文包。
- `variant="outlined"`：**机器校验**。全局控件形态为描边式，不使用 `filled` / `borderless` 作为默认。
- `theme` 由 `app/theme.tsx` 生成，见下一节。

## 2. 主题与颜色

主题只通过 antd token 表达，**样式表里不写具体色值**——`styles.css` 全部引用 CSS 变量。

### 2.1 三种外观模式

`app/theme.tsx` 提供 `default` / `dark` / `compact` 三种模式（**机器校验**），
用户选择持久化在 `localStorage.rental_admin_appearance`，并同步写到
`document.documentElement.dataset.appearance` 与 `style.colorScheme`。

| 模式 | 算法 |
| --- | --- |
| `default` | `theme.defaultAlgorithm` |
| `dark` | `theme.darkAlgorithm` |
| `compact` | `[theme.defaultAlgorithm, theme.compactAlgorithm]` |

三者都是 antd 官方算法。**不允许**自定义 `glass` 之类的算法（**机器校验**）。

### 2.2 CSS 变量

```ts
cssVar: { key: `rental-os-${mode}`, prefix: "rental" }
```

因此所有 token 在 CSS 中以 `--rental-*` 暴露，例如 `var(--rental-color-primary)`、
`var(--rental-color-border-secondary)`、`var(--rental-border-radius-lg)`。
新增样式必须用变量取色，不得硬编码 `#xxxxxx`。

### 2.3 全局 token

| token | 值 | 说明 |
| --- | --- | --- |
| `colorPrimary` / `colorInfo` | `#1677ff` | antd 默认主色，未做品牌改色 |
| `colorSuccess` | `#52c41a` | |
| `colorWarning` | `#faad14` | |
| `colorError` | `#ff4d4f` | |
| `colorBgLayout` | `#f5f8ff`（仅浅色） | 冷调浅蓝背景，衬托白色卡片 |
| `borderRadius` | `6` | 基础圆角 |
| `fontSize` | `14` | |
| `fontWeightStrong` | `600` | 标题与强调统一 600，不用 700 |

### 2.4 组件级 token

| 组件 | 覆盖 | 意图 |
| --- | --- | --- |
| `Layout` | `headerHeight: 56`、`headerPadding: "0 24px"`、`bodyBg/footerBg: #f5f8ff`、`headerBg/siderBg: #ffffff` | 顶栏 56px；正文冷底、容器纯白（**机器校验** `bodyBg`） |
| `Menu` | `activeBarBorderWidth: 0`、`itemBg/subMenuItemBg: transparent`、`itemHeight: 40`、`itemBorderRadius/subMenuItemBorderRadius: 8` | 去掉选中态右侧竖条，改为圆角块（**机器校验**） |
| `Card` | `headerHeight: 56`、`bodyPadding: 24` | 卡片头与顶栏同高 |
| `Table` | `cellPaddingBlock: 12`、`cellPaddingInline: 8`、`headerBorderRadius: 8`、浅色下 `headerBg: #fafafa`、`rowHoverBg: #f5f8ff` | 仪表板密度（**机器校验** `cellPaddingBlock: 12`） |
| `Tabs` | `horizontalItemGutter: 24` | |
| `Progress` | 浅色下固定文本色与轨道色 | 避免深浅切换时对比度不足 |

## 3. 布局骨架

### 3.1 应用外框

`components/AppShell.tsx` + `styles.css`：

```
.app-frame-stage   全屏容器，padding: 6px，底色 fill-tertiary   ← 机器校验（6px）
└─ .app-shell      border-radius: 14px + 1px 描边 + 轻投影      ← 机器校验（14px）
   ├─ Header  .app-global-header   grid: 200px | 1fr | auto，高 56
   └─ .app-body
      ├─ Sider .app-sider          216px（收起 56px）
      └─ .app-workspace
         ├─ .workspace-context     面包屑行，min-height 54
         └─ Content .app-content   padding: 0 24px 24px，纵向滚动
```

- 外框留白固定 **6px**，是刻意的窄边距；**不得**改成 12px（**机器校验**明确拦截）。
- 页面滚动发生在 `.app-content` 内部，`body` 设 `overflow: hidden`，因此顶栏与侧栏不随内容滚动。
- 登录页用同构的 `.login-stage` / `.login-frame`（**机器校验** `login-frame`）。

### 3.2 顶栏

从左到右固定三段：品牌（点击回首页）→ 空隙 → 操作区（经营空间切换器 → 外观切换 → 分隔线 → 账号下拉）。
账号下拉当前只有「退出登录」。

### 3.3 侧栏

- 单层折叠菜单（`Menu mode="inline"`），一次只展开一个分组（`onOpenChange` 只保留最新展开项）。
- 菜单区可滚动但隐藏滚动条；底部固定「收起导航」按钮。
- 收起时 `openKeys` 传 `undefined`，交给 antd 弹出浮层。

### 3.4 面包屑

三段：首页图标 → 当前分组（**带可选菜单**，可在同组路由间跳转，**机器校验** `menu: { items: breadcrumbMenuItems }`）→ 当前页。
面包屑与左侧菜单同源于导航注册表，不单独维护。

## 4. 导航与路由注册

**唯一事实源**是 `app/navigation.tsx`：`APP_ROUTES`（路由表）+ `APP_NAVIGATION`（分组）。
外壳与路由器都从这里派生（**机器校验**：`shell` 必须调 `buildNavigationSections`、
`router` 必须消费 `APP_ROUTES`）。

每条路由的元数据：

```ts
{ path, label, permission, legacyPermissions?, icon, audience: "tenant" | "saas", capability?, categories?, menu? }
```

- `audience` 隔离 SaaS 平台面与租户经营面，`(route.audience === "saas") !== isSaasAdmin` 即拒绝（**机器校验**）。
- `permission` / `legacyPermissions` / `capability` / `categories` 共同决定可见性与可进入性，判定函数是 `canAccessRoute`。
- **前端隐藏不替代后端鉴权**：直接访问路由时 `AppRouter` 里的 `RouteAccess` 会渲染 403，后端仍各自校验。
- 切换经营空间时以 `租户:空间` 为 key 重挂整个受保护区（**机器校验** `<AppShell key={workspaceScopeKey}>`），避免残留上一个空间的数据。

### 4.1 品类术语覆盖

`app/navigation-terminology.ts` 是**无 JSX 纯模块**，按当前经营空间的品类术语覆盖
「商品目录 / 定价分组 / 资产 / 履约地点」四条路由与所属分组的 `label`。

规则：

- 只覆盖 `label`，**绝不**改 `path`、`permission`、`capability`、`audience`。
- 模块内**不出现任何品类编码**（camera / vehicle 等）；品类知识只存在于共享包的品类事实源。
- 无品类档案（SaaS 账号、档案未就绪）时返回空覆盖，回落固定文案，不猜品类。
- 指标类文案不做术语替换：菜单叫「经营报表」而不是「器材报表」——指标定义不随品类变化，
  标签跟着品类变会让同一个数字被读成两种含义。

## 5. 页面结构范式

一个业务页面自上而下按这个顺序组织，缺哪层就省略哪层：

```tsx
<>
  <PageHeader title="…" description="…" view={<筛选/切换>} extra={<主操作按钮>} />
  <Alert type="info" showIcon title="口径说明" description="…" />   {/* 可选，解释数字含义 */}
  <QueryState loading={…} error={…}>
    <Row className="page-metrics">…指标卡…</Row>                    {/* 可选 */}
    <Card className="data-panel" title="…">…表格 / 明细…</Card>
  </QueryState>
  <Drawer …>…表单…</Drawer>                                        {/* 可选 */}
</>
```

### 5.1 PageHeader

`components/PageHeader.tsx` 只做两件事：

1. 设置 `document.title = "${title} · Rental OS"`；
2. 当且仅当传了 `view` 或 `extra` 时，渲染一行工具条 `.page-toolbar`（**机器校验**）。

因此**页面上没有大标题**——标题信息由面包屑与浏览器标签承载。禁止事项（**机器校验**）：

- PageHeader 内不得使用 `Typography.Title` / `Typography.Paragraph` 重新引入「标题+副标题」块；
- PageHeader 不得内置 `Segmented`，把某个页面特有的切换器强加给所有页面。

`description` 目前写入 `data-description` 属性，供无障碍与后续使用，不直接显示。

### 5.2 卡片与面板

- 常规内容容器：`<Card className="data-panel">`。
- 概览页大面板：`workspace-panel`；指标卡：`metric-card` + `metric-grid`（4 列，1180px 降 2 列，640px 降 1 列）。
- 卡片标题带计数时用 `<span className="panel-title">名称 <span className="panel-count">12</span></span>`。
- 卡片内工具条用 `panel-toolbar` / `table-toolbar`（左右两段，900px 以下改纵向堆叠）。
- 卡片一律无投影（`.ant-card { box-shadow: none; }`），层级靠描边与底色区分。

### 5.3 页签

页签统一是**胶囊态**（`border-radius: 999px`，**机器校验**），不是 antd 默认下划线，也**不允许** `type="card"`（**机器校验**）。

作为页面主导航的页签必须与内容面板**分离**：

```tsx
<Card className="tabbed-workspace">
  <Tabs className="standalone-tabs" items={…} />
</Card>
```

`tabbed-workspace` 去掉卡片自身的边框与内边距，`standalone-tabs` 把内容区单独包成带描边的白色面板。
**禁止** `<Card className="data-panel"><Tabs …>` 这种把主页签嵌在内容卡里的写法——
`validate-react-admin.cjs` 会逐文件扫描并报 `primary tabs remain embedded in content cards`。

### 5.4 表格

- 密度由 Table token 统一（12/8），页面不再逐个调 `size`。
- 表头 600 字重、`#fafafa` 底（浅色）。
- 表格内的行内操作用 `type="link"`，样式已被改造成**胶囊描边按钮**（见 `.ant-table-wrapper .ant-table-tbody .ant-btn-link`），危险操作加 `danger`。
- 金额列右对齐（`align: "right"`）。
- 每张表都要给 `locale={{ emptyText: "…" }}`，写清「这里为什么是空的」，不要留 antd 默认「暂无数据」。

### 5.5 表单与抽屉

- 新增 / 编辑统一用 `Drawer`，不用 `Modal` 承载长表单。
- 抽屉右上角放主操作（`extra={<Button type="primary" onClick={() => form.submit()}>保存</Button>}`），
  校验交给 `Form` 的 `rules`，不在按钮上手写判断。
- 抽屉关闭即销毁（`destroyOnHidden`），避免下次打开残留上一条记录的值。
- 表单底部操作条用 `.form-actions`（右对齐 + 上分隔线）。

### 5.6 加载、空态与错误

统一走 `components/QueryState.tsx`：加载显示居中 `Spin`（最小高度 280），出错显示
`Empty description="数据暂不可用，请检查 API 服务和登录状态"`。
页面不要各写一套骨架屏或 alert。

### 5.7 提示信息

- 页面级口径说明用 `Alert type="info" showIcon`。
- 轻量行内说明用 `.context-note`（info 底色的圆角条，带图标）。
- 次要文字统一 `className="muted"`。
- 操作结果用 `App.useApp()` 的 `message`，不要 `notification` 弹卡。
- 按钮不可用时用 `Tooltip` 说明**为什么**不可用（缺哪个权限、缺哪一步前置），而不是只置灰。

## 6. Ant Design v6 API 约定

v6 改了几个高频 prop 名。**新代码一律用 v6 写法**；仓库里仍有 v5 遗留用法（会在控制台打 deprecation 警告），改到哪个文件就顺手换掉那个文件。

| 组件 | v6（用这个） | v5 遗留（不要新增） | 当前遗留数量 |
| --- | --- | --- | --- |
| `Alert` | `title` | `message` | 27 处 |
| `Space` | `orientation="vertical"` | `direction="vertical"` | 28 处 |
| `Drawer` | `size`（数字或 `"default"`/`"large"`） | `width` | 31 处 |
| `Modal` / `Drawer` | `destroyOnHidden` | `destroyOnClose` | 0 处（已清完） |

其他注意点：

- `Card` 用 `styles={{ body: … }}`，不用已废弃的 `bodyStyle`。
- `Select` 支持 `status="error"`，表单外的即时校验用它，不要自绘红框。
- v6 的 `Button` 在双字中文标签间会插入空格（如「编 辑」），做文本匹配时要按去空格后比较。

## 7. 响应式

三档断点，均在 `styles.css` 末尾：

| 断点 | 变化 |
| --- | --- |
| ≤ 1180px | 指标卡 4 → 2 列；`workspace-grid` 变单列 |
| ≤ 900px | 顶栏收成两段、隐藏账号文字；内容边距 24 → 16；工具条改纵向 |
| ≤ 640px | 外框留白与圆角归零（占满全屏）；隐藏品牌文字；指标卡单列 |

## 8. 动效与可访问性

- 按钮有按压反馈 `transform: scale(.97)`（**机器校验**），过渡 0.2s。
- 圆形图标按钮 `border-radius: 50%`。
- `@media (prefers-reduced-motion: reduce)` 下关闭全部动画与按压位移。
- 纯图标按钮必须给 `aria-label`（例：`aria-label="刷新经营概览"`）。
- 深浅两种模式都要保证对比度；这也是 `Progress` 在浅色下固定文本色的原因。

## 9. 明确禁止

以下由 `validate-react-admin.cjs` 拦截：

- 装饰性渐变：`linear-gradient`、`radial-gradient`（外壳、登录页、样式表内）；
- 装饰性光斑 `stage-orb`；
- 卡片式页签 `type="card"`；
- 自定义 `"glass"` 主题算法；
- 应用外框留白放宽到 12px；
- 主页签嵌进 `data-panel` 卡片；
- 引入 Vue / element-plus 等第二套前端体系；
- 重建 HTTP 客户端或另起一份 query client（必须复用 `api/http.ts` 与 `app/queryClient.ts`）。

另外几条虽未机器校验，但同样不要做：

- 不在样式表里硬编码颜色；
- 不给页面加自定义大标题块（标题归面包屑与 `document.title`）；
- 不为单个页面引入新的图标库或字体。

## 10. 自检命令

```bash
npm run test:admin
```

```bash
npm run lint -w @store-rental/admin
```

```bash
npm run build -w @store-rental/admin
```

`test:admin` 即 `scripts/validate-react-admin.cjs`，覆盖本文所有「机器校验」条目；
`lint` 是 `tsc -b --noEmit` 类型检查。三条都过才算界面改动完成。
