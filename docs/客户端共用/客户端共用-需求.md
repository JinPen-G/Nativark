# 客户端共用需求

版本：v1.0（既有范围整理）；日期：2026-10-31。

> 来源为[原开发任务v1.0](客户端共用-开发任务.md)、[平台需求](../管理后台/管理后台-需求.md)及[客户端API说明](../公共技术资料/接口说明/客户端-API说明.md)。本册归纳已批准的共用需求，不新增渠道或业务；字段合同以shared/DTO/OpenAPI正式出口为准。现状见[开发记录](客户端共用-开发记录.md)，接手见[协作接续](客户端共用-协作接续.md)。

## 1. 职责与消费者

为客户小程序、租户预约网站和后续APP提供同一客户认证、会员、公开目录、报价/订单、渠道和外部集成事实。后台及员工适用的支付/文件/通知仍复用原服务，不借客户门面扩大audience。页面、宿主权限、导航、打包和发布归各端专项。

租户品牌、客服、协议/版本、帮助、横幅、发布空间和登录开关为共用配置；AppID、商户/证书等按渠道受控管理。已发布不等于已获交易资格；客户只见公开及本人受权范围，租户共享会员不开放跨空间订单/资金。

[企业客户后台](../企业客户后台/企业客户后台-需求.md)复用本共用身份/渠道/文件底座，但其企业管理授权、申请/审批和非本人订单投影为独立ECP增量；不直接放宽现有本人接口，也不改变本册八项原任务分母。

## 2. 原八项需求

| 原任务 | 需求结果 |
| --- | --- |
| CLIENT-CHANNEL-01 | 各端读取同一租户配置，未发布空间不可见，保存修订冲突不覆盖 |
| EXT-01D | 适用币种/租金instrument的下单、查单、验签回调、退款和对账使用原支付操作；客户端成功不入账，unknown不自动重做 |
| PREAUTH-01 | 真实冻结、转扣、释放采用独立资金事实及原供应商依据；未接入时明确模拟，不冒充银行冻结 |
| EXT-02 | 短信outbox、限流、重试、回执和原消息查询闭合，租户/空间额度隔离、号码脱敏，未知不重发 |
| EXT-03 | 上传会话、归属、短时访问、清理和审计同一生命周期，客户端不获长期密钥/原对象键，跨范围访问拒绝 |
| CAT-IMAGE-01 | 商品图片复用FileAsset，已授权端读取短时地址，删除/失败可追溯 |
| CLIENT-ACCEPT-01 | 两租户、两空间、本人/他人、重复/重启/隐私的真实组合验收；不能使用运营token替客户会话 |
| CLIENT-CONTRACT-01 | shared运行时合同、DTO/OpenAPI、Controller与API说明一致，client渠道/能力/错误语义可供各端正式消费 |

以上原任务范围、依赖和验收以任务册原行唯一维护，不复制百分比或另建子任务。

## 3. 前置与安全约束

真实微信、支付、短信和存储凭据、域名/证书及供应商测试环境由负责人另行授权准备；不在文档保存秘密。配置完整、连通成功、业务真实交易/回执分别证明。缺真实依赖保持明确不可用，不用mock补生产成功。

订单/金额/库存仍由Rental Core决定；查询、草稿、正式提交和原结果读取分开。同一操作失应答先按原引用核对，不换ID/供应商重复；历史配置关联与对象ACL不被当前配置替换。

## 4. 验收与范围限制

原顺序为渠道→合同→具备真实前置后的文件/短信/支付→组合验收。每端另行验证宿主行为，共用层通过不等于各端发布通过。当前八项百分比均待核实，本册不作实现审计，不因补齐需求开启APP、专业模块、生产渠道或真实交易。
