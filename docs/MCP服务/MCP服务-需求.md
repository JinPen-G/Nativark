# MCP 服务：受控业务能力接入需求

> 专项：Rental OS MCP 服务。
> 版本：v1.0；建立日期：2026-10-28。
> 正式方向：MCP优先，与Harness接入共同推进；Harness是首个客户端，Rental插件只补连接与会话体验，不另建插件专用业务通路。服务端提供授权、受控事实与业务能力，各客户端Agent自主决定呈现形式。
> 文档性质：负责人本轮确认的需求方向；仅授权更新文档，不代表已实现、已准许具体字段外发、安装、迁移、联调或生产开放。
> 配套：[开发任务](MCP服务-开发任务.md) · [开发记录](MCP服务-开发记录.md) · [协作接续](MCP服务-协作接续.md)。Harness消费者见[插件需求](../Harness插件/Harness插件-需求.md)。[原接入方案v0.3](../Agent接入改造/MCP服务-接入方案.md)保留为历史研究，不再作为活动任务表。

## 1. 目标与职责

提供运行在Rental OS服务端的标准MCP Server。经过后台开通和用户授权后，Harness、Codex、Claude Code及其他经验证的MCP客户端可以调用同一批获准能力；不要求安装Rental定制Electron，不依赖运营电脑在线，不需要先完成Harness插件再做MCP。

```text
Harness原Agent ─ 原MCP客户端（Rental插件按需增强连接 / 提示词）─┐
Codex / Claude Code / 其他获准MCP Host ────────────────────────┤
                                                            ↓
                         Rental OS MCP Server：标准协议 / 专用身份适配
                                                            ↓
                         当前权限 / 字段政策 / 限额 / 原操作关联
                                                            ↓
                         原reader / Core / 原请求与批准 / 原Task
                                                            ↓
                         原收据 + 最少获准事实 + 业务说明
                                                            ↓
                         各客户端Agent自主分析与呈现
```

原Web继续使用原登录和正式Controller；MCP是新的受控入口，不替换Web API或Core。共同建设指一套服务端接入治理、工具映射、投影、计量和执行适配，不是多个客户端共用一枚token。每个client / 用户 / 空间独立授权和撤销。

| 责任方 | 唯一职责 | 不承担 |
| --- | --- | --- |
| MCP专项与原身份 / 业务作者 | 标准运输、OAuth / grant、后台开通、工具发布、字段释放、服务端计量及原业务适配 | 新建Agent循环、定价器、批准系统、第二业务任务库或最终页面引擎 |
| Harness插件专项 | 原生MCP连接消费、必要授权交互 / 凭据适配、空间与会话绑定、提示词加载和原生展示验证 | 再实现一套服务端OAuth / 政策、绕MCP直调业务API、重复注册同一业务工具 |
| 各客户端Agent | 理解目标、选择获准工具、分析结果，自主生成文字、表格、图表、报告或展示文件 | 决定权限、改写Core事实、替人批准或承诺服务端可删除全部本地副本 |
| 原可信Web / Core / 执行器 | 人类真实选择、必要核对与批准、正式业务执行、原收据 | 被模型生成页面、聊天肯定或MCP提示词替代 |

所有原AI Native、定制客户端、Web / 官网 / 小程序、源码、测试、文档、依赖、隔离产物及WIP实际保留。原「Agent接入改造」v1.5仍在原目录封存，不改编号或进度。MCP与插件各自记录服务端交付、客户端消费证据，不把同一实现重复统计成两份完成。

## 2. 分阶段闭环

1. **首片：** 后台登记并开通最少范围 → 用户OAuth登录 / 同意 → Harness原生MCP连接 → 当前空间及获准工具发现 → 有界目录读取 → Harness自主安全呈现 → 撤权 / 过期 / 越权拒绝。
2. **只读扩展：** 可用性、原订单事实、本人原操作 / 任务结果读取；读取不新建云模型run，不将来源缺失补成事实。
3. **准备与执行：** 可信客户选择与澄清 → Core报价 / 原持久提案 → 可信Web核对 / 必要批准 → 原唯一执行 → 原收据；报价保存本身先具备恢复与计量。
4. **有限协同：** 先已有任务结果，后单独开通有限云场景发起及原取消意图；无人值守 / 服务身份、任意跨用户委派、资金处分不在本批范围。
5. **其他客户端：** Codex和Claude Code分别做真实版本验证，其他Host按声明补矩阵。首片Harness通过不等于任意客户端通过；整体通用接入验收仍包含指定Codex / Claude Code，不要求首片等待所有可选扩展。

最小只读MCP及其安全前置从第一片就进入真实调用链；不先做插件私有API再改造。Harness原功能足够时可直接连接；插件只补实际缺口，不成为MCP服务的强制前置。所有业务端口和字段仍按成熟度逐项开放。

## 3. 正式需求

### MCP-R01：标准协议与统一入口

- 主路径为HTTPS Streamable HTTP，使用实施前核验并固定的官方协议 / SDK版本，不把普通JSON API命名为MCP。首版以Tools为共同最小能力，Resources / Prompts按实现声明，不把Sampling、Roots、Elicitation、MCP Apps或长任务扩展作为基本查询或批准的前置。
- 既有研究以2026-07-28为目标、2025-11-25为明确兼容代次；每代发现 / 初始化、版本与方法元数据、结果序列化、取消、会话及HTTP方法分别按其规范验证，不能混合。实现时重新核对标准与目标Host支持，不从历史“latest”推断发布现状。首片按Harness实际共同代次验收，最终支持范围按MCP-A01 / A10逐代完成，不静默取消兼容要求。
- 未知 / 不兼容版本拒绝；协商只在业务执行前发生。新代次无协议Session时不能发行旧Session凭据；使用旧代次Session时仍绑定当前授权，Session ID / JSON-RPC ID都不是身份或业务幂等键。
- 验证合法Origin及元数据一致性；CORS / IP白名单不代替身份，缺Origin的原生客户端仍须认证。受保护响应不由公共缓存复用，不接受任意endpoint、redirect或模型拼接的业务URL。
- stdio远程连接器等兼容方式后续按明确需求提供，只代理同一远程受权服务，不直连数据库、不持有全平台身份。首片不因Host认证不支持就退回永久Bearer或关闭认证。

### MCP-R02：后台准入与最小授权

有效权限为平台接入许可 ∩ 有效客户端登记 ∩ 租户开通 ∩ 用户grant ∩ 原角色 / SaaS权益 ∩ tenant / workspace / location / dataScope ∩ 工具白名单 / OAuth scopes ∩ 字段政策 ∩ 资源上限 ∩ 必要原批准。缺任何依赖即拒绝，不提供匿名业务工具或数据。

| 后台对象 | 必须支持 |
| --- | --- |
| 接入应用 | client ID、public / confidential类型、可信回调、负责人、状态 / 到期和适用范围；不能只按客户端显示名白名单 |
| 租户接入政策 | 默认关闭；获准工具、风险、信息类别 / 字段、客户端类别、数量 / 速率 / 并发及云调用范围 |
| 用户grant与同意页 | 原用户、client、tenant / workspace、范围、修订、期限及撤销；明确外部模型 / 存储 / 分享边界，不默认一次申请所有写权 |
| 连接与撤销 | 本人及有管理权者可查看安全授权摘要、最近使用和撤销状态，不展示token；分别支持grant / 应用 / 租户停用 |
| 审计与政策保存 | 签发、扩权、拒绝、撤销、超限与原操作关联；政策修改沿原CAS / 幂等收据，unknown按原键核对 |

平台管理员不自动获得租户业务权；租户管理员不能扩大用户原权限。以上是原身份控制面的接入元数据，不是另一套用户 / 角色系统；持久化与迁移另按正式设计及当轮授权执行。

### MCP-R03：OAuth、凭据和原身份适配

1. 使用可信浏览器授权码 / PKCE S256，复用Rental原账号、改密与适用二次验证。MCP资源服务器提供RFC9728元数据；授权服务器提供RFC8414 / OIDC discovery；校验issuer、resource / audience、state、client、一次性授权码和登记回调，拒绝混淆授权服务器。
2. 授权服务器 / grant实现由MCP-02和原身份作者唯一交付，不另在Harness插件重建。优先成熟标准实现与原身份适配；已有Web Bearer解析不证明已支持OAuth AS。
3. 签发MCP资源专用短期access token；适用refresh轮换、并发刷新和复用检测须闭合。授权取消、超时及迟到回调不发布可用身份；已签发但客户端未收到的grant沿原机制核对 / 撤销，不伪称未签发。
4. 未携有效凭据返回规范认证错误及安全发现信息；token签名 / expiry通过后仍按当前grant与权限复核。不得透传MCP token给原Web HTTP，或用后台Cookie、Web token、模型Key、管理员服务账号代替。可信服务端适配必须接通Controller等价授权和ALS，包含原链中再次解析凭据的接点。
5. 默认grant固定一个tenant / workspace。切空间经可信选择取得适用授权，不让Web全局空间改变已绑定外部会话；主体、连接、client与请求范围固定到调用，迟到结果不得进入新范围。普通客户端会话ID只能关联，不能自授权。
6. client ID、User-Agent、`clientInfo.name`不证明官方二进制或受管设备；更高保证需要真实受管控制。优先预登记public client，不能把安装包内固定secret当秘密；CIMD仅经白名单与SSRF / 私网 / 跳转 / 缓存更新控制。回调精确校验登记scheme / host / path，只允许可信HTTPS或原生OAuth标准loopback例外，不能用任意域 / 路径通配放行。匿名动态登记、PAT、有期Bearer兼容、服务身份、mTLS / DPoP等不因本次方向自动开通。
7. 客户端凭据不能进入模型、工具参数、输出、普通项目配置或日志。默认本地文件、同OS用户进程和插件命名空间不是隔离证明；各Host须核对实际读取面。安全存储缺口不以复制长期token兜底。取消 / 断开只确认本地停止时，不得宣称服务端已撤销；远端撤销状态及可信后台入口应可核对。

### MCP-R04：现行能力与受控工具

MCP只发布原业务作者确认的能力，包含原工具码 / 版本、真实生产者、参数与输出schema、读权 / 风险 / 副作用、投影、原操作与计量规则。OpenAPI和历史工具清单只用于发现，不能自动全量开放。

| 业务能力 | 首批作用与限制 |
| --- | --- |
| 当前连接 / 范围摘要 | 安全授权标签和可用能力，无凭据 / 完整角色树，不返回其他人的授权 |
| 目录、可用性 | 复用`rental.catalog.search` / `rental.availability.check`，有界事实，不含未批准字段，不等于库存预占 |
| 客户选择结果 | 原`membership.customer.resolve` / 可信选择器的安全引用；候选个人资料不先送模型，同名不默认首项 |
| 原订单事实 | 复用`rental.order.explain` / 原reader，缺支付记录不等于未支付，读取不暗中发云模型 |
| Core报价与原提案 | 复用`rental.quote.preview` / `rental.order.propose`及原生产者，区分准备、持久保存、待确认和待审批 |
| 原批准建单 | 只在原批准及唯一执行全部条件满足时暴露`rental.order.commit`，不提供批准工具 |
| 原操作 / 收据索引与精确读取 | 当前独立读权、本人原关联、分页有界；不按最近记录猜本次结果 |
| 原任务 / 来源与有限协同 | 读状态 / 结果与发起云任务分工具、分scope；取消返回原意图收据，不伪称回滚 |
| 可信人类Action | 返回固定登记的获准页面入口，不含自动批准凭据，不接任意URL |

运输名称在MCP-01固定，原业务码不改；各Host允许加自己的命名空间，但同一连接只注册一份同一业务工具。列表按当前grant / 权限过滤并有界分页，缓存旧列表和直接 / 嵌套调用仍逐次验权。模型参数拒绝actor / scope / approval自授、未知字段、任意路径 / Header / SQL / 脚本或工具名。

### MCP-R05：信息释放、来源与生成材料

- 所有文本、结构化value、Resources、Prompts、安全状态、错误和审计先取当前受权的最少投影，不能只过滤模型展示字符串而保留完整后台响应给PTC / 嵌套工具。
- 输出按业务保留必要单位 / 币种、对象受控引用、观察时点、版本、范围、覆盖 / 缺项和原状态；partial不是全量，缺金额不是零，缺来源不以当前配置补历史。原`human_preview / not_sent`结果不直接转为MCP模型结果。
- 个人资料、凭据、模型Key、敏感附件及未审查自由文本不得外发；禁止在普通聊天粘贴敏感输入，实际选择留可信Web。服务器拒绝原文不能倒推客户端尚未将输入发给模型。
- 通用客户端只接正式批准可交外部处理者的字段；企业受管类别另需真实模型目的地 / 设备 / 存储 / 网络证据。严格要求无法证明则只给安全公开说明、可信入口或unavailable，不因要兼容而默许释放。
- 服务端不能保证普通Host历史、生成文件、截图、导出、其他插件和模型供应商副本会被远程删除。生成代码、隐藏节点和派生物都属材料，保存 / 分享须在同一释放许可内；TTL、audience和提示词不是强制回收。
- 平台 / 插件实际控制的业务缓存及派生摘要默认最长30天，临时未绑定附件最长7天，更短来源 / 政策期限优先；所有可控读取、重放、索引、导出 / 备份恢复均须遵守。无可靠可控链时不交付要求强制到期的正文；原业务文件、批准、订单和审计按原制度保存，不随客户端清理删除。

### MCP-R06：提示词与客户端自主呈现

服务端返回事实与约束，不返回必须套用的最终业务页面。各Agent根据目标和用户格式要求，自主输出文字、列表、表格、图表、报告或合规展示文件，不强制每轮生成代码，不新建Rental专用渲染器。

| 说明通路 | 要求 |
| --- | --- |
| 工具描述与安全结果说明 | 提供理解每个调用所需的条件、原副作用、单位、来源、缺项及unknown语义；不把凭据或权限快照当提示词授权 |
| MCP服务器instructions | 支持代次下提供简短版本化业务 / 展示指引；客户端是否采用、作用域及更新需逐端验证，不承诺强制注入 |
| `prompts/list` / `prompts/get` | 可选、无副作用的任务起步与展示引导；不可假设自动进入系统提示词，无此UI仍能通过Tools查询 |
| Harness插件会话贡献 | 只适配原Host不足的加载 / 作用域体验，消费同一说明版本并去重，不复制第二套业务规则，不替换完整系统提示词 |
| 可选Resources | 受权、版本化说明或原结果引用，每次读仍验权；URI不是bearer，不能提供任意文件 / URL模板 |

指引要求模型区分分析与正式事实，不省略关键金额 / 状态 / 来源，不重算Core结果、不把样本当全量；重新排版不重报或重执行业务。展示代码不取得凭据、不直接请求业务API或伪造授权 / 批准控件；必要选择与批准仍由原可信Web处理。

提示词未加载、被忽略、过期或恶意内容要求越权时，服务端控制仍成立。各Host的预览隔离、渲染失败降级和实际提示词生效属于客户端适配验收；服务端只控制释放什么及执行什么，不虚构对所有Host的完整约束。需要更强呈现 / 留存控制的资料缺证据即不交付。

### MCP-R07：可信选择、批准与唯一执行

报价的价格、押金、资格、时间 / 时区、币种和规则版本来自原Core。客户 / 商品选择、材料核对、必要审批沿原可信Web和固定Action；MCP工具确认、聊天肯定、生成页面表单 / 合成事件、Elicitation或`confirmed: true`都不能代替人类真实选择和批准。

准备、持久保存、批准请求、批准、Core提交、原收据分别表达。正式执行前及批准消费点复核当前主体 / grant / scope、原输入、选择证明、报价 / 对象 / 批准修订和业务前置；原批准原子消费，同一原操作跨Web / Harness / 其他Host仍只一份业务结果。

不发布人类批准、资金处分、收款 / 扣款 / 退款、高风险例外、授权管理、任意提示词代理、数据库管理或任意跨用户接管工具。服务端不能因客户端号称管理员或已确认而放开。

### MCP-R08：累计资源、原键与unknown

| 项目 | 首批固定上限 / 语义 |
| --- | --- |
| 自动业务目标 | 最多20次业务调用，含适用重试 / 轮询；最多2个并行只读、1个在途副作用 |
| 累计活跃时间 | 最长5分钟；人类等待不计活跃时间，但输入 / 报价 / 批准期限继续生效 |
| 列表与文本 | 最多50条，每个可外发文本字段最多2,000字符，实际读取有界 |
| 工具结果 | 最多64 KiB序列化UTF-8，包含MCP envelope、文本与结构化重复表示，不截断成虚假有效结果 |
| 单次只读 / 提交等待 | 最长15秒 / 30秒；只读超时unavailable，提交超时unknown，不证明远端停止 |
| 重试 | 只读瞬时故障最多1次，不延长原截止；权限 / 版本拒绝不重试，副作用不自动重发 |

首次自动业务调用前，原服务端建立持久目标 / 调用关联，绑定主体、grant、scope、用途、输入与政策版本，并原子计量次数 / 活跃时间 / 并发。MCP-04是只读首片的适用前置，不等到写入时才补；本地Map、自报目标ID、新连接 / token / 子Agent / 换客户端不能重置。协议发现、人工当前展示复核、主动原收据核对与自动调用分别受限，分类由固定方法和原事实决定，不能自报“人工”豁免。

Harness适配仍执行一次可控模型材料最多256 KiB；MCP服务器只能保证自身输出及服务端累计限额，不能宣称能计量任意Host聚合后的全部模型上下文。更严格上下文 / 每次发送要求缺Host证据时拒绝该类资料，不能拿64 KiB单结果假充总体保证。

保存报价、建单和云任务受理前须有提交前可恢复的原操作键、首应答丢失时的本人受权索引和精确收据读取。超时、TTL、租约过期、断线、取消、客户端卸载、无记录均不证明未执行 / 未消耗 / 已回滚；保持unknown，按原键核对，不换协议、ID、模型或入口重做。MCP SDK / HTTP自动重试也须受此约束，不能只限制应用层重试。

### MCP-R09：服务端任务协同与费用

客户端模型由各Host用户配置并自付；确定性业务查询不额外调用云模型。MCP不代理用户模型Key，也不使用Sampling让客户端代付服务端任务。

已有任务状态、事实、答案及来源先做受权只读；随后单独开通有限云场景发起及原取消意图。真实云模型走原Gateway / 财务单账及任务累计资源，不建立第二账本。关Host不丢已受理任务，回连不重派；受理、执行、结果、取消请求和取消收据分开。原Web / 官网 / 小程序 / 巡检 / 协作继续独立发展，不以MCP完成为整体前置，不允许本批自动递归本地 / 云委托。

### MCP-R10：兼容、故障、发布与成果保留

- 第一客户端是Harness，分别记录原生直连和有插件增强的配置；只要满足同一安全要求，不强制安装增强插件。各grant独立，插件不是第二认证权威。
- 原版Harness若缺OAuth接入、安全凭据、scope绑定或可靠重试控制，补受支持的客户端适配；仍只走同一MCP，不启用私有业务API兜底。无安全接点时报告阻塞，不能把静态Header示例当授权完成。
- 固定服务端 / schema / 提示词、Host / SDK及Web确认页组合。Tools / Resources / Prompts、认证、取消、恢复及展示能力逐端报告；未验证的Host不承诺兼容。不兼容或渲染失败提供安全文本和原人工入口，不弱化授权。
- 授权撤销持久化后在敏感读取 / 返回 / 提交点拒绝；多实例传播和最大陈旧期限有证据，未知则拒绝。通知只加速本地更新，不充当授权。停止新执行时仍按独立当前读权保留原收据核对；完全撤销grant拒绝全部请求，用户可另经Web核对。
- 分阶段按工具与租户启用；紧急停用 / 回退不删grant、原操作或收据，不复活旧权限或重放副作用。安装、迁移、真实联调、签名、部署和生产开通各按当轮授权。
