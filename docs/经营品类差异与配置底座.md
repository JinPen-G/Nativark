## 1. 当前结论

### 已确认事实

- “租户”只指使用 Rental OS 的 SaaS 经营主体；个人客户和企业客户属于租赁业务域。
- 一个 SaaS 租户只经营一个品类，当前预置 `vehicle`、`camera`、`camping`、`construction` 四种品类。
- 品类创建后不能通过普通编辑切换；存在标的、订单、资金或审计数据时，必须新建租户或执行专项迁移。
- 当前 `RentalCategoryDefinition` 已能描述库存模式、capability、术语和简单属性 schema。
- 当前 `Rental Core v0.1` 已支持序列化资产、数量库存、套装、多行订单、预占、分配和检查模板，但运行数据仍在内存。
- 当前通用订单仍由调用方直接提交 `unitPrice`，还没有通用品类定价引擎。
- 旧 `/store-rental/*`、多数 React 业务页面、权限码、报表和演示订单仍以车辆租赁为主，不能因为页面改成“资产”文案就视为通用化完成。

### 本轮修正的演示数据合同

| 登录租户 | 租户 ID | 经营品类 | 样本目标 | 当前约束 |
| --- | --- | --- | --- | --- |
| `demo` | `tenant_001` | 摄影设备 `camera` | 验证序列化资产、套装、快门读数、取还检查 | 旧车辆兼容数据仍挂在该租户下，只能作为历史兼容 fixture，后续必须拆分 |
| `demo2` | `tenant_002` | 露营设备 `camping` | 验证数量库存、套装、缺件和清洁检查 | 旧车辆业务样本较少，适合作为数量库存样本 |

当前不得再出现“租户管理显示未配置，但 Rental Core 内部按租户 ID 推断品类”的结果。内存数据、MySQL seed、登录租户上下文和 Rental Core 样本必须返回一致品类。

## 2. 配置分层与唯一事实源

经营品类不是一个页面标签，而是贯穿租赁全流程的租户级策略入口。目标事实源按四层管理：

| 层级 | 目标对象 | 负责内容 | 可变规则 |
| --- | --- | --- | --- |
| 平台品类模板 | `RentalCategoryDefinition` | 支持的库存模式、默认 capability、术语、属性 schema、定价/履约/检查模板入口 | 由 SaaS 平台版本化发布，不能由租户任意改结构 |
| 租户品类档案 | `TenantRentalProfile` | 唯一品类、启用 capability、允许的术语覆盖、模板版本快照 | 无业务数据时可初始化；产生业务数据后锁定品类 |
| 商品/资产配置 | `RentalItemGroup`、`RentalAsset`、`RentalStockBalance` | 商品属性、库存方式、租赁单位、计价配置、押金、使用量、套装组成 | 租户管理员维护，修改后新订单使用新版本 |
| 交易快照 | `RentalOrder`、`RentalOrderLine`、报价/规则/检查快照 | 下单时实际采用的品类、价格、规则、术语、模板和费用口径 | 创建后不可被后续配置覆盖，只能走变更单 |

必须满足：

```text
订单品类 = 租户品类
标的品类 = 租户品类
允许的库存模式 ⊆ 品类支持的库存模式
启用的 capability ⊆ 品类允许的 capability
订单价格 = 服务端报价快照，不接受前端直接决定最终单价
```

## 3. 四类经营品类差异基线

以下是开发基线，不表示所有能力首期都必须开启。

| 差异维度 | 车辆载具 | 摄影设备 | 露营设备 | 工程设备 |
| --- | --- | --- | --- | --- |
| 主库存模式 | 序列化 | 序列化 + 套装，少量数量型配件 | 数量 + 套装，贵重装备可序列化 | 序列化 + 数量 + 套装/附件 |
| 核心标识 | 车牌、VIN | 资产编号、SN | SKU/条码，贵重品 SN | 设备编号、出厂号 |
| 常用租赁单位 | 小时、24 小时/日、周、月 | 24 小时/日、周末套餐、周 | 日/夜、周末套餐、套 | 工时、班次、日、周、月 |
| 使用量 | 里程、油量/电量 | 快门次数、灯具使用时长 | 通常无连续读数，可记录损耗/使用次数 | 发动机工时、里程、作业量 |
| 套装特征 | 车辆 + 随车物资，通常不可拆成多车 | 机身 + 镜头 + 电池 + 灯光，可替代同组配件 | 帐篷 + 桌椅 + 炊具，允许数量组合和缺件 | 主机 + 属具 + 工具，可有兼容性约束 |
| 履约方式 | 门店取还、异店还车、调度 | 门店、自提柜、寄送/上门 | 仓库、门店、配送 | 仓库、工地交付、运输、现场交接 |
| 资质 | 驾照、年龄、驾驶资格 | 高价值设备信用/押金要求 | 通常无专业资质 | 操作证、项目/企业资质、安全培训 |
| 交付检查 | 车况、里程、油电、证照、随车物资 | 外观、功能、传感器、快门、配件清单 | 数量、清洁、破损、组件齐全 | 安全状态、工时、属具、油液、现场交接 |
| 归还重点 | 超里程、油电差、事故、异店费 | 损坏、快门增量、配件丢失、逾期 | 清洁、污损、缺件、耗材 | 超工时、损坏、燃油、运输、停机 |
| 资产运营 | 维保、证照、事故、TBox、调度 | 清洁、维修、固件、校准、快门寿命 | 清洁消杀、维修、报废、补件 | 点检、保养、年检、属具兼容、IoT |
| 默认 capability | 调度、使用量、资质、IoT | 使用量、套装、配送，可选智能柜 | 数量、套装、配送 | 调度、配送、使用量、资质、IoT |

## 5. 通用定价模型

### 5.1 定价不是品类模板中的一个固定数字

品类只定义“允许采用哪些计价能力和默认模板”，实际价格由租户的价格计划和标的分组决定。建议新增：

```text
RentalPricingProfile
├─ billingCadences[]       hour / shift / day / night / week / month / fixed_period
├─ durationRule            单位分钟、最小计费、进位方式、宽限时间
├─ usageRule?              指标、免费额度、单位、超额单价、读数要求
├─ depositRule             固定/按行/按资产/按替换价值比例/免押
├─ bundlePricingRule?      组成求和/套装固定价/折扣价
├─ calendarRule            工作日/周末/节假日/旺季
├─ fulfillmentFees         配送、异地、运输、上门、装卸
├─ exceptionFees           逾期、清洁、缺件、损坏、燃油、停机
└─ version                 可追溯版本
```

### 5.2 通用金额公式

```text
计费时长单位数 = durationRule(结束时间 - 开始时间)
基础租金 = Σ(订单行数量 × 命中时长单位数 × 行单位价)
使用量超额费 = max(0, 结束读数 - 开始读数 - 免费额度) × 使用量单价
订单应收 = 基础租金 + 履约费 + 增值服务费 + 使用量超额费 + 异常费 - 优惠金额
押金/预授权 = depositRule(订单行、资产替换价值、客户权益、企业额度)
```

金额以租户币种最小单位计算；报价、下单、变更和结算必须保存公式输入、命中规则、版本及舍入结果。

### 5.3 品类默认计价模板

| 品类 | 首期计价周期 | 使用量收费 | 押金建议 | 主要附加费 |
| --- | --- | --- | --- | --- |
| 车辆 | 小时、24 小时/日、周、月 | 免费里程 + 超里程，可记录油电差 | 预授权或固定押金，可叠加违章预留 | 异店还车、超时、油电、事故、清洁 |
| 摄影 | 24 小时/日、周末套餐、周 | 快门/灯具时长首期可只记录，按标的选择是否收费 | 按资产/套装固定或替换价值比例 | 逾期、损坏、配件丢失、加急配送 |
| 露营 | 日/夜、周末套餐、套 | 通常关闭连续使用量计费 | 固定押金或按套装 | 清洁、严重污损、缺件、耗材、配送 |
| 工程 | 小时、班次、日、周、月 | 工时/里程超额 | 固定、信用额度或设备价值比例 | 运输、装卸、操作员、燃油、停机、属具 |

## 6. capability 与页面/接口关系

capability 既影响页面可见性，也必须在后端拒绝不适用的动作。权限回答“这个账号能不能做”，capability 回答“这个租户的业务是否具备这个能力”，两者必须同时成立。

| capability | 影响模块 | 后端校验示例 |
| --- | --- | --- |
| `serialized_inventory` | 独立资产、序列号、具体资产分配 | 禁止为不支持的品类创建 `RentalAsset` |
| `quantity_inventory` | 库存余额、库存流水、批次 | 禁止维护数量余额 |
| `bundle_inventory` | 套装组成、缺件、替代 | 禁止创建套装分组 |
| `delivery` | 配送地址、运费、物流任务 | 禁止选择配送履约方式 |
| `locker` | 柜机、取件码、柜门日志 | 禁止创建柜机交付 |
| `dispatch` | 调度看板、跨点任务、锁定 | 菜单隐藏且接口返回 403/业务错误 |
| `usage_reading` | 读数配置、检查、超额结算 | 无该能力时不得要求使用量字段 |
| `qualification` | 客户/操作员资质、到期校验 | 下单和交付前校验资质 |
| `iot` | 设备绑定、遥测和控制 | 禁止绑定或下发设备指令 |

## 7. 演示数据建设标准

### 7.1 `demo` 摄影设备样本

- 标的：全画幅机身、标准镜头、补光灯、标准拍摄套装。
- 库存：机身/镜头序列化，灯架/电池可数量化，套装引用组成项。
- 价格：单日、周末套餐、周租；机身/套装押金；逾期和配件丢失费。
- 订单：草稿、已预占、待取机、租赁中、待归还检查、已完成各至少一单。
- 检查：外观、功能、快门次数、电池/配件、照片；至少一单有配件缺失异常。

### 7.2 `demo2` 露营设备样本

- 标的：帐篷、折叠椅、桌、炊具、双人/四人套装。
- 库存：数量型为主，至少一个贵重序列化标的，套装共享组件库存。
- 价格：日/夜、周末套餐、套装固定价；清洁、污损、缺件和配送费。
- 订单：覆盖多数量、多套装、套装与单品同时预占、防超卖、部分异常归还。
- 检查：数量齐全、清洁等级、破损、缺件清单、照片。

### 7.3 后续独立样本租户

- `demo_vehicle`：承接现有车辆兼容数据，验证迁移 facade 和旧接口回归。
- `demo_construction`：验证工时计价、运输/装卸、资质、属具和维护窗口。

演示数据必须由可重复 seed 创建，不能通过服务里的租户 ID 条件临时拼装。seed 重跑不得重复记录，且四个租户之间不能共享业务主键或查询结果。

## 8. 开发工作包

| 顺序 | 工作包 | 主要产物 | 退出条件 |
| --- | --- | --- | --- |
| CAT-P0 | 品类事实源与演示数据 | 统一 category definition、租户 profile、登录上下文；修正 demo/demo2；seed 校验 | 平台列表、登录、Core profile、数据库查询返回同一品类 |
| CAT-P1 | capability 导航与后端守卫 | 菜单 capability 过滤、通用权限码、接口 capability guard | 不适用品类看不到且调用不了调度/IoT/数量库存等能力 |
| CAT-P2 | 商品与库存配置 | 属性 schema 校验、库存流水、套装替代、周转缓冲 | 摄影与露营样本可维护且可用性不超卖 |
| CAT-P3 | 通用定价 v0.1 | pricing profile、服务端报价、订单价格快照、四类默认模板 | 前端不能提交最终价格；报价可解释并可复算 |
| CAT-P4 | 订单与履约 | 多履约方式、部分分配/归还、检查异常到费用 | 摄影/露营从报价到结算形成真实闭环 |
| CAT-P5 | 资产运营与报表 | 通用维护、使用量、品类指标、capability 运营模块 | 不再依赖车辆表生成通用品类运营数据 |
| CAT-P6 | 车辆兼容迁移 | `demo_vehicle`、数据迁移、`/store-rental/*` facade | 车辆和通用接口使用同一事实源，无长期双写 |

首个实际开发顺序应为 `CAT-P0 -> CAT-P1 -> CAT-P3`。如果先做更多页面，仍会继续固化手填价格、车辆权限码和双事实源。

## 9. 验收标准

### 品类一致性

- Given SaaS 管理员查看租户列表，When 加载 `demo` 和 `demo2`，Then 分别显示摄影设备和露营设备，且组织/账号数量为数字。
- Given 租户登录，When 返回登录上下文并查询 `/api/rental/v1/tenant-profile`，Then 两处 `categoryCode` 一致。
- Given 已有标的或订单的租户，When 尝试切换品类，Then 后端拒绝并保留原数据。

### capability

- Given 露营租户没有 `dispatch`/`iot`，When 打开菜单或直接调用接口，Then 页面不展示且后端拒绝。
- Given 摄影租户启用 `usage_reading`，When 办理取还检查，Then 使用快门次数及其单位，不出现里程字段。

### 定价

- Given 同一标的选择不同租期，When 服务端报价，Then 按命中的小时/日/周规则和舍入规则返回可解释分段。
- Given 露营套装与组成单品同时下单，When 报价和预占，Then 价格按套装策略计算，库存按共享组件合并占用。
- Given 配置在订单创建后调整，When 查看历史订单，Then 金额和说明仍使用订单快照版本。

### 数据隔离与演示 seed

- seed 可重复执行且不产生重复租户、标的、资产、订单或价格版本。
- 四类租户的列表、详情、导出、动作和报表都不能读取其他租户数据。
- MySQL 模式重启后租户品类、价格快照、预占、检查和费用不丢失。

## 10. 暂不阻塞开发的待确认项

| 问题 | 当前推荐 | 影响阶段 |
| --- | --- | --- |
| 摄影快门次数首期是否收费 | 默认只记录；允许标的级开启超额收费 | CAT-P3 |
| 露营套装是否允许部分归还 | 模型预留，首期整套归还；缺件走异常 | CAT-P4 |
| 工程设备操作员是否作为订单行 | 建议作为服务行，不作为资产行 | CAT-P3/CAT-P4 |
| 一个订单是否跨多个履约地点 | 首期禁止；后续拆履约单 | CAT-P4 |
| 品类术语允许租户改到什么程度 | 只允许文案覆盖，不允许改变字段语义和数据类型 | CAT-P1 |
