# OPS-01B：发布候选清单与只读发布门禁

> 本文只覆盖 **OPS-01B**：把一次发布候选的事实固定下来，并用一道**默认只读**的门禁
> 检查「现在能不能发」。它**不执行**发布——不迁移、不起服务、不替换任何运行实例、
> 不接触共享或生产环境。完整 `OPS-01` 仍未完成，见 §6。
>
> 前置：[OPS-01A 发布与数据恢复预检](OPS-01A-发布与数据恢复预检.md)。

## 1. 命令

```bash
npm run ops:release-gate
```

默认是 **dry-run**：只观察、只打印，不写任何文件。要把清单落盘：

```bash
npm run ops:release-gate -- --emit
```

专项测试：

```bash
npm run test:ops-release
```

## 2. 门禁检查项

| 检查 | 判据 | 失败含义 |
| --- | --- | --- |
| Git 提交已固定 | 能取到 HEAD 完整/短 SHA、分支、提交时间 | 不在 git 仓库或仓库损坏 |
| 工作区干净 | `git status --porcelain` 为空 | 有未提交或未跟踪文件；清单里的提交号名不副实，产物可能包含未入库内容 |
| Node / npm 版本 | 均可取到 | 环境不完整 |
| Prisma 版本已锁定 | `apps/api/package.json` 里声明了 `prisma` 与 `@prisma/client` | 未锁定版本，发布与验证环境可能用不同 Prisma |
| 构建产物可摘要 | `apps/api/dist`、`apps/admin/dist`、`packages/shared/dist` 均非空并算出指纹 | 产物缺失，先 `npm run build` |
| 必需环境变量 | `DATABASE_URL`、`AUTH_TOKEN_SECRET` 存在且非空白 | 缺失即不可发布（见 §3） |
| 目标库守卫 | 通过 OPS-01A 的专用库与容器端点守卫 | 目标配错，或指向共享/生产库 |
| 迁移状态（只读） | `prisma migrate status` 已同步 | 有待应用迁移；由人工按 OPS-01A §5 决定 deploy 时机 |
| docker 可用 | `docker --version` 成功 | 部署前置缺失（本门禁不启动任何容器） |
| 健康检查入口 | 已登记 `/api/health` 等入口 | — |

任一项失败即退出非零，并列出失败项。门禁只报告，不代劳。

## 3. 环境变量口径：只记名字，不记值

清单里出现的永远只有**变量名**、是否存在、以及用途说明。

`required` 的判据是「缺了它这次发布一定不可用或不安全」：

- `DATABASE_URL`：缺失则服务连不上库；
- `AUTH_TOKEN_SECRET`：缺失时 `NODE_ENV=production` 直接抛错；非生产会回落到
  **仓库里那个公开的开发密钥**——发布候选不接受这种回落。

空串与纯空白按缺失处理。`AUTH_TOKEN_SECRET=` 这种写法比没写更危险，因为它看起来像已经配过了。

## 4. 清单内容与敏感值闸门

`--emit` 写出 `artifacts/release/release-candidate-<短SHA>-<时间戳>.json`（`artifacts/` 已在 `.gitignore`）。

固定内容：提交信息、工具链版本、三个包的产物指纹（文件数/字节数/合成 sha256）、
环境变量名清单、目标库名与守卫结论、迁移状态结论、健康检查入口、未覆盖边界。

落盘前必过 `assertNoSecrets`，三条并行判定：

1. 任何字符串值**整体等于**已知秘密 → 拒绝；
2. 值形如 `user:pass@host` 连接串，或 URL 型值里含已知秘密 → 拒绝；
3. 键名是 `password`/`secret`/`token`/`authorization`/`credential` 且值未掩码 → 拒绝。

> 刻意**不用**「整份 JSON 搜子串」：本地夹具的库口令恰好是库名前缀
> （`store_rental` 与 `store_rental_claude`），子串匹配会把一个本就不是秘密的库名判成泄露。
> 一个总在误报的检查很快会被人关掉，那比没有检查更糟。

产物指纹按「路径归一 → 逐文件 sha256 → 按路径排序 → 合成总摘要」计算，
因此同一份产物在不同机器上得到同一个值，「验过的产物」与「要发的产物」可被证明是同一份。

## 5. 门禁不做的事

- 不执行 `prisma migrate dev/deploy`：发布前最该知道的是差什么，而不是已经替你改了；
- 不启动、不重启、不替换任何服务或容器；
- 不写除清单以外的任何文件（专项断言了脚本里只有建目录与写清单两种写盘动作）；
- 不连接共享库或生产库：目标库必须先过专用库守卫。
