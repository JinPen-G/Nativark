# Rental OS 员工履约小程序需求说明

## 版本记录

| 版本 | 日期 | 状态 | 说明 |
| --- | --- | --- | --- |
| v1.0 | 2026-09-20 | 已确认需求，尚未开发 | 确认建设独立员工履约小程序：一套应用服务多个租户，按经营空间与履约地点授权，覆盖配货、现场交付、归还检查、库存处置和现场事实记录。 |

本文定义门店、仓库和现场交付人员使用的员工履约小程序。平台的订单、金额、库存、检查、权限和状态规则仍以[《多品类租赁平台需求说明》](多品类租赁平台需求说明.md)为准；本文只规定移动履约入口、操作边界和验收，不建立第二套订单或库存模型。实现计划登记在[《微信小程序开发任务》](开发任务/微信小程序开发任务.md)。

## 1. 产品定位与范围

员工履约小程序用于现场作业，不面向租赁客户，也不替代完整运营管理端。首期目标是让获得授权的员工在手机上完成从备货到交付、再到归还和库存处置的现场闭环，减少回到电脑端补录事实的情况。

平台提供一套统一的小程序服务多个租户。员工使用租户编码和租户运营账号登录；后续可增加微信身份绑定以便快速登录，但绑定关系不能绕过账号状态、成员关系、空间权限和地点数据范围。

### 1.1 STAFF-MP-R1 首期包含

- 登录、会话恢复、退出和密码修改入口。
- 选择/切换获授权的经营空间和履约地点。
- 今日待办、逾期待办、任务筛选和扫码查单。
- 订单摘要、客户交接信息、资金/资质/条款门禁结果。
- 预分配、扫描实物、调整分配并锁定资源。
- 领取检查、客户确认、现场交付。
- 整单或逐批归还、归还检查、异常事实和库存处置。
- 在获得单独权限时登记现金或银行转账收款及凭证。
- 操作记录、本人作业历史和失败恢复提示。

### 1.2 首期不包含

- 新建报价、创建订单、维护商品/价格/日历/规则或配置第三方平台。
- 由普通现场员工裁定异常费用、批准退款、强制结算或修改历史商业快照。
- 跨租户工作台、跨未授权空间经营汇总或跨地点调拨审批。
- 离线推进领取、归还、收款或库存终态。
- IoT 开锁、物流承运、电子签章和完整财务对账；这些能力另行启用时仍关联原订单和履约批次。

## 2. 角色、权限与数据范围

### 2.1 角色

| 角色 | 默认职责 | 默认不具备 |
| --- | --- | --- |
| 门店/仓库员工 | 查看本地点待办、扫码、配货、交付、归还、检查和提交处置结果 | 费用裁定、退款审批、最终结算、经营配置 |
| 现场主管 | 普通员工能力，加上强制改配、异常复核、任务转派和必要的人工解锁 | 跨未授权空间/地点操作、修改历史快照 |
| 租户管理员 | 在管理端配置账号、角色、空间及地点范围；可按权限进入小程序验收 | 不能以管理员身份绕过订单状态、库存和金额规则 |

角色名称可由租户配置，但权限含义和服务端校验必须稳定。不能仅凭前端隐藏按钮代替权限控制。

### 2.2 授权层级

有效访问范围为：

`租户账号有效 AND 租户成员有效 AND 经营空间成员有效 AND 角色操作权限通过 AND 履约地点数据范围命中`

- 只有一个有效经营空间时直接进入；有多个时必须选择，可随时切换。
- 每次切换空间都重新加载权限、地点范围、品类术语、capability 和待办数据，并清空上一空间缓存。
- 员工可拥有不同空间的不同角色。例如在 A 空间可交付，在 B 空间只能查看。
- 空间内可进一步限定一个或多个履约地点。未授权地点的订单、资产、库存和任务不得出现在列表、搜索、扫码结果或统计中。
- 服务端以会话和授权事实确定空间、地点；客户端传入的 ID 只能缩小范围，不能扩大范围。
- 撤销空间或地点权限后，旧会话下一次请求立即拒绝，不等待重新登录。

### 2.3 建议权限码

| 权限 | 允许动作 |
| --- | --- |
| `staff:task:view` | 查看授权范围内待办和订单摘要 |
| `staff:allocation:operate` | 预分配、扫描、调整并锁定资源 |
| `staff:handover:operate` | 执行领取检查和现场交付 |
| `staff:return:operate` | 执行整单/逐批归还和归还检查 |
| `staff:stock-disposition:submit` | 提交回库、清洁、维修、下架等处置结果或建议 |
| `staff:exception:create` | 登记损坏、缺件、超用、证据和说明 |
| `staff:offline-payment:record` | 登记现金/转账收款及凭证，不代表财务对账完成 |
| `staff:supervise` | 强制改配、任务转派、异常复核；必须填写原因 |

权限码最终在契约任务中固化；不能用一个“operate”大权限覆盖全部敏感动作。

## 3. 信息架构与页面

底部使用四个入口：**工作台 / 扫码 / 订单 / 我的**。空间和地点属于工作上下文，放在顶部切换区，不单独占底部入口。

| 页面 ID | 页面 | 主要内容与动作 |
| --- | --- | --- |
| S01 | 登录 | 租户编码、账号、密码；后续可显示已绑定微信的快捷登录 |
| S02 | 选择工作范围 | 选择经营空间和履约地点；显示各空间可用角色摘要 |
| S03 | 工作台 | 今日待配货、待交付、待归还、异常待处理和逾期任务 |
| S04 | 扫码 | 扫订单码、资产码、商品码或任务码；无法识别时给出明确原因 |
| S05 | 订单/任务列表 | 按任务类型、时间、地点、状态和关键字筛选 |
| S06 | 履约订单详情 | 客户、租期、地点、资金/资质门禁、商品、分配、交付、归还和异常时间线 |
| S07 | 配货与锁定 | 查看候选资源、扫描实物、调整数量/套装、确认并锁定 |
| S08 | 领取检查与交付 | 按品类检查、拍照/读数、客户确认、提交交付 |
| S09 | 归还与检查 | 选择本批归还项、扫码核对、拍照/读数、登记缺件损坏和提交归还 |
| S10 | 库存处置 | 回库、待清洁、待维修、下架等允许结果及其原因/证据 |
| S11 | 现场收款 | 在获授权时登记现金或转账；显示应收用途、金额、凭证和待对账状态 |
| S12 | 操作历史 | 本人操作、失败重试、已撤销或被主管覆盖的记录 |
| S13 | 我的 | 当前租户、账号、空间/地点/权限摘要、密码修改、退出 |

## 4. 端到端作业流程

### 4.1 登录与进入工作范围

1. 员工输入租户编码、账号和密码。
2. 服务端校验账号、租户成员关系和可访问经营空间。
3. 仅一个空间时自动进入；多个空间时显示选择页。
4. 空间内仅一个授权地点时自动选中；多个地点时由员工选择，也允许查看“我有权限的全部地点”。
5. 进入后加载品类术语、capability、角色权限和待办；任一步失败都保留重新登录或重选范围的出口。

### 4.2 备货、预分配与锁定

1. 工作台按预约时间展示待配货订单。
2. 员工进入订单，查看资源需求和可分配候选项。
3. 员工扫描具体资产、数量库存或套装组件；服务端复核地点、状态、租期冲突、缓冲时间和品类限制。
4. 普通调整形成预分配；提交锁定时使用订单修订号和幂等键。
5. 资源已被他人锁定、状态变化或不兼容时，当前提交整体失败并提示冲突项，不留下半套锁定结果。
6. 主管强制改配必须有专门权限和原因，原分配及覆盖关系保留审计。

### 4.3 现场交付

允许交付必须同时满足：

`订单允许领取 AND 资源锁定完整 AND 资金门禁通过 AND 客户资质通过 AND 领取检查完成 AND 条款/确认完成`

员工按订单逐项扫码并完成领取检查。客户确认支持：

- **客户小程序扫码确认**：客户用本人账号扫描交接码，服务端校验本人、订单和一次性确认令牌。
- **现场签字留证**：员工设备上显示交接摘要，客户签字并保存时间、地点、操作者、订单和批次。该签字是现场交接证据，不自动等同于具有完整法律效力的电子签章。

交付提交成功后，由服务端原子推进订单和资源状态；前端不能先显示“已交付”再异步补写。客户暂时无法确认时，不允许普通员工跳过；主管按明确权限和原因使用人工例外，仍须保留证据。

### 4.4 归还、逐批归还与检查

1. 员工选择整单归还或本批归还项；已归还数量/资产不能再次选择。
2. 扫描实物并记录数量、套装组件、外观、功能、使用量及品类专属读数。
3. 缺件、损坏、超用或逾时只登记事实和证据，不由普通员工直接确定最终费用。
4. 提交后形成不可重复的归还批次；同一幂等键重试返回原结果。
5. 资源按检查结果进入回库可用、待清洁、待维修、下架或待复核状态；“已归还”不自动等于“可出租”。
6. 未归还部分继续保持占用并按平台规则计算逾时；已归还部分不再重复累计。

### 4.5 现场收款和异常

- 只有具备 `staff:offline-payment:record` 的人员可登记现金或银行转账。
- 登记内容包含订单、收款用途、金额、币种、方式、时间、收款人、凭证和备注；结果为“已登记/待对账”，不能冒充在线支付回调或财务对账完成。
- 费用建议由系统规则和现场事实生成；普通员工只能补充事实、证据和说明。费用裁定、客户异议处理、退款审批和最终结算继续在授权后台完成。

## 5. 四品类共用流程与扩展

所有品类共用任务、扫码、分配、检查、交付、归还、异常和库存处置骨架。页面标题、字段和检查项从当前空间的品类档案与已启用 capability 取得。

| 品类 | 首期移动履约扩展 |
| --- | --- |
| 摄影设备 | 机身/镜头/附件兼容提示、套装附件清点、快门或适用使用量、光学/外观检查 |
| 露营装备 | 套装组件和数量清点、清洁度、潮湿、破损、缺件及一次性耗材区分 |
| 车辆载具 | 驾驶资格门禁、车牌/VIN、里程、油量/电量、外观照片、随车附件和异地还车 |
| 工程设备 | 操作资格门禁、工时读数、安全检查、运输交接、检验有效期和停运状态 |

未知品类使用通用字段安全降级；缺少必选 capability 时禁止对应交付动作，不以空表单放行。

## 6. 扫码、文件与证据

- 扫码结果至少区分订单、任务、商品型号、序列化资产和套装/容器；码值只用于定位候选对象，最终仍校验租户、空间、地点、状态和权限。
- 照片、签字和附件通过服务端签发的上传凭证上传；小程序包和日志不得包含存储密钥或长期公开地址。
- 每份证据关联业务类型、订单、履约批次、采集人、采集时间、服务端接收时间和文件校验信息。
- 证据上传失败时不假装提交成功。可保存本地草稿并提示重试；改变订单或库存状态的最终提交必须确认所需证据已经服务端接收。

## 7. 并发、离线与失败恢复

- 同一订单同一作业阶段只允许一个有效操作锁；其他员工可只读查看并知道占用人和失效时间。
- 锁具有短期租约和续约机制，异常退出后可自动失效；主管人工解锁必须留原因和审计。
- 分配、交付、归还、库存处置和收款登记均使用幂等键、订单修订号和事务；重复点击、网络重试和扫码重放不产生重复事实。
- 断网时只允许保存检查草稿、照片待上传列表和未提交备注。恢复联网后必须重新读取订单状态、权限和资源占用，再决定是否可以提交。
- 服务器已成功但客户端未收到结果时，按幂等键查询原结果，不允许员工直接重复执行。
- 权限撤销、空间停用或地点范围变化后，未提交草稿可导出/放弃，但不能继续推进业务状态。

## 8. 接口与技术边界

员工端使用独立的 `/api/staff/v1/*` 契约和员工会话，不直接复用客户 token，也不把管理端全量 API 暴露给小程序。服务端可复用现有 Rental Core 领域服务、事务和状态机。

首期接口域至少包括：

- `auth`：登录、会话刷新、退出、密码修改、后续微信绑定。
- `contexts`：可访问空间、地点、当前权限和品类能力。
- `tasks`：待办列表、数量摘要和任务详情。
- `orders`：授权范围内订单搜索、扫码定位和履约摘要。
- `allocations`：候选资源、预分配、调整、锁定和改配。
- `inspections`：领取/归还检查模板、草稿和提交。
- `handovers`：交接确认令牌、客户确认状态和最终交付。
- `returns`：整单/逐批归还、归还批次和剩余占用。
- `stock-dispositions`：回库、清洁、维修、下架和复核。
- `exceptions`：异常事实、证据和处理状态。
- `offline-payments`：授权范围内线下收款登记及查询。
- `uploads`：短期上传凭证和文件状态。

每个写接口必须声明权限、数据范围、前置状态、幂等键、修订号、成功结果、冲突结果和可恢复方式。DTO 只返回移动作业需要的数据；客户证件、联系方式和内部金额信息按权限最小化、脱敏展示。

## 9. 通知与现场协作

- 工作台只展示与当前员工范围相关的任务；数量摘要必须与列表筛选条件一致。
- 可对临近交付、逾期未归还、锁冲突、证据上传失败和异常待复核发出小程序订阅消息或应用内提醒。
- 通知是提醒，不改变订单、库存或资金状态；通知发送失败不阻止已合法完成的业务事务，但必须可见并可重试。
- 任务转派只转移执行责任，不改变订单归属、地点和权限；接收人必须对目标空间和地点有权限。

## 10. 首期验收

| 场景 | 必须证明的结果 |
| --- | --- |
| 多租户与登录 | 同一小程序可登录不同租户，但一个会话只属于一个租户；错误租户编码、停用账号和撤权旧会话均被拒绝 |
| 空间与地点范围 | 员工只能看到和操作获授权空间/地点；切换后术语、权限和缓存同步更新，伪造 ID 不越权 |
| 配货锁定 | 扫描正确资源可锁定；租期/缓冲冲突、不兼容或他人占用时整体失败且无半套分配 |
| 现场交付 | 资金、资质、资源、检查和确认全部通过才交付；客户扫码与现场签字均形成完整证据 |
| 逐批归还 | 相同商品分批归还数量准确，同批重试不重复；未还部分继续占用，已还部分进入正确检查/处置状态 |
| 异常与权限 | 普通员工可登记损坏、缺件和证据，但不能裁定费用、退款或最终结算；主管覆盖有理由和审计 |
| 线下收款 | 只有专门权限可登记，重复提交不重复入账，结果明确为待对账且不冒充在线支付成功 |
| 四品类 | 四类空间复用同一主流程并显示各自术语和检查项；未知品类安全降级，缺必选能力不放行 |
| 并发与恢复 | 两名员工争抢操作锁只有一人成功；断网、超时、客户端重启和结果未知均可查询恢复且不重复写入 |
| 文件与隐私 | 上传密钥不进入小程序包；证据按租户/空间/订单隔离；客户敏感字段按最小权限脱敏 |

STAFF-MP-R1 只有在真实数据库、至少两个租户、同租户两个空间、不同地点范围、四品类代表性检查以及微信开发者工具/真机流程均通过后，才能标记完成。页面存在、静态检查或接口返回 200 不能单独作为完成依据。
