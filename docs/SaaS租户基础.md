## 1. 名词边界

- **SaaS 租户**：购买或使用 Rental OS 的租赁经营主体，例如一家摄影器材租赁公司。租户拥有独立组织、账号、角色、数据和唯一经营品类。
- **租赁客户**：向某个 SaaS 租户租用设备的个人或企业。客户属于业务域，不是 SaaS 租户。
- **SaaS 平台管理员**：Rental OS 运营方账号，只负责租户开通、资料和生命周期，不自动拥有任一租户的业务权限。
- **租户管理员**：某个 SaaS 租户的最高权限账号，只能访问本租户数据。

## 2. 当前已实现

### 管理面分离

- SaaS 平台管理员使用独立 `isSaasAdmin` 标识，登录后只显示“SaaS 租户”工作区。
- 租户管理员继续使用租户内 `TENANT_ADMIN` 角色，`*` 只表示当前租户内全权限。
- `/api/platform/tenants*` 和 `/api/platform/tenant-bootstrap*` 仅允许 SaaS 平台管理员访问。
- SaaS 平台管理员不能访问租户报表、订单、资产或组织权限页面。
- 登录租户上下文返回 `categoryCode/categoryName`；内存模式和 MySQL 模式必须与租户品类档案一致。

### 租户生命周期

- 支持 `active`、`frozen`、`disabled` 三种状态。
- 状态变更必须填写原因，并记录变更人、时间和审计日志。
- 冻结或停用会立即撤销该租户全部登录会话；恢复后必须重新登录。
- 租户不做物理删除，避免订单、资金和审计链断裂。

### 原子化租户初始化

一次初始化在同一数据库事务中创建：

1. 租户档案；
2. 唯一 `TenantRentalProfile` 与经营品类；
3. 根组织和首个履约组织；
4. `TENANT_ADMIN`、`STORE_OPERATOR` 默认角色及权限；
5. 首个租户管理员；
6. 系统规则、字典、编号规则和初始化审计。

任一步失败，事务整体回滚。管理员密码由服务端生成，只在初始化响应中返回一次，首次登录必须修改。

### 认证与会话

- 密码使用随机盐 `scrypt` 保存，不再接受 `dev-only:` 明文兼容格式。
- access token 为 15 分钟签名令牌；refresh token 为 30 天不透明令牌，数据库只保存哈希。
- refresh token 每次刷新后立即轮换，旧 token 失效。
- 重置密码、主动改密、账号停用、租户冻结/停用会撤销相关会话。
- 密码最低 8 位，必须包含字母、数字和特殊字符；首次登录改密由前后端同时强制。

### 数据隔离

- Rental Core API 只使用认证用户的 `tenantId`，不接受客户端指定租户。
- 组织、角色、用户的查询与写入均校验目标资源属于当前租户，不能通过猜测 ID 移动或修改其他租户记录。
- 旧 `/store-rental/*` MySQL repository 的默认租户来自请求级登录上下文，不再固定为 `tenant_001`。
- 文件、通知、异步任务、适配器日志和设备接入等 integrations 数据同样使用请求级租户上下文，不再固定到演示租户。
- 报表查询、导出创建、导出列表和文件下载均强制覆盖为登录租户，忽略前端传入的 `tenantId`。

## 3. 经营品类规则

- 一个 SaaS 租户只允许一个经营品类：`vehicle`、`camera`、`camping` 或 `construction`。
- 经营品类在租户初始化时创建并固定，不通过普通资料编辑接口修改。
- 品类决定术语、库存模式、检查模板和 capability；不能靠前端字符串替换伪造数据能力。
- 如需改变经营品类，应新建租户或执行单独的数据迁移方案。
- 品类涉及的库存、定价、订单、履约、资产运营、报表和集成差异，以 `经营品类差异与配置底座.md` 为开发基线。

## 4. 数据库变更

- `Tenant` 增加状态原因、状态变更时间和变更人。
- `User` 增加 SaaS 管理员、首次改密、token 版本、最后登录和密码变更时间。
- 新增 `auth_sessions`，存储 refresh token 哈希、有效期和撤销状态。
- 对应迁移：`20260813000200_saas_tenant_identity_foundation`。

## 5. 验证与已知边界

自动测试 `npm run test:saas-foundation` 已覆盖角色边界、跨租户读写拦截、integrations 租户上下文、初始化、首次改密、会话轮换、冻结撤销和密码哈希。生产环境必须显式配置 `AUTH_TOKEN_SECRET`，缺失时认证服务拒绝签发令牌。

平台、旧业务域和 integrations 默认数据源均为 MySQL；`memory` 只能由测试或演示显式开启，不作为租户隔离证明。仍需在有 MySQL 的环境执行迁移、seed 和真实 HTTP E2E，验证事务回滚、重启持久化及数据库约束。`Rental Core v0.1` 本身目前仍使用进程内演示数据；旧车辆兼容域和通用内核尚未成为同一事实源。`demo` 下仍存在旧车辆兼容 fixture，与其摄影品类样本并存，该数据必须在车辆 facade 阶段迁到独立 `demo_vehicle` 租户，不能作为生产数据结构。
