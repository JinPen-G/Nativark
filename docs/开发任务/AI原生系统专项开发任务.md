### 2.2 停止重复建设与可替换交付规则

1. 自本版起，停止新增与选定组件重复的通用图遍历/规划平台、全协议模型SDK、通用文档平台和可视化Agent搭建器。已有代码不删除、不废弃；先复用，再在替代路径验收后退出实际重叠部分。继续完成 Rental OS 特有的授权、事实、审批、预算、Core 工具及用户场景。
2. 默认只引入必要的库级能力，不同时部署 LiteLLM、Temporal、BullMQ、向量库及另一套应用平台。确需额外服务时提交已测缺口、最小拓扑、部署/维护成本、许可和回退方案，不能以框架推荐为理由自动扩容基础设施。
3. 每片记录复用的原文件/端口、上游包及版本、最小适配、失败证据、停止新增/拟退出的重复实现、原任务/验收映射和未验环境。通过实现与故障测试决定采用，不能只交一个interface或包依赖声明。
4. 组件优先外置适配，不无差别fork整仓。选型由主线按有界技术验证确认；库版本不兼容时给出具体替代，不升级整仓迁就示例。package/lock、shared、schema及部署依赖仍由唯一认领人变更，依赖安装/外联必须遵守当次授权。
5. 一个task绑定一个编排实现/版本，一个业务动作只有一个执行/派发归属，一次模型消费只有一套财务账本。框架checkpoint/重试不能代替业务收据、当前权限、累计资源或审批消费；不允许旧新路径并行执行副作用做对照。
6. 已完成的通用实现优先作为兼容/回退资产；替代后有明确退出条件，不能永久维护两套同功能引擎。开源无需预定全部改自研，替换须证明收益；未采集适配和剩余工时前不承诺“节省百分之几”。

## 4. 任务交付细则

### AIN-01 实现基线、业务工具成熟度和人工流程盘点

- 增量盘点现有Gateway、运行器、预算、知识和三端成果，按需求§16.2标记保留/适配/退出对象；复用已有切片证据。记录开源候选精确版本、许可证、传递依赖、所需运行时及兼容缺口，不把品牌云平台功能算作开源库能力。
- 逐一核对正式分支、目标工作树、部署版本、Core与品类治理提交；记录现有AI配置的模拟行为，不能把未合入代码列为已部署能力。
- 为计划工具建立清单：实际服务入口、原权限、scope、输入/输出、事务、副作用、幂等、实际验证和缺口，登记`unavailable / preview_only / executable`的判定依据。
- 建立四品类人工参考案例：选品、资格、计价、取还、报价、开单、检查、结算、变更解释；采集已实现范围，不补造数据口径。
- 交付当前事实清单、人工基线、依赖/缺陷归属和AI工具初始目录。不得直接修改其他专项规则；缺口按原专项关联。
- 验收：入口可追到代码/契约和证据；未验收能力明确降级；AIN-A27/A28已有可重复基线。

### AIN-02 共用契约、身份范围、错误与事件协议冻结

- 在既有公共契约外侧定义最小框架适配：图节点/interrupt/checkpoint到task/run/step、输入revision、结果引用、事件和错误的映射，及Gateway Provider的结果/用量映射。前端不接框架私有DTO；已有公共类型够用就不新增协议。明确执行、重试、恢复与事务事实的唯一所有者。
- 冻结工具注册schema、认证后的执行上下文、任务/步骤状态转换表、提案/审批、结构化卡片、用量与知识引用契约。
- 明确scope判别联合类型，tenant/platform对象不强塞workspace；请求不能自授actor或audience；输入未知字段拒绝。
- 将最终路径、HTTP方法、权限码、DTO、分页/游标、幂等请求、错误码写入shared/OpenAPI；对SSE和轮询提供同一事件模型。定义取消、未知结果、部分完成的确切语义。
- 为后台/平台/员工/客户给出成功、拒绝、失效、断线和旧协议的契约夹具；冻结版本、生产者和消费者，规定兼容期/升级方式。
- 验收：契约校验与消费者编译通过；任何一端不维护私有同名DTO；角色与数据范围负例可测试；跨AI已确认冻结记录。

### AIN-03 任务/提案/用量/知识持久化及迁移

- 复用已交付Prisma模型与收据，不因引入LangGraph重建业务表。核验持久checkpointer与当前MySQL/Prisma的实际兼容；优先成熟存储实现，缺口只做有界适配。不默认增加PostgreSQL/Redis，不用内存saver声称可跨重启恢复。
- checkpoint映射必须绑定服务器解析的owner/audience/scope/task/run/图版本/输入修订；保存和读取均经授权，敏感字段/清理/保留遵守原政策。验证“业务已提交但checkpoint未写”和相反中断窗口，按原收据恢复或核对，不声称两者天然同事务；旧任务不得无映射热迁移。
- 按需求§16盘点已有对象，选择复用/新增并记录字段映射；任务与run分离，审批与业务事实分别保存。
- 实现scope、owner、状态revision、actionId、请求指纹、关联业务对象、预算预留、知识版本及必要索引/唯一约束；不依赖仅应用内变量去重。
- 迁移定义字段备注、时间/币种/用量精度、敏感字段策略、历史数据默认值和安全回退。迁移文件由唯一认领人排序整合。
- AI 配置增加 `platform_managed / tenant_managed`；新租户默认平台，旧无 mode 的自定义配置按 BYOK 兼容读取，不丢加密密钥、协议、URL、模型。模式切换保留原自定义配置；损坏/不完整旧配置不可补造就绪。验证空库、旧配置升级、重复迁移、修订冲突及兼容回退。
- 交付受限仓储接口与迁移测试；验证跨租户关系拒绝、并发唯一性、删除聊天不删除业务事实，以及失败迁移后的恢复方式。
- 验收：只在预检查不存在的新`rental_os_e2e_*`库执行；空库与支持的升级路径真实通过并清理自身资源。不得操作共享库。

### AIN-04 业务共用授权入口与执行上下文

- 为图节点、checkpointer/store、恢复/回放及SDK发起点复用当前授权适配；线程ID或图配置不能充当授权。框架缓存与消息历史只能保存必要数据引用，恢复后按当前访问权限读取正文；禁止默认全局memory或任意工具绕过Guard/ALS。
- 将适用业务权限检查放到HTTP、AI工具和Worker都可调用的应用入口；保持既有路由认证及行为，不复制易漂移的鉴权分支。
- 服务端解析tenant/workspace/audience/成员/角色/dataScope/locationScope；读历史、来源、下载与事件流同样检查。内部调用禁止回落到初始化空间。
- 每步重验撤权、冻结、订阅与政策；任务owner离职或自动化政策撤销后停止新动作，保留合法人工善后。
- 自动主体独立建模，其能力不得超出租户授权政策；客户端令牌不得进入后台/平台工具。
- 验收：AIN-A02～A04与原HTTP权限等价回归；覆盖同租户不同空间、共享会员非共享订单、地点缩权和任务恢复后撤权。

### AIN-05 真实模型网关、能力声明与凭据管理

- 沿用统一 Gateway → Provider Router → 平台/租户配置 → Provider Adapter；首选以AI SDK Provider包替代底层重复协议编码/解析，不重建Gateway。Agent/图节点仅提交场景与能力，不直接读连接配置或SDK。绑定实际配置来源、修订和模型；平台缺配置如实不可用。
- 先接当前已有且需要的协议；实例由服务端配置和Vault构造，注入受控fetch/传输、总deadline和取消。必须测试请求目标、DNS/连接地址/重定向、附件URL与敏感header没有旁路；SDK无法满足则该适配unavailable，不退回不受控全局fetch。
- 显式关闭SDK隐藏重试、自动fallback、自动多步工具执行和非授权遥测；AI SDK采用时将maxRetries设为0并验证实际请求次数。不得使用隐式云Gateway/全局凭据。新的模型请求重新经过原准入/预算，unknown不自动重派；缺usage不能映射为零。
- 能力检测至少覆盖 Text、Streaming、Tool Calling、Structured Output、Vision、Embedding、Reasoning，分支持/不支持/未验证及 mock/live；连接成功不等于能力支持。必需能力缺失或未验证在调用前拒绝，可选能力不授予额外权限。首期不实现复杂多模型路由或自动故障转移。
- 替换或衔接现有模拟连接测试，明确mock/真实；服务端密钥加密引用、轮换、掩码、出网限制及重定向校验。
- 实现超时、取消、限流、供应商错误映射、允许模型选择与用量回传；降级只能走预先批准的数据范围和能力。
- 交付假适配器故障夹具和真实适配器定向测试，两类结果分开；缺凭据时可完成接口和测试夹具，但本项保持未结。
- 以实际SDK解析器驱动已有协议/流式/结构化/tool-call分帧用例，与旧适配做契约差分（错误、部分流、取消、重复ID和计量）。旧适配在等价验证及回退准备之前保留；新协议不再默认手写解析器。LiteLLM不列为必装，确有SDK覆盖缺口时另留采用依据。
- 验收：两轨均经过相同网关及安全/预算入口；配置修订变化、跨租户凭据和未支持协议拒绝；真实认证失败/超时/能力不足不报成功。已实现协议的真实连接、必需能力及工具往返/用量有可核对证据，mock 不替代，日志不泄密。

### AIN-06 持久化任务运行器、步骤恢复和接管

- 使用LangGraph.js承接有限图编排、条件分支与暂停，不再扩写一套通用图引擎。接入现有运行器执行端口与已冻结任务状态；图节点的模型调用只经Gateway，工具调用只经受权工具目录，澄清与授权分开。不得将SDK另一个Agent循环嵌入图中自行调工具。
- 首批选择最小只读图适配，随后在原依赖内接澄清/确认。节点返回业务结果引用，不按框架“图结束”直接置任务成功；interrupt恢复必须带原task/run/step、输入或提案修订并核验当前身份，不能将resume:true当批准。
- 持久化领取、租约、fencing及版本控制；崩溃后恢复同一actionId，过期worker不得继续写入。不得在模型等待期间占用业务事务。
- 复用已落地领取、fencing、累计Steps/Calls/ActiveMs/OutputBytes与未知收据；初期执行权仍归现有运行器，图只通过受控端口推进。图节点重入、checkpoint回退、fork/time-travel不能重复派发或重置上限；默认关闭副作用节点的框架自动重试。
- 重试前验证已提交业务结果；未知外部结果保持待核对，取消只停止未发出的动作；部分成功保留逐步结果和人工接管入口。
- 实现步骤/并发/时间/输出上限，接入预算检查接口；AIN-11未齐备时不得生产开放。任务事件游标可重连，落库事实先于成功事件。
- 交付真实LangGraph库与现有仓储/运行器/Gateway端口的组合测试，覆盖checkpoint失败、旧图版本、跨主体threadId、恢复后撤权和中断前节点重入。DB/模型可用明确替身，不能把框架本身也替换成只返回成功的假图。旧通用循环仅在这些证据及存量任务回退路径齐备后退出。
- 验收：提交前后崩溃、响应丢失、双worker、取消竞态、权限改变、幂等记录过期均有测试；无限循环被有界终止。

### AIN-07 提案确认、授权绑定、重校验与幂等

- 复用现有审批消费及Core组合，不新建框架审批库。图interrupt仅用于暂停和通知，正式批准/拒绝由原接口产生；恢复时查受权、有效、同一方案的持久事实，不接受模型或客户端声明“已批准”。节点重入仍走原幂等/收据，审批与Core原子边界不降低。
- 实现不可变方案revision、规范化payloadHash、对象/报价/政策版本、确认人/scope/期限、拒绝及单次消费；批准动作不是模型工具。
- 复用Core业务幂等，审批消费与业务提交具备可恢复的一致性关联；禁止确认已消耗但订单重复、或业务已落库却显示未执行后再次创建。
- 提交点重验权限、价格、库存、资格、对象版本及取消状态；效果变化产生新提案，不能静默改商品或金额。
- 多动作显示原子边界、部分完成和补偿策略；外部副作用不承诺回滚。高风险维持原审核链。
- 验收：篡改/过期/跨人/跨范围确认拒绝；重复请求返回同一事实；并发变更与故障恢复真库测试通过。

### AIN-08 经营只读工具与权威事实查询

- 沿用现有工具schema、成熟度及Guard/ALS链，向LangGraph注册的是受控包装，不复制权限算法或Core查询。已完成客户候选/订单快照/开业风险等切片继续复用；库的工具description不是权限来源，依赖缺失保持unavailable。
- 封装商品、可用性、客户候选、订单事实/快照、开业检查、经营风险等最小工具；先核验现有入口，不建立任意SQL问答。
- 每工具落实schema、权限、成熟度、最大返回量、脱敏和查询时点；未交付的场景返回可解释不可用。
- 历史规则/价格/检查模板按订单适用依据读取；当前库存不可被当作历史利用率，缺成本不输出利润事实。
- 为模型提供简洁、可引用、可核对的数据，工具结果自然语言视为不可信内容。
- 验收：四品类实际差异由定义/能力驱动；越权资源、缺失历史、同名客户、无结果等用例通过。

### AIN-09 Core报价工具与四品类输入规范

- 编排仅收集/澄清输入并调用现有报价工具；复用已实现的参数绑定及金额校验。采用开源结构化输出不更改Core计价，也不让模型工具执行回调绕过原场景授权。
- 将自然语言候选转换为待确认参数：商品/数量、客户或企业身份、开始结束时间/时区、计价与履约方式、地点；枚举由服务器解析，不开放不适用品类选项。
- 调用Core正式计价，不允许模型覆写计算结果；确认报价是否持久化并在工具风险说明标明。
- 输出分项、总额、币种、单位、规则/价格/优惠版本、有效期、查询时点及是否占用资源；报价与库存锁定不可混淆。
- 提供结构化歧义、缺项、缺货、资格、过期与当前不支持的返回值，允许用户更改后重新报价。
- 验收：四品类相同输入与人工入口报价完全一致；相对日期/时区/数量边界有确定性断言。

### AIN-10 知识文档、权限检索、来源及结构化记忆

- 复用文件上传与现有knowledge生命周期/Prisma adapter。解析、分块和检索连接器优先采用成熟开源组件，只适配批准格式、大小/资源限制；未知格式拒绝，不另建通用知识平台或全局无权限索引。
- ACL在检索召回及正文读取前落实，tenant/scope/版本/权限修订隔离缓存，撤回/删除传播至索引、缓存和来源访问。
- 当前业务实时事实走工具，不塞入知识索引；历史依据与通用SOP分别处理。每个来源可追到版本及具体段落/资源。
- 偏好只存经用户确认的结构化值，支持查看/修改/删除；任务记忆不得存永久授权、密钥或跨空间复用的敏感摘要。
- 框架checkpointer/store不得取代正式文档/偏好确认仓储；消息历史与长期记忆分开。用真实解析/召回实现驱动原ACL、撤回、恶意文档、缓存隔离与资源上限测试；词法/向量方式如实登记，不为引库强制引入向量数据库。
- 验收：跨租户召回、撤权缓存、撤回引用、解析失败、文档注入、无证据回答的测试及内容权限复核通过。

### AIN-11 平台/租户AI设置、权益、预算与计量

- 平台配置已验证供应商/模型/凭据引用、能力、限流和全局停用；租户默认“Rental OS AI（推荐）”，不要求 Base URL/API Key/协议/模型。高级模式“自定义 AI 服务 / BYOK”才展示这些管理字段及连接测试；两轨共用场景、角色/空间、预算和自动化政策。
- 模式使用 `platform_managed / tenant_managed`；旧自定义配置保留，切平台不自动删除密钥。保存、读视图、内部凭据引用分开；修订/CAS 冲突和轮换后旧任务重校验。BYOK URL 经过与平台相同的 DNS/连接地址/重定向策略，不能用 schema 格式验证冒充出网安全。
- 场景code、提示词/模型/工具集合及政策采用版本化配置，变更有草稿差异、评测与发布/回退记录；租户只能调整明确开放字段，不能用提示词覆盖系统授权。首期不建设通用可视化Agent编排器。
- 与既有订阅/能力交集，不重新定义Basic/PRO、不自行收费；预算未配置或为0时不得解释为无限额。
- 预留—实际/估算结算—释放须并发安全与幂等，含失败/重试/降级成本；缺用量进入待核对，预算拒绝后不调用供应商。
- 继续使用现有单账财务预算，框架/SDK的token统计只是待核验用量输入；不启用第二套钱包或代理账本扣费。框架恢复不重置任务累计资源；SDK/图的一次实际外呼必须绑定原request/run/step/invocation/reservation/dispatch及配置版本。错配、重复和unknown沿原规则拒绝/核对，开源默认计价不替代可信价格依据。
- 按任务/模型/场景查询最少用量，平台默认看聚合不看租户正文；关闭AI保留合法历史与人工经营。
- 验收：默认模式无供应商字段、BYOK 字段按模式显示、旧记录无损兼容及切换保留配置；并发压满、失败/未知用量、重复结算、配置撤销、密钥脱敏和设置权限通过。平台供应商信息不暴露给普通租户；UI 公共文件由 F 认领人整合。

### AIN-12 后台任务中心、受控卡片与公共交互

- 保留已做Workbench、事件消费者和真实页面默认关闭装配；框架事件须映射成既有公开任务投影后进入UI，不重建第二套聊天后台，不把框架私有游标或图成功态直接暴露成业务成功。
- 在既有后台增加全局/当前业务入口及任务列表、详情、澄清、确认、取消/重试/接管；不替换正常菜单与表单。
- 实现schema驱动的订单/报价/差异/风险/检查/步骤卡片；只渲染注册组件，模型文本与来源安全处理，禁止动态代码。
- 与平台/租户设置页联调，统一中英、主题与圆角/字号token、加载态、键盘、窄桌面/移动端布局及减少动画。
- AI 服务设置采用平台默认/BYOK 双模式，按模式显示字段、真实连接及逐能力结果，未验证不画成功勾；场景运行前明确列出缺失必需能力，传统人工入口保持可用。
- 重连去重、断线恢复、迟到响应、权限变化、预算不足、部分成功、模型失败和来源无权限都有明确状态。
- 验收：真实浏览器操作与截图/断言齐备；更换主题/语言、缩窄窗口、切空间不会串任务或丢确认语义；夹具测试不当作真实业务验收。

### AIN-13 订单解释及下一步指引

- 作为首个开源编排纵向场景，完成订单页/用户选择 → 现有任务 → LangGraph只读图 → Gateway及AIN-08工具 → 来源/结果 → 原Workbench。识别问题并读取授权范围内最少事实/历史依据；没有正式依赖保持关闭，不能用框架demo替代现有实现。
- 清晰区分应收/实收/押金/预授权、退款申请/受理/成功；解释给出来源和查询时点，缺证据不补造原因。
- 下一步只引用实际可用的工具/人工入口，自动推断的建议与事实分开；本任务不实现未经确认的资金动作。
- 建立已付款/未付款/部分归还/待结算/变更/争议/失败退款等实际支持状态的评测集，无法支持的案例说明依赖。
- 验收：关键金额与状态逐条确定性对照；模型答案不可把失败润色为成功，权限负例和后台实流通过。

### AIN-14 开业诊断与分区配置提案

- 复用AIN-06已验证图适配和AIN-08诊断工具，不复制第二套Agent循环；各分区按既有事实生成解释/提案，写入仍等待AIN-07/16合法路径。
- 接入正式开业检查、品类定义、能力、营业规则/日历与第三方配置状态；输出必需/可选/未实现/外部待配置的区别。
- 对可配置分区生成差异提案，未有业务草稿入口时只保存AI提案；不能为让检查变绿直接改活动配置。
- 不虚构地址、证件、密钥、真实连接或已发布状态；提供对应配置页和人工所需信息。
- 明确每个分区独立保存、审核/发布与采用边界，提案编排复用AIN-07但执行在AIN-16承接。
- 验收：空租户、部分开业、能力未交付、连接mock/失败、旧规则版本和并发修改等场景输出符合真实检查。

### AIN-15 自然语言报价到确认开单闭环

- 在同一开源编排适配内组合已验收AIN-07/09端口；图只决定受控步骤顺序，不替代报价/审批/业务事务。每个暂停和恢复均绑定既有任务及不可变方案，框架自动工具调用不得直达Core写入。
- 串起澄清、客户/企业身份选择、目录/库存/资格、Core报价、提案确认、正式创建及订单链接；最终结果来自持久化业务事实。
- 不自动选择同名客户、不把客户一句“可以”复用为其他动作批准；更改日期、替代商品、数量、优惠或价款均重新生成方案。
- 复用现有支付/待办入口；建单成功不表示已支付、已锁定或已交付；失败保留可继续草稿和明确人工出口。
- 测试正常、缺货、并发抢占、过期报价、撤权、响应丢失与取消；四品类同一工具路径，差异按正式定义。
- 验收：每类至少完整成功案例及关键失败案例，在独立真库证明一确认一业务动作，人工入口与AI路径业务结果等价。

### AIN-16 客户资料与获准配置写入闭环

- 首批明确工具白名单：资料普通字段及开业配置草稿/获准设置；高风险敏感字段仅引导原验证/审核，不扩大到任意配置更新。
- 逐字段展示现值、新值、来源与共享范围；手机/身份/企业关系沿用原校验，禁止AI代造已审核事实。
- 业务草稿、AI提案、实际写入、发布分别返回；expectedRevision冲突刷新差异再确认，部分失败逐项标明。
- 配置发布等R3只调用正式权限与审批链，不替代品类或规则版本机制。
- 验收：共享会员与空间信息隔离、敏感验证、多人编辑、失效批准、重复提交、草稿未发布不生效均通过。

### AIN-17 可靠业务事件、Outbox与有界触发

- 盘点实际事件机制；可靠性不足才增量建设事务Outbox，保证业务写入与待投递事实一致，禁止旁路扫描全部业务私自推断事件。
- 事件契约含scope/资源版本/类型/trace；消费者至少一次投递、有界重试、死信/人工处理、领取和去重。
- 优先复用现有事件投递；有已测队列缺口时才引入成熟开源队列。明确Outbox、队列、图和执行Worker的边界；不得因引入队列/Temporal再提供一套副作用恢复所有者，不以框架重试代替业务幂等。
- 仅接交付资源风险、归还异常、通知/退款明确失败和开业缺项；过期事件查当前状态，任务自触发有因果标识和循环限制。
- 不改既有确定性对账/到期作业职责；事件系统停用不应使原业务写入因模型不可用失败。
- 验收：事务回滚不发事件，提交后宕机不漏可恢复事件；重复/乱序/worker接管不重复副作用，有真库故障证据。

### AIN-18 主动经营、影子模式及低风险自动化

- 将AIN-17限定事件转为风险解释、候选方案与待办；已解决资源不保留失效建议，人工处理结果可反馈去重。
- 初期仅影子/人工确认；自动化政策登记主体、工具白名单、scope、收件人、上限、冷却、有效期、启用人和修订。
- 自动动作按批准政策及当前权限执行，R3强制人工；退款失败场景只提示/核对，不自主再次退款。
- 配置全局/租户/场景停用、预算上限和人工接管；限制通知频率并复用真实通知服务，未知投递先查询。
- 验收：影子不写业务、撤权立即停止新动作、重复事件不重复通知、过期政策和循环拒绝；生产白名单未确认保持关闭。

### AIN-19 图片/语音识别草稿与来源定位

- 接入已有合法文件链与选定模型能力，绑定订单/资源/阶段/冻结模板；异步识别上下文不可切换到新订单。
- 输出字段code、候选值、原文、图片区域/音频时段、置信提示及缺项；保存人工更正与原候选的对应关系。
- VIN/车牌/序列号/里程/工时/数量使用原格式验证，模糊留空；疑似损坏仅证据候选，不自动判责或增加费用。
- 多模态提供商若与文本不同，重新审批数据处理配置；恶意附件/超大文件有资源限制，不执行内容代码。
- 验收：合成及有授权测试素材覆盖遮挡、模糊、跨资产、倒退读数、缺领取基线、换表与恶意指令；真实识别与模拟夹具分开。

### AIN-20 员工小程序AI履约交互及宿主接入

- 接入员工白名单身份、空间/地点范围及订单分配；从现有交付/归还检查入口使用AIN-19，仍由员工确认最终事实。
- 展示来源、候选/人工值差异和缺项；只有当前模板要求满足且原业务校验通过才提交，不把识别完成当履约完成。
- 实现相机/相册/录音、上传进度、弱网草稿、重试和同步状态；迟到识别、切空间、退出会话不得写错对象。
- 微信传输用轮询或已支持事件方案，不为套用SSE绕过宿主限制；权限拒绝可人工填单。
- 验收：实际微信宿主和指定真机走交付/归还及异常；代码构建、浏览器夹具、宿主、真机分别标记，缺设备不得结项。

### AIN-21 客户助手后端场景及独立安全边界

- 为客户单独暴露公开选品/报价、本人订单解释和正式办理入口，绑定渠道发布空间、客户或企业授权身份。
- 匿名只读公开内容、登录后按会话归属显式迁移，禁止用任务ID关联别人会话；限流和预算防滥用。
- 客户不能访问内部客户候选、全库存、成本、审核意见、平台配置或后台任务；所有引用/事件/下载同样隔离。
- 业务动作若在客户端范围开放，同样经过AIN-07；首批以正式下单/支付页面承接，接口返回办理状态而非聊天承诺。
- 验收：匿名枚举、跨客户/企业、越权工具、支付伪造、会话迁移与身份改变后旧任务访问负例通过。

### AIN-22 客户小程序与现有预约网站AI入口

- 分别在既有客户小程序和租户预约网站接入同一场景契约，明确各端可用能力；不重复实现后台业务计算。
- 展示选品澄清、可租方案、Core报价、订单解释与正式办理入口，复用品牌/主题/语言和常规支付/预约流程。
- 处理登录、企业身份切换、发布空间、断线/取消/重连、模型失败及人工客服出口；无AI时常规流程可走通。
- 独立APP只保留版本化接口、身份要求与示例，不创建APP工程；两端可由不同AI认领独立目录。
- 验收：Web浏览器与微信宿主/真机证据分别齐备，公开/本人数据隔离和既有收银台跳转真实通过；外部支付成功只用真实回调证据确认。

### AIN-23 平台品类草稿、校验与发布采用助手

- 读取目标部署的正式治理能力，按真实策略/字段/模板目录生成内置或新增品类草稿，不接未合入分支的虚拟接口。
- 接入正式校验、差异/历史影响报告；新增必填/唯一性/计价库存范围收窄有阻塞和准备项，不通过提示词强行跳过。
- 发布、租户可采用资格、空间采用分别走权限与确认，展示各自结果；不宣称发布等于全空间升级。
- 品类治理尚未支持的部分明确依赖CAT-GOV对应任务，可先完成已有范围，整体仍未完成；禁止并行AI在本任务重建治理内核。
- 验收：内置品类与正式支持的新类分别实流验证，历史订单依据不变；能力未交付拒绝，高风险发布/采用确认和并发冲突通过。

### AIN-24 攻击/越权评测、业务评测与审计隐私

- 增加开源适配威胁面：跨scope线程/checkpoint/store读取、节点重入、伪造resume、旧图回放、隐式重试/媒体下载、SDK工具执行、默认遥测、插件供应链及凭据外传。驱动实际库与现有安全入口，许可证/依赖审计与业务负例分开留证；禁用任意SQL/HTTP/代码/终端能力。
- AIN-02后即建立测试集和威胁模型，随每场景落地持续验证；记录模型/提示词/工具/数据版本，确定性业务断言与语言人工评分分开。
- 覆盖越权、提示注入、任意出网、恶意附件、XSS、过量读取、来源/缓存泄漏、审批伪造、预算竞态及任务恢复提权。
- 审计只存可核对输入摘要/计划/工具/授权/结果，不保存模型内部思维链；实现正文脱敏、敏感访问审计和分类留存/删除传播。
- 构建固定与对抗用例，不能由同一个模型评价自己就判通过；关键越权、未授权R3、重复资金动作验收零容忍。
- 补双模式负例：跨租户/平台凭据误用、模式或配置修订过期、未验证能力、BYOK SSRF/DNS 重绑定/重定向、旧配置泄密；明确静态与真实出网证据区别。
- 验收：每个已开放端和工具有负例覆盖；阶段报告在记录中追加，只有全专项范围及修复复验齐备才归档本项。

### AIN-25 性能成本、故障降级及运行SLO

- 对实际采用的开源路线测量适配后延迟、checkpoint开销、内存与部署依赖；比较剩余开发/维护工作和适配、迁移、升级成本，不把已有投入算作可节省工时。未采样不填节省比例，也不为展示“先进架构”引入多个重叠运行时。
- 测量首字/首卡、完整任务时延、成功/接管率、模型/工具耗时、任务成本、预算拒绝、取消和恢复；注明并发、样本量与设备。
- 使用AIN-01人工基线，给出可审查的首发SLO/容量/每任务成本限制，记录AIN-D05决定；未测不得编造达标数值。
- 压测模型限流/超时、DB/worker故障、事件积压、多租户公平性及配额突发，验证有界队列、背压、告警与恢复。
- 降级到已验证模型或人工入口，禁止扩大数据范围；模型升级保留版本和回滚，关闭AI不拖累经营主链。
- 验收：实际环境测量报告、预算/超时/故障演练齐备，能按版本回到原配置；没有真实供应商时不声称真实成本已验证。

### AIN-26 四品类真库与多端组合验收

- 冻结待验收API构建、客户端构建、数据库迁移、模型/提示词/工具/政策版本与数据夹具哈希；不同AI不能共用同一运行实例边测边改。
- 在新建独立测试库覆盖摄影/露营/车辆/工程成功、失败、澄清、并发、取消、恢复和接管；业务能力差异可解释，不能四套硬编码测试假通过。
- 组合后台、员工、客户Web/小程序、平台助手与事件任务；复核人工报价/履约/结算不回归，资金测试模拟/沙箱/真实模式明确。
- 逐项登记AIN-A01～A29证据、未运行项、缺陷归属和复测；静态、数据库、浏览器、微信宿主/设备各自成证据层。
- 将需求§18开源适配条件纳入相应原验收项。旧/新路径对照确定性业务事实、调用次数、审批/预算收据和权限结果，不要求模型逐字相同；对照只读或离线副作用替身，禁止双跑真实写入。已有失败断言保留，不因换框架skip/todo。
- 验收：关键用例全过，未解决缺陷不以总体通过率掩盖；清理本轮数据库/进程/端口，保留脱敏可复查报告，不碰共享资源。

### AIN-27 真供应商、试点灰度与部署回退

- 在负责人批准的模型、数据处理、额度和试点范围内启用真实供应商；验证工具调用、用量、认证失败、超时、限流及适用多模态。
- 分别验收 Rental OS AI 和 BYOK；核对新租户无供应商配置体验、旧自定义数据升级/回退、能力不足前置提示和两轨相同权限/审计/预算边界。供应商采购、生产密钥和试点开放仍需独立授权。
- 分别检查部署配置、密钥轮换、回调/域名、队列、监控、数据留存与停用；不以开发机成功代替部署验收。
- 灰度先只读/草稿，再确认写入，再经额外批准的有限自动化；每阶段有放量/停止条件、责任人及人工回退路线。
- 演练模型/提示词/工具政策回退，数据库采用可兼容迁移或明确补偿，不做无备份破坏式降级；已提交业务事实继续可查。
- 锁定图、SDK、checkpointer及存储版本，按服务端政策给新任务选择实现；旧在途任务默认沿旧版结束。演练关新入口、排空/人工处理在途、回退及历史读回；不得换引擎后重置actionId/审批/预算，或因旧checkpoint不可读而盲重派。新旧通用路径退出清单随灰度留证。
- 验收：AIN-A30/A31真实证据及实际负责人放行齐备。缺凭据或经营决策登记具体阻塞，本项不伪完成。

### AIN-28 独立复核、缺陷清零、文档归档与交付

- 由非实现作者复核需求覆盖、跨模块契约、授权、恢复、成本、数据边界与用户操作；若只能同一执行者复查，标明“自复查”，不冒充独立Review。
- 修复所有阻断及高风险缺陷，逐个关联原任务和复验；明确不纳入本期的Reserved，不把未实现需求移到储备以结项。
- 整理部署/运行/停用/接管、管理员和员工客户使用说明、工具/API契约、决策及证据索引；完成任务移入唯一归档。
- 归档开源组件版本、许可证/NOTICE、依赖清单、已知风险、补丁来源、升级/回退责任和重复实现退出证据。核对未引入未经许可的云服务/遥测；开源本身长期保留不构成未完成项，也不以日后全量自研作为结项条件。
- 总进度核对原28项，确认无未处理范围、无未交接工作树/测试资源、无虚构真机/支付/模型验收。
- 验收：负责人收到可操作交付与风险边界；专项全部真实完成才计100%，只完成底座或演示不能结项。

## 5. 统一完成定义

每项归档前必须同时具备：

1. 原需求及本任务范围全部实现；业务边界冲突已明确处理，无未实现功能用mock遮盖。
2. 生产者/消费者契约一致，服务端最终鉴权，持久化与错误/人工出口可用。
3. 相关单测、契约、类型/构建及按风险的真实数据库/浏览器/宿主/外部环境验证通过；明确未运行内容。
4. 实现理由、原入口复用、代码提交、测试命令/实际结果、失败修复和资源清理有记录。
5. 独立复核问题完成复验；整合后的提交再次验证，不只看某个工作树独立通过。

使用开源库的任务还须满足需求§16/18的映射、许可、升级/退出和适配故障条件。包能安装、示例能运行或框架自身测试通过均不能代替产品集成；原先已通过的业务证据继续保留，受影响部分有风险地复验，不为换路线重跑无关测试凑数量。

本专项不授权修改共享数据库、其他AI工作树，不自动授权合并main、推送或生产启用。测试只操作预检查不存在的新`rental_os_e2e_*`库；环境准备与清理由实际任务责任人留证。正式业务写入只在明确授权的测试/试点范围内。
