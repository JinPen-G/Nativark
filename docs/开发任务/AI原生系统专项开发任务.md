## 置顶核心规则：功能实现优先，验证有界（2026-10-10）

**先完成核心功能和实际生产者/消费者接线，不要把开发变成测试脚本工程。此规则适用于所有接手者；压缩对话、交接、心跳或旧派工不得覆盖。**

- 优先复用现有测试，必要时只补直接覆盖本片功能或已确认缺陷的最少断言；不为每片新建测试脚本、检查器或成套矩阵，也不借复用文件无限扩充用例。
- 每个完整功能片做一次定向小冒烟，类型检查只在确有必要时进行；通过后立即推进下一功能，不默认整套回归、重复审计或逐片深测。
- 失败只定位并修复本片相关问题，做必要复测，不借机扩大范围。用户要求检查某批改动时同样遵守此边界。
- 全量组合、故障矩阵、性能和真实环境深测留到集中验收阶段；如实记下未验范围，不能拿轻量验证代替正式验收。
- 功能优先不放松授权、审批、幂等、预算单账和离线禁令，不删除已有源码、测试、output或锁。交接应先说已实现功能与下一实际缺口，不用测试数量充当进度。

### AIN-ENTRY-01：多端 audience 与场景目录

- 登记 `operations`、`staff`、`customer`；`platform` 仅在平台正式授权和工具白名单存在后开放，不能作为普通租户万能入口。
- 明确四端入口：租户管理后台、员工小程序、客户微信小程序、租户消费者预约网站；客户小程序与网站共用后端场景契约，分别处理登录、渲染和导航。
- 服务端解析并复核 tenant、workspace、location、role、customer/enterprise relation、dataScope 和能力/订阅；模型、客户端字段、URL 参数、旧缓存不能授予范围。
- 每个场景登记可用工具、原权限、最大返回量、脱敏、查询时点、成熟度、风险级别、人工出口和停用方式。

### AIN-ENTRY-02：结构化 Action 与固定导航接入

- 建立版本化 Action 注册表，首批允许 `OPEN_ORDER`、`OPEN_CUSTOMER`、`OPEN_PRODUCT`、`OPEN_BOOKING`、`OPEN_PROFILE`、`OPEN_PAYMENT`、`OPEN_DISPATCH`、`CREATE_BOOKING_DRAFT`、`CREATE_NOTIFICATION_DRAFT`。
- Action 至少校验 `contractVersion`、`actionCode`、`audience`、target/resourceVersion、surface、scope、`requiresConfirmation`、`riskLevel`、`expiresAt`、输入指纹和 task/proposal/quote/draft 引用。
- 客户端只做 Action Code 到固定页面/行为的映射；不得执行模型 URL、脚本、任意组件名或任意路由。未知、过期、篡改、跨端、跨 scope 和不兼容版本必须拒绝。

### AIN-ENTRY-03：客户需求澄清与 Booking Draft

- 实现“描述需求→结构化条件→真实商品/可用性/报价→Booking Draft→用户明确继续→原预约页面确认”的装配。
- 草稿只绑定已明确输入、正式默认或 Core 规范化字段；不代替订单、库存锁、支付或审批。
- 草稿持久事实至少包含 audience、会话/创建者、tenant/发布空间、输入指纹、选择修订、报价/规则/可用性观察版本和过期时间；不保存支付令牌或未授权敏感资料。
- 身份、空间、商品、时间、地点、可用性或报价变化时旧草稿立即失效并重新准备，不自动替换商品或合并匿名与登录状态。

### AIN-ENTRY-04：跨端转接和身份切换

- 小程序与预约网站只共享版本化场景/草稿引用，不默认共享会话、任务、缓存或权限；跨端必须使用有期限、一次性或可核验的服务端引用重新绑定当前身份和 scope。
- 匿名访客登录、客户/企业身份切换、租户/空间切换、登出重登时，旧 Action、草稿、异步回调和敏感内容必须隔离或失效。
- 页面和宿主不能通过保存 taskId/customerId 或前端过滤恢复旧授权。

### AIN-ENTRY-05：运营后台结果与人工操作

- Operations Agent 的结果优先提供事实、来源、观察时间、风险/阻碍和已登记的下一步，而非只给长文本；可以跳转订单、客户、商品或调度查看页。
- 只读、预览、需要确认的准备动作和正式业务写入分开；退款、资金处分、调度、通知、建单等 R2/R3 仍走现有权限、Proposal/Approval、预算、幂等和 Core 提交链。
- 没有正式 allowed-action 服务时只返回已核实的人工入口或 `candidates_only`，不把权限码本身当作业务可执行许可。

### AIN-ENTRY-06：员工履约入口

- 员工只读取当前 tenant/workspace/location/role 白名单内的订单、客户、资产和履约资料。
- AI 可以引导交付、归还、检查、拍照、读数和资料补全，但不直接提交检查、不判责、不改收费、不绕现有上传、审批和业务提交入口。
- 弱网、卸载、切空间、权限撤销、识别未知结果和人工更正必须保持草稿/同步/待核对语义，不显示假成功。

### AIN-ENTRY-07：Core 事实和正式报价装配

- 所有库存、可用性、最终报价、押金、优惠、资格、退款、订单和付款事实必须来自 Rental Core/正式只读服务；AI 不重算、不覆写、不把报价当锁定。
- 报价准备输出分项、总额、币种、计价单位、规则/价格/优惠版本、有效期、查询时间、资源占用语义和持久化副作用；缺字段保持缺失/未知。
- 报价或草稿确认不等于建单批准，只有既有固定接口和正式审批/提交链齐备后才可接入下一步；否则交付 `prepared_not_submitted` 或 `unavailable`。

### AIN-ENTRY-08：风险、权限和生命周期降级

- 统一风险级别：R0 只读/导航，R1 报价/草稿/通知草稿，R2 候选和准备，R3 建单/支付/退款/取消/调度/发布等业务写入。
- AI 不可用、预算耗尽、工具 unavailable、未登录、权限变化、离线、报价过期、库存变化、Action 无效或结果 unknown 时，转原页面/人工办理，禁止假成功和自动重派未知副作用。
- R1～R3 均须声明未提交/未执行状态；R2/R3 在执行前重新核查身份、scope、对象/报价版本、能力、预算和审批。

### AIN-ENTRY-09：隐私、刷新和结构化显示

- 不向客户泄露其他客户、内部成本、审核意见、隐藏库存、支付令牌或密钥；员工/管理员也仅见当前授权范围。
- Action、事实、报价和可用性带查询时点、来源/版本、有效期或未知标记；模型文字不能覆盖确定性金额、状态、资格和 Core 结果。
- 模型链接、HTML、控制字符和导航参数走既有安全呈现/白名单；不通过富文本、任意 URL 或前端隐藏绕过服务端授权。

### AIN-ENTRY-10：固定入口与人工兼容

- 将入口接入现有显式组合、任务/事件和页面宿主，不注册第二套 HTTP、Worker、Runtime 或客户端路由系统。
- 任何端关闭 AI、缺后端能力或失去权限时，传统订单、预约、履约、支付和人工流程保持可用。
- 入口交付需列明真实页面/宿主装配、默认关闭位置、Action 映射、可用工具、人工出口和未接通依赖。

### AIN-ENTRY-11：组合快检和证据等级

- 复用真实业务服务和现有离线夹具，按 audience 各选正常、缺依赖、权限变化、过期/unknown、重复点击和迟到响应案例；不复制产品逻辑到夹具。
- 证据分开记录为静态/类型、服务行为、离线宿主模拟、真实 Core/数据库、浏览器、微信宿主/真机和供应商；低等级证据不得升级为高等级结论。
- 只做边界内定向快检，失败保留首轮证据并修实际缺陷；不以新增脚本数替代功能实现。

### AIN-ENTRY-12：交接与未来替换资料

- 每片留下稳定输入/输出、生产者/消费者、Action/草稿状态、持久化事实、授权/预算/审批/Core 依赖、当前耦合和未验项。
- 未来替换 Runtime 或 Provider SDK 时只替换编排/适配边界；不得改变业务 Action、Task、Proposal、Core 收据和预算单账语义。未验证的迁移、checkpoint 映射和回退条件标为待验证。
- 本增量队列清空不等于原 AIN-01～AIN-28 结项；主线须按原任务和需求文档完成独立验收。

### AIN-ENTRY-13：稳定契约与事实来源优先级

- 冻结 Action、Booking Draft、事实投影、错误和证据等级的生产者/消费者；缺字段时提出公共契约补丁并保持 `unavailable`，不造私有同名 DTO。
- 对每个输入记录“用户明确输入/选择、服务端正式默认、Core 规范化、受权事实、模型候选”的来源；模型、缓存、客户端回传不能升级为确认输入、权限或业务事实。
- Runtime/Provider SDK 类型只留适配边界；Task、Proposal、Core 收据、预算单账、Action 和 Draft 状态不绑定具体框架或供应商对象。

### AIN-ENTRY-14：Booking Draft 与 Action 状态转移

- 实现并验证 Draft 的允许状态转移、失效终态、选择修订、输入指纹、过期和提交语义；`submitted` 不得解释为订单/支付/履约成功。
- Action 在签发、展示、执行前分别复核版本、过期、audience、surface、scope、资源修订和当前权限；重复点击使用幂等关联，不创建第二订单、Proposal、Draft 或资金动作。
- 跨端引用必须由服务端签发、短期/一次性消费并重新绑定身份和 scope；不得用前端 taskId/customerId、URL 或缓存恢复授权。

### AIN-ENTRY-15：端/租户发布、停用和传统路径

- 为每个端、租户和场景登记默认关闭位置、能力探测、停用行为、人工出口和回退页面；关闭或依赖缺失时零 AI 读取、零轮询、零动作。
- 禁止 URL、localStorage、模型文本和客户端自报能力启用入口；停用后新请求拒绝，在途未知按原规则核对，不自动重派。

### AIN-05 真实模型网关、能力声明与凭据管理

**重点施工要求：当前模型协议开发必须为后续接入成熟开源 Provider SDK 做准备，与 Runtime 可替换性同等重视，但两者独立实施。** 当前继续复用已有协议实现，不以此要求启动 SDK 安装、迁移或全仓重构。

- 在本线切片记录中同步维护请求/响应字段、终态、错误、usage、工具标识及取消映射，受控传输注入位置、重试所有者、实际请求次数、兼容测试入口、耦合点与未来替换/回退步骤。接口变化时更新；不只写“以后可接 SDK”。
- 保持平台/BYOK 配置与凭据修订、能力准入、受控出网、唯一 dispatch 和预算单账；SDK 不得隐式使用环境密钥、全局 fetch、云代理、媒体下载、遥测、自动工具循环或未批准的重试/模型回退。
- 当前触及的代码保留可验证的请求/终态/用量证据和有限快检；实际采用时以锁定发布包验证导入、许可、运行时兼容和旧新契约差分。SDK 缺值补零、生成 ID、流内错误等行为不得改变原事实与 unknown/reconcile 语义；结果未知不切换适配器重发，不双发真实模型做对照。
- Provider SDK 可替换性落实到原 AIN-02/05/11/24 的接口、单账和验证交付，不新增正式任务或调整28项状态；已有代码与测试实际保留，后续启用与回退另行确认。每批相关底座派工必须同时带上 Runtime 和 Provider SDK 提醒，保持每片一次定向冒烟/必要类型检查的功能优先节奏。

- 建立统一 Gateway → Provider Router → 平台/租户配置 → Provider Adapter；保留已有受控协议，Agent 仅提交场景与能力需求，不直接读供应商连接配置或 SDK。绑定实际配置来源、修订和模型；平台缺配置如实不可用。

- 替换或衔接现有模拟连接测试，明确mock/真实；服务端密钥加密引用、轮换、掩码、出网限制及重定向校验。
- 实现超时、取消、限流、供应商错误映射、允许模型选择与用量回传；降级只能走预先批准的数据范围和能力。
- 交付假适配器故障夹具和真实适配器定向测试，两类结果分开；缺凭据时可完成接口和测试夹具，但本项保持未结。
- 验收：两轨均经过相同网关及安全/预算入口；配置修订变化、跨租户凭据和未支持协议拒绝；真实认证失败/超时/能力不足不报成功。已实现协议的真实连接、必需能力及工具往返/用量有可核对证据，mock 不替代，日志不泄密。

- 提供结构化歧义、缺项、缺货、资格、过期与当前不支持的返回值，允许用户更改后重新报价。
- 验收：四品类相同输入与人工入口报价完全一致；相对日期/时区/数量边界有确定性断言。

### AIN-11 平台/租户AI设置、权益、预算与计量

- 平台配置已验证供应商/模型/凭据引用、能力、限流和全局停用；租户默认“Rental OS AI（推荐）”，不要求 Base URL/API Key/协议/模型。高级模式“自定义 AI 服务 / BYOK”才展示这些管理字段及连接测试；两轨共用场景、角色/空间、预算和自动化政策。
- 模式使用 `platform_managed / tenant_managed`；旧自定义配置保留，切平台不自动删除密钥。保存、读视图、内部凭据引用分开；修订/CAS 冲突和轮换后旧任务重校验。BYOK URL 经过与平台相同的 DNS/连接地址/重定向策略，不能用 schema 格式验证冒充出网安全。
- 场景code、提示词/模型/工具集合及政策采用版本化配置，变更有草稿差异、评测与发布/回退记录；租户只能调整明确开放字段，不能用提示词覆盖系统授权。首期不建设通用可视化Agent编排器。
- 与既有订阅/能力交集，不重新定义Basic/PRO、不自行收费；预算未配置或为0时不得解释为无限额。
- 预留—实际/估算结算—释放须并发安全与幂等，含失败/重试/降级成本；缺用量进入待核对，预算拒绝后不调用供应商。
- 按任务/模型/场景查询最少用量，平台默认看聚合不看租户正文；关闭AI保留合法历史与人工经营。
- 验收：默认模式无供应商字段、BYOK 字段按模式显示、旧记录无损兼容及切换保留配置；并发压满、失败/未知用量、重复结算、配置撤销、密钥脱敏和设置权限通过。平台供应商信息不暴露给普通租户；UI 公共文件由 F 认领人整合。

### AIN-12 后台任务中心、受控卡片与公共交互

- 在既有后台增加全局/当前业务入口及任务列表、详情、澄清、确认、取消/重试/接管；不替换正常菜单与表单。
- 实现schema驱动的订单/报价/差异/风险/检查/步骤卡片；只渲染注册组件，模型文本与来源安全处理，禁止动态代码。
- 与平台/租户设置页联调，统一中英、主题与圆角/字号token、加载态、键盘、窄桌面/移动端布局及减少动画。
- AI 服务设置采用平台默认/BYOK 双模式，按模式显示字段、真实连接及逐能力结果，未验证不画成功勾；场景运行前明确列出缺失必需能力，传统人工入口保持可用。
- 重连去重、断线恢复、迟到响应、权限变化、预算不足、部分成功、模型失败和来源无权限都有明确状态。
- 验收：真实浏览器操作与截图/断言齐备；更换主题/语言、缩窄窗口、切空间不会串任务或丢确认语义；夹具测试不当作真实业务验收。

### AIN-13 订单解释及下一步指引

- 完成从订单页或用户选择进入的解释工作流，识别问题并读取授权范围内最少事实和历史依据。
- 清晰区分应收/实收/押金/预授权、退款申请/受理/成功；解释给出来源和查询时点，缺证据不补造原因。
- 下一步只引用实际可用的工具/人工入口，自动推断的建议与事实分开；本任务不实现未经确认的资金动作。
- 建立已付款/未付款/部分归还/待结算/变更/争议/失败退款等实际支持状态的评测集，无法支持的案例说明依赖。
- 验收：关键金额与状态逐条确定性对照；模型答案不可把失败润色为成功，权限负例和后台实流通过。

### AIN-14 开业诊断与分区配置提案

- 接入正式开业检查、品类定义、能力、营业规则/日历与第三方配置状态；输出必需/可选/未实现/外部待配置的区别。
- 对可配置分区生成差异提案，未有业务草稿入口时只保存AI提案；不能为让检查变绿直接改活动配置。
- 不虚构地址、证件、密钥、真实连接或已发布状态；提供对应配置页和人工所需信息。
- 明确每个分区独立保存、审核/发布与采用边界，提案编排复用AIN-07但执行在AIN-16承接。
- 验收：空租户、部分开业、能力未交付、连接mock/失败、旧规则版本和并发修改等场景输出符合真实检查。

### AIN-15 自然语言报价到确认开单闭环

- 串起澄清、客户/企业身份选择、目录/库存/资格、Core报价、提案确认、正式创建及订单链接；最终结果来自持久化业务事实。
- 不自动选择同名客户、不把客户一句“可以”复用为其他动作批准；更改日期、替代商品、数量、优惠或价款均重新生成方案。
- 复用现有支付/待办入口；建单成功不表示已支付、已锁定或已交付；失败保留可继续草稿和明确人工出口。
- 测试正常、缺货、并发抢占、过期报价、撤权、响应丢失与取消；四品类同一工具路径，差异按正式定义。
- 验收：每类至少完整成功案例及关键失败案例，在独立真库证明一确认一业务动作，人工入口与AI路径业务结果等价。

### AIN-16 客户资料与获准配置写入闭环

- 首批明确工具白名单：资料普通字段及开业配置草稿/获准设置；高风险敏感字段仅引导原验证/审核，不扩大到任意配置更新。
- 逐字段展示现值、新值、来源与共享范围；手机/身份/企业关系沿用原校验，禁止AI代造已审核事实。
- 业务草稿、AI提案、实际写入、发布分别返回；expectedRevision冲突刷新差异再确认，部分失败逐项标明。
- 配置发布等R3只调用正式权限与审批链，不替代品类或规则版本机制。
- 验收：共享会员与空间信息隔离、敏感验证、多人编辑、失效批准、重复提交、草稿未发布不生效均通过。

### AIN-17 可靠业务事件、Outbox与有界触发

- 盘点实际事件机制；可靠性不足才增量建设事务Outbox，保证业务写入与待投递事实一致，禁止旁路扫描全部业务私自推断事件。
- 事件契约含scope/资源版本/类型/trace；消费者至少一次投递、有界重试、死信/人工处理、领取和去重。
- 仅接交付资源风险、归还异常、通知/退款明确失败和开业缺项；过期事件查当前状态，任务自触发有因果标识和循环限制。
- 不改既有确定性对账/到期作业职责；事件系统停用不应使原业务写入因模型不可用失败。
- 验收：事务回滚不发事件，提交后宕机不漏可恢复事件；重复/乱序/worker接管不重复副作用，有真库故障证据。

### AIN-18 主动经营、影子模式及低风险自动化

- 将AIN-17限定事件转为风险解释、候选方案与待办；已解决资源不保留失效建议，人工处理结果可反馈去重。
- 初期仅影子/人工确认；自动化政策登记主体、工具白名单、scope、收件人、上限、冷却、有效期、启用人和修订。
- 自动动作按批准政策及当前权限执行，R3强制人工；退款失败场景只提示/核对，不自主再次退款。
- 配置全局/租户/场景停用、预算上限和人工接管；限制通知频率并复用真实通知服务，未知投递先查询。
- 验收：影子不写业务、撤权立即停止新动作、重复事件不重复通知、过期政策和循环拒绝；生产白名单未确认保持关闭。

### AIN-19 图片/语音识别草稿与来源定位

- 接入已有合法文件链与选定模型能力，绑定订单/资源/阶段/冻结模板；异步识别上下文不可切换到新订单。
- 输出字段code、候选值、原文、图片区域/音频时段、置信提示及缺项；保存人工更正与原候选的对应关系。
- VIN/车牌/序列号/里程/工时/数量使用原格式验证，模糊留空；疑似损坏仅证据候选，不自动判责或增加费用。
- 多模态提供商若与文本不同，重新审批数据处理配置；恶意附件/超大文件有资源限制，不执行内容代码。
- 验收：合成及有授权测试素材覆盖遮挡、模糊、跨资产、倒退读数、缺领取基线、换表与恶意指令；真实识别与模拟夹具分开。

### AIN-20 员工小程序AI履约交互及宿主接入

- 接入员工白名单身份、空间/地点范围及订单分配；从现有交付/归还检查入口使用AIN-19，仍由员工确认最终事实。

- 实现相机/相册/录音、上传进度、弱网草稿、重试和同步状态；迟到识别、切空间、退出会话不得写错对象。

- 验收：实际微信宿主和指定真机走交付/归还及异常；代码构建、浏览器夹具、宿主、真机分别标记，缺设备不得结项。

### AIN-21 客户助手后端场景及独立安全边界

- 为客户单独暴露公开选品/报价、本人订单解释和正式办理入口，绑定渠道发布空间、客户或企业授权身份。

- 验收：匿名枚举、跨客户/企业、越权工具、支付伪造、会话迁移与身份改变后旧任务访问负例通过。

### AIN-22 客户小程序与现有预约网站AI入口

- 分别在既有客户小程序和租户预约网站接入同一场景契约，明确各端可用能力；不重复实现后台业务计算。

- 处理登录、企业身份切换、发布空间、断线/取消/重连、模型失败及人工客服出口；无AI时常规流程可走通。
- 独立APP只保留版本化接口、身份要求与示例，不创建APP工程；两端可由不同AI认领独立目录。
- 验收：Web浏览器与微信宿主/真机证据分别齐备，公开/本人数据隔离和既有收银台跳转真实通过；外部支付成功只用真实回调证据确认。

### AIN-23 平台品类草稿、校验与发布采用助手

- 读取目标部署的正式治理能力，按真实策略/字段/模板目录生成内置或新增品类草稿，不接未合入分支的虚拟接口。

- 验收：内置品类与正式支持的新类分别实流验证，历史订单依据不变；能力未交付拒绝，高风险发布/采用确认和并发冲突通过。

### AIN-24 攻击/越权评测、业务评测与审计隐私

- AIN-02后即建立测试集和威胁模型，随每场景落地持续验证；记录模型/提示词/工具/数据版本，确定性业务断言与语言人工评分分开。
- 覆盖越权、提示注入、任意出网、恶意附件、XSS、过量读取、来源/缓存泄漏、审批伪造、预算竞态及任务恢复提权。
- 审计只存可核对输入摘要/计划/工具/授权/结果，不保存模型内部思维链；实现正文脱敏、敏感访问审计和分类留存/删除传播。
- 构建固定与对抗用例，不能由同一个模型评价自己就判通过；关键越权、未授权R3、重复资金动作验收零容忍。
- 补双模式负例：跨租户/平台凭据误用、模式或配置修订过期、未验证能力、BYOK SSRF/DNS 重绑定/重定向、旧配置泄密；明确静态与真实出网证据区别。
- 验收：每个已开放端和工具有负例覆盖；阶段报告在记录中追加，只有全专项范围及修复复验齐备才归档本项。

### AIN-25 性能成本、故障降级及运行SLO

- 测量首字/首卡、完整任务时延、成功/接管率、模型/工具耗时、任务成本、预算拒绝、取消和恢复；注明并发、样本量与设备。

- 压测模型限流/超时、DB/worker故障、事件积压、多租户公平性及配额突发，验证有界队列、背压、告警与恢复。
- 降级到已验证模型或人工入口，禁止扩大数据范围；模型升级保留版本和回滚，关闭AI不拖累经营主链。
- 验收：实际环境测量报告、预算/超时/故障演练齐备，能按版本回到原配置；没有真实供应商时不声称真实成本已验证。

### AIN-26 四品类真库与多端组合验收

- 冻结待验收API构建、客户端构建、数据库迁移、模型/提示词/工具/政策版本与数据夹具哈希；不同AI不能共用同一运行实例边测边改。
- 在新建独立测试库覆盖摄影/露营/车辆/工程成功、失败、澄清、并发、取消、恢复和接管；业务能力差异可解释，不能四套硬编码测试假通过。
- 组合后台、员工、客户Web/小程序、平台助手与事件任务；复核人工报价/履约/结算不回归，资金测试模拟/沙箱/真实模式明确。
- 逐项登记AIN-A01～A29证据、未运行项、缺陷归属和复测；静态、数据库、浏览器、微信宿主/设备各自成证据层。
- 验收：关键用例全过，未解决缺陷不以总体通过率掩盖；清理本轮数据库/进程/端口，保留脱敏可复查报告，不碰共享资源。

### AIN-27 真供应商、试点灰度与部署回退

- 在负责人批准的模型、数据处理、额度和试点范围内启用真实供应商；验证工具调用、用量、认证失败、超时、限流及适用多模态。

- 分别检查部署配置、密钥轮换、回调/域名、队列、监控、数据留存与停用；不以开发机成功代替部署验收。
- 灰度先只读/草稿，再确认写入，再经额外批准的有限自动化；每阶段有放量/停止条件、责任人及人工回退路线。
- 演练模型/提示词/工具政策回退，数据库采用可兼容迁移或明确补偿，不做无备份破坏式降级；已提交业务事实继续可查。
- 验收：AIN-A30/A31真实证据及实际负责人放行齐备。缺凭据或经营决策登记具体阻塞，本项不伪完成。

### AIN-28 独立复核、缺陷清零、文档归档与交付

- 由非实现作者复核需求覆盖、跨模块契约、授权、恢复、成本、数据边界与用户操作；若只能同一执行者复查，标明“自复查”，不冒充独立Review。

- 整理部署/运行/停用/接管、管理员和员工客户使用说明、工具/API契约、决策及证据索引；完成任务移入唯一归档。
- 总进度核对原28项，确认无未处理范围、无未交接工作树/测试资源、无虚构真机/支付/模型验收。
- 验收：负责人收到可操作交付与风险边界；专项全部真实完成才计100%，只完成底座或演示不能结项。

## 5. 统一完成定义

每项归档前必须同时具备：
