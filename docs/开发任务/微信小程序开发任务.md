## 1. 当前基线

`apps/miniprogram` 已存在原生微信小程序工程，包含首页、分类、详情、确认订单、付款、订单、取消、续租、地址、资料、资质、会员、优惠券、帮助、协议和账号注销等首期页面；服务端也已交付多数首期接口。当前不能标记 MP-R1 完成，原因是部分金额/履约投影仍未补齐，最新迁移和组合场景尚未统一真库验收，真实 AppID、短信、微信支付和真机证据也未完成。

当前工作区的小程序导航、Logo、Seed 和静态测试存在未提交修改；在其归属明确、独立 Review 和提交前，不得派发会覆盖这些文件的新任务。

## 3. STAFF-MP-R1 员工履约小程序任务

员工履约小程序是独立于客户小程序的第二套移动端，专项需求见[《租户端小程序需求说明》](../租户端小程序需求说明.md)。当前已有独立原生 TypeScript 工程、员工会话与 `/api/staff/v1` 白名单门面；员工端构建、静态流程检查、API/DTO/权限合同检查和 Prisma schema 校验通过。但当前没有运行中的本机 API/开发者工具 MCP 监听，数据库迁移尚未应用，且缺少改后微信渲染截图与真机验收，因此以下任务保持 `In Progress` 或 `Blocked`，不按“代码存在”标记完成。员工端继续复用 Rental Core 领域服务，不复制订单、库存、金额或状态逻辑。

## 4. 推荐执行批次

1. **数据与契约收口**：CLIENT-CHANNEL-01、MP-03、MP-06、MP-09、MP-11。
2. **交易恢复收口**：MP-05、MP-10，并与支付用途、订单资金事实联调。
3. **真库组合验收**：MP-02B、MP-12、MP-13。
4. **真实微信验收**：MP-02A、MP-07、MP-14。

员工履约小程序按以下顺序推进：

1. **身份与范围**：STAFF-MP-01、STAFF-MP-02。
2. **现场主流程**：STAFF-MP-03～STAFF-MP-06。
3. **金额、品类与安全**：STAFF-MP-07～STAFF-MP-09。
4. **组合验收**：STAFF-MP-10。

同一批不得同时重写会话、支付 runtime、订单金额和数据库迁移；这些共用文件必须指定唯一负责人。

## 6. 任务更新规则

- 页面存在、TypeScript 通过或接口数量增加都不能单独标记完成。
- 微信授权、JSAPI 支付、合法域名和前后台恢复必须使用开发者工具或真机证据。
- 完成任务从本文件移除并进入[统一归档](../归档/多品类租赁平台已完成任务归档.md)。
