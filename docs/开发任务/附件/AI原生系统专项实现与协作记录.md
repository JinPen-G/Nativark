## 3. 多AI协作协议

### 3.1 单一协调者与中央认领

1. 开发开始时指定一位协调者，负责公共契约、主任务状态、本记录及集成顺序。当前协调者为**Codex当前会话**，依据负责人“合入，然后开始ai native”“你先自己做吧”授权；未创建或派遣其他AI。
2. 工作者先阅读三份文档、当前认领和前置交付，再报告待做原任务/切片、目标文件和基线提交。通过负责人分派或已获授权的协作渠道申请；不因本协议自行向其他会话发消息。
3. 协调者核查现有写入人及文件重叠后，在中央记录分配`CLAIM-ID`、工作树/分支、文件范围和有效期，并明确确认。**单个工作树内的自填认领不是中央锁**，未确认前只能只读盘点。
4. 中央记录只能由协调者写；多人不能同时修改此Markdown来“抢锁”。换协调者需交接中央记录版本与未完成认领，不能出现两个主控。
5. 认领过期只代表需要复核，不自动授权另一AI覆盖文件。协调者核查进程/未提交改动并确认原作者停止或已交接，才释放并重新分配。

### 3.2 工作树、文件与契约所有权

- 每位写代码的AI在专用工作树及非main分支工作，基线提交必须记录。不得复用其他AI活动工作树，不得`reset --hard`或删除未知修改。
- 一个文件/迁移目录同时只有一个写入人；同一任务可分多个不重叠切片，但每个切片的公共接口版本必须一致。
- 高冲突区：Prisma schema/迁移、shared导出/OpenAPI、公共鉴权、前端全局路由/菜单/locale、package及lock、任务主文档。先指派整合者，再提交小范围补丁；不能各自格式化全文件或自动全量重写。
- 子模块内部文件可由工作者独立维护；需要扩大文件范围先更新认领。新增依赖、公共接口或数据模型改变须先登记影响与决定，不私自升级全仓库。
- 同一切片实现与验收可以拆人，但测试人员不得边测边改作者构建；缺陷反馈给明确责任人后重建、冻结、复测。

### 3.3 同步时点及冲突处理

- 开工、契约变化、提交待集成、验证失败/新阻塞、交接或结束切片时更新；长任务每个可交付节点留一次，不按分钟堆砌无变化日志。
- 工作者写自己的切片记录，建议路径：`docs/开发任务/附件/AI原生系统协作切片/<AIN-ID>-<日期>-<owner>.md`。本轮尚未创建切片文件；开始后由协调者登记精确文件名，避免多人同名。
- 协调者阅读证据后更新主任务状态与本记录索引；工作者不同时改三份主文档。既有文档有他人修改时先比对，做局部补丁，不整份复制覆盖。
- 契约冲突先停受影响接口写入，登记生产者/消费者差异；无关任务继续。经营规则冲突交负责人决定，工程实现选择在既定边界内由指定责任人决定并留理由。
- 跨专项依赖只引用具体任务/提交/接口及成熟度；若所需代码未进入目标集成分支，记为未具备，不在自己的工作树悄悄实现第二套。

### 3.4 集成与验证顺序

1. 工作者提交单一逻辑切片，说明基线、范围、实现与测试；用户要求合并批次时，可同一批次包含多个明确切片，证据仍逐项列出。
2. 协调者确认依赖提交和契约一致、文件归属无冲突，安排在指定集成分支整合；本协议不自动授权合并main或推送。
3. 集成后重跑受影响契约、类型/构建与风险用例，不能只收集各工作树“单独通过”后宣称组合通过。
4. 独立复核者登记问题；作者修复，复核者验原问题及相关回归。自复查可记录，但不冒称独立人员Review。
5. 满足统一完成定义才由协调者更新主进度并移入唯一归档；部分切片完成时保留原任务`In Progress`及剩余范围。

## 8. 验证证据与缺陷模板

### 8.1 证据等级

| 层级 | 可以证明 | 不能替代 |
| --- | --- | --- |
| 静态/类型/构建 | 结构、语法、类型及可构建 | 运行行为、数据库并发、设备体验 |
| 单元/契约/模拟供应商 | 指定输入与协议、模拟故障逻辑 | 真模型能力/成本、第三方网络行为 |
| 独立MySQL真库 | 持久化、迁移、锁/事务、指定并发恢复 | 浏览器、微信真机、外部到账 |
| 真实浏览器 | 实际页面交互与授权API组合 | 微信宿主/录音相机、生产部署 |
| 微信宿主/指定真机 | 指定版本/设备的真实行为 | 未测试设备或所有客户端兼容 |
| 真实供应商/沙箱 | 实际接口调用、用量及指定错误 | 生产支付到账、其他供应商兼容 |
| 授权灰度/生产 | 指定租户、范围、时间与版本的实况 | 未放行功能、其他租户全量可用 |

每条证据包含：`EVID-ID、AIN-A、原任务、执行人、时间、源码/构建SHA、契约/模型/提示词/数据版本、环境、命令或步骤、预期、实际、通过/失败/未运行、脱敏产物路径、清理结果`。日志中的“成功”文本要与数据库/工具真实结果核对。

文档校验属于文档交付证据，不计为AIN-A业务验收。涉及支付/退款只读解释可用受控业务数据验证，但不得因此宣称真实外部支付已通过。
