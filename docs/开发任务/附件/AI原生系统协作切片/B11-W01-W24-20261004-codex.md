# B11 原生 AI 宿主装配辅助记录

## 基线与范围

基于 `97709257`，仅新增两端 feature-local 原生组件、B11 测试和本记录；未修改 shared/API/Core/Prisma、页面注册、app.json、登录/支付/上传链。两张历史截图保持未跟踪。

## 已实现

- 两端新增 `ai-task-workbench` 组合 Component，组合任务卡片、步骤时间线、澄清、提案、来源、偏好、状态面板，以及客户端订单解释/员工检查草稿。
- 宿主通过组件实例 `attachHost(host)`、`detachHost()`、`hostShow()`、`hostHide()`、`hostLogout()` 和显式 `readSnapshot()/selectTask()` 绑定；回调只存实例 WeakMap 或实例闭包，不进入 properties、data、setData 或事件 detail。
- 轮询复用现有 `AiPollingController/AiPollingLoop` 与 `consumeCursorPage`；未知版本、reset、游标缺口停止同步并清空展示，未提供正式快照游标时进入 `snapshot_only`，不虚构继续游标。
- 任务、上下文、输入 revision、提案 id+revision 通过本地代际校验隔离；动作完成不推进任务状态，不产生审批记录，不解释取消为回滚。
- 默认无宿主/未启用不读取、不定时、不动作；隐藏、解绑、登出销毁轮询并清理展示。

为保持既有 B09 原生组件检查器回归，组合工作台使用具名 slot，不在自身 JSON 中声明嵌套 `usingComponents`。未来页面需显式注册 B11 已有组件并放入对应 slot；工作台在渲染完成后通过 `selectComponent` 对澄清、提案、来源子组件调用实例 `attachHost/detachHost`。这样不会把函数穿过 properties/WXML，但当前只是可接线组件，尚未声明为已接入业务页面。
