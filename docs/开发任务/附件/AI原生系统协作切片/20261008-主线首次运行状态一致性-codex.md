# 首次运行 task/run 启动一致性

范围：主线 ai-task-transition.repository.ts 与既有 task-application 测试。保留中央记录和 output，不修改其他作者文件。

A 线真实组合发现：createTask 初始化 run=QUEUED，领取仅获得租约；任务 start 后 run 未启动，累计资源仓储拒绝执行。原测试仅改 task 状态，隐藏了缺陷。

修复：原 task transition 同一 Serializable 事务内，在有效当前身份、租约、revision/fence 条件下，将 RUNNING 目标对应 run 激活为 RUNNING。领取租约本身仍不授予执行权，其他目标不变；失败沿原事务回滚，不新增派发链。

验证：既有测试 make(QUEUED) 同时初始化 run=QUEUED；held prepare 检查 task/run 均 RUNNING。红测 18 pass / 17 fail / 0 skip / 0 todo，退出1；修复后 35 pass / 0 fail / 0 skip / 0 todo，退出0。
