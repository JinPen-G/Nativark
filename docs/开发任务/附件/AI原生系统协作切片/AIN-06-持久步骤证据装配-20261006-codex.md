新增 `runner/prisma-task-step-evidence.authority.ts`，使用本树隔离生成的真实 Prisma 类型，
从实际 task/run/step/plan/artifact/charge delegate 读取，不使用手写 delegate 或内存授权表：

1. 当前 `transition_task` 动作授权建立身份，再按 owner/audience/scope 读取任务。
2. 核对当前 run 的 actor、holder、fence、有效期；实际事务 CAS 仍由原步骤仓储执行。
3. 校验已保存计划 JSON schema、planHash、task/run，以及原登记规则导出的 actionId。
4. 复验外部正式 plan authority 的版本、hash、有效期；这不是该 authority 的生产来源实现。
5. 仅允许现有 AIN-08 四个只读工具的证据适配，且计划 operation 必须 readonly。
   该私有限制是授权上界，不是 executable 工具注册表，不改变工具成熟度。
6. start 只接受当前 PENDING/NONE 与既有 `start-${stepId}` 证据引用，不执行业务。
7. result_observed 必须读取已持久化、同 scope/task/run/step/action/fingerprint/holder/fence 的完整结果。
   校验内容 hash、输出字节与活动时长界限；同时要求对应步骤/活动/输出资源 charge 的同源绑定。
   成功只产生 `effect:none, facts:[]`，不从模型结果伪造权威业务事实。
8. 已知失败仅接受现有公开错误码，输出固定安全提示、`retryable:false` 与人工出口。
   不透传结果正文作为错误文案。unknown、不完整结果、写操作和未知工具保持 unavailable。
9. 等待证据读取后再次复核身份；grant 摘要绑定 plan proof 及结果/charge 来源。
   原仓储锁定后再次读取证据，使用原状态机、任务/步骤/run CAS 和事件事务。
   顺序复验不是跨服务原子授权，不声称已验证 MySQL 行锁。

## 提交应答不明修复

真实步骤仓储先完成 task/run/step/event 的事务回调，但 COMMIT 应答不明时，
原来返回 `AI_STORAGE_UNAVAILABLE`。现在返回内部 `AiStepTransitionResultUnknownError`：
`AI_RESULT_UNKNOWN + retryable:false + reconcile`。不盲重试、不重新执行工具。
回调中实际 CAS/权限错误保留原语义；回调未完成的普通存储失败仍为 storage unavailable。
回调完成后的提交失败可能已回滚，也可能已提交；客户端不能从异常猜测没有事实。
旧测试的提交故障与 commit_ack 两例强化为 unknown/reconcile，回滚、事件、单事务断言全部保留。
