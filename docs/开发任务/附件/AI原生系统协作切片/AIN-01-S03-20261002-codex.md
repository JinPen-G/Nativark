## 2. 方法、输入和替身边界

测试直接通过 ts-node 加载当前树的生产 TypeScript，不使用旧 dist，也不复制鉴权、计价或状态算法。`authorization-baseline.cjs` 只生成身份、请求、订单、历史凭证与恶意 actor 字段等合成输入。

真实入口包含：

- `AuthService.resolveAccessContext` 及真实 JWT 签名/验证；`ApiAuthGuard.canActivate` 与其实际资源检查。
- `ClientAuthService.authenticate` 及真实客户端签名/解析，接到 Guard 客户端分支。
- `resolveScopeWorkspaceId`；`MembershipService.listPersonalOptions/listBookingOptions/assertBookingQualificationForAction`。
- `RentalWorkspaceReportRepository.getOperationReport` 的 own 拒绝入口。
- `RentalCoreController.order/orderDocument/orderDocumentVersion/createOrder`。
- `RentalCoreService.getOrder`；`RentalDocumentService.render/readSnapshot` 与实际凭证 renderer。
- `RentalOrderConfirmationService.createOrder` 的已有幂等记录早期回放分支、实际 `requestFingerprint`。

会话、账号、成员、资源、资金与幂等仓储查询由受控替身提供。查询断言核对真实方法产生的 tenant/workspace/own/location 条件；替身**不实现数据库过滤、关联、锁或事务语义**。不存在“夹具断言夹具”的独立鉴权实现，但这些查询断言也不等于真实 SQL 隔离证明。

客户端只替换实例的 `secret()` 为测试常量，不读 `.env` 或 process.env 取得密钥，不输出令牌。客户端限流服务为吸收替身，验证调用前后两个限流入口，不验证配额算法。其 `lastUsedAt` 更新仅进入受控 `updateMany`，没有实际写库。

普通订单详情测试复用既有吸收式配置/事实 store 初始化经营空间，再调用真实 Core；初始化只在内存及吸收仓储执行。建单控制器例外权限测试的应用服务是受控替身；回放测试则替换为真实应用服务，但预置“已提交订单及幂等记录”，**不进入首次创建事务**。
