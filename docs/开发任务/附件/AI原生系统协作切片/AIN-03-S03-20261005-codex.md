## 实现与装配

- 新增 `AiPlatformModelConnection`，追加迁移 `20261005020000_ai_platform_model_connection`；Profile FK、同一 configRevision、URL/输出上限及加密 TEXT。历史迁移未改；不执行迁移。
- `PrismaPlatformModelConnection` 直接使用本树真实生成的 Prisma delegate 和事务类型，没有手写 Delegate 或 `prisma as unknown as`。
- `save` 仅更新已有规范 PLATFORM Profile；必须是当前 platform/saas_admin 主体，另需明确的 `PlatformConnectionAuthority.manage` 动作授权。tenant/workspace actor 不能管理平台凭据。没有该授权实现则不可装配，不能用 scope 类型合法当授权。
- 同一事务通过 Profile 的 owner/mode/expectedRevision 条件更新取得写入权，再写 vault；CAS 失败/凭据写入失败/事务失败不能留下半个配置。Profile 与 vault 同时使用下一修订；保留旧 capability evidence 作为历史，但旧 fingerprint/revision 不再匹配新 Profile。
- retain 必须同 endpoint/protocol，model 变化重新绑定密文；replace 使用现有 SecretBox AES-GCM；clear 清空凭据并停用 Profile。密文绑定 profileId、规范 scopeId、revision、protocol、model、baseUrl。返回保存摘要不含 key/URL/内部授权。
- resolver：动作授权 → 现有 `AiScopeRepository.resolveRoutingScopes('platform_managed')` → Profile/vault 关系读取 → 修订/目的地密文绑定核查 → 当前身份复验 → 配置复读 → 内部 transport connection。
- 关系加载可能是多条 Prisma SQL，不能宣称单个查询即原子快照；用修订绑定及复读拒绝混合版本。顺序复验仍不是原子 dispatch 许可，Gateway 最终 fencing/当前授权检查不可省略。
- 输出仅交给既有 `RoutedModelTransport` 的 `platform` resolver 槽位，复用 `ChatCompletionsAdapter`，没有新派发器、tenant fallback、公共 DTO、根模块注册或启用开关。

## 故障证据层级及剩余

定向测试实际调用新持久化实现、SecretBox、RoutedModelTransport、ChatCompletionsAdapter。数据库替身只模拟真实 Prisma predicates、串行事务、回滚及应答丢失；授权使用显式受控依赖；网络执行使用合成 HTTP 替身。不是 MySQL 行锁、真实平台认证、真实模型或完整 Gateway 预算链验收。

- 覆盖重建读取、密文脱敏、缺 vault、跨 owner/mode、停用、CAS 竞争、部分写入回滚、提交失败、commit 应答丢失不自动重试、retain/clear、密文复制、修订不一致、授权等待撤销和能力列表变化。
- 配置保存启用不等于 live 能力验真、套餐权益或预算开放，既有 Router/preflight 和预算门仍须执行。
- 平台管理动作仍需绑定现有实际 SaaS 授权入口；本批接口不是已接通的真实管理授权 adapter。调用侧需要真实当前身份源和 invoke 动作检查，不能填恒定成功方法。
- 当前 transport context 只支持 workspace user；平台任务、tenant-only consumer、client/automation 不伪装支持，继续拒绝。
- 只更新已有 Profile，不自动创建规范 scope 或 bootstrap Profile；受权平台管理应用入口尚未注册。
- 租户配置/Profile 同事务统一修订、旧配置受权转换、能力验真与 Gateway 预算单账生命周期继续按原依赖推进。
- 真 MySQL 迁移/并发、真实模型/支付、浏览器/设备、生产运行未验证；没有独立 Review，不写审查通过。
