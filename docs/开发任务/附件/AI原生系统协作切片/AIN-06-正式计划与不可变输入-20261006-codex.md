## 失败过程与修复

- 新实现缺文件时 MODULE_NOT_FOUND/exit1，只是缺实现，不算安全机制红测。
- 初次组合把 execution.authorize 放在持锁事务内部：实际权益源另开事务，离线事务替身出现排队等待。
  移至提交前与提交后当前复核；事务内继续复核动作、政策和 lease。只停止本轮两个测试进程，未动他人服务或成果。
- 首次 lost-ack 注入误命中授权的只读事务，未产生输入，断言失败；改为精确注入输入写事务提交后，不放宽期望。
- 原资源政策端口传 `expiresAt:''`，最初输入源误把呈现字段当必填 ISO，实际组合被拒绝。
  改为只约束呈现字段长度；授权仍读实际 run 的 leaseExpiresAt，不能由 caller expiry 获权。
- 新迁移与 Prisma diff 比较首次 1/2 失败，仅索引/REFERENCES 括号前空格不同；调整未提交新 SQL 与真实输出一致，复验2/2。
- 移动时钟行为红测1/1失败：输入重读比较包含新 authorizedAt，错误拒绝实际执行。
  修成精确比较身份（排除 requestId/authorizedAt）、registrationRef 与规范输入；不忽略权限/scope/audience变化。
  修后新文件23/23，exit0；fail/cancel/skip/todo均0。
