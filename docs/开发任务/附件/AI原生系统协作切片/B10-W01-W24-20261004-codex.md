# B10 管理端 AI 任务工作台辅助实现记录

## 范围与基线

本切片在 `ai/ai-native-foundation-20261002` 分支、基线 `cb02eb32` 上施工。仅新增/修改 `apps/admin/src/features/ai-native/**`、B10 测试和本记录；保留两张历史截图，不加入提交。主 Claude 负责授权、任务运行器、公共契约和最终整合；本切片不改 shared、API、路由、schema 或业务页面。

## W01-W04：宿主装配

新增 `AiTaskWorkbench.tsx`，实际组合既有 TaskList、TaskTimeline、MissingFieldsPanel、ProposalPreview、HumanConfirmShell、CancelRecoveryStatus、KnowledgeSources、MemoryPreferences、AiServiceSummary 和 CapabilityStatus。宿主显式提供 context、readTask、onResync 与动作回调；默认不读取、不请求、不选模型、不推断权限。任务列表补充 UIArc Button 的明确选择入口，不可用投影禁用。

详情读取在 task/context/visibility 变化时清空旧详情，使用本地 epoch + AbortSignal 丢弃迟到结果；这只是前端显示隔离，不是服务端授权。宿主未提供读取能力、无任务、读取中、失败、不可见分别展示；不补造成功结果。

## W05-W08：读取边界

当前 Workbench 仅接收宿主提供的投影和读取回调，不复制 event-reducer/polling-consumer，不发明 cursor。既有 polling-consumer、event-reducer 的离线边界由 B04-B09 保持；正式公共任务/事件契约缺口不在本切片补造。后续宿主应在 readTask/onResync 中完成快照与正式 cursor 衔接，并传入已授权 projection。

## W09-W16：人类交互及只读结果

缺失字段默认只读展示；确认、取消、恢复、来源打开、偏好核对均只在宿主提供相应回调/投影时装配，组件回调 Promise 仍由既有 UIArc ActionButton 处理。WorkBench 不生成 approvalId、不推进 task 状态、不解释取消为回滚。服务摘要复用既有安全投影，平台模式只显示 Rental OS AI；客户/供应商凭据不由本切片读取。

## W17-W24：验证与接线

测试：`node --test tests/ai-native-b10-workbench.test.cjs tests/ai-native-b10-workbench-contract.test.cjs` 退出 0，7/7；`npm run lint -w @rental-os/admin` 退出 0。另运行 `node scripts/audit-admin-components.cjs --json`，输出现有完整 UIArc 清单但脚本退出 1（仓库既有审计状态，不是本切片类型失败），仅作组件清单审计，不作为浏览器验收。

验证层级是 TypeScript、静态边界测试和 UIArc 组件导入检查；未启动服务，未连接数据库/模型/支付，未运行浏览器 DOM、真实 HTTP、微信宿主或真机。现有 B04-B09 回归不改其失败基线，B09 正式状态契约和真实宿主缺口仍待主线。

宿主接线顺序：先在已授权页面取得 tenant/audience/workspace context，再把已脱敏任务列表传入；宿主通过 `onSelectTask` 保存选择并提供 `readTask(taskId, context, signal)`；投影/权限变化时调用 `onResync`，动作回调必须连接服务端确定性能力并返回真实 Promise。未提供回调时工作台保持不可用/只读。当前未注册任何路由或业务入口。
