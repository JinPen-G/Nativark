## 实际实现与调用链

新增 `approval-execution/prisma-approved-order-original-input.source.ts`，实现已有 `ApprovedOrderOriginalInputSource`，使用真实 Prisma TransactionClient 类型，不自造 delegate。

实际链：PersistedApprovedOrderPolicyAuthority（AuthService、当前身份、任务 owner/scope/audience、动作政策、SubscriptionService 与预算 gate）→ 当前 RUNNING 步骤 → inputRef 指向 AiTaskActionInput → scope/task/run/tool/version/原 fingerprint 校验 → 原 Core CreateRentalOrderDto ValidationPipe → 再次当前授权和两条记录一致性复核 → 原 ApprovedOrderPreparationService 的 Guard/ALS、报价验证与 pending proposal/snapshot 事务。

拒绝缺 inputRef/记录、过期、跨 scope/run、工具/版本不符、载荷篡改、撤权/停 gate、未知 DTO 字段、嵌套 DTO 无效与 capabilityExceptions。返回规范 JSON，无 class-transformer 添加的 undefined 属性。调用方 context 仅供与正式身份比对，不授予权限。读取本身不改数据库、不授审批、不领取 dispatch、不创建订单。

装配方式：由现有组合调用方构造 `new PrismaApprovedOrderOriginalInputSource(policy, toolVersion, clock)`，显式作为 `composePersistedApprovedOrder` 的 inputSource；不改现有缺依赖拒绝门。准备服务仍拥有事务、当前 lease/fencing 与步骤锁；本 adapter 不是脱离准备服务的执行权限端口。

## 必须保留的未接通项

- 这是读取适配，不是建单输入生产端。现有正式发布器仅支持 catalog；没有新增/放开 write plan 或“自动登记建单”能力，缺记录仍拒绝。测试的合成存储输入不是生产者验收。
- 建单服务器规范化输入的受权不可变发布、版本化 write-plan 政策及正式步骤登记，尚需接入同一持久链；不能从当前 quote 反推客户或 bookingIdentity，不能把模型/caller body 当可信原输入。
- 本记录的 policyRevision 仅验证记录格式，不宣称已完成 write-plan 政策修订核验。正式 write producer/plan authority 未落地前，原组合仍默认缺依赖不可用。
- 当前授权与读取复验是顺序检查，不称跨服务原子授权；真实提交继续由原审批消费/Core事务和派发前复验处理。
- 历史输入读取与执行时效分离、正式 HTTP/worker/生产装配均未完成；不改变0/28或M1口径。
