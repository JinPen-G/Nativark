# Rental OS AI Native 关键长任务总接续册

版本：交接草案 v1.0；日期：2026-10-07。适用执行者：后续接手的 Codex，或负责人指定的 Claude。

> **这是一份统一任务总册，不是把四条线合成一个施工树。A、B、AIN-06、AIN-07必须分别在各自原工作树开发。Codex接管06/07，也必须进入06/07各自的树；不得把它们的实现搬到A/B树开发。** 主线只在自己的树接收固定交付。
>
> **任务目标是持续补齐完整的关键功能，不是不断做零散修补。** 一次小修复、一个包装器、一个DTO、一份文档或几条测试，不算本册一个工作包完成。已经交付的实现先复用，沿真实生产者→授权→持久化→执行→收据→读回链补缺口；不要换名称重复实现。
>
> **现在自研，同时为以后 LangGraph 等 Agent Runtime 与开源 Provider SDK 独立接入做好准备。** 两条边界独立，当前不安装、不迁移。编排、模型协议与业务授权/审批/Core/唯一Gateway预算单账隔离，随功能留下接口、状态/行为/收据映射、耦合及迁移回退说明。旧源码、测试和原Codex“开发建议”实际保留。

## 4. 防止退化为零散任务的执行规则

1. **按完整工作包推进。** 开始时写清本包输入、权威来源、当前授权、持久对象、提交点、结果读回及消费者；实现必须接回本线实际composition/application。
2. 一个包可以有多个独立功能提交，但修一个字段、加一个包装函数、补一项测试，只是包内步骤，不能宣称整个包完成或立即停下。
3. 不做同义接口、重复factory、无消费者的DTO、重复Map仓储、第二Gateway/账本、第二runner/审批器；已经存在的服务必须复用。
4. 不根据旧任务状态为Pending就认定零实现。先确认实际生产者/消费者，缺哪一段补哪一段；不能用“重新调研全部底座”消耗整批。
5. 每个完整功能片一次定向冒烟/必要类型检查；失败修明显问题，仅复验受影响范围。深度回归和跨场景验收集中在后续，不递归派审计、不每片扩大到全仓。
6. 依赖缺失时返回明确unavailable/unknown，列出所缺签名、权威生产者、字段和调用点，并继续其他可做包；不能把长期阻塞伪装成成功，更不能为避免停工做空包装。
7. 固定交付后立刻继续下一可做包，不逐片等待“继续”。整批可做项完成时主动报告下一组真实关键缺口，由总控续派；辅助之间可以协调接口，但不互相接管派工或改对方文件。
8. “已编码、离线组合通过、真库通过、模型/宿主通过、生产启用”分层记录。测试数量和提交数量不代表原AIN整项完成。
9. 下文写到“生产者/正式入口”，要求实现可被合法生产组合使用的代码；不意味着当前获得了启动真实服务或启用生产的授权。
