# AIN-07-S02｜提案不可变版本与动作引用持久化

## 交付

- 新增 `ai-proposal-repository.ts`，复用已提交的 `AiProposal`、`AiProposalVersion`、`AiProposalAction` 模型；创建时校验共享 C05 payload fingerprint、版本/动作唯一性，并在 Serializable 事务内写入提案头、不可变版本和已存在的 `AiStep` 动作引用。
- 不写入原始 prompt、密钥或完整业务对象；提案仍处于 `PENDING_CONFIRMATION`，不会被此仓储视为审批或业务成功。
- 重放相同 proposal/version/hash 返回既有头；不同载荷冲突。动作不存在时拒绝，不创建孤立 action。

## 验证与限制

命令：`node --test tests/ai-native-ain07-proposal-repository.test.cjs`。本片在提交前补记真实结果；当前离线测试使用受控 Prisma transaction/delegate 替身，未连接 MySQL，不能证明真实回滚、锁与外键行为。

审批确认、Core 业务幂等消费、业务结果写入和权限适配仍由后续 AIN-07/主线负责；不注册 Controller/AppModule，不启用生产链路。
