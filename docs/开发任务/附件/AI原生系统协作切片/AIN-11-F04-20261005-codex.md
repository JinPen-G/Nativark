## 失败复现与实现

实际 BudgetGatewayAdapter 在等待持久绑定来源时仍比较 caller 的原对象：调用方修改 actorId 后，来源返回修改后的 actor 会通过比较；reserve 的 callId 同样在等待中被修改，导致合法原请求被误拒绝。另一个缺陷是把平台/租户 Profile owner scope 当作 workspace 消费 scope 接受。

先新增三项失败行为测试，原实现运行结果 5 通过 / 3 失败，退出 1。修复 reserve 在第一次 await 前快照 context/request；所有后续动作的绑定读取也在 await 前快照 context。窄 GatewayContext 已明确只表达 workspace 消费，关联 scope 必须同 tenant/workspace；平台统一模型不因此变成平台消费。平台或 tenant 自身任务需要另一个能携带正式执行上下文的接入边界，当前适配器不伪装支持。

不改 Gateway、供应商派发、账本或公共契约；不会产生第二套派发许可。补 settle/release/unknown/reconcile 的等待竞态负例及同租户不同消费层级负例。
