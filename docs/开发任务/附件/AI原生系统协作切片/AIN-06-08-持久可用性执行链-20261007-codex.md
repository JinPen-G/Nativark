## 实际实现

复用 `AiAvailabilityReadFactsService` 的既有严格输入 schema，公开供持久输入生产端消费；不复制库存计算、权限或状态算法。

原 `PrismaTaskPlanInputSource` 增量支持服务器构造时选择的两个既有只读工具：catalog与availability。默认仍catalog。每个实例只接所选工具，政策必须匹配，模型/请求不能切tool；输入继续绑定scope/task/run/ref/fingerprint/policyRevision，计划存储后禁止注入新动作。availability使用实际Core输入schema，拒绝未知字段；原catalog接口保持拒绝availability输入。

场景政策repository增加服务器组合选择的availability工具，仍走真实Auth/配置Guard、canonical scope与expectedRevision CAS；请求不接受tools/scene/scope。无政策不执行，没有seed或默认开启。

`composePersistedAvailabilityTaskRunner` 与catalog共用既有组合根/仓储，不另造运行器。真实链为：当前Auth/任务政策/订阅权益与gates → scope/scene版本政策 → 不可变availability输入 → 原计划与步骤登记 → lease/fence及action/input复核 → 实际ApiAuthGuard/ALS → AiAvailabilityReadFactsService → Core.availability → 当前权限再复核 → 持久result/artifact与累计资源 → 原步骤/事件/任务事务。

可用性不是库存预占或建单；无需供应商调用，不另扣财务预算账。中断保留waiting_external/unknown资源，不因恢复重发Core。缺工具、能力、正式来源仍unavailable，不注册HTTP/worker/AppModule。
