## 4. Provider的实际接入位置

现有接点：

- [ModelAdapter](../../../../apps/api/src/modules/ai-native/model-gateway.ports.ts)：`generate`和可选`stream`；文本、usage、受限工具候选/结构化结果。
- [RoutedModelTransport](../../../../apps/api/src/modules/ai-native/routed-model-transport.ts)：已接受adapter注册表，当前配置与凭据修订复验、平台/租户resolver和输出秘密检查继续保留。
- [ModelEgressTransport](../../../../apps/api/src/modules/ai-native/model-egress.transport.ts)：DNS地址审查、连接IP绑定、HTTPS/重定向/字节/队列限制、取消继续作为唯一出网层。

拟新增文件仅作实现建议、当前不存在：`providers/ai-sdk-chat-completions.adapter.ts`与`providers/ai-sdk-controlled-fetch.ts`。实际命名由主线认领确定，不创建第二套公共DTO。

调用关系：`原Gateway → 原RoutedModelTransport → 新ModelAdapter → 显式AI SDK Provider → 受控fetch桥 → 原ModelEgressTransport`。Agent不直接import供应商包；不引入LangChain供应商连接作为另一条旁路。

AI SDK官方兼容Provider支持显式`baseURL/apiKey/fetch`。因此无需另建租户配置或Router，也不需要先部署LiteLLM。但**现有transport不是fetch签名，不能直接把对象强转成fetch**：

1. 当前`post`返回status/body，`postStream`返回status/字节帧；新桥需构造正确Response/ReadableStream并保持背压、取消、迭代器return与总deadline。响应头信息当前未暴露；按所选SDK真实要求最小补齐可信响应元数据，不能凭空画成功header。
2. 现有请求只允许Bearer认证与JSON Content-Type两项header。核对SDK实际追加的metadata/header，明确丢弃不需要的非业务元数据或做最小白名单适配；不能放开任意header、method、URL、body、重定向或媒体下载。
3. 使用显式Provider实例与服务端传入配置，禁止隐式云Gateway、全局fetch或环境密钥fallback。`maxRetries:0`；不传自动执行工具，不叠加Agent多步循环；遥测按显式禁用/网络拦截验证。
4. SDK usage缺失仍是unknown，不填0；终止原因、拒绝、输出上限、tool ID/参数、结构化schema及秘密泄漏按现有边界检查。stream不能只看“收到文本”就成功结算。
5. 复用原SSE/分帧/取消/工具/usage语料驱动**实际SDK解析器**；旧新做离线契约差分，不双跑真实模型或财务路径。某协议不能满足则unavailable，不降级到不受控fetch。

当前成熟Chat Completions可继续作为回退；先证明SDK接法和收益，再替换重复编码/解析。不先重写Gateway，不为接一个Provider升级全仓框架。

## 6. 持久checkpoint与恢复：不能漏掉的适配

LangGraph的checkpoint用来保存编排进度，不替代`AiTaskRunArtifact`、审批消费、财务账本或Core提交。官方interrupt恢复会重新进入节点；中断前的节点代码可能再次执行。因此派发/写入节点不能直接依赖“图记得跑过”来保证不重复。

现有measured effects会在执行前持久登记RUNNING artifact；缺完整结果时恢复走证据读取，不自动重执行。把checkpointer塞进executor，**并不会让当前runner自动获得图的逐节点resume能力**。需明确采用现有已授权步骤重放/结果读取，或在原运行器内补一个被批准的图恢复适配，不能另开拥有执行权的图worker。

存储选择：本次已读官方JS文档和checkpoint接口，未确认一个可直接采用且满足本项目约束的维护中MySQL saver；这不是断言社区绝无实现。实施前先检索候选的JS版本、许可证、幂等写入/删除/并发契约。若无合适候选，再做薄的Prisma/MySQL `BaseCheckpointSaver`适配；不默认为了框架增加PostgreSQL或Redis。

适配至少处理`getTuple/list/put/putWrites/deleteThread`及选定版本的channel历史/序列化语义，不能只存一份JSON。持久pending writes、parent checkpoint、namespace和版本都需保留。

- 服务器建立thread到owner/audience/scope/task/run/graphVersion/inputRevision的不可伪造关联；threadId不授予权限，每次读写/恢复复验当前权利与fence。
- checkpoint仅存最小引用/有界安全数据，不存密钥、授权封套或不必要的客户正文。跨租户同ID、删线程、旧图/旧输入与撤权缓存分别测。
- “业务成功但checkpoint失败”读原收据；“checkpoint完成但结果/计量没落库”不得画业务成功。unknown只核对，不因节点重入再次调用供应商。
- 先验证实际库的基础与存储契约，再验证实际Rental服务的崩溃窗口。MemorySaver可用于明确标注的库试验，不能当跨进程持久恢复交付。

## 7. 依赖兼容研究的已知结论
