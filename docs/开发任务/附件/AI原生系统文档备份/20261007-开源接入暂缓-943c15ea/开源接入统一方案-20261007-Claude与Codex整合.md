# Rental OS Agent Runtime 开源接入统一方案

日期：2026-10-07。性质：Claude 与 Codex 既有研究的整合设计，供当前可替换性开发及未来迁移使用。

> **当前决定：继续自研、功能优先，从现在起为以后切换 LangGraph 等 Agent Runtime 做准备；当前不安装框架、不执行迁移。** 本文不是恢复历史“立即转开源”派工的授权。主线开发仍按负责人最新通知进行，本次只整合方案。
>
> **统一目标：保留全部既有代码、测试与业务成果；使未来主要更换编排运行层和必要适配，而不是重写工具、授权、审批、预算、Core、知识及客户端。** 可合法参考和复用成熟开源成果，不要求全部从零写；但不为未来可能性堆空接口、提前复制框架API或拖慢当前功能交付。

## 3. 目标架构与唯一所有者

目标依赖方向：

```text
现有页面/宿主与场景入口
  → 本系统稳定任务、输入、事件与结果契约
  → Runtime Host及内部编排端口
      → 当前自研驱动 / 未来LangGraph驱动（二选一）
      → 既有受控单步执行边界
          → 当前身份、动作授权、lease/fencing/CAS
          → 输入/步骤/结果收据与任务累计资源
          → 受权业务工具 → Core等原业务服务
          → 唯一Gateway → Router/准入/派发/预算绑定
              → 当前ModelAdapter / 未来SDK Provider适配
                  → 原受控出网层
  → 既有持久结果与公开事件 → 原Workbench
```

| 边界 | 权威归属 | 不允许的替代 |
| --- | --- | --- |
| 下一节点、条件分支、等待信号 | 所选Runtime驱动 | 不自行取得业务执行权或签发批准 |
| 领取、租约、fence、步骤提交和恢复核对 | Rental OS现有执行服务 | 不另开图worker重复claim，不在每节点调用完整runner.run |
| 当前身份与资源动作权限 | 原Auth/Guard/正式授权服务 | threadId、图配置、checkpoint或旧context不是授权凭据 |
| 模型调用与配置解析 | 唯一Gateway及现有派发链 | 图不得直连SDK，SDK不得隐式选择云代理/环境密钥 |
| 财务预留、结算、释放和核对 | 原预算单账 | SDK token统计和图计数不是另一份钱包 |
| 订单、报价、资金与业务幂等 | Core及原业务仓储 | 图结束、checkpoint成功不代表业务提交 |
| 文档、来源、ACL与人类偏好确认 | 原Knowledge/Memory服务 | 不以框架默认store替代资源权限和确认记录 |
| 用户看到的状态与卡片 | 本系统公开契约及受权投影 | 不直接暴露框架内部状态为业务成功 |

以上是设计职责，不表示已存在可直接调用的统一Runtime接口或单步服务。实现前核对实际源码，优先利用已有ports和composition，仅提取当前功能确实需要的边界。

## 4. 当前自研阶段必须做什么

1. 编排逻辑不侵入Core算法、授权政策、预算和业务工具；工具不依赖具体运行器的内部对象或生命周期。
2. 公共DTO、错误、事件、输入和结果引用保持本系统拥有的版本化契约；未来框架节点、消息、checkpoint类型只进入内部适配层。
3. 保留task/run/step/actionId、registrationRef、请求指纹、invocation及业务结果关联；先收集事实、冻结实际输入，再登记和派发，不能登记A而发送B。
4. 分清框架进度、任务执行事实、业务提交和费用事实，不以一份运行时JSON代替全部收据。
5. 等待输入、等待确认、取消、unknown/reconcile和部分完成有明确语义；模型或用户普通回复不能变成批准。
6. 当前必要功能继续实现，不因历史“停止通用扩建”一语停掉实际缺口；同时避免建设与近期需求无关的通用图平台、全协议SDK或第二套知识平台。
7. 同步记录真实接口和耦合；目前没有需要的迁移适配只记设计，不创建空壳。全部既有源码、测试与WIP保留。

### 每片最少接手记录

在既有本线切片记录中增加简短“Runtime替换准备”段：

- 实际入口、依赖方向和组合位置。
- 稳定服务与可替换编排部分各是什么。
- 状态/错误/事件与持久化事实如何对应。
- actionId、输入指纹、提交点、收据和重试/核对约束。
- 已知硬耦合、未来替换步骤、在途任务及回退注意事项。
- 已验证内容、未验证内容和公共依赖。

不再创建第二份进度台账；记录应随契约变化更新，不要求每个无关业务小改动写长篇迁移论文。

## 5. 未来LangGraph集成设计

### 5.1 单驱动、复用原执行边界

在实际接入获准后，评估从当前runner提取原有单步执行逻辑，完整保留步骤登记、资源占用、effects调用、结果收据、unknown及释放顺序。原自研驱动和LangGraph驱动调用同一个受控边界，每个任务只使用其中一个。

图只决定有限模板内的下一步；不套用可以自行执行任意工具的通用ReAct例子，不把SDK的Agent循环再嵌入图。框架自动重试默认关闭或明确限制为一次，具体配置须按选定发布版验证，不能依赖未查证的默认值。

旧不可变plan.steps与图分支并非天然兼容：按实际需求定义封闭模板或受控后续步骤登记，仍验证场景、工具、输入、政策和资源上限。多轮模型调用不能藏进一个只登记一次调用的executor。

### 5.2 checkpoint适配

优先保留MySQL/Prisma。实施前核对维护中JS saver的版本、许可、并发与删除契约；无合适候选时实现薄存储适配，不重写上游checkpoint算法。

历史研究列出的BaseCheckpointSaver方法为getTuple/list/put/putWrites/deleteThread；正式实施以锁定发布包为准。适配必须覆盖父checkpoint、namespace、channel版本、typed序列化、metadata及pending writes，不只存一份state JSON。

建议存储职责：服务器拥有的task/engine/graphVersion绑定；run/input修订与checkpoint head；checkpoint记录；pending writes。具体表或字段由主线schema认领人设计，不在本文宣布新增表已获准。

所有读写/列表/删除都核验当前主体和scope；head推进受现有fence与CAS约束。LangGraph内部taskId不能混同Rental OS AiTask.id。图状态尽量存有界引用；活跃lease、凭据、服务实例和不必要的敏感正文不写入checkpoint。

checkpoint与模型请求/Core提交不是一个事务。写入应答不明时核对原ID/hash，不能生成新动作继续推进。内存saver只作库级测试，不证明跨进程恢复。

## 6. Provider SDK独立采用方案

Runtime迁移可以继续使用当前ModelAdapter；Provider协议升级也可以继续由自研Runtime驱动。两件事不必一起上线。

未来候选调用链：原Gateway → 原RoutedModelTransport → SDK ModelAdapter → 显式Provider实例 → 受控fetch桥 → 原ModelEgressTransport。

必须保留：

- 平台/BYOK配置、凭据归属、修订和能力准入；没有合法配置即不可用。
- DNS地址审查、固定连接IP/TLS、URL/method/header白名单、禁止未经允许的重定向、响应字节限制、背压及取消。
- SDK不能回退global fetch、隐式云Gateway、环境密钥、自动媒体下载或遥测外发。
- 一次已批准派发对应一次实际请求；高层API如有自动重试必须关闭，低层API也要统计真实请求次数。
- 原始usage缺失或字段不全保持unknown/reconcile，不把SDK补0当真实费用证据；SDK生成的tool-call ID不能冒充供应商返回值。
- 流中的error事件、缺finish、截断、取消和秘密回显仍需显式校验，不能收到文本就结算成功。

受控传输不是fetch签名，不能类型强转。桥接Response/ReadableStream时按所选SDK实际需要传递可信状态和响应元数据，处理cancel/iterator return与总deadline；不要为兼容SDK开放任意header或重新实现一套出网政策。

### 历史候选版本，仅作复核起点

Claude历史研究列出：@langchain/langgraph 1.4.20、@langchain/core 1.2.17、@langchain/langgraph-checkpoint 1.1.6、@ai-sdk/openai-compatible 2.0.81、@ai-sdk/provider 3.0.18；textsplitters 1.0.2为后续按需候选。上述版本、许可和导出信息是原报告记录，本次未重新下载验证，不是当前已安装版本或最终锁定决策。

实施时重新检查正式发布包、Node生产基线、CommonJS/ESM、TS/Zod、传递依赖、许可证/NOTICE、漏洞与维护状态。优先局部适配或合适发布版，不整仓转ESM迁就示例；不能把“有dist-tag”当长期安全支持承诺。

## 7. 首个迁移纵向切片

推荐：**operator在当前workspace的只读订单解释**。

流程：合法任务及原输入 → 当前受权订单事实 → 保存并冻结解释输入和来源 → 登记模型调用 → 有界图调用原Gateway一次文本总结 → 既有结果/计量/事件 → 原Workbench。

- 模型只总结，不自主决定工具、不报价、不建单、不处理收退款。
- 权威状态、金额与生成文字分区；历史/付款证据缺失如实显示，不用当前规则补历史。
- Knowledge可选且必须已有合法ACL、文件与来源依赖，不能注入空授权满足构造器。
- 一个图节点不必对应每个辅助函数，但每个实际模型调用/业务动作必须纳入原登记、计量和恢复边界。
- 库级单次图试验、离线纵向组合、跨进程持久恢复、正式场景验收分别留证，不能相互替代。

### 历史缺口不可直接照抄为当前待办

两份研究以943c15ea为快照。本会话已有固定交付记录：d50fe465补公共Gateway AbortSignal传递，04eac695补order.commit原输入发布与计划证明；f5b1f293及65acf109补已提交结果核对和批准目标报价版本绑定。这些改变了旧报告部分缺口，但不证明全部场景已接通。本轮未重跑产品验证。

实际迁移前重新核对任务创建前原输入生产者、模型intent冻结、步骤注册、结果读回、正式Knowledge/Memory政策和文件能力。另一工作树的报告不等于主线已接收，固定提交成功也不等于真环境验收。

## 9. 关键失败语义与迁移检查

| 窗口 | 统一处理 |
| --- | --- |
| 节点恢复或重入 | 复用原action/registration/invocation，读取原收据；不因节点再运行创建新动作 |
| 业务或模型已提交，checkpoint失败 | 保留原事实并核对，不重复业务调用或扣费 |
| checkpoint存在，引用结果缺失或不一致 | unknown/人工核对；不能假定未执行后自动补发 |
| 派发成功但响应丢失 | 原invocation核对，缺证据继续unknown |
| usage缺失或半缺 | 保守占用、原单账核对，禁止SDK默认0直接结算 |
| 派发前/后取消 | 前者停止新动作；后者传递取消并保留已提交或未知事实，不声称远端撤回 |
| interrupt恢复 | 当前输入或批准事实复验，resume值不是批准 |
| 双实例或旧holder迟到 | 原lease/fence/CAS保护步骤和checkpoint head，旧worker不得继续推进 |
| 撤权、切空间、政策/图版本变化 | 拒绝不合法恢复与正文访问，不能热替换版本继续执行 |
| 多轮恢复 | 累计Steps/Calls/ActiveMs/OutputBytes与费用不归零 |
| 回退 | 停止新任务采用新引擎；存量保持原版本处理或人工核对，不换引擎重做动作 |

实际迁移使用真实选定库驱动契约与故障夹具；保留全部原负例。静态、实际库离线、真实MySQL、供应商、宿主和生产证据分层记录，不合并为一个“全绿”。当前文档整合不运行这些测试。

## 10. 分工、收益和不做事项

主线负责公共契约、schema/lock、执行权划分、Gateway/预算边界和固定提交整合。Runtime/checkpoint、Provider桥可以在明确独立文件范围后并行；业务工具与Knowledge线继续维护可被两种驱动复用的服务。实际认领以届时协作记录为准，本方案不向任何会话下达新施工指令。

预期收益是减少未来通用分支/等待编排与Provider协议维护的重复工作，不会免除Rental业务授权、可信金额、审批一致性、事实来源与场景验收。新增成本包括执行边界提取、存储映射、版本绑定、重入/故障验证和上游维护。没有工时采样，不承诺节省比例或迁移工期。

不做：整套应用平台替换、第二任务/审批/账本、双驱动真实副作用对照、任意图goto/fork/time-travel开放、默认托管追踪、为采用框架增加LiteLLM/Temporal/BullMQ/向量数据库。确需新增能力或基础设施时另行说明缺口和取得批准。
