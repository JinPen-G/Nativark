# Agent 接入改造：本地运营与服务端协同需求

> 专项：Rental OS AI Native Agent 接入改造。
> 版本：v1.4；建立日期：2026-10-22；修订日期：2026-10-23。
> 本次修订：明确两端统一业务能力上限、早期正式 Web API 接入与个人通用功能边界；保留原基础阶段及并行服务端范围。
> 文档性质：负责人批准的需求依据；未经授权不随意变更，不写开发流水。文档形成不等于功能已实现、执行授权或验收。
> 配套：[开发任务](Agent接入改造-开发任务.md) · [开发记录](Agent接入改造-开发记录.md) · [当前协作接续](Agent接入改造-协作接续.md)。

## 1. 目标与产品定位

以 DeepSeek Harness 的 Electron 客户端为基础，把 Rental OS 的后台登录和已有管理页面接入同一个工作台。用户先登录 Rental OS，再选择经营空间和工作方式：AI 使用 Harness 原界面；传统使用现有后台菜单和业务页面。

**登录与界面接入是本地路线的基础阶段，不是本地 Agent 的最终范围。** 在保留原阶段要求的基础上，追加获准查询、Core 报价、草稿及经原确认 / 审批链建单；不是把全部 API 开成工具，也不是重做 Agent。

模型由本地用户在 Harness 中配置提供商、模型与 API Key，客户端直接使用其模型服务。模型费用、tokens 和供应商用量由用户自己的账号承担，**不经过 Rental OS AI Gateway，不接平台模型预算、价格或用量账**。Rental OS 服务器继续负责正式业务 API、身份权限及原有业务处理。

### 1.1 与原专项的关系

- 本专项有独立的需求、任务和验收编号，不并入原 AI Native 28 项或 ENTRY 增量，不修改它们的百分比、范围和验收。
- 原 AI Native 服务端编排、任务恢复、业务工具、协议、知识、Gateway、预算、用量，以及业务后台、API、Core、测试、文档、历史和所有未提交成果全部**实际保留**。不能删除后以“Git 历史还能找回”代替保留，不能改成仅调用新客户端的空包装。
- 负责人后续会继续开发这些成果；服务端 Agent 是长期并存的产品能力，不是因客户端方向取消的旧实现或仅供废弃回退的备份。保留不要求新客户端每次对话都调用它，也不表示本轮恢复全部服务端开发。
- 本专项明确的本地用户模型通道是新的产品范围；原服务端托管模型路线继续保持其原 Gateway 和单账要求，不通过改旧文档把两条路线混在一起。
- 先前 Runtime 替换方案保留原状，不再继续编辑；其中平台代付或本地模型另批的旧设计不作为本专项实施依据。
- 本专项不替代原 Web 后台，不删除旧 AI 页面；它们在传统菜单中仍按原权限和功能开关出现，但不能配置或计量 Harness 的本地模型。

### 1.2 客户端、服务端与 Web 长期并存

- **本地客户端 Agent：** 使用 Harness，作为经营者、店长和获准运营人员的个人运营工具；可查询真实事实、生成方案，并在当前权限及必要的原确认 / 审批下调用获准业务工具。客户端私有模型由用户自行配置。
- **服务端 Agent：** 为独立管理后台 Web、租户消费者官网以及客户 / 员工小程序提供受权 API 和场景能力，不要求先安装或启动本地客户端；同时承接持续巡检、异常解释、共享任务及跨用户协作。运营、员工、客户、平台 audience 的权限与工具分别控制，不能共用万能 Agent。确定性查询和规则能完成的检查不强制交给模型重算。
- **独立 Web 后台：** 除传统页面外，提供由服务端 Agent 驱动的正式 AI 聊天页面，支持目标输入、多轮澄清、资料 / 报价、确认 / 审批、任务进度及原结果；不是仅提供 API 或只读任务列表。浏览器可独立登录使用，不要求安装或启动 Harness，不因新增客户端取消原入口和业务权限。
- **原业务系统：** 两种 Agent 和两种界面都复用原业务 API与权威事实；不能建设第二套订单、库存、资金或权限实现。

服务端后续结果先持久保存为受权任务 / 结果，再按接收者权限由对话卡片、任务中心、站内通知或获准外部渠道展示；通知发送不替代任务结果，也不让每个渠道重跑 Agent。每位用户可在自己的默认对话中接收或委派任务，不必共享完整聊天历史；正式任务独立于对话和客户端在线状态，只传必要任务、业务引用与状态。

后续协作须复用当前授权、审批和幂等，委派不扩大接收者权限；同一任务 / 业务动作明确执行方，客户端和服务端不能双跑。转交、接收、执行、完成分别记录，断线或超时按原任务 / 收据核对，不换 ID重做。服务端模型凭据和费用另行明确，不能读取或借用用户的本地 Key；复用旧服务端模型路线时仍沿其原 Gateway和单账。

两条路线**并行且可独立选择推进**：不要求本地路线全部完成后才开发服务端，也不要求每次本地对话先创建服务端 Agent 任务。共享接点按实际依赖协调；服务端沿原 AI Native 正式任务继续，不在本专项重建一套相同任务或计费设施。客户端与服务端可以协同，但协同不是所有调用的强制前置，具体边界见 AGC-R13。

Web AI 聊天的模型执行在服务端，经原 Gateway / 单账；本地 AI 聊天的模型执行在 Harness，经用户自配通路。桌面传统页中打开 Web AI 页面时仍是服务端路线，不因外壳变成桌面就改用个人 Key。界面须标明当前使用本地模型还是服务端任务及费用归属，切换不自动重发消息、复制完整历史或接管在途动作。

原登录 / 页面阶段仍以 AGC-R01～R06、AGC-A01～A08 为范围；新增受控业务及协同要求单列，不悄然扩张原阶段验收分母。巡检调度、多渠道投递和各端页面按原任务与后续具体授权推进，不因本次文档补充自动启用。

### 1.3 管理后台一份源码、同一发布、两种外壳

1. `apps/admin/` 继续作为管理后台功能页面、导航和请求链的唯一维护源。浏览器显示完整 Web 外壳；Harness 内嵌同一 Web 应用的受控内容模式，避免重复导航。
2. 首期按**加载同一套已部署的 Web 后台**设计，不将后台功能页复制到 Harness，也不将后台静态构建副本作为随安装包冻结的业务页来源。Harness 自身外壳与 Agent 仍可本地打包。
3. 页面、表单、列表、样式及一般菜单修改只在后台维护；发布 Web 后，Harness 刷新或重新打开并取得该部署的新版本资源即可更新，通常不需重新打包客户端。只改源码未发布不生效，已打开的页面不承诺立即热更新；不得为了同步强制刷新并丢弃未保存草稿或重复业务提交。
4. Harness 的业务菜单动态消费同一后台导航注册表派生的当前受权投影，不随客户端安装包维护一份固定副本。新增普通菜单 / 页面不应要求更新壳；新增原生能力或改变宿主通信协议时可能需要客户端升级，须明确最低版本和兼容处理。
5. Web发布应保证静态资源版本和缓存可取得一致的新页面；宿主消息与页面版本不兼容时明确提示或拒绝不支持的操作，不放宽 origin、sender、权限或消息校验迁就旧壳。
6. 后台受控 origin来自获准部署配置，不由模型、任意 URL或页面字段决定。Web不可达时明确不可用，不回退未核验的本地业务副本或缓存假登录。未来若要离线后台另行批准，不混称本期同步能力。

### 2.1 受控业务工作台的交互方向

采用“目标对话 → 真实业务资料与报价 → 人类核对 / 必要审批 → 正式执行 → 原收据”的方式。可在工作区展示客户选择、商品、绝对时间与时区、地点、数量、Core 金额 / 押金、版本、有效期和缺项；真实资料按当前权限展示，发给模型的内容另按 AGC-R08 最小化，二者不能混同。

负责人提供的预约与库存示意图用于确认这种未来交互，不代表本期逐像素重做页面。右侧资料、按钮和确认弹窗均须消费真实状态；示例报价 / 演示回执不能充当正式结果。“报价合适”不构成有界批准，“确认报价”不等于批准建单；确认内容变化、过期或失权时重新核对，不执行旧批准。

## 3. 首期需求

### AGC-R01：接入现有后台登录

1. 启动客户端后，未登录 Rental OS 时先显示后台登录入口，不进入 AI 或传统工作台。
2. 复用现有租户编码、账号、密码及租户专属登录流程；不增加平行账号库，不把 DeepSeek 账号登录当作 Rental OS 登录。
3. 登录结果与启动恢复沿原服务端会话核验；本地缓存存在不等于登录有效。必须改密的账号保留原改密门槛。
4. 用户登录成功后即可进入工作台；尚未配置模型只影响 AI 调用，不阻止访问传统页面或模型设置。原 DeepSeek 模型欢迎流程不能替代业务登录门槛。
5. 保留原 token 刷新、注销和失效处理。退出或会话失效后，收回业务菜单、内容和宿主业务通信，不残留上个账号的页面。
6. 会话核验失败或离线时如实提示并停止进入受保护工作区，不用缓存或模拟账号补成功。

### AGC-R02：左上角品类经营空间选择

1. 选择对象是服务端返回、当前账号有权进入的经营空间，不是任意品类编码。
2. 复用现有空间名称、品类信息和切换 API；由原服务端复核成员资格、空间状态和当前权限。
3. 单空间显示当前空间但不提供无意义切换；平台账号显示原平台管理面；无空间账号显示原无空间状态，不虚构空间。
4. 切换中显示进行状态；拒绝或失败不先显示成功。不把页面字段、本地存储或模型生成的空间 ID 当作授权。
5. 成功切换后先清旧查询缓存并中止旧请求，再发布新身份和菜单。旧空间详情、草稿、迟到响应不得混入新空间。
6. 当前传统页若不再可访问，回到新空间的原可访问默认入口；AI 模式保持所选工作方式，不能因切空间自动发起模型或业务动作。

### AGC-R03：AI / 传统工作方式

1. 左侧提供明确的“AI / 传统”切换；首次成功登录默认进入 AI，可手动转传统。
2. AI 模式显示 Harness 原导航、会话和主内容；传统模式显示现有后台分组菜单和对应业务内容。
3. 切换仅改变展示和导航，不改变账号、租户、经营空间、业务权限或模型凭据。
4. 切换不自动提交表单、开单、支付、发送消息或启动模型调用；保留已有页面的草稿和离开提示语义。
5. AI 会话仍由 Harness 管理，不因普通工作方式切换删除或重建。原运行中任务不因内容区隐藏被错误标为取消或成功。
6. 传统模式下选定菜单与右侧实际路由一致；返回 AI 后仍可继续原会话，不重新初始化整套 Harness。

### AGC-R04：传统菜单与已有页面

1. 左侧下方显示原后台菜单分组；菜单、面包屑和路由仍派生自后台唯一导航注册表，不手工维护第二份业务目录。
2. 沿当前账号的 audience、permission、legacyPermissions、capability、品类与会员管理权限控制可见和可进入的页面。原功能开关仍生效。
3. 右侧复用原后台真实页面及 API 请求链，不用示例卡片、截图或复制表单替代已有功能。
4. 保留列表、筛选、分页、详情跳转、上传、下载、异步确认、保存和错误反馈等现有行为。嵌入导致的差异须逐项记录和补接，不能隐藏后称全量接入。
5. 桌面模式只调整后台外壳：避免重复顶栏、重复侧栏和重复空间选择；普通浏览器访问继续保持原后台布局和行为。
6. 页面沿 React / UIArc 适配、原主题 token、语言与必要 AntD Form 兼容语义；不修改 vendor，不恢复旧深蓝主题或替换用户已选组件。
7. 当前账号无任何可访问传统菜单时显示真实无权限状态；未知或未注册路由不能作为任意地址打开。
8. 后台功能页只有 `apps/admin/` 一份源码，浏览器与 Harness 读取同一 Web 发布；Web更新后获取新资源即可同步页面和受权菜单，不复制第二套实现、不以安装包中的旧后台副本作为正式页面。
9. 普通页面 / 菜单更新不要求重打包 Harness；壳层、原生能力和宿主协议变化需分别管理兼容和客户端更新，不承诺任意 Web改动都能适配全部历史客户端。同步不自动提交业务、重跑 Agent或清除未保存内容。

### AGC-R05：Harness AI 功能先保留

1. 保留当前版本已经提供的 Agent、会话、模型配置、文件、终端、工具、插件和其他功能，不在本期开展功能大裁剪或 Agent 循环替换。
2. 原可选功能保留其可选状态；存在源码不等于默认启用。首期不为演示自动开启定时任务、第三方插件或实验能力。
3. 模型设置复用 Harness 原提供商与 Key 配置，不创建 Rental OS 平台模型配置依赖，不迁移服务器已有密钥，不上传本地 Key 到平台。
4. Rental OS 空间与 Harness 本地 Workspace 是两种对象；不得将前者直接当成本机目录，也不得自动创建或切换后者。
5. 首期不自动向模型传入后台订单、资金、客户资料或后台登录凭据，不因嵌入页面就授予 Agent 读取页面 DOM、自动点击或业务 API 的能力。
6. “保留功能”不等于上游已安全审计或生产通过；后续启用和发布仍要按目标功能核对权限、隐私和依赖。

### AGC-R06：宿主与业务凭据隔离

1. Electron main、本地 Harness Host、Harness 主渲染器和后台业务视图分别负责自己的生命周期；本地 Host 不是 Rental OS 云端 API 服务。
2. 新接入采用受限的页面导航、会话展示信息和空间切换通信，不给业务网页开放 Node、文件系统、终端、任意 IPC 或通用 HTTP 代理。
3. 后台登录凭据不能进入模型上下文、会话日志、URL、业务菜单投影或任意第三方页面；模型 Key 不能变成业务权限凭证。
4. 保留 contextIsolation、sandbox、webSecurity 和关闭 nodeIntegration 的安全配置；消息校验发送者、受控 origin、消息类型与当前会话代次。
5. 数据读取与写入最终仍经原 Auth / Guard / ALS 和 Controller，不修改后端授权来迁就桌面 UI。
6. 登出、账号变化、空间切换、加载失败和视图销毁均要撤回过期业务通信。迟到消息不能重新显示旧菜单或旧空间数据。
7. 未登录或会话失效时不新启动工作台 Agent 调用；正在运行的调用按 Harness 原停止与善后能力处理，不能声称已经回滚，也不清除历史会话或用户模型配置。
8. 宿主桥复用已有公共协议，明确版本兼容、页面 / 会话代次、请求 ID、身份绑定、消息类型 / 大小上限、期限与应答状态；未知版本 / 消息拒绝。请求超时可能已完成，不能据此自动重发切换或其他命令；刷新 / 重连先重新核验，不复用旧执行消息。
9. 打印、文件预览、下载与获准外部地址分别限定用途、origin 和生命周期；新窗口不继承任意 preload / Node / 业务凭据。确需下载原业务文件时沿原授权入口与获准地址，不能为页面兼容开放任意跳转、通用抓取或跨域 token 转发；不支持的行为如实提示。

## 4. 登录与页面阶段以外的范围

以下内容**不计入原登录 / 页面阶段 AGC-01～07 的分母**。其中第 7 节已批准的受控业务能力按追加任务推进；其余仍按原专项或后续具体授权安排，不因列在这里取消需求、废弃成果或自动启动：

- 为全部后台 API 建业务工具目录，让 Agent 办理订单、库存、会员、资金或配置。
- 服务端持续巡检、定时查询经营数据、自动汇总、结果多渠道通知或无人值守业务写入。
- 跨用户任务委派、各自对话收件、共享任务跟踪及客户端 / 服务端任务转交；保留第 1.2 节方向，后续另行开发。
- 修改 AI 对话内容、右侧业务卡片、业务规划器、行业提示词或“只回答业务”的策略。
- 全面裁剪 Shell、文件、浏览器、MCP、插件、子 Agent、工作流等 Harness 功能。

完整首批业务出口是“当前受权商品 / 客户选择 → 时间地点与资格澄清 → Core 报价 → 原确认 / 审批 → 正式订单原收据”，并能受权解释已有订单。开业 / 风险、跨用户委派、资金自动处理不因首批表扩大范围，继续沿各自原任务。

业务模式需要所选模型适配具备有界工具调用、严格参数校验、可识别的终止 / 错误和取消处理；模型 ID、协议、base URL 仍由用户配置，不硬编码供应商。适配未验证或模型不支持工具时只保留人工页面和允许的非执行辅助，不自动伪造工具调用或替换模型重做。能力声明不是业务授权，真实提供商兼容性另行验收。

#### R09.2 统一业务能力上限与阶段接入差异

1. **本地 Harness 的 Rental OS 业务能力是服务端统一定义并允许开放能力的子集。** 两端使用同一业务语义、事实与权限来源，目标是业务范围对齐，不要求 UI、运行方式或开发完成度完全相同；服务端能力可用不自动授权本地开放。比较以同一主体、audience、tenant / workspace、地点与数据范围为前提，不将运营权限开放给客户。
2. 上限不是“服务端 Agent 当前已包装成工具的接口数量”。前期服务端 Agent 尚未完成接线时，本地可先经 R07.1 受限业务桥复用**已实现、当前受权且获准开放的 Web 正式业务 API**，因此局部接入能力可以暂时领先。仅规划中的 Core 能力不能调用；安全停用、明确禁止、缺权益或审批的能力不能借 Web API 绕过。API 存在、菜单可见或人工页面可操作，均不等于允许 Agent 调用。
3. 过渡入口仍逐项纳入 R09.1 及原能力登记：明确正式生产者 / 接口版本、输入输出、当前权限和本地接入政策、数据投影、副作用、原操作与收据；分别说明服务端业务 API、本地适配和服务端 Agent 接线是否就绪。复用原目录与合同，不维护第二套业务规则、权限或计价。新增首批清单之外的能力须按正式任务与负责人授权扩展，不能以“对齐”为由全量开放。
4. 本地取得的数据可能比当前服务端 Agent 已接入的字段多，但不超过当前主体的正式授权；**用户可在受权页面查看，不代表可发给本地或服务端模型**。两端模型材料均按各自适用的最少字段、脱敏和外发政策处理。不得以任意 HTTP、页面抓取、Cookie / token 提取或 Shell 代替登记的业务入口。
5. 服务端 Agent 后续接齐时复用同一正式业务实现和原操作合同，按登记逐项收敛适配；不强制所有确定性查询改成云模型任务。一次动作只能选一条执行通路；超时或 unknown 不自动从本地工具切到服务端 Agent 重做，原键读取与当前权限仍为准。保存、建单及其他副作用始终满足 R10，不因采用 Web API 降级为只读。
6. 上述上限**仅约束 Rental OS 业务能力**。Harness 自有个人聊天、个人文件、终端等通用能力不要求服务端逐一实现，也不据此删减；但它们不获得 Rental 身份凭据或业务数据权限，不能用来绕过受控业务模式、外发规则和审批。个人通用模式与业务模式的权限、上下文和工具边界须可辨识；无法隔离敏感业务上下文时不得开放相关通用工具。

### AGC-R10：人类确认、原审批与正式建单

1. 获准建单复用原受控工具及已有确认 / Proposal / Approval / Core 提交链；不是直接给 Harness 任意 API 或数据库写权，也不复制审批状态机。
2. 人类看到并确认具体对象、scope、输入 / 报价版本、金额与副作用；须审批的动作仍走原审批，用户聊天肯定或桌面弹窗不替代正式批准。确认与执行均复核当前权限、报价有效性、库存及业务前置。
3. 首批不由 Agent 自动执行退款、收款 / 扣款、资金处分和高风险例外；只向有权用户提供原人工入口。普通权限码或订单状态看似允许，不等于业务工具已经开放。
4. 同一操作使用原业务幂等键和原收据。收到应答前不得显示已建单；超时、取消、断线或宕机保持可能已执行的 unknown，按原操作核对，不换 ID、账号、模型或执行引擎重做。

5. 正式写入的执行权始终在原服务端受控执行器 / Core。本地负责提出、显示和委托；不把服务端 lease / fencing token 发给 Harness，让它冒充 worker。已有建单入口要求正式原请求、Task / Run / Step、冻结输入、选择证明与批准时逐项沿原生产顺序创建，不能跳过或手填状态。确定性业务链不因此强制调用云端模型；实际入口如仍必需云模型，须明确此依赖及费用，不能伪称纯本地已接通。
6. 人类确认使用原可信业务界面与审批接口，绑定实际显示的对象、金额、报价 / 输入哈希、政策及批准版本；确认路径不放进模型可调用工具清单。聊天“是”、客户端 `confirmed: true` 或模型生成批准均不接受；审批人、发起者与不可自批规则沿原政策，不新增随意放行规则。
7. 开放任何保存 / 建单副作用前，必须同时有当前授权、真实提交入口、审计、提交前可恢复的原操作定位、原键结果读取和 unknown 展示。**建单还必须有可信确认 / 必要审批界面**；这些不能作为执行上线后的补课。请求身份与操作键须在发送前按原正式入口确定，重启仍能找回；没有可恢复的原键时禁止提交。

### AGC-R11：业务结果、固定 Action 与人工回退

1. 工作区将确定性业务事实、模型建议、待确认方案及正式结果分开呈现。模型文本不能覆盖 Core 金额 / 状态，不能把预约成功说成付款、交付或退款成功。
2. 导航及操作沿原注册 Action / 路由映射，按端支持情况呈现；不执行模型生成的任意 URL、脚本、页面路径或命令。缺入口 / 权限时说明缺项，不造按钮或模拟成功。
3. 模型、工具或服务不可用时保留可合法提供的事实与人工路径；撤权不能被可选来源降级吞掉。返回条数、文本 / 附件量、工具次数、时长和重试须有界，取消停止新动作，不能声称回滚已发生副作用。

#### R11.1 首批运行上限

以下为首批受控业务模式的默认上限，不是性能达标声明；使用服务端有版本政策，现有业务 / 任务更严格的限制优先，客户端只能收紧。没有可信限额配置不得开启自动业务工具。模型自身费用仍由本地账号承担。

| 项目 | 默认上限及处理 |
| --- | --- |
| 一次前台目标的业务调用 | 20 次，包含重试 / 轮询；最多 2 个并行只读，最多 1 个在途副作用操作。拆子 Agent、刷新或恢复不得给同一原目标重发额度 |
| 单次列表 / 单条文本 | 最多 50 条；每个可外发文本字段最多 2,000 字符；查询使用原分页 / 上限，不把返回后 slice 说成数据库有界 |
| 单次工具 / 一次模型材料 | 最多 64 KiB / 256 KiB（序列化 UTF-8），金额、引用、缺项与状态不得截断成有效新值；超限拒绝或显式 partial 并提供受权分页 |
| 单次只读 / 副作用提交等待 | 最长 15 秒 / 30 秒；只读超时返回 unavailable，提交超时返回 unknown 并保留原键。取消网络等待不证明服务端停止 |
| 一次前台自动推进 | 最长 5 分钟累计活跃时间；人类等待不占活跃时间，但仍受原输入 / 报价 / 审批有效期限制；到期停止新动作，不把旧 unknown 改成失败或成功 |
| 自动重试与附件 | 只读瞬时故障最多重试 1 次且不延长原截止时间；拒权、版本冲突不重试。副作用不自动重发，只读原键。首批无敏感附件外发；非敏感附件需单独正式类型 / 大小 / ACL 能力，未交付即不可用 |

限额分两层：宿主有界等待及调用管理用于及时退出，服务端原动作政策 / 限流及适用的任务累计资源负责可信约束，不能只在本地 Map 计数后声称服务端受控。无服务端任务的本地查询目标使用原接入调用关联与限流能力；若原能力无法跨恢复绑定该目标，上限生产者需先补齐，不能改建一套任务数据库或使用模型自报计数。后台原收据继续可由用户在当前读取权限下主动核对，不因本地目标额度耗尽而永久锁死。

### AGC-R12：业务留痕、原操作恢复与费用归属

1. 服务端沿原业务审计记录发起主体、scope、动作、原操作键、输入 / 报价 / 批准引用及结果，不能只靠个人聊天作为正式执行证据；模型分析记录不携带秘密或超范围原文。
2. 重启或断线后先受权读取原业务收据，区分已保存、已执行、失败、未知和当前是否仍可办理；读历史收据不重新授予派发或执行权。取消请求不证明取消成功，旧句柄 / 迟到结果不能覆盖新上下文。
3. 本地用户模型费用仍走其自配提供商，不增记平台模型账；业务工具的权限、审批、幂等、业务额度 / 库存约束及审计不因此取消。若某协同任务另由服务端调用模型，该调用仅走服务端原 Gateway / 预算单账，不把同一调用扣两次或使用本地 Key。

### AGC-R13：并行服务端入口与可选协同

1. 本地运营路线与服务端路线可独立推进。服务端明确面向**浏览器管理后台 Web、租户消费者官网、客户小程序及员工小程序**；按 operations / staff / customer / platform 的逻辑场景映射原正式身份与 audience，不另造可自授的身份枚举或共享万能工具集。
2. 本地可将获准的正式任务交服务端持久执行 / 等待 / 巡检，服务端任务也可回到本地或 Web 展示、澄清、确认、人工接管或继续办理；客户端不在线不使服务端任务自动丢失，客户与员工 API 不依赖某台运营电脑。
3. 复用原 Task / Run / Step、输入、提案 / 审批、业务原操作和结果，不另建协同任务库或第二账本。交接材料只含必要任务 / 业务引用、输入与版本、发起主体 / scope、状态及当前执行归属；不默认同步个人完整聊天、附件、推理过程或凭据。接收方按当前权限重新解析，委派不能扩大权限。
4. 对一次正式业务动作明确唯一执行方与代次 / 条件接管，转交请求、服务端受理、执行、结果持久化、通知与接收确认分别表达。已有执行或结果未知时先核对原任务 / 收据，不能把转交超时当失败并由另一端重复提交；不能同时让本地和服务端驱动同一动作。
5. 服务端仅信任正式认证、持久输入、批准和业务证据，不信任桌面自报“已批准 / 未执行 / 已付款”。回传结果同样复验当前接收者权限；撤权不继续推送旧敏感详情。普通展示更新、通知重复或重连只读均不得重启业务。
6. 服务端模型、供应商协议、任务资源及财务预算继续沿原配置和单账。跨用户委派、自动巡检和无人值守动作仍须原独立主体、政策与阶段门；本次协同方向不是全自动写入或新调度启用授权。

#### R13.1 第一条协同闭环与责任归属

先做**同一运营主体的订单解释任务**：本地明确选定受权订单和有限问题范围 → 使用原请求生产者登记输入 → 原服务端订单解释任务受理 → 本地及独立 Web 按原任务读取状态、受权事实 / 已有答案与来源。可以从已有任务的只读回读先交付，再接任务发起；读取现有结果不能顺手启动模型或新 run。原订单解释分支若需要模型，则明确由服务端 Gateway 计费，用户知悉后发起；缺云端模型依赖时只提供当前可用的事实与历史结果，不制造“任务已执行”。

后续在建单链齐备后做**原报价 / 提案 → 本地或 Web 人类确认 → 服务端原执行 → 两端读取同一收据**。不是两端各确认一次、各建一份订单；本地与 Web 对同一提案竞争确认时由原 revision / CAS 和批准策略处理。首批不实现任意跨租户 / 跨用户委派。

| 状况 | 必须遵守的行为 |
| --- | --- |
| 发送前 / 受理后 | 原请求关联在发送前可恢复；持久受理回执只证明接收，不证明执行成功。读任务、读输入、读批准和读业务结果分别取原事实 |
| 受理应答丢失 / 重复点击 / 两端同时观察 | 先按原请求键核对；unknown 不换键发起另一任务。重复展示、通知和回读不得触发新 run 或新模型调用 |
| 关闭窗口 / 网络断开 | 已受理服务端任务沿原政策继续或等待，不依赖本地在线；重开只读恢复。客户端不能把本地停止等同服务端取消 |
| 退出、撤权、切空间 | 本地立即停止展示旧详情和新动作；服务端在后续权限敏感步骤复核原主体当前资格。新会话不自动继承旧任务；已发生的副作用仍保留原结果，当前失去读权不回传详情 |
| 澄清 / 批准等待 | 等待是持久事实，恢复输入绑定原任务、步骤、修订与当前主体；过期后不得复用旧报价 / 批准，需沿原正式入口重新准备 |
| 取消 / 接管 | 使用原取消及条件接管接口与收据。人工接管意味着流程控制权按原代次变化，不把业务执行 lease 移交桌面；旧执行者不得追加动作，已派发 unknown 先核对，不自动重派 |
| 通知 / 查询受限 | 不因推送失败重跑业务；权限改变后通知只保留安全提示。只能按当前授权读取结果，不把桌面会话收件人当任务 owner |

上述是对原状态 / 事件的语义要求，不新建同名状态机。公共契约未能表达任一必要绑定时，由唯一公共作者补原合同及生产者，再接两端消费者；不能以桌面自报完成代替持久证据。

#### R13.2 本地 Agent 调用服务端 Agent 能力

除直接调用获准业务工具外，本地 Agent 后续可以通过**有限、注册的场景工具**委托服务端 Agent，并将受权结果作为后续分析输入。这样可复用服务端知识检索、经营分析、持久任务及获准巡检等已实现能力；列举方向不等于这些能力已装配或全部进入首批白名单。首条接入仍按 R13.1 的订单解释任务，不另建通用远程 Agent 执行平台。

- **业务工具调用**只取得原业务事实或执行已获准业务动作；**服务端 Agent 委托**可能创建持久任务、调用云模型、消耗预算并等待人工节点。两类须在工具声明、确认与结果中明确区分，不能把会计副作用藏在“查询”名称下。
- 委托使用固定场景代码 / 合同版本、允许的结构化输入、原请求键及必要引用；不允许任意系统提示词、任意工具清单、跨用户任务 owner、任意代码或模型指定的服务器凭据。
- 接受的是当前发起人的授权范围与该场景的正式政策，**不是服务端机器或管理员的权限**。知识 / 记忆 / 文件另验 ACL 和用途；接收结果再次经过当前权限与本地模型外发投影，服务端可以展示给人看的资料不等于可送个人模型。
- 本地不代签人工批准。服务端遇澄清 / 审批返回持久等待及原引用，由真实人类在本地可信业务视图或 Web AI 页面处理；本地模型回答不能充当“用户已确认”。
- 有云模型调用时告知费用归属，并使用服务端原 Gateway / 预算单账；本地再次总结是另一笔用户个人模型调用，不得宣称全部免费或混为同一次计量。未许可云调用时只返回可用事实 / 人工出口，不静默委托。
- 服务端任务不反向自动委托同一本地 Agent，再由本地递归委托形成环。首批禁止自动嵌套跨端委托；后续扩展必须在原任务关联中约束深度、调用数、期限、取消与唯一执行方。查询状态 / 重连不重新发起任务，unknown 只按原键核对。

“让客户端获得服务端能力”指上述受权复用，不把服务端 Runtime、数据库、全量知识或密钥复制到本机；也不让服务端的自动主体权限通过本地工具暴露给普通用户。

以下验收与原 AGC-A01～A08 分开登记；本地与服务端不以对方全量完工为前置，但实际共享接口须有正式生产者。文档或界面样例不算业务链通过。

| 验收 ID | 对应需求 | 必须观察到的结果 |
| --- | --- | --- |
| AGC-A09 | R07 | 原认证通路实际调用业务服务，模型 / Host 不获得 token；租户禁用、地点缩权、切账号 / 空间、撤权与迟到响应均拒绝旧业务。个人历史保留但业务片段 / 摘要不可越权重放；验证 30 天 / 7 天期限和失权即时撤回，新执行关闭后仍可按独立当前权限读原收据 |
| AGC-A10 | R08 | 输入姓名 / 电话、粘贴文本、附件名及旧摘要在第一次模型请求前被阻断或转为允许字段，不依赖外部模型脱敏；Core 报价正确投影，凭据 / 个人信息不入请求或日志。通用文件 / Shell / 插件旁路有实际限制证据，无法隔离不开业务模式 |
| AGC-A11 | R09 | 沿首批清单完成当前受权查询、同名明确选择、时区澄清与真实 Core 报价 / 材料；已支持品类各有代表输入、不支持明确拒绝；金额 / 版本同源、无库存预占误报。保存应答丢失只核对原键，不创建第二报价；不支持工具的模型降级不造执行。核对 R09.2 能力映射：服务端 Agent 未接线但获准正式 API 已具备时本地可用；被停用 / 越权能力不可通过 Web 或通用工具绕过，unknown 不跨通路重派 |
| AGC-A12 | R10 | 可信人类确认、必要原审批、审计及恢复先齐备再开放建单；篡改金额 / 版本 / confirmed 字段、自批或复用失效批准被拒绝。服务端唯一执行并回读原订单，首批资金动作不开放；已执行后丢应答仍只一份订单 |
| AGC-A13 | R11 | 资料、确认与结果绑定同一原输入，Action 仅固定映射；验证次数 / 并发 / 字节 / 超时上限、重启不重置适用累计额度，超限停止新动作而不丢原收据。非合作等待能退出，取消不显示已回滚；失权不得返回旧敏感材料 |
| AGC-A14 | R12 | 提交前可恢复定位原操作，重启 / 取消 / 超时后可独立核对；区分未找到、失败与 unknown，不能用不存在的“未找到即未执行”推断。自付本地不记平台模型账；实际云模型调用走唯一 Gateway / 单账，费用与业务执行归属可解释 |
| AGC-A15 | R13 | 分别验证同主体订单解释只读协同、原报价 / 提案的人类确认建单协同；本地场景工具实际消费服务端 Agent 原任务，不只是跳转链接。任意场景 / 超权输入 / 自动递归委托被拒绝，云调用费用明确，返回材料再验外发政策。两端同源结果，断网、关客户端、双端确认、撤权及受理丢应答不双跑。独立 Web AI 聊天及官网 / 小程序不依赖桌面在线，其完整场景验收归原任务，不用本地演示代替 |

追加阶段允许先以有界定向冒烟及类型检查收口功能片；真实提供商、Electron 宿主、Web / 微信宿主、数据库并发与部署各自按获准环境验收，不互相冒充。

### 8.1 分阶段完成出口

- **基础阶段：** A01～A08，登录 / 空间 / 页面 / 原 Harness 能力可用；不得称业务 Agent 已可建单。
- **受控查询与报价阶段：** A09～A11、A13～A14 的适用部分，原身份、输入 / 输出隐私、可信上限、查询 / 保存报价及原键核对齐备；只开放完成的工具。
- **正式建单阶段：** A12 及 A13～A14 的完整动作链，报价选择、人类确认 / 必要审批、唯一服务端提交和原收据齐备；目标不是自动付款或全自动经营。
- **协同阶段：** A15 分只读订单解释与后续建单协同登记；只读通过不能称写入转交通过。服务端 Web / 客户 / 员工能力按原任务独立验收，不要求本地全部完成。

正式收口须同时具备实际生产者、消费者、当前授权、错误 / unknown / 人工回退和对应证据。目录、界面、接口声明、文档或局部冒烟都不能单独代表某阶段完成；未支持项必须在真实产品中明确不可用，而非演示成功。
