## 1. 当前负责人要求

1. **两条路线并行，不设先后总门槛：** 本地 Harness 是运营人员个人业务工具；独立管理后台 Web 也有服务端驱动的 AI 聊天页面，不只是 API / 任务列表；服务端同时面向租户消费者官网、客户 / 员工小程序，并承接巡检和协作。负责人可随时选择推进任一条，不能再把服务端仅写成“本地做完之后的巡检”。
2. 本地基础阶段仍为原登录、经营空间、AI / 传统与菜单页面；追加阶段接获准查询、Core 报价、草稿和经原确认 / 审批的建单。退款、收款 / 扣款、资金处分及高风险例外先留原人工流程，不开放全部 API。
3. 本地模型由用户自配直连自付，不进平台模型账；服务端模型继续原 Gateway / 预算单账，绝不借本地 Key。业务权限、审批、原幂等 / 收据和业务约束不因自付免除。
4. 当前沿用 Harness 个人共享会话 / 历史 / 附件 / 模型设置，不新建按 Rental 账号 / 租户分区的聊天库。业务调用只认当前服务端身份；旧业务历史再次送模型或续接前须筛选复验，不能跨账号 / 空间沿用批准或工具引用。
5. 模型可消费最少受权、去标识业务事实及真实 Core 报价；客户 / 订单用受控引用，个人资料、秘密和敏感附件不传。用户键入 / 粘贴也须在首次模型请求前转换为允许字段，未知文本不透传；真实页面与模型材料分开。投影覆盖工具、历史、附件、日志、摘要与协同，受控业务模式限制 Shell / 文件 / 插件旁路；不能靠提示词或 Electron 视图隔离宣称全机安全。
6. 本地与服务端可以交接正式任务及结果 / 确认。只传必要任务、业务引用和版本，不默认同步完整聊天；同一动作执行方唯一，丢应答按原键核对，不能另一端重做。服务端任务独立于桌面在线状态，Web 不依赖安装客户端。
7. 全部旧服务端 / 业务 / Web源码、测试、历史与 WIP 实际保留，不以 Git 可恢复代替。后台 `apps/admin/` 一份源码、同一 Web发布；本地受控嵌入与浏览器独立使用并存，不复制后台。
8. 本对话负责客户端原生桥、工作台、后台 `features/agent-desktop/` / `api/desktopBusiness.ts`、API `ai-native/desktop-business/`、新增政策迁移和 `shared/agent-desktop*`。公共 AppModule / Guard / OpenAPI 仅补本片必要接线；其他线的 Gateway / 预算 / runner / 模型合同 WIP保留，不新增会话或心跳。
9. 不再编辑旧 Runtime 替换方案。参考预约 / 报价效果图仅确认未来“对话 → 业务资料 → 人类确认 → 原结果”的交互，不是本轮 UI 实现或真实业务证明。
10. 本地 Rental 业务范围不超过服务端统一定义且允许开放的范围；早期可复用获准 Web 正式 API 领先接线，不可领先权限或绕过停用。原能力登记区分 API / 本地适配 / 服务端 Agent 就绪；个人通用功能单独保留但不得作业务旁路。实现沿 R09.2、AGC-10 与 A11，不新建工具体系。

## 3. 接入决定与下一片

首期采用：**Harness 本地外壳 / AI 继续复用；隔离 WebContentsView 加载同一套 Web后台发布的登录和业务页；原导航动态派生无凭据菜单投影。** 后台一份源码、一个 Web发布、浏览器完整外壳和桌面受控内容模式，不复制业务页到客户端。两套工程保持独立依赖，不能把 React 18 / 19 组件直接混入同一运行时。

Web修改只有发布并取得新资源才生效，已打开页面不承诺即时热更新；刷新保留原未保存提示，不重复提交。Harness 壳 / 原生能力 / 宿主协议改变另管兼容与客户端更新，不解除 origin或发送者验证。当前没有运行或验证此同步链路。

当前接续分工与未完成事项：

1. **本地基础阶段 AGC-01～07：** 导航 / 空间结果核对、切空间撤回旧Host、迟到身份拒绝、有限握手和新文档复核后解锁已随功能提交，不重复实现。剩余为获准地址下的 Windows Electron / Web组合、真实登录 / 改密 / 撤权、AI / 传统布局及打印 / 下载 / 发布刷新验收；源码冒烟不替代这些条件。
2. **本地追加阶段：** 按 08 → 09 → 13 → 10 → 12 → 11 接当前政策 / 受限业务桥、输入与结果投影、前置原键 / 审计 / 可信上限、封闭查询与报价清单、可信人类确认工作区，再接原批准建单。任务编号不等于执行顺序；不得先开放写入后补确认和恢复，不建新审批 / 账本或通用代理。
3. **服务端路线：** 按原 AI Native任务独立推进，不以本地全部完成为前置。本轮只补客户端依赖的专用政策 / 目录API，不改原Runtime / Gateway / 账本，也未重审原任务完成度。
4. **协同 AGC-14：** 先复用同主体原订单解释任务，在本地 / Web 读取同一状态与事实，再接正式发起；不等待建单整链。后续待 11 齐备做原报价 / 提案跨端人类确认与同一订单收据。实际云模型任务须另过原配置 / 预算；不能以本地自付假装云端免费。取消、接管沿原收据，不给桌面服务端 lease。
5. **已接入口：** 原“AI服务设置”页仍负责当前空间政策 / CAS / 本人原键核对，unknown不换键，sessionStorage不保证整窗关闭后的引用恢复。侧栏目录语法只在本机解析；输入已配置Provider / 模型ID后，经 `catalogForModel` 由私有Host实际 `prepareCall` 取得初始路由，再走原Auth / Guard / ALS / 政策 / 有界Core / 审计，最后重新准备并比较路由及 `preparationVersion`。时间不混入指纹，端点 / 协议 / 准备参数或身份变化拒绝；不回退手填URL / 旧桥。支持显式Key的标准Responses / Completions / Messages及直接Messages；账号切路由、隐式认证或缺路由元数据保持不可用。结果最长30秒，仅人查看，不进模型 / 聊天历史。接口及限制见[客户端说明](../../clients/agent-desktop/README.md#受控目录预览与政策接口)。新迁移未执行，缺表 / 政策 / 审计仍拒绝。
6. **下一片与发布门：** 本批只证明适配器准备时的初始路由，不证明远程设备、最终重定向 / 附件落点、普通聊天当前模型或旧调用未发送；不能拿检查结果派发、释放占用或重做unknown。下一步仍须把受审查适配器 / 插件、模型 / 协议外发政策、实际发送对象与同一真实准备调用绑定；补业务会话 / 历史 / 摘要 / 附件统一投影、过期 / 撤权及Shell / 文件旁路隔离。随后接原跨恢复累计资源 / 原操作定位，再开放模型工具 / 报价 / 建单与协同。当前单次截止 / 条数 / 字节上限不是累计额度，政策收据不是业务恢复收据。08 / 09仍G1各25%，其余追加任务0%。个人历史保留，30天业务片段 / 7天临时附件保留源仍待接。
7. **两份需求的适用关系：** 原 AI Native 需求 v1.10 的 §1.3 是服务端侧的并行约定，本专项 v1.4 是本地具体接入依据；服务端 BYOK 与本地用户自配模型不能混用，实际云模型委托仍记原单账。统一业务能力上限不强制等待服务端 Agent 接线，合法过渡 API 沿 R09.2。共享批准 / 原操作 / Action 合同只维护一份；原任务范围、百分比和旧 Runtime 方案未因此变更。
8. **服务端能力供本地消费：** R13.2 明确可用固定场景工具委托服务端 Agent，不只是跳转页面；第一条为原订单解释任务。仍按发起人当前权限、原任务 / 单账 / 收据与结果外发政策，不获得服务端高权限、不自动递归委托。Web AI 聊天与本地聊天分别显示通路与费用；桌面打开 Web AI 页面不改变该页面的服务端归属。

本轮使用已安装工具链做离线验证和定向构建，未安装、启服务、访问真实API / DB / 模型或迁移。查询、报价保存、建单、协同分开开放；原权威业务记录不随本地删聊天删除，unknown按原键核对。当前人工预览不授予普通Harness对话业务访问，原业务写入及模型费用归属不变。
