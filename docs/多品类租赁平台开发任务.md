## 1. 基线判定规则

- 产品定位与业务验收以 `多品类租赁平台需求说明.md` 为准。
- 开发前必须重新检查当前分支、提交、工作区改动和实际代码，不在正文写死容易过期的 commit 或工作区快照。
- 已完成工作、验证命令、结果与剩余风险只记录在第 7 节；历史通过记录不得替代当前复核。
- 页面存在、静态类型通过、内存测试通过或开发者自报均不能单独证明 MySQL、并发、租户隔离、外部集成或生产就绪。

## 2. 完成定义

任务只有同时满足下列条件才能标记 `Done`：

- 需求规则、异常和权限边界明确；
- 前端、API、共享类型和数据库变更保持一致；
- 所有查询和写入按 SaaS 租户隔离；
- 金额、库存、优惠券和状态动作由服务端校验；
- 关键写入具备事务、幂等和审计；
- 自动测试覆盖正常、异常和跨租户场景；
- `npm run test:rental-foundation`、`npm run build`、`git diff --check` 通过；
- 涉及数据库时验证空库部署、已有库升级和重启恢复。

状态只能使用：`Done`、`In Progress`、`Pending`、`Reserved`。

### 3-A：开发分支与任务归属

`main` 是唯一集成分支，只允许 Codex 在完成代码 Review、验证和必要修复后合并。开发 AI 不得直接在 `main` 修改、提交或推送。为控制分支数量，项目只预建以下四条模块分支；开发 AI 必须使用被分配的现有分支，不得自行新增分支。

| 分支 | 当前状态 | 任务归属 | 启动条件与当前入口 |
| --- | --- | --- | --- |
| `ai/rental-core` | Active | `RC-01`、`RC-02`、`RC-03`、`RC-04`、`RC-05` | 当前只执行 `RC-01`；后续任务必须按 ID 顺序且经 Codex Review 前一任务后再启动 |
| `ai/catalog-assets` | Standby | `CAT-01`、`CAT-02`、`CAT-03`、`CAT-04` | 等 `RC-01` 的事实表边界稳定，并由 Codex 明确分配具体任务后启动 |
| `ai/commerce-orders` | Standby | `PRICE-01`、`PRICE-02`、`MKT-01`、`MKT-02`、`RULE-01`、`ORDER-01`、`ORDER-02` | 依赖 Rental Core 事务、库存和幂等边界；每次只允许一个具体任务进入开发 |
| `ai/customer-operations` | Standby | `CUSTOMER-01`、`BENEFIT-01`、`NOTICE-01`、`REPORT-01`、`CLIENT-01`、`OPS-01` | 依赖规范化订单事实和对应业务事件；按 Codex 分配的具体任务启动 |

`EXT-01`、`EXT-02` 仍为 `Reserved`，在项目负责人确认真实供应商前不进入任何开发分支。分支归属只解决代码隔离，不改变本任务表的优先级、前置依赖和验收要求。

分支执行规则：

1. 同一时间每条分支最多分配给一个开发 AI；一个 AI 只处理一个已分配任务 ID。
2. 开发 AI 开始前必须确认当前分支与任务归属一致；不一致立即停止，不得在错误分支“先改再说”。
3. 开发 AI 可以在被分配分支提交并推送，但不得创建或删除分支、不得强制推送、不得合并或推送 `main`、不得自行创建 PR。
4. 开发完成后，开发 AI 交付分支名、提交 SHA、实际测试、未完成项和风险；不得把自报测试写成 Codex 已复核。
5. Codex 从 `main...开发分支` 审查完整 diff，复跑适用测试并修复问题；只有满足任务验收后才合并到 `main` 并推送。
6. 合并完成后，Codex 删除该模块分支并从最新 `main` 以相同名称重建；开发 AI 不得继续使用旧提交或旧工作区。
7. 若任务需要修改另一分支负责的模块，开发 AI 只报告依赖，不跨分支顺手实现；由 Codex 决定调整归属或安排后续任务。

## 4. 执行顺序

1. 从最高优先级中选择第一个未达到 `Done` 的任务；同级任务按 ID 顺序处理。
2. 当前 P0 未全部关闭前，不开始 `RC-01` 或任何新业务页面、外部 provider。
3. 不得自行假定环境可销毁，不得运行未通过安全审查的清库脚本。
4. 开发 AI 只能在第 3-A 节分配的模块分支提交和推送；不得直接修改、提交、推送或合并 `main`。
5. 模块分支的创建、删除、同步、Review 和合并只由 Codex 执行；开发 AI 不得自行创建额外分支或 PR。
6. 预建分支和任务归属不代表可以跳过优先级；未被 Codex 明确激活的 `Standby` 分支不得开始开发。

## 6. 台账维护规则

- 开发前选择一个任务 ID，不同时扩展多个不相干领域。
- 开发 AI 只能修改所执行任务的状态单元格，并在第 7 节追加一条进度记录；不得修改任务定义、优先级、实施要求、验收、当前基线或执行顺序。
- 只在实际代码、数据库和测试发生变化后更新任务状态；未满足全部验收时不得标记 `Done`。
- `Done` 必须满足本文完成定义；页面存在、类型检查通过或人工点击均不足以标记完成。
- 发现新增需求或任务定义需要变化时，只向项目负责人报告；未经明确授权不得修改需求文档或新增任务。
- 不再创建开发日志、分支流水账、日报、自动检查总结或重复路线图。
- 不在文档中保存账号密码、token、密钥或真实客户数据。
