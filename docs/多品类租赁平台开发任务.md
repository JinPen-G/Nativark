## 1. 文档职责

本文件是当前开发任务的总入口，不再记录逐次提交、测试流水或已经完成的任务。各分册只允许出现以下状态：

- `In Progress`：已经开工，仍有代码、验收或外部环境工作未完成。
- `Pending`：已经进入规划，尚未开工或等待前置任务。
- `Blocked`：代码可继续空间有限，必须等待凭据、经营决策或第三方环境。
- `Reserved`：后续能力，未授权当前开发。

任务达到“规则明确、页面或接口可操作、持久化一致、权限和租户/空间边界正确、异常有出口、定向验证通过并经独立 Review”后，从分册移除并登记到[已完成任务归档](归档/多品类租赁平台已完成任务归档.md)。不得在当前任务文档中保留 `Done` 行。

## 2. 当前交付方向

当前目标是把已经具备的后台经营能力，通过客户端和真实第三方平台形成可试点的业务闭环。开发顺序固定为：

1. 收口当前未提交改动并完成独立 Review，避免并发任务覆盖。
2. 完成客户端共用配置、真实支付、短信和文件存储沙箱验收。
3. 完成微信小程序首期的真实数据库、微信宿主、资金和异常恢复验收。
4. 选定真实试点租户，完成从客户注册到订单关闭、退款/对账和运营善后的完整演练。
5. 再补后台日常经营切片和第二品类；预约网站、APP及储备功能不抢占首期试点。

## 4. 跨端依赖顺序

| 顺序 | 交付物 | 依赖/说明 |
| --- | --- | --- |
| 1 | 客户端渠道配置迁移与真库验收 | 所有对客端共用品牌、客服、协议、帮助及发布空间 |
| 2 | 配送区域、时段和费用规则 | 小程序、预约网站和 APP 的确认订单共同依赖 |
| 3 | 微信/支付宝、短信、对象存储真实沙箱 | 没有真实凭据只能完成代码，不能完成试点放行 |
| 4 | 微信小程序 MP-R1 组合验收 | 真实 AppID、合法域名、回调和真机环境齐备后执行 |
| 5 | PILOT-01 真实商户试点 | 依赖业务参数、币税/凭证口径和停止试点方案 |
| 6 | 员工履约小程序 STAFF-MP-R1 | 复用已验收的 Rental Core 履约服务，先完成员工身份、空间/地点范围，再做配货、交付、归还和现场事实记录 |
| 7 | 预约网站与 APP | 不复制会员、订单、计价、支付或文件内核 |

## 6. 文档与协作规则

- 业务规则以[多品类租赁平台需求说明](多品类租赁平台需求说明.md)为准；客户小程序细节以[客户端小程序需求说明](客户端小程序需求说明.md)为准；员工现场履约以[租户端小程序需求说明](租户端小程序需求说明.md)为准；接口以[客户端 API 接口说明](客户端API接口说明.md)、员工端专项契约和 OpenAPI 为准。
- 开发 AI 每次只更新自己负责的任务分册，不修改其他端任务，也不把开发对话粘进文档。
- 一项任务的交付报告只保留：任务 ID、提交、完成范围、验证证据、未运行内容、残留资源和未完成边界。
- 合并前默认只跑改动直接相关的专项、类型检查、契约和构建；全量测试由明确的阶段验收任务执行。
- 当前工作区存在未提交修改时，新的任务不得覆盖相同文件；先确认归属并收口现有改动。
