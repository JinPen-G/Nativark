## 1. 文档职责

本文件是当前开发任务的总入口，不再记录逐次提交、测试流水或已经完成的任务。各分册只允许出现以下状态：

- `In Progress`：已经开工，仍有代码、验收或外部环境工作未完成。
- `Pending`：已经进入规划，尚未开工或等待前置任务。
- `Blocked`：代码可继续空间有限，必须等待凭据、经营决策或第三方环境。
- `Reserved`：后续能力，未授权当前开发。

任务达到“规则明确、页面或接口可操作、持久化一致、权限和租户/空间边界正确、异常有出口、定向验证通过并经独立 Review”后，从分册移除并登记到[已完成任务归档](../历史归档/整理前快照-20261016/docs/归档/多品类租赁平台已完成任务归档.md)。不得在当前任务文档中保留 `Done` 行。

## 2. 当前交付方向

当前目标是把已经具备的后台经营能力，通过客户端和真实第三方平台形成可试点的业务闭环。开发顺序固定为：

1. 收口当前未提交改动并完成独立 Review，避免并发任务覆盖。
2. 完成客户端共用配置、真实支付、短信和文件存储沙箱验收。
3. 完成微信小程序首期的真实数据库、微信宿主、资金和异常恢复验收。
4. 选定真实试点租户，完成从客户注册到订单关闭、退款/对账和运营善后的完整演练。
5. 再补后台日常经营切片和第二品类；预约网站、APP及储备功能不抢占首期试点。

新增AI Native演进方向由[独立专项任务](<AI Native-开发任务.md>)按M1～M4推进：先受控助手底座与订单解释/开业诊断，再确认开单，随后履约辅助、有限自动化及多端接入。写入工具必须依赖已验证的业务入口；不改变原业务试点和生产放行门槛。预约网站仅接已有工程，独立APP仍为储备。Core阶段集成已合入main `12bac46`，AI Native在独立工作树由Codex单人开始AIN-01，未接入真实模型、未生产启用。

AI Native另见[专项需求](<../需求文档/AI Native-需求.md>)、[专项任务](<AI Native-开发任务.md>)和[专项实现与协作记录](<../开发协作与实施/AI Native/AI Native-开发记录.md>)。工具共享Rental Core，不复制订单、资金、权限或品类治理；业务未交付时保持不可执行。该专项只读/草稿可先行，真实模型、写入、宿主和灰度各自验收，不能用AI演示抵销以下依赖。

平台品类治理另见[专项需求](../需求文档/品类治理-需求.md)及[专项任务](品类治理-开发任务.md)。三个阶段必须完整交付，不能将四品类编辑页当作“后台新增品类”完成；尚未授权开始实施，不改变以下既有业务任务的状态。各端接入与 APP 契约预留在专项唯一维护，不因此启动 APP 工程或专业扩展。

| 顺序 | 交付物 | 依赖/说明 |

| 7 | 预约网站与 APP | 不复制会员、订单、计价、支付或文件内核 |

## 6. 文档与协作规则

- 业务规则以[多品类租赁平台需求说明](../需求文档/租赁平台-需求.md)为准；客户小程序细节以[客户端小程序需求说明](../需求文档/客户小程序-需求.md)为准；员工现场履约以[租户端小程序需求说明](../需求文档/员工小程序-需求.md)为准；接口以[客户端 API 接口说明](../接口文档/客户端-API说明.md)、员工端专项契约和 OpenAPI 为准。
- 开发 AI 每次只更新自己负责的任务分册，不修改其他端任务，也不把开发对话粘进文档。
- 一项任务的交付报告只保留：任务 ID、提交、完成范围、验证证据、未运行内容、残留资源和未完成边界。
- 合并前默认只跑改动直接相关的专项、类型检查、契约和构建；全量测试由明确的阶段验收任务执行。
- 当前工作区存在未提交修改时，新的任务不得覆盖相同文件；先确认归属并收口现有改动。
- AI Native多AI开发须按独立协作记录中央认领：工作者写已认领的独立切片，协调者唯一更新该专项主文档和进度；公共契约/迁移/路由等文件单一写入，不将工作树内自填认领当成全局锁。
