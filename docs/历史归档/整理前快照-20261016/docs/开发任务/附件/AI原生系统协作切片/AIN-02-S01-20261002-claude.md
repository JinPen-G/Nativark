## 2. 实现方法

### C01 身份与执行范围

- `AiExecutionScope` 用 `platform | tenant | workspace` 判别联合；workspace 必须同时带 tenant/workspace 标识，不提供默认空间回退。
- `AiExecutionContext` 明确 audience、actor 与服务端授权时间；SaaS 管理员只能使用 platform 分支，普通 operator/staff、client、future automation 使用不同 actor 形状。
- 复用现有 `AuthUser`/`SystemDataScope` 的数据范围语义，`selected` 空地点集合保持 deny-all，不转成 all。
- 类型与 JSON Schema 只描述形状，不授予权限、不证明资源归属、不代替 AIN-04 的 HTTP/Worker/每步重授权。模型请求草案不接收 tenantId、workspaceId、actor、audience、金额、SQL、URL、命令或审批字段。

### C02 工具与结果错误

- `AI_TOOL_CODES` 与现有 AIN-01 工具盘点代码集合对齐；草案工具固定 `contractStatus=draft`、`aiMaturity=unavailable`，不含 dispatcher/handler。
- 工具元数据显式记录 risk、audiences、scopeKinds、原权限候选、附加授权检查、能力/订阅前置、边界、脱敏、幂等、重试、结果核验和人工出口。
- `AiFactReference` 区分 current、snapshot、missing 和显式 `legacy_current_fallback`；缺历史依据不能伪装成当前规则或历史快照。
- 稳定错误码覆盖停用、供应商不可用、预算、工具不可用、范围变化、确认过期、提案陈旧、未知结果、输入/版本/权限/业务拒绝。未知业务结果固定 `retryable=false`、`nextAction=reconcile`，不得盲重放或宣称成功。

### OpenAPI 处理

- 只向 `OPENAPI_COMPONENT_SCHEMAS` 和 `OPENAPI_DOCUMENT.components.schemas` 并入草案 schema，未新增 `API_CONTRACT_OPERATIONS`、paths 或 Controller。
- 所有具体对象 `additionalProperties=false`；数组有界；判别联合和错误封套通过 `oneOf`/枚举表达。
- OpenAPI 内部引用保持 `#/components/schemas/...`。测试 harness 将其转换为 AJV 本地 schema ID，仅为离线验证，不改变发布文档。
