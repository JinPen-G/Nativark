# 主线给 Fork 执行线的持久接口答复（2026-10-05）

对应用户转发的“Fork执行线接口需求”，基线124f5e80；主Claude继续唯一维护schema，fork只在ai-native-fork-execution实现运行器/审批。本文不改变原AIN顺序或28项验收口径。

## 已提供的模型与内部合同

- `AiTaskExecutionBudget`：`scopeId/taskId`复合主键与任务外键；policyVersion/policyFingerprint，四类max限额、reserved占用、consumed实际消耗和revision。全用unsigned BigInt，转公开number前必须检查安全整数，不能先Number再比较。
- `AiTaskExecutionCharge`：`scopeId/taskId/chargeId`复合主键；原run、可选step/action/fingerprint、原holder/fence、requestFingerprint、resource、amount、actualAmount、status、outcomeFingerprint/evidenceRef、revision。与预算/task、run、step和可选Gateway调用有复合scope外键。资源只有steps/calls/active_ms/output_bytes，没有币种或金额字段。
- `AiGatewayInvocation`：一个已授权Gateway步骤的非财务关联，绑定scope/task/run/step/action/fingerprint、actor、callId、完整intentHash、配置/配置hash、priceVersion、输出上限、holder/fence/期限；唯一scope+callId与scope+stepId。它不是dispatch许可或第三套账，不存prompt正文/密钥。
- 新迁移：`20261005030000_ai_budget_configuration_binding`、`20261005040000_ai_gateway_invocation_binding`、`20261005050000_ai_task_execution_resources`。只追加表、列与索引，不回填旧任务额度或伪造历史配置。旧任务没有资源budget行就关闭该执行入口。
- 内部窄接口：`apps/api/src/modules/ai-native/task-execution-budget.ports.ts`；由fork消费，不复制到shared或私造HTTP DTO。方法为initialize/load/reserve/record/reconcile/markUnknown。

## Fork 实现 adapter 时的确定语义

1. `initialize(taskId,lease)`必须从可信场景PolicySource取限额，调用方不能传更大数字覆盖；同policyVersion/fingerprint重复初始化返回已有记录，改变政策冲突，恢复不重新初始化、不清零。缺合法policy返回AI_RESOURCE_UNAVAILABLE。max为0不是无限。
2. 所有写操作重新核对当前task owner/audience/scope、当前run holder/fence与合法状态；锁顺序固定task→run→execution budget→charge→必要的step/invocation，不能反向抢锁。
3. reserve在同一事务内比较 `reserved[resource]+consumed[resource]+amount <= max[resource]`、增加占用并创建charge；相同chargeId必须全绑定同指纹，只回放一次，不再加计数；不同payload冲突。chargeId由可信运行器生成并持久传递，不能拿requestId统一占位。
4. 普通`record`只结算reserved；unknown必须显式`reconcile`并重新查可信EvidenceSource。二者读取evidenceRef获取actualAmount，不接受外部任意数字“报销”。占用扣回与实际入账、charge终态/证据同事务；重复回执必须同结果指纹。
5. actual大于预留不能截断或抹除，照实记并阻止后续调用；unsigned列不能借负数退款。只有证据证明未执行才能记0，unknown/超时/TTL不是证明；本合同没有可任意调用的release。
6. `target.kind='run'`仅允许active_ms，用于尚未进入具体step的活动时间段；stepId/actionId/stepFingerprint全部为空。其他resource必须绑定已有step三字段、原run及其fingerprint，不能混搭。schema的可空列不代表这些组合可以自由省略，adapter必须验证。
7. `calls`表示模型实际调用尝试计数，必须关联`gatewayInvocationId`，校验同scope/task/run/step/action；不能以step数量推测模型重试数。只读/业务工具步骤计入steps，不能把业务重试盲算为新的模型调用。
8. `gatewayInvocationId`仅关联，不授派发；真正赢家仍是Gateway admission/dispatchToken。资源预留不是AIN-11货币预算，不从AiBudgetPolicy/Reservation/货币账再次扣费。
9. charge保存原始fence；只有明确的同task/同主体恢复授权可以用新lease核对旧charge，不能改写原fence掩盖旧owner，旧worker不得新建charge或提交迟到结果。
10. 活动时间不含等待用户输入/确认；每段活动在对应run/step保守预留，结束时记录真实计量证据。重启无法确认的占用保持unknown，不能直接用startedAt/endedAt差替代所有分段。

## Gateway 关联与 fork command factory

主线的 `PrismaGatewayInvocationBindings` 实现BudgetGatewayBindingSource，register只接受已经持久化、正在运行且匹配当前owner/lease的步骤。Gateway文本步骤的requestFingerprint使用现有 `prepareGatewayTextIntent(intent, policy, 'invoke'|'stream').intentHash`，不要自己重写canonical规则。

registration接收服务器选择的配置引用和priceVersion并完整绑定；这不证明价格已批准、权益已存在或能力已live验真。相应正式source仍由主线补齐，缺失不得dispatch。恢复读取预算关联可以使用原配置快照，不因随后轮换改写历史费用；新的reserve仍要当前profile/lease/intent一致。

新资源模型只提供可以实现的持久结构/端口，不是已经交付资源预算adapter、正式plan/result evidence或完整Gateway预算单账。fork可以实现adapter/事务/重启测试并列出其真实未接依赖，不要mock常量填全生产组合。

## 权限与结果引用：尚未交付，不伪造别名授权

现有`AiTaskRepositoryAuthority`只有read_metadata/read_events/claim_run/claim_recovery_run/release_run/transition_task声明，主线尚无覆盖全部任务动作的真实生产组合。

- `read_step_terminal`和`takeover_run`不得映射成“所有任务动作默认允许”。本次没有假造这两个动作的生产授权实现。
