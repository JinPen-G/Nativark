## 新的正式生产者

`integrations/inspection-object-reader.ts` 的 `TenantInspectionObjectReader` 实现 `open(reference, signal)`：

- 仅接受现有 FileAsset 精确引用，复核 tenant、订单 workspace、active 上传、completed 会话及 storageKey/provider。
- 从既有 TenantIntegrationService.runtimeConfig 取当前已验证 S3 配置，不从调用方接 endpoint/凭据。
- S3 SigV4 Header 鉴权，URL 不含签名/凭据查询参数；使用现有 outbound-url 策略，禁止重定向。
- MIME、Content-Length、流累计字节数绑定原资产；上限 20 MiB；对象读取/流读取 8 秒有界且响应取消。等待后再次核查资产、当前存储配置和订单归属。
- 只支持 `s3_compatible`。OSS/COS、local_mock 不伪装支持。鉴权和当前业务动作权限仍由现有消费者/Auth 完成，内部对象引用不是权限凭证。

`inspection-assist/inspection-object-reader.provider.ts` 导出 `createInspectionObjectReaderProvider(db, integrations)`，返回 `INSPECTION_OBJECT_READER` 的显式 provider。将它放在能向 FileStorageRuntimeService 提供该 token 的 opt-in 模块中；也可实例化后作为现有 FileStorageRuntimeService 第四参数注入。未修改生产根模块，不默认启用。
