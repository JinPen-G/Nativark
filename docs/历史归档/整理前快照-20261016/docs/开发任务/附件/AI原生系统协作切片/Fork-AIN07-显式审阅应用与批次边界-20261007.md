## 调用与审阅投影

```ts
const app = composeControlledApprovedOrder(serverDependencies);
const review = await app.approvals.readProposal(taskId, originalReference);
// 在独立的显式人类决定请求中消费共享契约；展示、聊天和报价选择不会调用它。
const record = await app.approvals.decide(taskId, humanDecisionRequest);
const receipt = await app.approvals.readReceipt(taskId, humanDecisionRequest);
```

- `originalReference`为现有共享`AiProposalDecisionRequestDraft`去掉decision，含contractVersion/proposalId/proposalRevision/reviewedPayloadHash；`humanDecisionRequest`严格消费现有共享契约，decision只取approve/reject。taskId为独立资源引用参数；请求携带生成文案、金额、actor、context都拒绝。
- `readProposal`返回原`proposal:AiProposalRecordDraft`、原`facts`、类型明确的`deterministic`及独立的`generatedText:null`。
- `deterministic.target`为原动作target；`quoteAmounts`逐项返回原报价rentalAmount/discountAmount/couponAmount/serviceAmount/fulfillmentAmount/depositAmount/preAuthAmount/payableAmount/receivableAmount；另带原currency、quoteExpiresAt、decisionExpiresAt。字段源于已校验的原PREVIEW，不用最新quote替换，也不把报价应收或批准事实当已收款/已交付。
- 新旧报价变化或新执行权益失效，不改写原审阅事实；当前读权限撤销仍拒绝读取。决定和Core执行各自重新验证自身权限/政策/期限。
- 人类决定返回收据后，真正的任务恢复仍由AIN06原受权状态机提供当前lease；随后调用`.waiting.execute(originalInput, signal)`。只有原持久approve会submit，收到unknown则调用`.waiting.reconcile/readInterrupted`，不得重新发一个action。

## 公共运输契约需求（主线所有）

固定shared已有`AiProposalDecisionRequestDraft`、`AiProposalRecordDraft`、`AiApprovalRecordDraft`，尚未冻结本应用完整展示与回执查询运输契约；本线不私造平行公共DTO。主线如接HTTP/客户端可据实际签名统一发布：

- 审阅请求：`Pick<AiProposalDecisionRequestDraft, 'contractVersion'|'proposalId'|'proposalRevision'|'reviewedPayloadHash'>`，taskId在受权资源路径。
- 决策回执查询请求：`AiProposalDecisionRequestDraft`原样，指定原decision以拒相反决定；响应`{kind:'recorded',record:AiApprovalRecordDraft}` / `{kind:'absent',retryable:false}` / `{kind:'unknown',retryable:false,nextAction:'read_decision_receipt'}`。
- 展示响应：原`AiProposalRecordDraft` + 原input/preview snapshot refs与payload + 上述deterministic报价投影，生成文案必须独立。运输响应如何裁剪客户/报价敏感字段，由主线公共契约与界面所有者统一确认；本片是服务器内部应用接口，不冒充公开API安全验收。
- 公共路由须绑定服务器当前session credential source；禁止把客户端actor/scope、展示hash本身或任意header拼装结果当作授权。正式路由及启动策略不在本片启用。
