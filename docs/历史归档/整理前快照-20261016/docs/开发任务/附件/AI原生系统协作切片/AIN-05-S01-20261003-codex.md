## 配置安全与持久化接续

- 保存密钥只走 SecretBox，不返回原文。生产 SecretBox 要求服务器已有加密密钥，测试使用合成密钥，不读 .env。
- Base URL 强制 HTTPS、禁止嵌入凭据/查询/片段及直接本机/私有地址；**此为字符串校验，不代表完整 SSRF 验收**。DNS 重绑定、所有解析地址检查、IP pinning/TLS hostname 校验和禁止重定向必须由接续安全 egress transport 实现。没有默认网络 transport，因此当前不能直接真实联网。
- 改 endpoint/protocol 不得静默保留旧 key；必须重新提供。改模型可保留同一目的地密钥，再加密并提升配置版本。
- repository 端口要求真实原子 compare-and-swap；此轮只有内存测试仓储，未提供数据库适配器，不能称持久化功能上线。
- authorize 端口必须接既有实时身份、租户、空间与操作权限；当前受控替身不证明完整 Guard/HTTP 链路。
- 预算 reserve/settle/reconcile/release 为必需端口，尚未接 AIN-11 持久化预算与核对流水。超时后不释放已发出请求的预留；适配器不响应 abort 时保留并发槽直到操作结束。
- 超时覆盖适配器调用阶段，授权、配置、凭据及预算等待尚无整条链路 deadline。并发是单进程租户协议维度，不是分布式限流。
- profile 与 credential 的版本核对拒绝配置修改后的旧引用；凭据取得后到 dispatch 的竞态/在途撤权、凭据删除、配置审计及事务接续仍需整链设计。
