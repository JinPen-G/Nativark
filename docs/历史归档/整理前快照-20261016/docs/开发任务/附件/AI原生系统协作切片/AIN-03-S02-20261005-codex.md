## 实际调用链

`createPersistedTenantModelConfiguration` → `TenantModelConfigService` → `PrismaTenantModelConfigRepository` → 本树真实生成的 `aiTenantModelConfiguration` delegate。

设置读取/管理：`TenantModelConfigurationAuthority` → 现有 `ApiAuthGuard` → `AuthService` 当前session/user/workspace与 `system:params:manage` 权限。调用身份复核：服务器绑定的 `AiCurrentScopeAuthority`（本批负例复用 `AiOrderRouteContextAuthority` 的实际Guard路径），不将配置管理权当作订单读取权或AI权益。

BYOK transport接线：`createScopeBoundTenantModelConnection` → 当前 `AiScopeRepository.resolveRoutingScopes` → 已有 `TenantModelConnectionResolver` → 上述已保存配置服务/加密凭据。核对当前actor、tenant、workspace、规范TENANT owner，以及configRevision/model/protocol/credentialRef；顺序复核不等于原子派发授权。没有新模型派发器，没有绕过Gateway。

## 持久化与双轨行为

- 新增 `AiTenantModelConfiguration`；追加迁移 `20261005010000_ai_tenant_model_configuration`，FK引用既有Tenant、主键tenantId、revision UnsignedInt、nullable settings JSON及加密TEXT。历史迁移未改。
- 缺记录默认展示Rental OS AI/not_verified，不落库、不激活、不免预算。首次写入由唯一主键解决竞争，后续写入tenantId+expectedRevision CAS；拒绝跨租户/非连续revision/溢出/未知字段/明文密钥。
- mode切换保留原BYOK密文；retain/replace/clear复用原配置服务。clear使enabled=false。重建服务从仓储恢复，不依赖生产Map。
- 明确检测旧 `system-rules.aiModel`。没有新记录但存在旧AI配置（包括masked/mock-success）时返回CREDENTIAL_UNAVAILABLE，保持旧内容不动，不将其当新租户或真实live证据。畸形旧JSON返回CONFIG_INVALID。
- 本批没有自动转换旧格式：旧格式缺真实密钥/加密绑定/可靠修订时不能推造。正式转换还需受权的旧数据来源核对及旧写入口冻结/版本协调；这里的legacy读取+新表首次写入不是两套配置的原子迁移。
- 新表尚未与ProviderProfile在同一事务同步revision；不一致会拒绝调用，不能声称统一配置来源已经完整装配。

## 装配合同与剩余

1. 宿主提供真实PrismaClient、服务端配置的SecretBox及 `TenantModelConfigurationAuthority.authorize.bind(authority)`，不传恒定成功授权。实例绑定当前credential source；invoke的当前资源authority须来自原合法业务入口。
2. Router使用真实AiScope规范owner，Profile/config修订和credentialRef必须一致，再将scope-bound resolver注入RoutedModelTransport的tenant端。平台端必须独立实现，不回退借用租户密钥。
3. 仍缺：平台凭据持久化/resolver、配置与Profile统一事务修订、受权旧配置转换、预算权益/价格/可信用量/调用关联的真实接线、Gateway单账生命周期与其他主体支持。
4. 不自动注册AppModule/Controller/Cron、不生产启用。配置授权不替代AI权益、预算或dispatch；UI保存不等于模型能力验证。
