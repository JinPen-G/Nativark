## 实际实现

新增 `runner/prisma-task-plan-policy.repository.ts`，复用已提交AiTaskPlanPolicy模型与真实Prisma类型，不加第二政策表或公共DTO。

- 只处理服务器构造时选定的sceneCode/sceneVersion，scope由实际AiScopeRepository解析；请求不能提供scope/scene/tool列表。
- 当前身份来自实际AiTaskCurrentIdentityAuthority→AuthService。管理复用TenantModelConfigurationAuthority→ApiAuthGuard的既有AI配置PUT权限 `system:params:manage`，仅operator/user/workspace；staff、client、automation、SaaS平台政策管理未开放。
- 这是已有AI配置管理权限下的workspace场景设置，不把任务owner/read权限当政策管理许可，不提供跨租户政策管理或任意工具启用。
- 必须显式给enabled；无记录返回not_configured，不seed、不upsert。允许的执行工具固定为上一片已接通catalog readonly版本，资源上限复用现有runner schema。
- 事务按canonical scope行→同场景政策行锁定。首次创建expectedRevision=null；更新精确scope/scene/version/revision条件CAS，修订由服务器递增；同事务复核当前Auth/Guard与到期时间，败方/撤权全回滚。
- 写回严格比较key/revision/enabled/limits/expiry，返回有限投影，不返回凭据/授权封套。
- COMMIT应答不明返回AI_RESULT_UNKNOWN、retryable:false、reconcile；已写记录可能存在，必须当前管理权限重读，不默认重新写或重新执行任务。
- 管理写不授予订阅、预算、任务动作或工具派发权限；禁用/修订变化由已有计划源拒绝旧证明。不注册Controller/AppModule/worker，未生产启用。
