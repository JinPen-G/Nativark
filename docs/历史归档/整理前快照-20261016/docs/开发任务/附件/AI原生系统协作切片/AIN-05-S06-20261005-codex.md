## 范围与基线

## 实际实现

- `TenantModelConfigService.setAllowedCapabilities` 是内部服务管理入口，复用当前 `manage` 授权；严格限定现有七种能力、唯一列表和 expectedRevision。不新增 shared DTO、HTTP 入口或默认能力证明。
- `PrismaTenantModelProfileRepository` 将白名单与配置、DEFAULT Profile 修订和凭据引用放在原有同一事务/CAS 中更新。复用规范租户 scope 和原配置 CAS。密文原样保留；platform_managed 下保留的 BYOK 不因白名单更新而启用。普通配置保存不清空白名单；显式空列表才清除。
- 平台配置保存支持同事务白名单更新；retain 仍要求相同目的地，密文按新修订重新绑定。没有字段则保留，显式空列表则清除。配置所属 Profile 仍禁止通用 Profile CAS 独立改写。
- 平台配置事务补上 vault 写入后的当前管理权限及主体/scope 绑定复核。等待期间撤权导致整个事务回滚。顺序复核不是原子派发授权，也不能消除事务提交后发生撤权的全部窗口。
- 能力白名单不等于模型能力验真。测试实际调用 `ProviderCapabilityService.preflight`，白名单允许但无证据仍拒绝。配置修订变化继续使用既有证据修订/指纹失效规则，不将 mock 当 live。

## 装配与剩余
