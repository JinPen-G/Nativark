## 原问题与修复

1. API此前解析根目录旧Prisma Client，缺品类治理及新增AI模型，导致全量API类型检查失败。
2. 最初临时node_modules链接导致Prisma想写共享 `.cache/prisma`；preload在写入前拒绝，未放宽防护。改为临时复制Prisma工具链，cache/home/temp全部限定自建临时目录，阻止网络及.env加载，禁自动安装。
3. 上轮当前Node环境中跨盘 `fs.cpSync` 返回但客户端目标为空，递归删除也残留目录；自建文件探针已复现。修复为逐文件复制和明确递归清理，必需文件/AI及Core委托声明校验，不再根据退出0判断成功。
4. 产物只装在本树 `apps/api/node_modules/@prisma/client`，带owner/schemaHash/generatorVersion/文件hash清单。未知客户端或他人修改拒绝覆盖；同schema完整产物返回no-op；锁避免同工具并发；不把根目录客户端改成本树版本。
5. 生成的runtime只读链接到已安装runtime，保持Prisma错误类identity，不产生本树与旧测试两个不同错误类。复制时先跳过runtime，再创建明确链接；清理不沿链接进入共享目录。
6. 生成前后检查已列出的共享client关键文件hash相同；防护覆盖Node层常用写入API与链接目标路径，不宣称完整OS安全沙箱。数据库没有连接或迁移。
