## 数据模型选择

- `AiScope`：platform/tenant/workspace判别，platform不填假tenant；tenant/workspace复合FK保持经营空间属于同一租户。length-prefixed scopeKey唯一，支持ID含分隔符而不碰撞；CHECK明确处理NULL，避免SQL UNKNOWN放行。既有Tenant/BusinessWorkspace只加Prisma反向关系，不改现有物理列或业务数据。
- `AiTask`：scope+scopeKind复合FK、audience/owner、自动主体政策修订/期限、contract/scene版本、trace、输入/结果引用、revision、取消及软归档。owner是审计引用，不是永续授权；用户删除/撤权后的动作仍须AIN-04拒绝。
- `AiRun`：任务内唯一run序号，实际principal与租约holder分开，actorKind通过FK与任务主体类型一致；授权时点只审计。精确Decimal(20,0) fencingToken、租约截止、网关路由引用及提示词版本，不存Base URL/密钥，不让Agent绑定模型。
- `AiStep`：scope/task/run复合关系；task内actionId唯一，run内sequence唯一，动作指纹不可被另一提案引用替换。状态与effect/error/result引用由CHECK配对，unknown保持待核对。
- `AiProposal` + `AiProposalVersion`：可CAS的head与版本payload分开。currentRevision通过复合FK指向本scope/task/proposal的真实版本；head未接好版本不能confirmed。版本payload只存C05严格metadata/ref，不含聊天或凭据。
- `AiProposalAction`：物化动作引用是为了数据库外键，不是第二份业务事实。引用同task下的step/action/fingerprint，并与proposal版本同事务写入；顺序唯一。
- `AiApproval`：绑定同scope/task/proposal/revision/hash，单actor单版本决定唯一；拒绝自动主体充当人工确认人。有效期仅存事实，当前有效权限和期限仍在应用提交点重验。
- `AiApprovalConsumption`：scope/task/action主键防止换approval重新消费；同时FK绑定批准版本与该版本真实动作/指纹。Core仍为业务幂等权威，业务键保留用于核对，不复制另一个Core去重规则。
- `AiTaskEvent`：每task独立cursor，**不使用全局自增数暴露其他租户活动间隙**。task.eventCursor与事件追加须同事务更新；复合主键去重。事件body只有C04最少payload/ref，读取必须重新授权。

全部新外键RESTRICT，不因删除聊天/任务而级联删除审批或业务事实。硬删除租户/空间若已有AI记录会被约束阻止；软冻结/停用不受影响。留存清理政策、实体删除顺序和合法人工善后仍需后续实现，不擅自默认永久保留或做清库。
