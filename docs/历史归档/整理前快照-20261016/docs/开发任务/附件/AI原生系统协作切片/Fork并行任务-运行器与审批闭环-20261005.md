## 四、阶段1：把现有运行器补成真正可恢复的任务链

### 已有基础，不另造状态机

`AiTaskRepository`已有claim/recovery/release与fencing；步骤注册/转换和任务迁移仓储已存在。`runner/ai-task-runner-outcome-adapter.ts`已能映射succeeded/failed/partial/waiting/cancelled，不能再当成尚无任务结果适配器。

静态看到以下待验证位置，先红测而非直接宣称缺陷成立：
- runner多处commitTaskOutcome后只取outcome返回，返回的新lease/taskRevision没有写回finally释放所用变量。
- 异常/cleanup失败存在早返回路径，可能未提交task-level结果。
- repository adapter的registration replay仍返回existingStatus:null，缺受权持久终态投影。
- maxConcurrent仅1，调用数/输出/活动时长主要按本次执行计数，恢复累计边界尚待验证。

### 必须完成

1. 修复终态commit→最新revision/fence→释放的完整链；空计划取消、部分成功、step成功/task失败、task成功/release应答丢失、异常/cleanup路径都必须保持真实状态。
2. 实现受权步骤终态读取，绑定scope/task/run/step/action/fingerprint。重启实例后replay已有成功只读事实、不再effect；未知只reconcile，无证据保持unknown/unavailable。
3. 接通任务级waiting_input/waiting_confirmation/waiting_external、cancel_requested/cancelled、恢复与人工接管。普通输入不等于批准，租约过期不等于外部未执行，取消不伪装业务回滚。
4. 旧worker在接管/lease过期后不能提交新步骤或迟到结果；每步重新检查当前身份、成员/地点范围、冻结、任务取消与正式执行政策。
5. 限额按任务累计，恢复不得重置步骤数/模型调用数/累计输出与主动运行时长；等待用户不占主动时间，核对有独立时限。缺持久字段尽早给主力最小需求，不能Map计数假装跨进程。
6. 先完成串行正确性；确有持久CAS支持时再实现有界只读并发，写同资源有序。不直接调高maxConcurrent或Promise.all后吞冲突。
7. 提供服务器固定计划/command factory/effect组合；Gateway effect只消费公共AiGatewayPortDraft，不能读取provider/model/密钥或绕预算。主线Gateway尚未齐备时显式缺依赖拒绝，测试替身不作为生产默认值。

## 五、阶段2：审批消费进入原 Core 建单事务

### 已有基础与真实事务位置

不可变提案、审批决策CAS及消费表已存在，但 `PrismaAiApprovalConsumptionRepository`目前自行开事务，`commit`接受resultRef，不代表与Core订单原子提交。

实际建单路径是 `RentalOrderConfirmationService.createOrder`（固定基线约134行，事务约224行起），已有客户资格、库存锁、报价/优惠消费、业务幂等和replay。不要新造订单服务，也不要误以为改通用RentalIdempotentActionService就覆盖了该路径。

### 必须完成

1. 绑定proposal/revision/payloadHash、actionId/requestFingerprint、actor/scope、期限与当前提案/审批状态；更改提案或撤销批准后旧确认失效。查询与replay也需当前访问权限。
2. 通过服务器内部的窄事务参与接口，把最终批准检查与消费接入Core现有建单事务，与订单、库存预占、报价消费、业务幂等共同提交/回滚；不能先消费审批再调用另一个独立事务。
3. 不向HTTP DTO/模型输入暴露回调、自由授权标记或可自造resultRef。普通人工createOrder保持现有行为，不强迫其走AI批准。
4. 处理事务外快速replay、事务内并发replay及唯一冲突赢家返回；不同action/指纹/人/空间不能复用批准。已授权同动作重试只返回真实已有事实，不再次建单。
5. Core仍决定金额、库存、报价版本、会员资格和状态；提交效果变化要求新提案，不自动修改已确认商品或金额。
6. COMMIT应答丢失/外部结果未知进入核对；UNKNOWN不能由调用方随便改成功，FAILED_NO_EFFECT必须有可信未执行/回滚证据。重试不重复通知、付款或订单。
7. 幂等记录过期但业务事实存在时先核对，不把过期当成可以再执行；当前无权限时不泄漏原业务结果。
