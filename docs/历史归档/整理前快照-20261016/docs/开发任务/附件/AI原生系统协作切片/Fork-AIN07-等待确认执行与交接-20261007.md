## 实际入口

`composeControlledApprovedOrder(dependencies).waiting`：

- `resolve(toolCode, toolVersion)`：仅 `rental.order.commit` / `AI_TOOL_DRAFT_VERSION` 返回 `{operation:'idempotent',execute}`，其余null。
- `execute(input, signal)`：input直接取现有`AiTaskRegisteredExecutor`方法参数类型，含原taskId/runId/stepId/actionId/inputRef/fingerprint/lease；clarifications不作为决定或订单变更凭据。
- `readWaiting(input)`：读取原步骤、原proposal action/version、原快照及当前人类收据，返回 missing 或 waiting_reference。后者含 binding、presented lease、原 proposal引用与 recorded/absent/unknown receipt。读取不会创建提案、审批、订单或任务事件。
- `reconcile(input)` / `readInterrupted(input)`：只有原持久批准才能进一步调用受控`reconcile`；无提案、无批准或无可核对订单均unknown，不推断未执行。不调用submit；recovery_only执行也只走这条路径。

## 结果与AIN06对接

- 返回终态复用现有registered executor结果形状 `{kind:'succeeded'|'failed'|'unknown',payload,errorCode?}`，仅加等待分支 `{kind:'paused',pause:'confirmation',payload}`。
- payload固定`version:'approved-order-wait-1'`，携带原`binding:{scopeId,taskId,runId,stepId,actionId,inputRef,fingerprint}`、`presentedLease`、`proposal:{contractVersion,proposalId,proposalRevision,reviewedPayloadHash}`（已持久化时）、`decisionRef/decision`（有实际收据时）及`effectState`。成功才带`businessResultRef`（真实受控reconcile/submit返回的order.id）和replayed。
- `presentedLease`是本次宿主呈交租约，不冒充提案中储存的租约。新准备/等待重入/实际submit各自校验当前执行资格与原fence；历史核对不重过旧lease expiry或输入执行资格。
- `effectState`：awaiting_decision、rejected、preparation_unknown、unresolved、committed。批准收据本身不是committed；订单、付款、交付、模型费用事实不得混为一步成功。
- **外部具体缺口**：固定runner的`AiTaskRegisteredExecutor.execute`和`PrismaTaskRunEvidenceRepository.capture`当前只接受succeeded/failed/unknown，不能直接注册新增paused结果。AIN06需接入该等待分支，重新读取`.waiting.readWaiting(input)`核对原引用，再用原`steps.pause(...,'confirmation',resultRef)`与原事件系统持久推进；计量artifactRef和businessResultRef显式关联。不得将paused映射succeeded、将普通payload当批准、或新建事件台账。本片没有改其接口/枚举/计量。
- waiting_reference证明待确认**提案**已持久化，不宣称task/step已转为等待态；真正WAITING_CONFIRMATION与人类决定后的RUNNING/lease恢复由AIN06原受权状态机完成，业务适配绝不偷偷开runner或写RUNNING。

## 单动作与取消

- 无原提案时，真实原输入读取→确定性原action提案ID→受控prepare；仅返回等待。prepare丢ACK时保留原proposalId核对，绝不自动批准/提交。
- 已有待确认提案时只复核原事实，不重新报价/换提案；明确人类拒绝返回failed，批准才走原submit。过期/政策变更/旧fence等保持原授权错误，要求停止或重新准备，不能自动更换业务键。
- 等待中取消/批准后取消禁止新Core效果。已可能提交后的取消只核对原action；COMMITTED在当前读权限下返回历史订单，即使任务取消、输入过期、预算开关失效。订单结果暂缺仍unknown，不重建。
- 原task/step/事件/计量artifact由宿主拥有，执行器不修改它们；原登记已存在的事件必须保留。
