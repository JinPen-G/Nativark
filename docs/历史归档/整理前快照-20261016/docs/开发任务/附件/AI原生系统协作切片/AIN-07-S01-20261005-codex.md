# AIN-07-S01｜持久化审批动作消费边界

## 交付

- 新增 `approval-consumption.ports.ts` 与 `approval-consumption.service.ts`：审批动作按 `scope/task/action` 绑定，先经过外部当前授权适配，再进入持久化预留；服务只记录动作消费，不执行 Core 业务。
- 新增 `prisma-approval-consumption.repository.ts`：复用已存在的 `ai_proposals`、`ai_proposal_versions`、`ai_proposal_actions`、`ai_approvals`、`ai_approval_consumptions` 表，在 Serializable 事务中校验当前 proposal revision、确认状态、approval 过期、payload hash、action fingerprint，并用唯一主键实现单次预留。
- `committed` 只能从 `reserved` 进入，重复同载荷幂等；`unknown` 保持粘性，禁止普通 commit/retry 伪造完成；`failed_no_effect` 也只能从 reserved 进入。

## 验证

命令：`node --test tests/ai-native-ain07-approval-consumption.test.cjs`，结果：3/3 通过，退出码 0。

测试驱动实际 `AiApprovalConsumptionService`，仓储部分使用受控持久化替身验证唯一消费和状态转换；尚未连接真实数据库，因此不代表 MySQL 事务/锁验收。

## 未验与交接

- `authorize` 必须由主线接入真实当前身份、scope、proposal/action 归属与业务动作权限；缺适配时服务拒绝。
- `commit` 的 `resultRef` 必须在同一个 Core 业务幂等事务中产生；本切片不创建订单、不调用工具、不授予模型或 automation 审批权限。
- `unknown` 只能由主线依据 dispatch/外部结果核对后处理；本切片不提供自动释放或重派。
- Prisma 真库并发、提交应答丢失、Core 业务消费与 HTTP/模型/设备验收未运行。
- 作者自测完成，尚无独立复核，不宣布 AIN-07 或 AIN 专项完成。
