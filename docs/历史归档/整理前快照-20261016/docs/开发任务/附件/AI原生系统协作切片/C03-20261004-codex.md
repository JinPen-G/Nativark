## 已修复的代码问题

1. `budget-quantity.ts` 在写入前对数量做数据库列宽校验：calls 不超过 Prisma `UNSIGNED INT` 最大值，tokens 不超过 `UNSIGNED BIGINT`，非法值不进入 repository。
2. `prisma-budget.repository.ts` 的 money formatter 改为 BigInt 微单位到十进制字符串转换，全程不经过 `Number(atoms)`；reservation、actual、ledger、回读和幂等比较均沿用同一精确路径。
3. 锁策略顺序补齐 `scopeKind → scopeId → sceneCode`。每一行 `FOR UPDATE` 后重新读取策略，禁止用锁前快照继续判断 gate/allowlist/额度。
4. 每个 policy key 通过 `AiScope` 持久化归属校验，与当前 association 的租户/空间对应；空、重复、跨租户、跨场景和缺 consumer policy 均拒绝。
5. 预算读取/结算链补齐 request/run/step/action、call、actor、scope、configRevision、priceVersion 关联检查；证据 adapter 对另一 actor、另一 scope、另一调用直接拒绝。
6. 活动 reservation/pending 用于并发与单 run 计数；已结算 reservation 按实际 tokens/calls/money 计入后续预算，超额实耗不会回收或截断。
7. `budget-gateway-contract.ts` 只定义 Gateway→预算的结果映射和证据门禁，不拥有供应商派发权。unknown 只能保留待核对；普通失败只有持久化证据明确未派发才能 release；completed/reconciled 必须有 dispatch token 和 usage ref。

## Gateway 精确接入合同

- Gateway 取得真实 authority、可信 quote 后调用 `reserve`；成功只表示预算占用，不表示可派发。
- Gateway 取得自身 `AiInvocationAdmission.dispatchId`/dispatch token 后调用预算 `dispatch` 标记；该标记不能授权供应商派发，也不能替代 admission CAS。
- provider 已完成且有同一 reservation/call/actor/scope/config/price 关联的持久 usage evidence 时调用 `settle`。
- provider 明确未调用，且持久 evidence 明确 `not_dispatched` 时才允许 `release`。
- provider 超时、COMMIT 应答丢失、usage 缺失或证据不明调用 `markUnknown`，保留占用，不自动 retry/release；获得新的授权与可信 usage 后调用 `reconcile`。
- 每个 invocation 只使用一套预算账本；旧 usage 不能另建新 budget 记录重复结算。
- 缺 authority、正式 entitlement、quote、dispatch/usage evidence 任一依赖时 fail closed/unavailable；预算模块不注册 AppModule，不新增供应商派发器。
