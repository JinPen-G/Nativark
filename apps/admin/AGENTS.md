# Admin UI component conventions

- Use React. Do not introduce Vue or a second admin UI framework.
- Existing and new page-level buttons, plain inputs, tabs, segmented controls, menus, tooltips and compatible drawers import from `@/components/ui`.
- Date/time/color fields, document editors, uploads, pagination, tables, alerts, steps and progress also use the adapter entry. Keep explicit compatibility fallbacks; never replace business table/transport semantics with a visual-only demo.
- Rich documents use the shared safe-node codec, not raw HTML. Keep all consuming client readers in sync, preserve plain-text documents, and validate the existing API character limit before saving.
- Original public UIArc source and its motion/themes are reserved in `packages/ui-arc/vendor`; consult its README and manifest before adding another component.
- Consult `packages/ui-arc/COMPONENTS.md` and run `node scripts/audit-admin-components.cjs --json` for current source/import/hash inventory. Basic multiple selects and standalone checkboxes use adapters; slider uses the native Arc API. Distinguish downloaded, referenced and compatibility-fallback status.
- Do not edit vendor styles or motion to recreate an approximation. Integration, tenant colors/radii, locale, permissions and sound belong to adapters/tokens. Admin defaults follow the UIArc screen roles: containers 12px, buttons/inputs 8px; configurable integer bounds are containers 4–20px and buttons/inputs 4–16px. Use the shared appearance contract for UI, DTO and service validation. Large legacy values render within these bounds without rewriting stored preferences; only explicit saves persist changes, preserving omitted fields, null semantics and expectedRevision. Keep avatars, round icon targets and switches in their native shapes.
- List-query widths come from the shared toolbar/filter adapters. Search/date/explicit-width fields use `ADMIN_LIST_CONTROL_WIDTH`; ordinary list selectors start compact and adapt to the selected label within `ADMIN_LIST_METRICS` bounds, as requested by the owner. `ListFilterItem width="selectWide"` retains an explicit role. Keep measurement and transitions in ListFilterBar, with shared reduced-motion support; do not add page-local pixel widths. New/edit forms retain their grid sizing and `ADMIN_CONTROL_WIDTH` baselines.
- List hierarchy uses `ADMIN_CONTENT_TONES`, `ADMIN_LIST_TYPOGRAPHY` and `ADMIN_TABLE_METRICS` from designTokens.ts. Primary facts use neutral foreground, metadata uses secondary ink, separators use subtle borders; keep semantic warnings distinct. Summaries belong in PageHeader.summary as a single 13px line, never tall metric cards. Use DataTableText for primary/secondary facts and CustomerPreview presentation="list" for two-line identities. Ordinary rows start at 52px with 8px block padding and 18px/17px text lines; let long content grow. Keep 32px interactive targets without allocating that height to plain primary text. Do not repeat rows in decorative timelines or add sidebars without decision-relevant content.
- Shared Table pins action columns on the right unless the caller explicitly supplies another pinning choice, including grouped fallback columns. Narrow screens retain right-side actions while leading identity columns may scroll. Never globally disable all pinning at a mobile breakpoint.
- Lists default to the order list's content-responsive widths: compact controls/scalars/actions, flexible names/descriptions, shared space-2 cell padding and space-4 ordinary outer edges. Action cells use symmetric space-1 gutters, equal-width primary actions within each table and right-aligned overflow menus; preserve native click targets and use concise labels without artificial Chinese spaces or slash-joined actions. Honor explicit minWidth; legacy width/scroll.x totals must not force empty space. Multiple pinned columns use measured layout widths, including column visibility/font/image changes; loading placeholders align to those same widths. Precise fixed forms may explicitly opt out with tableLayout="fixed"; do not reintroduce per-page sizing rules for ordinary lists.
- PageHeader owns the 8px gap to the first view/content; tabs and table toolbars use their shared 8px spacing roles. Full-width page stacks use block/flex flow, not inline baseline layout. One container owns each gap: never add a standalone toolbar margin inside a vertical Space gap. Count the original tab track padding/frame in its 36px total height; preserve vendor motion. Actual forms, required notices and distinct sections may occupy space, but never reserve an empty subtitle or spacer row.
- The shared breadcrumb/context header is 48px in expanded and collapsed sidebar modes; the compact tenant identity row has its separate ADMIN_SHELL_METRICS geometry. ADMIN_LAYOUT_SPACING owns pageTop=0 and contextOpticalInset=space-1 (4px inside that fixed height). Measure optical gaps from the content-panel inner top to breadcrumb ink and title ink. Page titles use ADMIN_TYPOGRAPHY.pageTitle (18px/26px/500) in the shared action row; do not add private offsets. Inline CustomerPreview capsules keep the original leading avatar; list identities use the unframed avatar and two-line presentation.
- Business Tabs use text labels without decorative icons; retain the dedicated icon-only view switch. Page-title icons are 22px and sidebar icons 18px. Use the original Animate UI Hugeicons via AnimatedIcon; overview/report must remain distinct. Respect the shared System/Full/Reduced preference and preserve source manifests/license.
- AI Operator at /ai-operator reuses the user-supplied local archive AI chat/agent-run/shared under features/ai-operator/archive; preserve SOURCE.md, baseline hashes, licenses and original styles. Do not label this reconstructed archive as official Pro React source. Chat uses original history/edit/retry/version/stream/tool/source behavior, a two-level composer with model selection inside, and a recent/new-chat top bar. Agent run renders local resource/tool steps only, then the existing typed ArtifactView. All examples remain frontend-only; callbacks, models, upload, persistence and real business execution require separate integration. Scope state by authenticated tenant/workspace; inherit existing capability visibility. Each capability owns multiple conversations bound to an immutable capabilityId; history and all new-chat entries stay within that capability, and switching capabilities restores its last selected conversation. Keep messages/artifacts/receipts separate per conversation. Frontend scoping is not server authorization or a tool allowlist. Bind theme/radius and the shared live motion preference in adapters; keep reserved vendor immutable.
- `ListSection` defaults to automatic heading placement: a pure single table (including a ready QueryState wrapper) shares its name/actions with filters/tools. Do not require page-by-page opt-in. Composite summaries, forms, warnings, multiple tables and empty/error branches keep a standalone section name; explicit `above`/`toolbar` remain available. Never duplicate headings/actions or pass the parent name into expanded child tables.
- `Tabs` switches content views and stays above the query row, visible at every width. Same-list classification uses `Segmented` in list controls and may enter More filters. Do not treat changes of data schema, forms or configuration sections as query conditions; the shared toolbar separates accidentally supplied Tabs from query controls. Both adapters use `ADMIN_CHOICE_STYLE` neutral text states; never add per-page tab colors, selected font weights or accent ink.
- Order details put status/customer, current pickup/return facts, server funding summary and stage actions first. Group fulfillment, charges/payments, inspections and history/documents into task views; keep pending work discoverable. Use `ADMIN_DETAIL_LAYOUT`, frameless groups and existing table tools. Separate rental, deposit and preauthorization ledgers; missing/failed/restricted reads are not zero. Sort a copied event list by occurrence time, preserve ties and all original query/mutation/modal guards.
- Long-lived customer/company records, reconciliation batches and price comparisons use registered detail routes with `RecordDetailLayout`/`RecordFacts`; short edits, decisions and contextual previews keep their overlays. Summarize identity/state first, group by task, open editors deliberately, and reset editing state when the route object changes. Inherit parent route permissions and menu selection; never treat missing credit configuration as zero funds or a failed read.
- Preserve AntD Form validation, disabled context, nullable values, ref behavior, async failures and keyboard access. Fall back explicitly if a registry component lacks an existing business capability.
- Destructive inline actions use ConfirmAction and await the real API promise. Never invent Undo or display success before the request completes.
- Saves use SaveButton (validateFields + mutateAsync); other promise-returning commands use ActionButton. Preserve all existing payload transforms and domain checks. Never pass fire-and-forget mutate(), form.submit(), swallowed failures or timers as an operation promise.
- Import reserved components individually. Do not bundle the whole catalog or install malformed/unreviewed dependency entries.
- Pro source is not present and requires authorization/license before use.
- Optional list tools use `Table` exportConfig/importConfig/cardView/batchActions and the shared list capability adapters. Declare public export fields; distinguish filtered complete data from a server page. `ListTransferTools.loadExportRows` obtains the complete applied filter/sort result before download; it must retain the original session scope, stop at identity changes, and reject failed reads without downloading partial rows. Selection export still uses only selected rows. Imports require templates, preview, create-only duplicate handling and per-row outcomes. Personal imports stay unavailable until the server advertises supportsOnlyNewImport; never send them to a legacy registration endpoint that may activate an existing member.
- Layout switching uses the icon-only Segmented at the far right of table tools. Preserve query/sort/page/selection state and vendor slider motion; center icons in their actual button boxes. Bulk actions appear only after selection, use original guarded commands, and stop on unknown outcomes without automatic retries.
- Browsable record cards use the original UIArc Card with its native content padding and quick-look motion. Title/metric scale follows ADMIN_RECORD_CARD_METRICS. Keep summaries compact; no decorative header bands or fixed tall cards. Use shared grid/media metrics: product packshots use object-fit: contain in a 190px media slot so equipment is not cropped; the frame remains full width. Full read-only content lives in desktop quick-look or mobile BottomSheet, and original commands start only after the preview has exited. Selection stays separate from preview activation.
- Inside record cards and their previews, import original UIArc Button and Checkbox directly. Preserve native variants, hit areas and motion; do not add opaque selection backplates or propagate a featured-card border token to the nested controls.
- Record selection belongs beside the title's first line, including photo cards; never overlay the media or duplicate selection inside the quick look. Keep the native morph shell clipped and scroll its inner content with a themed thin scrollbar. Plan cards show real level/benefits, catalog cards omit unfilled specs, and commercial cards group rate/eligibility/coverage facts; do not fabricate fees, counts or active benefits.
- Customer references with stable master IDs use shared CustomerPreview and the original HoverCard/HoverCardProfile layout. Preserve the native 26px portal radius, shadow and motion; fetch masked current facts only after opening, under the original customer-read guard. Scope and reset preview caches by session/permission/data range, project safe fields only, and keep historical row snapshots unchanged. Optional standalone record context uses original ExpandableCard through RecordDisclosure; keep required actions, money and risks visible. Validate in the actual signed-in admin browser; do not substitute a new demonstration page for page inspection.
- Common navigation, title and action icons use Lucide through `components/ui/icons.tsx` (legacy names are compatibility exports). Brand marks retain their original assets. Icon geometry follows `ADMIN_ICON_METRICS`; do not mix in new Ant UI symbols or icon fonts.
- Interactive transfer/refresh icons may use original Animate UI Lucide variants through `AnimatedIcon`. Keep pinned sources/license and shared motion preferences. The application sidebar is the native Animate UI Base UI example in `components/animate-sidebar`: 240px expanded, 48px icons, original mobile Sheet sizing. Use ADMIN_SIDEBAR_METRICS for 32px Chinese rows, 2px gaps, 24px group labels and 18px icons. Preserve source classes, Hugeicons, collapse trigger and NavUser popup dimensions/motion; keep logo search and permission-filtered real routes. In both the tenant Admin Console and Agent workspace, the outer frame fills the browser with square corners and no outer padding, border or shadow; the desktop workspace keeps its shared radius and 8px top/right/bottom inset. ADMIN_SHELL_METRICS owns the compact 40px top row, 36px identity control, 22px mark and 32px collapse button on its right. Keep the tenant name visible at 13px above the 12px workspace name; truncate each separately while exposing both full names. The collapsed rail keeps separate workspace and restore targets; mobile retains a header opener. Preserve the existing mobile full-width layout and SaaS frame. Both tenant modes share the rest entry and already-started break within the original account/tenant/workspace shell; identity changes still release media. sidebar-adapter.css binds menu/button, field and popup radii to the existing button/input/container tokens, and shares one theme-aware surface behind the sidebar and workspace corners. Do not restore the old 80px icon/label rail or edge circle unless requested. Default account avatar uses the preserved example asset; tenant/customer identities remain independent. Route selection glides with the original Animate UI controlled Highlight in parent mode, using the fixed UIArc Metrics Dashboard neutral palette in both tenant modes; account accent continues to style business actions and the unchanged SaaS shell. Match its theme-specific sidebar/background, content-panel, menu/icon and hover/selected colors. Hover cannot change the selected route background. Keep animateOnHover=false on the Sidebar provider and hover/click=false on the controlled Highlight; actual permitted route state is the sole owner. Measure the visible trigger row, never a list item containing an entering/exiting submenu. In the collapsed rail the target stays the 32px icon button while the outer column changes width. Closing the active group or collapsing the rail moves selection to its parent; unmatched search hides the highlight. In the collapsed rail, business groups open the native right-side DropdownMenu instead of expanding the sidebar. Use the shared submenu minimum width and 32px rows; route choice closes the popup and retains the 48px rail. Center all 18px navigation icons in their 32px buttons, with no invisible label width or trailing arrow space. Preserve collapse and overlay motion and the shared reduced-motion setting. Sidebar commands use the global sound preference gate, with page/press semantics and one sound for trusted snapshot click replay.
- Motion preferences are browser-local System/Full/Reduced settings on Appearance. Read effective policy through `motionPreferences`/`usePrefersReducedMotion`, never a separate media query. The Vite dependency/CSS adapter routes reserved components through that same policy without editing their sources or variants; preserve all upstream Motion exports. A preference change must not remount business forms, reset data or leave navigation snapshots/inert active.
- Status ink/surface pairs use `ADMIN_STATUS_COLORS` independently of tenant brand colors in both themes; maintain 4.5:1 text contrast. Main status uses one badge; subordinate progress/reminders use secondary text and a meaningful static icon, preserving necessary risks and pending work.
- Meaningful UI changes require continuous feedback. WorkspaceNavigation owns route entrances: sidebar links use ADMIN_NAVIGATION_MOTION stack snapshots; details/back/ordinary navigation use the short Animate UI fade after WorkspaceRouteReady commits. Keep header/sidebar still and one live route; legacy PageEnter is suppressed inside this owner. Preserve Suspense/auth boundaries and release snapshots/inert on interruption.
- Use stable ContentTransition for list/card and loading/error/ready changes. External Tabs whose content lives outside the native panel pass a transitionKey or wrap that content; native UIArc Tabs, cards, overlays and Motiq retain their own motion. Fade uses Animate UI's 200ms token and ADMIN_CONTENT_MOTION; parent/stack motion suppresses duplicate fades. Do not animate each keystroke, re-key forms or retain two business trees. Batch bars reuse the supplied local UIArc SelectionToolbar in components/selection-toolbar, preserve its native CSS and motion, become inert on exit and unmount after completion. Its adapter owns theme/radius tokens, localization, disabled states, host height and focus restoration; do not reintroduce the old Slide shell or Ant buttons. Import/confirmation dialogs likewise retain their original close lifecycle. Effective reduced-motion skips added movement/fades without losing state.

- Reused archive components keep their original functions, interaction and motion. Adapt business data/callbacks, locale and shared theme tokens. Add business extensions only when explicitly authorized, using separate slots rather than replacing the supplied behavior.
