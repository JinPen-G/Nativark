# Admin UI component conventions

- Use React. Do not introduce Vue or a second admin UI framework.
- Existing and new page-level buttons, plain inputs, tabs, segmented controls, menus, tooltips and compatible drawers import from `@/components/ui`.
- Date/time/color fields, document editors, uploads, pagination, tables, alerts, steps and progress also use the adapter entry. Keep explicit compatibility fallbacks; never replace business table/transport semantics with a visual-only demo.
- Rich documents use the shared safe-node codec, not raw HTML. Keep all consuming client readers in sync, preserve plain-text documents, and validate the existing API character limit before saving.
- Original public UIArc source and its motion/themes are reserved in `packages/ui-arc/vendor`; consult its README and manifest before adding another component.
- Consult `packages/ui-arc/COMPONENTS.md` and run `node scripts/audit-admin-components.cjs --json` for current source/import/hash inventory. Basic multiple selects and standalone checkboxes use adapters; slider uses the native Arc API. Distinguish downloaded, referenced and compatibility-fallback status.
- Do not edit vendor styles or motion to recreate an approximation. Integration, tenant colors/radii, locale, permissions and sound belong to adapters/tokens.
- List-query widths come from `ADMIN_LIST_CONTROL_WIDTH` through the shared toolbar/filter adapters. Use role widths for search, select and dates; declare longer selectors with `ListFilterItem width="selectWide"`. Do not add page-local pixel widths or resize fields to their selected text. New/edit forms retain their grid sizing and `ADMIN_CONTROL_WIDTH` baselines.
- Shared Table pins action columns on the right unless the caller explicitly supplies another pinning choice, including grouped fallback columns. Narrow screens retain right-side actions while leading identity columns may scroll. Never globally disable all pinning at a mobile breakpoint.
- PageHeader owns the 8px gap to the first view/content; tabs and table toolbars use their shared 8px spacing roles. Full-width page stacks use block/flex flow, not inline baseline layout. One container owns each gap: never add a standalone toolbar margin inside a vertical Space gap. Count the original tab track padding/frame in its 36px total height; preserve vendor motion. Actual forms, required notices and distinct sections may occupy space, but never reserve an empty subtitle or spacer row.
- `ListSection` defaults to automatic heading placement: a pure single table (including a ready QueryState wrapper) shares its name/actions with filters/tools. Do not require page-by-page opt-in. Composite summaries, forms, warnings, multiple tables and empty/error branches keep a standalone section name; explicit `above`/`toolbar` remain available. Never duplicate headings/actions or pass the parent name into expanded child tables.
- `Tabs` switches content views and stays above the query row, visible at every width. Same-list classification uses `Segmented` in list controls and may enter More filters. Do not treat changes of data schema, forms or configuration sections as query conditions; the shared toolbar separates accidentally supplied Tabs from query controls. Both adapters use `ADMIN_CHOICE_STYLE` neutral text states; never add per-page tab colors, selected font weights or accent ink.
- Order details put status/customer, current pickup/return facts, server funding summary and stage actions first. Group fulfillment, charges/payments, inspections and history/documents into task views; keep pending work discoverable. Use `ADMIN_DETAIL_LAYOUT`, frameless groups and existing table tools. Separate rental, deposit and preauthorization ledgers; missing/failed/restricted reads are not zero. Sort a copied event list by occurrence time, preserve ties and all original query/mutation/modal guards.
- Long-lived customer/company records, reconciliation batches and price comparisons use registered detail routes with `RecordDetailLayout`/`RecordFacts`; short edits, decisions and contextual previews keep their overlays. Summarize identity/state first, group by task, open editors deliberately, and reset editing state when the route object changes. Inherit parent route permissions and menu selection; never treat missing credit configuration as zero funds or a failed read.
- Preserve AntD Form validation, disabled context, nullable values, ref behavior, async failures and keyboard access. Fall back explicitly if a registry component lacks an existing business capability.
- Destructive inline actions use ConfirmAction and await the real API promise. Never invent Undo or display success before the request completes.
- Saves use SaveButton (validateFields + mutateAsync); other promise-returning commands use ActionButton. Preserve all existing payload transforms and domain checks. Never pass fire-and-forget mutate(), form.submit(), swallowed failures or timers as an operation promise.
- Import reserved components individually. Do not bundle the whole catalog or install malformed/unreviewed dependency entries.
- Pro source is not present and requires authorization/license before use.
- Optional list tools use `Table` exportConfig/importConfig/cardView/batchActions and the shared list capability adapters. Declare public export fields; distinguish filtered complete data from a server page. Imports require templates, preview, create-only duplicate handling and per-row outcomes. Personal imports stay unavailable until the server advertises supportsOnlyNewImport; never send them to a legacy registration endpoint that may activate an existing member.
- Layout switching uses the icon-only Segmented at the far right of table tools. Preserve query/sort/page/selection state and vendor slider motion; center icons in their actual button boxes. Bulk actions appear only after selection, use original guarded commands, and stop on unknown outcomes without automatic retries.
- Browsable record cards use the original UIArc Card with its native content padding, title scale and quick-look motion. Keep summaries compact; no decorative header bands or fixed tall cards. Use shared grid/media metrics; photos fill the media edge to edge with object-fit: cover. Full read-only content lives in desktop quick-look or mobile BottomSheet, and original commands start only after the preview has exited. Selection stays separate from preview activation.
- Inside record cards and their previews, import original UIArc Button and Checkbox directly. Preserve native variants, hit areas and motion; do not add opaque selection backplates or propagate a featured-card border token to the nested controls.
- Record selection belongs beside the title's first line, including photo cards; never overlay the media or duplicate selection inside the quick look. Keep the native morph shell clipped and scroll its inner content with a themed thin scrollbar. Plan cards show real level/benefits, catalog cards omit unfilled specs, and commercial cards group rate/eligibility/coverage facts; do not fabricate fees, counts or active benefits.
- Customer references with stable master IDs use shared CustomerPreview and the original HoverCard/HoverCardProfile layout. Preserve the native 26px portal radius, shadow and motion; fetch masked current facts only after opening, under the original customer-read guard. Scope and reset preview caches by session/permission/data range, project safe fields only, and keep historical row snapshots unchanged. Optional standalone record context uses original ExpandableCard through RecordDisclosure; keep required actions, money and risks visible. Validate in the actual signed-in admin browser; do not substitute a new demonstration page for page inspection.
- Common navigation, title and action icons use Lucide through `components/ui/icons.tsx` (legacy names are compatibility exports). Brand marks retain their original assets. Icon geometry follows `ADMIN_ICON_METRICS`; do not mix in new Ant UI symbols or icon fonts.
- Interactive navigation/transfer/refresh icons may use original Animate UI Lucide variants through `AnimatedIcon`. Preserve pinned sources, hashes and license; one-shot hover/focus, busy-only refresh loops and reduced-motion static fallback. Keep status/risk icons static. Sidebar dimensions use `ADMIN_SIDEBAR_METRICS`; compact navigation retains group labels beneath icons and the original submenu engine. Short display aliases never alter route permissions or category terminology facts.
- Status ink/surface pairs use `ADMIN_STATUS_COLORS` independently of tenant brand colors in both themes; maintain 4.5:1 text contrast. Main status uses one badge; subordinate progress/reminders use secondary text and a meaningful static icon, preserving necessary risks and pending work.
- Sidebar route changes alone use WorkspaceNavigation's stack snapshots and ADMIN_NAVIGATION_MOTION; keep the header/sidebar still and one live route. PageEnter skips its fade during stack navigation. Tabs, filters, paging and detail links keep their current motion; reduced-motion/unsupported/overlay cases navigate directly. Preserve the original Suspense and auth boundaries, release inert/snapshots on interruption, and never mount duplicate business pages for an exit animation.
