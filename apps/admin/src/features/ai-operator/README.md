## 能力与会话归属

- 左侧每一项是固定业务范围的 Agent 能力，不是一条对话。一个能力可创建多条独立工作对话。
- 顶部历史菜单与侧栏的「当前能力的对话」只显示当前能力的记录；顶部、菜单和左侧「新对话」均在当前能力内创建。
- 每条会话固定绑定创建时的 capabilityId。消息、编辑版本、附件、运行状态、工作成果与回执按会话独立保存；切换能力恢复该能力上次选中的会话，不转移或复用其他能力的上下文。
- 自动化手动演示按任务配置的能力创建新会话。历史选择和本地 responder 校验会话归属；不会通过选择另一能力的历史来改变当前能力。
- 以上是前端演示边界，不是服务端权限控制。真实接入时须由后端校验租户、空间、能力、会话及工具允许范围；不能仅靠前端筛选或提示词限制。

## 服务端原记录入口

工作中心的「服务端对话」切换与Copilot的同名入口共用[受权对话宿主](../ai-native/ServerConversationPanel.tsx)。工作中心提供完整宽度的原对话列表、生命周期、受理、任务创建与结果入口；Copilot所选对话可经固定导航在工作中心继续，沿同一原对话引用重新读取，不复制上下文、创建第二任务或重发原动作。切换只停止本地演示，不取消已受理业务任务。

[导航定位](../ai-native/conversation-navigation.ts)仅接受当前账号/租户/空间和会话纪元、正式版本及登记能力；不接受任意URL或额外字段，也不授读/执行权限。转接后仍需显式读取原轮次。重开后保留输入、已关联原Task/Run的订单轮次可读取原执行准备；明确首次启动与未知结果核对仍由原执行服务控制，清理输入及创建关闭不能恢复执行。

报价原Task的[补充信息](../ai-native/TaskClarification.tsx)仅把核实过的原回答引用交给[Core报价确认](../ai-native/ConversationQuoteConfirmation.tsx)。[确认会话](../ai-native/conversation-quote-confirmation-session.ts)经原模型报价Controller重新读取当前准备，展示正式客户/商品/租期/履约条件，明确确认后请求Core保存报价；确认前条件或当前版本变化则重新核对。金额、分项和版本直接取原Core报价，不以模型文本或候选名称补造。浏览器仅保留原引用和核对指纹；发送后未知或重开只经同原回答读取原报价操作，不重提交回答、调用模型或创建第二报价。订单批准仍走原任务独立批准链。

原任务中心的[规则业务草稿](../ai-native/TaskRuleDraft.tsx)从选定的开业Task读取原规则提案，经当前权限和原Core完整复核后展示差异，明确保存仅写业务草稿；发布/采用继续原规则流程。浏览器在派发前只保留Task/Run/Step定位并回读确认，原保存未知只读同一业务收据。定位损坏或不可保存不能当无记录重发。正式[服务端入口](../../../../api/src/modules/ai-native/task-rule-draft.application.ts)复用原授权、原提案引用、Rule Guard及Core收据，保存开关由既有显式配置提供，默认未开放不代表生产可写。

开业诊断同样接入[原模型执行消费者](../ai-native/ConversationOpeningExecution.tsx)：读取原创建收据及任务状态，明确启动原`opening-model`入口，再由原任务读取结果。它只解释所选分区，不保存或发布配置。当前原请求必须保留、未过期、任务未开始且关联一致；发送前保留最少原定位，刷新后只核原收据，未知应答不重发。客户端等待沿原服务端120秒HTTP上限，不改变租约、模型或任务资源限额。

报价对话通过[租赁条件](../ai-native/QuoteCandidateFields.tsx)保存人类明确输入的客户/商品/数量、时间和地点候选，允许多行及缺项；原场景负责澄清、身份/能力/可租性和Core计价。[报价执行](../ai-native/ConversationQuoteExecution.tsx)绑定同一原请求/Task/Run，并复用原补充信息和人工确认组件。候选、原请求受理、模型回答、Core报价、批准建单及支付分别处理，模型或条件不当作报价/业务收据。原报价材料重新准备/确认到建单的完整消费仍按对应正式场景接入，不以本入口的模型启动代表全闭环。

[工作区](AiOperatorPage.tsx)通过明确的「服务端对话」按钮复用[本人对话历史](../ai-native/ConversationHistory.tsx)，沿[既有对话 API](../../api/aiConversations.ts)读取原对话、请求及任务结果。入口复用任务中心权限集、原 Auth 会话及租户/空间身份，不新增路由、运输协议、模型直连或任务状态机。

- 打开面板不自动读取记录；读取、对话生命周期、请求受理、任务创建及后续确认仍分别由原组件的显式动作发起。读记录不启动模型或业务，不能把读成功当成执行成功。
- 左侧聊天与本地成果仍是演示，服务端记录模式有独立标识和说明；演示确认、复制及下载不作用于服务端记录。
- 收起工作区、关闭抽屉、隐藏文档、切换本地会话/能力、账号/空间/会话纪元变化及权限撤回均撤下该模式；返回旧选择不自动恢复或重读。异步回调还要核对当前入口和原会话。
- 原操作日记只沿既有账号/租户/空间身份保存用于 unknown 核对；面板开关不更换原操作键。左侧能力候选与服务端对话能力并非一一映射，不据演示插件开关授予服务端能力。
- 这一入口不是聊天模型接通、动态代码沙箱、全场景执行或跨入口同一任务闭环的验收结论。

## 状态与边界

- `OperatorProvider` 位于已认证的租户/空间 AppShell 内；切换空间或账号后跟随原 shell 卸载清空。刷新后不保留聊天、任务与插件开关，不写业务缓存或localStorage。
- 页面沿既有路由授权展示能力，插件开关仅控制本次演示。状态不代表服务端授权或能力开通。
- 原聊天保留流式回复、停止、执行摘要折叠、工具输入/输出、来源预览、模型菜单、会话切换、编辑/重试分支、版本切换、复制及本地评价。
- Agent run 仅展示任务范围、示例资料读取、规则检索、结果整理等运行步骤。步骤可展开看输入与输出；完成后展示原 `ArtifactView`，不显示原编码示例的差异、测试或 PR。
- 所有时序均为本地模拟。输入「模拟失败」或 `[error]` 可体验一次读取失败与重试；停止、切换会话、禁用能力和卸载均取消旧运行，旧结果不得覆盖新运行。
- 演示步骤仅为可见操作摘要，不展示模型隐藏推理。计时只对应演示，不代表真实接口耗时。
- 工作区渲染 `OperatorArtifact` 的已知语义类型，支持清单、指标、时间表、比较等差异化结果。不执行模型提供的HTML、脚本或React源码；后续扩展格式先增加受控渲染器。
- 附件只保留文件名、类型、大小及图片的本地对象URL，不上传、不解析内容。会话内切换页面时保留预览，租户/空间 shell 卸载时统一释放。复制与下载均为当前示例结果。
- 确认仅生成本地演示回执；不会创建预约、履约任务、资金处理或发送通知。
- 自动化任务支持本地新增、编辑、删除、开关与运行演示。没有后台调度，关闭页面或到达计划时间不会执行。
- 后续接入需补充授权能力目录、模型流式会话、工具调用状态、业务确认与真实执行回执；所有资金以服务端业务结果为准。

## 响应式

宽屏使用原可拖动双栏，收起不会重挂聊天输入。1050px及以下默认收起工作区，按钮打开原Drawer；对话保持一份。插件卡片自适应列数，任务操作在窄屏换行。

## 后续接入

当前 `OperatorContext.respond` 是本地异步事件流；原聊天接收 `ChatStreamEvent`（文本、执行摘要、工具、来源、错误）和 AbortSignal。真实接入时替换该回调，以同一运行ID发布工具事件与受控 `OperatorArtifact`。模型目录、上传、会话持久化和业务确认均需单独接入，不以本地演示状态充当真实执行凭据。
