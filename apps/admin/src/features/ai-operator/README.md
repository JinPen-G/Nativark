# Agent 工作台：原生界面与受控服务接线

入口为原 `/ai-operator`。聊天、最近对话、模型菜单、发送／停止、可调整分栏、窄屏工作区和原主题／动态偏好继续由已完成的前端组件提供。业务宿主不再提供“本地演示／服务端对话”双模式；已有候选能力不等于服务端已开放，未接入项提供原人工业务入口。

## 调用链

[页面](AiOperatorPage.tsx) → [当前范围状态](OperatorContext.tsx) → [原会话桥](native-session.ts) → [正式会话API](../../api/aiConversations.ts) → 原Controller／Guard／场景／Task／Gateway。显式发送才可沿原受理、Task创建、准备及首次启动链调用模型；原权限、预算、资源及业务批准仍由服务端决定。模型菜单只显示服务端路由信息，不能让客户端选择一个原场景协议不会采用的模型。

[右工作区](NativeOperatorWorkspace.tsx)复用[原结果与动态展示](../ai-native/ConversationResult.tsx)、原补充信息、Core报价核对、选单及必要确认组件。候选采用、报价保存、审批、批准、Core执行和原收据读取分别办理；模型文本不证明订单或资金成功。新回复不能覆盖尚未提交的合法草稿，撤权、隐藏及切换范围撤回当前展示。

## 会话与恢复

能力与对话独立绑定，历史只从原服务端有界读取。打开、转接或重开不会新建Task、重发模型或提交业务。浏览器仅保存原定位／操作键，不保存客户正文或模型输出；存储不可读、定位损坏或丢应答时沿原键观察，不能把未观察到当作未发生。新输入和原轮次继续需区分，不将新的用户要求静默替换成旧答案。

原关闭控件核验关闭或释放收据，再复验准确的空闲修订并轮换原journal。下一轮状态仅在该原修订的页面生命周期中有效，结果刷新保留这份证明；历史正文仍按只读方式展示。报价需求沿原4096字合同预检并保留输入原文，拒绝的输入保留在输入框。原Markdown正文携带准确Task／Run／resultId，只有明确启动后才建立首字观测，读取和重开不建立计时窗口。

Copilot通过[固定会话导航](../ai-native/conversation-navigation.ts)转接同一受权对话。引用必须绑定当前账号、租户、空间和会话纪元；服务端重新核验原Task／Run／材料，客户端定位不授予权限。
