# 通知与消息中心

- 原组件：UIArc NotificationCenter（仓库已归档公开源码）、本地组件库 Inbox triage。目录和依赖已复制；样式哈希见 source.json，上游使用说明见 archive/upstream-inbox-triage.md。保留原出处与适用许可，不将本地还原 TSX 声称为官方 Pro 源码。
- NotificationProvider 读取当前租户/空间工作台待办，合并同一订单；AI 消息只来自当前会话实际运行的本地演示，不把预置历史示例当成新通知。
- 消息读取状态与业务待处理状态分离。仅消息 ID、已读和文件夹保存在当前用户/租户/空间的本机状态中；个人状态不写订单、资金或工单；用户明确点击领取/派工时才调用原工单 API。AI 仍只生成本地演示回执。源待办消失后不伪造历史通知，服务端收件箱及跨设备历史仍需正式接入。
- 保留原收件箱/稍后/归档、未读筛选、展开、撤销与键盘功能。稍后沿用原移动文件夹行为，不自行增加一小时自动提醒。铃铛按用户要求单独替换为 Animate UI 动态图标并移除外框。
- 新到事项使用既有通知声音入口，首次读取不播放；沿用用户动效/音效偏好、作用域与跨标签去重。60 秒可见页轮询只用于现有待办投影，不冒充服务端实时推送。
- 原组件不能满足的新业务交互必须先确认范围，再通过独立扩展接入；不得删除或替换已有功能。
- 消息中心通过宿主适配占满可用内容宽度，原 CSS 与分拣交互保留。发件人栏优先显示关联订单号；标题与摘要分层，已知外观损伤枚举仅在展示层转为可读文字。工单事实和业务动作集中在原展开区的有限阅读宽度内，不跨整行拉开标签和值。

## 已授权的业务扩展

- 铃铛弹窗增加“待处理”；消息中心在原未读筛选旁增加“待处理”。两者按业务待办/AI 草稿状态过滤，不用已读代替已处理，原文件夹范围和操作保留。
- 工单展开后按需读取真实资料与可派工账号，支持领取、派工/转交；复用原 API，提交前复核权限、会话作用域、状态和资料版本。原始只读详情入口保留；当前未接入通知内验收、退款或资金裁定。
- AI 展开区支持核对同一结果的事实、确认示例、记录补充要求、下载示例结果。确认逻辑按对话与 run 绑定，补充要求进入原对话并暂停旧草稿确认；新运行清除补充状态。此路径不调用真实模型或提交业务。
- 业务写入不自动重试；结果未知时在当前会话中阻止再次提交，进入原工单核对。原读/归档/稍后/撤销不撤销真实派工。
- 验证使用真实后台页面和只读接口；派工错误路径由独立浏览器拦截写请求并模拟 503，未执行真实派工。
